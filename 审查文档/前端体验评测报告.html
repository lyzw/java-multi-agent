管理控制台（admin-console）前端体验评测报告

评测对象：admin-console（React 18 + TypeScript 5 + Ant Design v5 + Vite 6，平台级管理控制台）
评测范围：登录、平台治理（租户/用户/角色矩阵/审计）、能力目录（Agent/Tool/Skill/MCP/路由策略）、知识与数据（RAG）、系统配置（字典）、观测度量（指标/录入）、AI 实验室
评测日期：2026-10-30
评测方法与边界说明（请先读）：本次评测本计划以真实终端用户身份在浏览器中点击走查。但当前沙箱环境存在网络命名空间隔离—— 浏览器实例仅能访问到用户既有后端（8080/8081），而我能拉起的前端 dev server 处于不可达的独立命名空间，且不应打扰用户正在运行的线上后端， 因此未能完成“真实浏览器点击”式走查。 为保证结论可证伪、不臆测，本报告改用两条可观测证据链：① 对实际前端执行生产构建（npm run build 通过，产物 dist/index-*.js = 1,519 KB / gzip 473 KB，无编译错误）； ② 逐文件审查已实现组件的渲染与交互逻辑（仅报告代码实际做了什么，所有结论附 文件:行号 引用）。 死代码 / 占位文案（如 PlaceholderPage、DashboardPage）作为“已存在但未接入”的客观事实列入问题，而非推测“未实现的功能”。

一、总体结论

架构与交互逻辑较强 视觉一致性中等 响应式薄弱 首屏性能偏弱

控制台在业务正确性上做得相当扎实：统一布局壳、角色过滤导航、fail-closed 的能力发布（无删除只有“停用”+三步+双人复核）、 用户自我保护与 SoD、指标“未采集=— / 样本不足”纪律、错误态区分 403/409/503、404 不泄露权限模型——这些都是高质量企业后台的标志。

主要短板集中在“观感与适配”：响应式几乎只有侧栏折叠一级；主题色/字号大量内联硬编码；术语中英混排与同义不统一； 首屏 1.5MB 单包、无代码分割。这些不会阻断功能，但会拉低专业感与在非常规屏幕上的可用性。

二、UI 层面

2.1 视觉布局 良好

  • 统一外壳：所有鉴权页共享 AdminLayout（antd Layout/Sider/Header/Content），含侧栏分组、面包屑、页脚，结构清晰（AdminLayout.tsx:94-177，router.tsx:42-48）。
  • 导航由单一数据源 NAV_GROUPS 派生，按角色过滤整组（无权整组不渲染），激活态与展开态自动同步（AdminLayout.tsx:28-82）。
  • 内容卡片统一 padding:24 / 圆角8 / 白底，列表页表格 + 搜索栏 + 状态 Tag 的范式在 Tool/Skill/MCP/Agent/租户/用户间高度一致。

2.2 配色与字体 内联硬编码偏多

  • 主色通过 ConfigProvider theme.token.colorPrimary='#2f6df6' 统一设置，并设 zhCN 中文语言包（App.tsx，正确做法）。
  • 但主题色/语义色大量散落为内联十六进制：如 AgentMetricsPage.tsx:334,376,426,459,472,566,633,640 的 #cf1322/#52c41a/#faad14，RoleMatrixPage.tsx:103 的 #52c41a；
  • global.css:20-26 与 App.tsx 各定义了一份 #2f6df6 的选中行底色，未来改主题色将“失同步”。建议统一改用 antd 语义色（colorSuccess/Error/Warning 或 Tag color），删除游离 hex。

2.3 组件一致性 良好

  • 列表页：均用 antd Table + rowKey，统一 loading 属性、emptyText 空态、Tag 表状态、Typography.Text code 表 ID（共享渲染器 displayBits.tsx）。
  • 错误态普遍用 Alert 且区分状态码（platformRequestBits.tsx:45-53 区分 403/503；PlatformPublishPanel.tsx:35-44 区分 400/403/409/503）。
  • 缺憾：无集中共享组件库（src/components 不存在，复用靠同目录就近放置），每个页面重复写 Alert+Table+Spin+emptyText 样板，建议抽 <PageState> / <ErrorBoundary> 统一收敛。

2.4 响应式与易用性 明显短板

  • 唯一的响应式措施是侧栏 breakpoint="lg" + collapsedWidth={screens.xs?0:80}（AdminLayout.tsx:100-101）；全代码库仅此一处 useBreakpoint，无任何 useMediaQuery/matchMedia/@media。
  • 统计卡固定 4 列：全站 85 处 <Col>，0 处响应式断点，全部 span={6}（如 AgentMetricsPage.tsx:322,325,341,344,366,406,409,412,421,447；Tool/Skill/MCP/Agent 注册表同此）。在 1280 以下笔记本/平板上会被挤压，不重排为 2/1 列。
  • 弹窗/抽屉固定像素宽：PlatformRegistrationModal width={960}（PlatformRegistrationModal.tsx:86）、指标下钻 Drawer width={720}（AgentMetricsPage.tsx:708）、详情抽屉 width={760}（platformDetailDrawer.tsx:48），窄屏下易横向溢出。
  • a11y 小缺口：侧栏折叠按钮为 <span onClick> 无 role/aria-label（AdminLayout.tsx:143）；“退出登录”下拉无 aria 标注。
  • 折叠态品牌名显示为 "PC"（AdminLayout.tsx:117），语义不清，建议用图标或“控制台”。

三、业务流程层面

3.1 登录 顺畅

用户名/密码 + 加载态 + 成功 message 跳回来源页；失败统一 Alert 且不区分原因（后端统一 401 防账号枚举，安全正确，LoginPage.tsx:23,49-58,84-86,108）。无租户 ID 输入（平台/租户身份隔离，符合设计）。落地页直接重定向到 /tenants——新用户缺少一个“总览/仪表盘”承接（见 3.7）。

3.2 能力三步发布（申请→审批→执行） 逻辑严谨

  • 三步在单面板并列呈现，强调“审批人≠申请人”双人复核（PlatformPublishPanel.tsx:69-78,80-268）；提交前 form.validateFields() 重型前端校验（kind 互斥、URL/超时、JSON 合法性、闭包自洽，platformObjectForm.ts:116-451）。
  • 审批队列抽屉提供“通过/执行”双入口并带 Popconfirm（platformRequestBits.tsx:147-259）；无删除，仅“停用”迁移到 DEPRECATED 终态（PlatformDeprecateCard.tsx，platformObjectForm.ts:467-468），fail-closed 设计优秀。
  • 可改进：三步“并列”呈现，新手可能不清楚“执行”需另一人触发；建议用步骤条（Steps）强化阶段感。

3.3 租户生命周期 顺畅

状态机只暴露合法迁移、非法迁移后端 409 并提示（TenantRegistryPage.tsx:32-39,82-99,117-118）；详情页三 Tab（基本信息/配额/能力授权），能力撤销用 Popconfirm（TenantDetailPage.tsx:295-303）。 短板：生命周期变更 Modal 的 OK 按钮无 confirmLoading，异步期间可重复点击（TenantRegistryPage.tsx:192-221）。

3.4 平台用户管理 完善

新建/启停/重置密码/赋撤角色齐全；自我保护到位：对自身操作禁用并 Tooltip 说明、自身不可改角色、最后超管保护、超管 SoD 禁用（UsersManagePage.tsx:44-51,147-206,276-324）；破坏性操作均有 Popconfirm（279-291,564-575）。 短板：角色撤销 Popconfirm 的异步无 loading/禁用态。

3.5 角色矩阵 / RAG / 指标 / 路由守卫 克制且诚实

  • 角色矩阵：按命名空间分 Tab 的“权限×6角色”只读冻结表（RoleMatrixPage.tsx:12-29,164-200），明确标注“只读·冻结”。
  • RAG：租户作用域（本租户/平台全局/跨租户盘点）显式选择并落到 X-Rag-Scope；403→“去领票据”，409 不给刷新避免重复非法转移（RagManagementPage.tsx:236-273，useRagManagement.ts:109-130）。缺憾：RAG 对 503 未像能力目录页那样显式区分（目录页有 503 分支，RAG hook 只分 timeout/409/403）。
  • 指标：未采集='—'（非 0）、样本量<30 显“样本不足”（AgentMetricsPage.tsx:75-109,546,564），链路成功率与任务成功率物理隔离——核心纪律已实现。
  • 路由守卫：RequireAuth 跳登录带 state.from；RequireRole 无权限给 403 Result；404 刻意不列站点地图（防泄露权限模型，NotFoundPage.tsx:7-11）。

3.6 核心操作路径顺畅度

登录→治理→能力发布→审计这条主链路整体顺畅、步骤合理、校验充分，关键写操作的“二次确认/双人复核/自身保护”均到位，不存在功能性阻断。困惑点主要来自信息呈现而非流程卡死。

3.7 阻断 / 困惑点

  • 落地即 /tenants，无仪表盘：新用户进入后缺乏总览；而 DashboardPage.tsx 已实现却完全未接线（死代码），说明“概览”能力被规划但丢弃。
  • 能力“执行”需平台运维通道：未接入会话窗时返回 503 不可达，用户可能困惑“为什么我不能执行/发布”。
  • 术语混用增加认知成本（见问题清单 P4）。
  • 窄屏拥挤：响应式缺失在 13 寸及以下笔记本、平板场景下明显（见 P1）。

四、问题清单（按严重程度分级）

#严重度问题位置（可证伪）影响 / 改进建议
P1严重 响应式几乎缺失：仅侧栏折叠一级；统计卡固定 4 列、弹窗/抽屉固定像素宽 AdminLayout.tsx:100-101；85 处 <Col span={6}> 无断点；PlatformRegistrationModal.tsx:86(960)、AgentMetricsPage.tsx:708(720) 13 寸笔记本/平板下拥挤甚至横向溢出。建议：关键栅格改用 xs/sm/md/lg 响应式断点；Modal/Drawer 用 width="80vw" maxWidth=... 或 responsive。
P2严重 首屏体积过大、无代码分割 构建产物 dist/index-*.js=1,519KB(gzip 473KB)；全仓无 lazy()/Suspense 首次访问（尤其弱网/海外）白屏时间长。建议：路由级 React.lazy + Suspense 分包；按需引入 antd 组件；评估 antd 的 transform-full-import / 仅引 Icon。
P3重要 主题色/语义色大量内联硬编码，脱离 design token AgentMetricsPage.tsx:334,376,426,459,472,566,633,640；RoleMatrixPage.tsx:103；global.css:20-26 与 App.tsx 双份 #2f6df6 换肤/改主题时会“失同步”，视觉不统一。建议：统一用 antd 语义色与 theme.token/theme.useToken()，删除游离 hex。
P4重要 术语与中英混排不一致 导航 “Tool/Skill/MCP Server” 保留英文 vs 其余中文；同义“停用/退役”“开通/登记/新建”不统一（navConfig.tsx:110-148、PlatformDeprecateCard.tsx、TenantRegistryPage.tsx:89、UsersManagePage.tsx:337） 增加用户认知负担、检索困难。建议：建统一术语表；能力对象名若须保留英文，至少在导航/标题给出中文括注（如“工具 Tool”）。
P5重要 死代码 / 孤儿页：已实现但未接线，含“coming soon”文案 PlaceholderPage.tsx、DashboardPage.tsx 全仓无引用（grep 仅定义处）；SettingsPage.tsx:127 “全局参数暂未开放” 维护噪音、易误判交付范围；缺失的仪表盘削弱首屏体验。建议：要么接线（仪表盘作为登录后落地页），要么删除死代码与占位提示。
P6一般 部分异步触发器缺 in-flight 禁用/旋转 租户生命周期 Modal OK 无 confirmLoading（TenantRegistryPage.tsx:192-221）；用户角色撤销 Popconfirm 无 loading（UsersManagePage.tsx:564-575） 存在重复提交/双击隐患。建议：异步期间禁用触发器并加旋转。
P7一般 RAG 对 503 未显式区分 useRagManagement.ts:118-134（仅分 timeout/409/403）vs 能力目录 platformRequestBits.tsx:48-49（有 503 分支） 运维通道未接入时，用户可能只看到笼统报错。建议：对齐能力目录页，显式提示“平台运维会话窗未接入”。
P8一般 列表无服务端分页 / 虚拟滚动 各列表 pagination={false} + 一次拉全量（limit:100/200）+ 前端过滤（TenantRegistryPage.tsx:68,154 等） 租户/对象量级变大后首屏慢、内存高。建议：引入服务端分页或虚拟滚动（react-window）。
P9一般 a11y 小缺口 + 折叠品牌名歧义 AdminLayout.tsx:143 折叠按钮无 aria；折叠态显示 "PC"（:117） 屏幕阅读器与新手理解成本。建议：补 role="button" aria-label；折叠态用图标或“控制台”。

五、优势沉淀（建议保留）

✓ 统一布局壳 + 角色过滤导航
✓ 错误态区分 403/409/503，RAG 403→领票据
✓ 指标“未采集=— / 样本不足”纪律落地
✓ 用户自我保护 + SoD + 最后超管保护
✓ 能力对象 fail-closed（无删除，三步+双人复核）
✓ 404 不泄露权限模型；前端生产构建通过

六、改进优先级建议

  • 第一优先（体验/性能硬伤）：P2 代码分割（投入小、收益大）、P1 关键栅格与弹窗响应式。
  • 第二优先（专业感）：P3 颜色走 token、P4 统一术语表、P5 清理死代码并上线仪表盘作为落地页。
  • 第三优先（打磨）：P6 in-flight 禁用、P7 RAG 503 提示、P8 分页、P9 a11y。
