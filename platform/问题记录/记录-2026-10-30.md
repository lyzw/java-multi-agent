### 问题 1: RunController.java 构造器注入顺序与 @Autowired 构造器不一致

**所在文件**: `/Users/zhouwei/code-workspace/ai-tech/java-multi-agent/platform/agent-api/src/main/java/cn/studykid/multiagent/api/run/RunController.java`

**问题描述**:
RunController 类有三个构造器：
1. 两参数构造器（第 73-78 行）
2. 四参数构造器（第 80-87 行）
3. @Autowired 五参数构造器（第 89-102 行）

第一个构造器调用第二个构造器时，参数顺序为：`(runCreation, authorization, retentionGate, currentPrincipal, NEVER_LIMIT)`
第二个构造器调用第三个构造器时，参数顺序为：`(runCreation, authorization, retentionGate, currentPrincipal, rateLimiter, promptGuard)`

但第二个构造器的参数列表顺序是：`(RunCreationService, AuthorizationService, ZeroRetentionGate, CurrentPrincipal, RateLimitPort)`

**原因分析**:
构造器链调用时参数顺序不一致，可能导致 Spring 依赖注入时参数绑定错误。虽然当前代码中第一个构造器调用第二个构造器时传入了正确的参数顺序，但这种不一致性容易在维护时引入错误。

**修复方式**:
```java
// 修复：统一构造器参数顺序
// 第一个构造器（两参数）

                     AuthorizationService authorization,
                     ZeroRetentionGate retentionGate,
                     CurrentPrincipal currentPrincipal) {
    this(runCreation, authorization, retentionGate, currentPrincipal, NEVER_LIMIT);
}

// 第二个构造器（五参数）
public RunController(RunCreationService runCreation,
                     AuthorizationService authorization,
                     ZeroRetentionGate retentionGate,
                     CurrentPrincipal currentPrincipal,
                     RateLimitPort rateLimiter) {
    this(runCreation, authorization, retentionGate, currentPrincipal, rateLimiter,
            new cn.studykid.multiagent.application.prompt.PromptGuard());
```

### 问题 3: ApiExceptionHandler.java handleResponseStatus 方法可能覆盖控制器声明的 5xx 状态

**所在文件**: `/Users/zhouwei/code-workspace/ai-tech/java-multi-agent/platform/agent-api/src/main/java/cn/studykid/multiagent/api/error/ApiExceptionHandler.java`

**问题描述**:
`handleResponseStatus` 方法（第 302-315 行）处理 `ResponseStatusException` 时，对于 5xx 状态码会将其转换为 500。但该方法可能覆盖控制器显式声明的 5xx 状态码。

**原因分析**:
```java
@ExceptionHandler(ResponseStatusException.class)
public ResponseEntity<ErrorResponse> handleResponseStatus(ResponseStatusException e) {
    HttpStatus status = HttpStatus.resolve(e.getStatusCode().value());
    // ⚠️ 未映射到 HttpStatus 的状态码按 500 处理
    if (status == null || status.is5xxServerError()) {
        log.error("控制器声明了非法或服务端错误状态: code={}", e.getStatusCode(), e);
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(new ErrorResponse("INTERNAL_ERROR", "服务暂时不可用"));
    }
    // ...
}
```

当控制器显式声明 5xx 状态码时（如 503 SERVICE_UNAVAILABLE），此方法会将其转换为 500，破坏了语义。

**修复方式**:
```java
@ExceptionHandler(ResponseStatusException.class)
public ResponseEntity<ErrorResponse> handleResponseStatus(ResponseStatusException e) {
    HttpStatus status = HttpStatus.resolve(e.getStatusCode().value());
    // ⚠️ 未映射到 HttpStatus 的状态码按 500 处理
    if (status == null) {
        log.error("控制器声明了非法状态码: code={}", e.getStatusCode(), e);
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(new ErrorResponse("INTERNAL_ERROR", "服务暂时不可用"));
    }
    // ⚠️ 控制器显式声明的 5xx 状态码保持原样
    if (status.is5xxServerError()) {
        log.warn("控制器声明了服务端错误状态: code={}", e.getStatusCode());
        return ResponseEntity.status(status)
                .body(new ErrorResponse(codeOf(status), messageOf(status)));
    }
    log.info("控制器声明的状态: code={}", e.getStatusCode());
    return ResponseEntity.status(status)
            .body(new ErrorResponse(codeOf(status), messageOf(status)));
}
```

### 问题 4: PlatformExecutionTicketService.java 审计记录中 targetId 可能为 null 导致 UUID.fromString 异常

**所在文件**: `/Users/zhouwei/code-workspace/ai-tech/java-multi-agent/platform/agent-api/src/main/java/cn/studykid/multiagent/api/platform/PlatformExecutionTicketService.java`

**问题描述**:
`record` 方法（第 303-312 行）中，当 `principalId` 为 null 或不是 UUID 格式时，`UUID.fromString(principalId)` 会抛出异常。

**原因分析**:
```java
private void record(PlatformPrincipal principal, String tenantId,
                    String principalId, String decision, String reasonCode) {
    audit.record(new PlatformAuditEvent(
            UUID.randomUUID(), principal.userId(), "PLATFORM_USER",
            AUDIT_ACTION, TARGET_TYPE, isUuid(tenantId) ? tenantId : null,
            decision, reasonCode,
            principalId == null || !isUuid(principalId)
                    ? null : UUID.fromString(principalId),  // 可能抛出异常
            null, Instant.now(), null));
}
```

虽然 `isUuid` 方法已经检查了 UUID 格式，但 `UUID.fromString` 仍可能抛出异常（如空字符串）。

**修复方式**:
```java
private void record(PlatformPrincipal principal, String tenantId,
                    String principalId, String decision, String reasonCode) {
    UUID principalUuid = null;
    if (principalId != null && isUuid(principalId)) {
        try {
            principalUuid = UUID.fromString(principalId);
        } catch (IllegalArgumentException e) {
            // 记录日志，但不抛出异常
            log.warn("principalId 不是有效的 UUID: {}", principalId);
        }
    }
    audit.record(new PlatformAuditEvent(
            UUID.randomUUID(), principal.userId(), "PLATFORM_USER",
            AUDIT_ACTION, TARGET_TYPE, isUuid(tenantId) ? tenantId : null,
            decision, reasonCode,
            principalUuid,
            null, Instant.now(), null));
}
```

### 问题 5: PlatformRagGovernanceTicketService.java auditableScope 方法可能返回 null 导致审计写入异常

**所在文件**: `/Users/zhouwei/code-workspace/ai-tech/java-multi-agent/platform/agent-api/src/main/java/cn/studykid/multiagent/api/platform/PlatformRagGovernanceTicketService.java`

**问题描述**:
`auditableScope` 方法（第 297-299 行）可能返回 null，而数据库 CHECK 约束可能不允许 null 值。

**原因分析**:
```java
private static @Nullable String auditableScope(@Nullable String raw) {
    return raw != null && AUDITABLE_SCOPES.contains(raw) ? raw : null;
}
```

当 `raw` 不在 `AUDITABLE_SCOPES` 中时，返回 null。但数据库 CHECK 约束 `platform_audit_event_ticket_scope_ck` 只承认三个规范值（PLATFORM / TENANT / ALL），null 值可能导致审计写入异常。

**修复方式**:
```java
private static @Nullable String auditableScope(@Nullable String raw) {
    if (raw != null && AUDITABLE_SCOPES.contains(raw)) {
        return raw;
    }
    // ⚠️ 规范集之外一律写 null（＝「档位不可知」），
    // 而「不可知」本身是可查的事实，好过一次为了填满列而编造的归因。
    return null;
}
```

当前实现是正确的，但需要在文档中明确说明 null 值的语义。

### 问题 6: ConfigPublishWorkflowService.java executeLifecycle 方法中异常处理可能丢失原始异常信息

**所在文件**: `/Users/zhouwei/code-workspace/ai-tech/java-multi-agent/platform/agent-application/src/main/java/cn/studykid/multiagent/application/cap/ConfigPublishWorkflowService.java`

**问题描述**:
`executeLifecycle` 方法（第 468-492 行）中，当 `lifecycle.transition` 返回 false 时，抛出 `ConfigPublishBaselineConflictException`，但原始异常信息可能被丢失。

**原因分析**:
```java
private void executeLifecycle(String tenantId, ConfigPublishRequest request,
                              ConfigPublishPayload payload) {
    ConfigPublishPayload.LifecycleSpec spec = payload.lifecycle();
    if (spec == null) {
        throw new IllegalArgumentException("生命周期申请缺少 lifecycle 参数");
    }
    requireTenantObjectType(spec.type());
    ConfigLifecycleState from;
    ConfigLifecycleState to;
    try {
        from = ConfigLifecycleState.valueOf(spec.expectedFrom());
        to = ConfigLifecycleState.valueOf(spec.to());
    } catch (IllegalArgumentException e) {
        throw new IllegalArgumentException("生命周期状态非法: " + e.getMessage(), e);
    }
    boolean moved = lifecycle.transition(spec.type(), tenantId, spec.objectId(),
            spec.version(), from, to);
    if (!moved) {
        // ⚠️ 原状态不符 = 并发竞争（CAS 前置条件不满足）。
        //    这不是「迁移非法」，而是「别人先动了」—— 两者必须能分开。
        throw new ConfigPublishBaselineConflictException(
                "生命周期迁移的原状态不符：期望 " + from + "，对象 " + spec.objectId()
                        + " v" + spec.version() + " 当前不在该状态");
    }
}
```

当 `lifecycle.transition` 抛出异常时，原始异常信息被丢失。

**修复方式**:
```java
private void executeLifecycle(String tenantId, ConfigPublishRequest request,
                              ConfigPublishPayload payload) {
    ConfigPublishPayload.LifecycleSpec spec = payload.lifecycle();
    if (spec == null) {
        throw new IllegalArgumentException("生命周期申请缺少 lifecycle 参数");
    }
    requireTenantObjectType(spec.type());
    ConfigLifecycleState from;
    ConfigLifecycleState to;
    try {
        from = ConfigLifecycleState.valueOf(spec.expectedFrom());
        to = ConfigLifecycleState.valueOf(spec.to());
    } catch (IllegalArgumentException e) {
        throw new IllegalArgumentException("生命周期状态非法: " + e.getMessage(), e);
    }
    try {
        boolean moved = lifecycle.transition(spec.type(), tenantId, spec.objectId(),
                spec.version(), from, to);
        if (!moved) {
            throw new ConfigPublishBaselineConflictException(
                    "生命周期迁移的原状态不符：期望 " + from + "，对象 " + spec.objectId()
                            + " v" + spec.version() + " 当前不在该状态");
        }
    } catch (RuntimeException e) {
        // ⚠️ 保留原始异常信息
        log.error("生命周期迁移失败: type={}, objectId={}, version={}",
                spec.type(), spec.objectId(), spec.version(), e);
        throw e;
    }
}
```
