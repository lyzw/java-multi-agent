# RAG 页面收口整理说明（2026-11-22）

## 现状问题

- RAG 在侧栏占 **4 个顶级分组**（录入与校对 / 审核 / 规则配置 / 运维），另有旧 `/rag` 五 Tab 单页与配置中心里的 RAG 规则索引。
- 改造前同一批页面在「菜单 / 旧单页 / 配置中心」各有一份路径认知，用户难以判断该从哪个入口进入。
- 路径本身无重复；问题是入口过多、命名不统一。

## 本次调整

1. **顶级入口收口为一个分组**
   - `navConfig.tsx`：四个 RAG 顶级分组合并为 `rag-workbench`（`RAG 工作台`），共 14 个节点。
   - `NavNode` 新增可选 `section`；组内按 `总览 / 录入与校对 / 审核 / 规则配置 / 运维` 渲染小标题。
   - 所有 RAG 路径仍全站唯一，面包屑统一为 `平台控制台 / RAG 工作台 / <页面>`。

2. **新增工作台总览页 `/rag`**
   - `src/pages/rag/RagWorkbenchPage.tsx` 只做索引与口径说明，不复制任何读写表单。
   - 页面卡片从 `NAV_GROUPS` 中 `rag-workbench` 分组的 `children` 派生，避免菜单与总览页各存一份路径清单而漂移。
   - 统一说明作用域、租户头、治理票据与切档清数据规则。

3. **旧单页降级为兼容路由**
   - `/rag` 从五 Tab 单页改为工作台总览；旧页移至 `/rag/legacy`，不进侧栏，能力不删。
   - 旧页仍保留 `RagManagementPage` 的五 Tab（统计 / 审核待办 / 有效期 / 维护等），仅不再占据主入口。

4. **命名统一**
   - `RagScopeShell` 页内面包屑从 `RAG 语料管理 · <域>` 改为 `RAG 工作台 · <域>`。
   - 配置中心 RAG 规则项的说明与标签改为「RAG 工作台」。

5. **菜单渲染支持组内小标题**
   - `AdminLayout.tsx` 新增 `toMenuChildren`，带 `section` 的节点渲染为 AntD `type: 'group'`，其他分组不受影响。

  - 侧栏只剩一个 `RAG 工作台` 分组，展开后显示 5 个域小标题；

  - `/rag/sources` 面包屑为 `RAG 工作台 / 来源列表`，页内小标题为 `RAG 工作台 · 录入与校对`；
  - `/rag/legacy` 仍可打开旧五 Tab 页。

## 边界

- 未改后端接口、数据库字段或任何 RAG 治理逻辑。
- 未删除任何页面；旧单页隐藏在 `/rag/legacy`，其页标题仍按父节点显示为「工作台总览」（兼容路由，不进侧栏）。
- 本次只整理入口与命名；RAG 功能正确性仍由既有 IT / 单测与专项报告负责。
