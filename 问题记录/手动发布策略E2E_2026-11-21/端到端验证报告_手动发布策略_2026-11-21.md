## 5. 发现的异常

### A1 · 平台超管口令与历史记录不一致（环境异常，已就地重置）

- 现象：`plat-superadmin / Plat#2026!` 登录返回 401；历史记录（2026-11-03）称已重置为该口令，实际 RDS `platform.platform_user` 哈希不匹配。
- 处理：作为测试前置，向 RDS 写入按服务端同算法（PBKDF2-HMAC-SHA256, 600000）生成的 `Plat#2026!` 哈希，仅改 `plat-superadmin` 一行；随后登录成功。仓库脚本 `dev-seed-platform-users.sh` 本次不可用（`SeedPlatformUsers.java` 引用的 `PrincipalRepository$PasswordHasher` 已迁移，编译失败）。
- 影响：不影响发布策略结论；但说明**开发凭据缺乏可靠交付方式**。**已于 §7 修复播种脚本**（哈希类迁移 + 校验语义对齐），并用两种模式 dry-run 复测通过。

### A2 · Tool 登记页提交必然 400（真实前端缺陷，与策略无关）

- 现象：按 UI 表单填写 Tool 标识/名称/风险等级/理由后提交，统一提示“门禁预检拒绝（400）”，无字段级错误；加参数重试仍失败。
- 抓包证据：UI 实际请求体为
  `{"tools":[{"toolId":"e2e-manual-tool-1121b","riskLevel":"READ","name":"…","inputSchema":"...","paramPolicies":"{}"}],"reason":"…"}`
  —— **缺少 `kind`**。原因是 `ToolFormFields` 用隐藏字段承载 `kind`，但 NATIVE 只由 Tab 推导 `activeKind`，从未写入表单字段；`buildToolSpec` 只读 `values.kind`，导致后端收到 `kind=null`。
- 对照：用同一后端 API 显式带 `kind: "NATIVE"` 提交，立即返回 `APPROVED`（MANUAL 分流），证明**后端策略链正常，缺陷仅在前端登记入口**。
- 影响：Tool 无法从控制台登记/改版（列表也无「改版」入口）；本次 Tool 链路改用 API 提交 + UI 手动执行完成验证。**已于 §7 修复**：隐藏 `kind` 增加 `initialValue="NATIVE"`、纯函数补 kind 守卫、Tool 目录补行内「改版」入口，并已用真实浏览器复测通过。
