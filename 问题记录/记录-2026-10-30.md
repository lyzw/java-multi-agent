### 问题 1: SkillCatalogPage.tsx - 表单加载状态与过滤数据不一致

**所在页面**: `src/pages/console/SkillCatalogPage.tsx`

**问题描述**:
在 `renderTable` 函数中，`loading` 状态设置为 `loading && data === filtered`。当用户进行搜索过滤时，`filtered` 数据可能已经加载完成，但 `loading` 状态仍为 `true`，导致表格显示加载状态而实际数据已可用。

**原因分析**:
```typescript
const renderTable = (data: SkillCatalogItem[]): JSX.Element => (
  <Table<SkillCatalogItem>
    rowKey="skillId"
    loading={loading && data === filtered}  // 问题所在
    dataSource={data}
    ...
  />
)
```
当 `data === filtered` 为 `true` 时，`loading` 状态仍为 `true`，导致表格持续显示加载状态。

**修复方式**:
```typescript
const renderTable = (data: SkillCatalogItem[]): JSX.Element => (
  <Table<SkillCatalogItem>
    rowKey="skillId"
    loading={loading && data.length === 0}  // 修复：仅当数据为空时显示加载
    dataSource={data}
    ...
  />
)
```

### 问题 2: SkillCatalogPage.tsx - 双 Modal 组件状态管理潜在风险

**所在页面**: `src/pages/console/SkillCatalogPage.tsx`

**问题描述**:
页面中存在两个 `PlatformRegistrationModal` 组件，分别用于登记和改版。当 `reviseRow` 变化时，`initialValues` 可能不会及时更新，导致表单预填数据不正确。

**原因分析**:
```tsx
<PlatformRegistrationModal<SkillFormValues & { reason: string; expectedPublishSeq?: number }>
  open={reviseRow !== null}
  title={reviseRow ? `改版 Skill · ${reviseRow.skillId}（申请 → 审批 → 执行）` : '改版 Skill'}
  initialValues={reviseRow ? skillToFormValues(reviseRow) : undefined}  // 潜在问题

  ...

```

  key={reviseRow?.skillId ?? 'register'}  // 添加 key 强制重新挂载

### 问题 3: AgentMetricsPage.tsx - 布尔值显示与未采集状态不一致

**所在页面**: `src/pages/metrics/AgentMetricsPage.tsx`

**问题描述**:
`yn` 函数用于显示布尔值，但当值为 `null` 时返回 `'—'`（NOT_COLLECTED），而其他函数如 `pct`、`ms`、`count` 也使用相同的 `NOT_COLLECTED` 常量。这可能导致显示不一致。

**原因分析**:
```typescript
function yn(v: boolean | null): string {
  if (v === null) {
    return NOT_COLLECTED  // 返回 '—'
  }
  return v ? '是' : '否'
}
```
当 `v` 为 `null` 时，显示 `'—'`，但用户可能期望看到 `'未采集'` 或其他更明确的提示。

**修复方式**:
```typescript
function yn(v: boolean | null): string {
  if (v === null) {
    return '未采集'  // 更明确的提示
  }
  return v ? '是' : '否'
}
```

### 问题 4: MetricEntryPage.tsx - Form 实例重复创建问题

**所在页面**: `src/pages/metrics/MetricEntryPage.tsx`

**问题描述**:
`EntryCard` 组件内部使用 `Form.useForm()` 创建表单实例，每次渲染都会创建新的表单实例，可能导致表单状态丢失。

**原因分析**:
```typescript
function EntryCard({ title, description, status, onFinish, children }: EntryCardProps): JSX.Element {
  const [form] = Form.useForm()  // 每次渲染创建新实例
  const submitting = status.kind === 'submitting'
  return (
    <Card title={title} size="small">
      <Form form={form} layout="vertical" disabled={submitting} onFinish={(v) => onFinish(v as Record<string, unknown>)}>
        ...
      </Form>
    </Card>
  )
}
```

**修复方式**:
```typescript
function EntryCard({ title, description, status, onFinish, children }: EntryCardProps): JSX.Element {
  const [form] = Form.useForm()  // 保持现有实现，但需要确保父组件不会不必要地重新渲染
  const submitting = status.kind === 'submitting'
  
  // 使用 React.memo 或 useMemo 来避免不必要的重新渲染
  const formElement = useMemo(() => (
    <Form form={form} layout="vertical" disabled={submitting} onFinish={(v) => onFinish(v as Record<string, unknown>)}>
      {children}
      <Space>
        <Button type="primary" htmlType="submit" loading={submitting}>
          提交录入
        </Button>
        <Button onClick={() => form.resetFields()} disabled={submitting}>
          重置
        </Button>
      </Space>
    </Form>
  ), [form, submitting, onFinish, children])
  
  return (
    <Card title={title} size="small">
      <Typography.Paragraph type="secondary" style={{ fontSize: 12 }}>
        {description}
      </Typography.Paragraph>
      {formElement}
      <StatusAlert status={status} />
    </Card>
  )
}
```

### 问题 5: AgentLabPage.tsx - 轮询定时器潜在内存泄漏

**所在页面**: `src/pages/agentlab/AgentLabPage.tsx`

**问题描述**:
`poll` 函数使用 `window.setInterval` 创建定时器，但在组件卸载时可能无法正确清理，导致内存泄漏。

**原因分析**:
```typescript
const poll = useCallback((...) => {
  stopPolling()
  setPolling(true)
  let n = 0
  let fails = 0
  pollTimer.current = window.setInterval(() => {
    // ...
  }, POLL_INTERVAL_MS)
}, [stopPolling])

useEffect(() => stopPolling, [stopPolling])  // 仅在 stopPolling 变化时清理
```
当组件卸载时，`stopPolling` 函数可能不会被调用，导致定时器继续运行。

**修复方式**:
```typescript
useEffect(() => {
  return () => {
    if (pollTimer.current !== null) {
      window.clearInterval(pollTimer.current)
      pollTimer.current = null
    }
  }
}, [])
```

### 问题 6: DependencyGraphPage.tsx - Checkbox.Group 重复渲染问题

**所在页面**: `src/pages/dependencies/DependencyGraphPage.tsx`

**问题描述**:
`Checkbox.Group` 的 `value` 属性使用 `[...activeTypes]` 创建新数组，每次渲染都会创建新的数组引用，导致 Checkbox.Group 不必要地重新渲染。

**原因分析**:
```typescript
<Checkbox.Group
  options={ALL_TYPES.map((t) => ({
    label: NODE_TYPE_LABELS[t],
    value: t,
  }))}
  value={[...activeTypes]}  // 每次渲染创建新数组
  onChange={(values) => setActiveTypes(new Set(values as GraphNodeType[]))}
/>
```

**修复方式**:
```typescript
const activeTypesArray = useMemo(() => [...activeTypes], [activeTypes])

<Checkbox.Group
  options={ALL_TYPES.map((t) => ({
    label: NODE_TYPE_LABELS[t],
    value: t,
  }))}
  value={activeTypesArray}
  onChange={(values) => setActiveTypes(new Set(values as GraphNodeType[]))}
/>
```

### 问题 7: PublishCenterPage.tsx - useEffect 依赖项不必要触发

**所在页面**: `src/pages/publish/PublishCenterPage.tsx`

**问题描述**:
`useEffect` 依赖 `load` 函数和 `tab` 状态，但 `load` 函数是使用 `useCallback` 记忆化的，不依赖 `tab`。这可能导致效果不必要地触发。

**原因分析**:
```typescript
const load = useCallback(async (state?: string) => {
  setLoading(true)
  try {
    const [page, ptr] = await Promise.all([
      getPublishRequests({ state, limit: 50 }),
      getPublishPointer(),
    ])
    setItems(page.items)
    setPointer(ptr)
  } finally {
    setLoading(false)
  }
}, [])  // 不依赖 tab

useEffect(() => {
  void load(STATE_TABS.find((t) => t.key === tab)?.state)
}, [load, tab])  // tab 变化时也会触发
```

**修复方式**:
```typescript
useEffect(() => {
  const state = STATE_TABS.find((t) => t.key === tab)?.state
  void load(state)
}, [load, tab])  // 保持现有实现，但可以添加注释说明为什么需要 tab 依赖
```

或者，如果 `load` 函数确实不需要 `tab` 参数，可以将其移到 `useEffect` 内部：

```typescript
useEffect(() => {
  const state = STATE_TABS.find((t) => t.key === tab)?.state
  const fetchData = async () => {
    setLoading(true)
    try {
      const [page, ptr] = await Promise.all([
        getPublishRequests({ state, limit: 50 }),
        getPublishPointer(),
      ])
      setItems(page.items)
      setPointer(ptr)
    } finally {
      setLoading(false)
    }
  }
  void fetchData()
}, [tab])  // 仅依赖 tab
```

### 问题 9: RagManagementPage.tsx - 作用域切换时可能中断用户操作

**所在页面**: `src/pages/rag/RagManagementPage.tsx`

**问题描述**:
当用户切换作用域（TENANT/PLATFORM/ALL）时，`useEffect` 会清空选中项、重置维护面板、作废票据等操作。如果用户正在编辑或查看某个语料来源，这些操作可能会中断用户的工作。

**原因分析**:
```typescript
useEffect(() => {
  setSelected(null)
  setMaintenanceKey((k) => k + 1)
  resetAll()
  revokeTicket()
  setSearches([])
  setImports([])
}, [tenantId, scope, resetAll, revokeTicket])
```

**修复方式**:
在清空操作前添加确认提示：
```typescript
useEffect(() => {
  if (tenantId === prevTenantIdRef.current && scope === prevScopeRef.current) {
    return
  }
  
  if (selected !== null || registerOpen) {
    // 显示确认对话框
    Modal.confirm({
      title: '切换作用域将清空当前操作',
      content: '您有未保存的更改，确定要切换吗？',
      onOk: () => {
        performClear()
      },
    })
    return
  }
  
  performClear()
}, [tenantId, scope, resetAll, revokeTicket])
```

### 问题 10: DictionaryAdminPage.tsx - 自动选择逻辑可能覆盖用户选择

**所在页面**: `src/pages/dictionaries/DictionaryAdminPage.tsx`

**问题描述**:
`useEffect` 会自动选择第一个字典，当字典列表变化时，可能会覆盖用户的当前选择。

**原因分析**:
```typescript
useEffect(() => {
  const first = list[0]
  if (selectedCode === null && first) {
    setSelectedCode(first.dictCode)
  }
}, [list, selectedCode])
```
当 `list` 变化时，如果 `selectedCode` 为 `null`，会自动选择第一个字典。但如果用户已经选择了某个字典，这个逻辑不会触发。问题在于，当 `list` 被清空后重新加载时，`selectedCode` 可能不会被正确重置。

**修复方式**:
```typescript
useEffect(() => {
  const first = list[0]
  if (selectedCode === null && first) {
    setSelectedCode(first.dictCode)
  } else if (selectedCode !== null && !list.some(d => d.dictCode === selectedCode)) {
    // 当前选择的字典不在列表中，选择第一个
    if (first) {
      setSelectedCode(first.dictCode)
    }
  }
}, [list, selectedCode])
```
