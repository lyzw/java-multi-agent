## 三、问题清单（编号与标注副本一一对应）

### P1　AI 回答直接把公式和 Markdown 源码符号显示给学生　`[V3 可读性]`
- **位置**：学生端结果页、学生端通用问答、错题反馈页；教师端结果页。
- **可见现象**：正文里直接出现 `\left[`、`\begin{matrix}…\end{matrix}`、`$$`、`##`、`**文字**`、`\times`、`\[ … \]`、`---` 等源码符号，没有渲染成公式或加粗/标题样式。
- **影响**：这是给学生看的错题辅导内容，公式以 `\times`、`\begin{matrix}` 这类源码形式出现，非数学专业人员读不懂，直接损害"看懂错在哪、怎么补"的核心价值。
- **建议**：在前端补上 Markdown + 数学公式渲染，把 `$$…$$`、`\[…\]` 渲染为排版公式，`**…**`、`### …` 渲染为加粗与标题。管理后台已有一套 katex/react-markdown 渲染链路（含数学定界符规范化），可复用其思路，避免再写一个不一致的版本。
- **复核条件**：同一条回答中源码符号不再以字面形式出现；公式以排版形式呈现；标题/加粗以字重字号体现。
- **标注副本**：`annotated/student_07-result__anno.png`、`teacher_07-result-raw__anno.png`、`student_14-chat-answer__anno.png`、`student_08-feedback__anno.png`

### P2　分析进度页把后端内部事件名当成执行正文　`[V2 视觉层级 / V3 可读性]`
- **位置**：学生端"分析进度"页、11-17 复跑进度页、教师端卡住状态进度页。
- **可见现象**：执行事件逐条显示 `#1 RUN_CREATED`、`#2 RUN_STARTED`、`#3 LOOP_START`、`#4 STEP_START`、`#5 MODEL_CALL_BEFORE`、`#7 MODEL_CALL_ERROR`、`#8 LOOP_COMPLETE`、`#9 TRACE_END`。
- **影响**：面向学生/教师展示 `MODEL_CALL_ERROR`、`LOOP_START` 这类工程术语，用户看不懂；错误事件与普通事件同色同级罗列，主次不分。
- **建议**：把事件名映射为用户语言，如"已创建分析 → 正在读题 → 正在检索教材 → 正在生成讲解"；错误步骤单独标记，与其他步骤区分。
- **复核条件**：进度列表不再出现下划线大写事件名；错误步骤在视觉上可区分。
- **标注副本**：`annotated/student_06-progress__anno.png`、`student_04-progress-v5__anno.png`、`teacher_06-stuck__anno.png`

### P3　管理后台顶部说明框技术细节过载，挤占首屏焦点　`[V2 视觉层级 / V6 信息密度]`
- **位置**：AI 对话页、Agent 效果测试页、RAG 来源登记页。
- **可见现象**：首屏最醒目的蓝色/黄色提示框里塞满 `/api/v1/retrieval + /api/v1/retrieval/generate`、`EXCERPT_ASSEMBLY`、`RAG_CORPUS_QA_SYNC_PIPELINE`、`/api/v1/runs`、`rag_retrieval.min_trust_tier`、`OFFICIAL_TUTORIAL` 等 API 路径与内部枚举。
- **影响**：管理员真正要操作的输入框/表单被推到首屏下方，视觉焦点落在大段技术说明上，主次错位。
- **建议**：技术说明收进可展开区或降为次级灰字；首屏只保留一句人话说明 + 明确的操作入口。
- **复核条件**：进入页面第一眼看到的是操作区，而不是整屏技术说明。
- **标注副本**：`annotated/admin_M29-ai-chat__anno.png`、`admin_M28-agent-lab__anno.png`、`admin_M11-rag-source-new__anno.png`

### P4　工作台入口卡片文案折行不一致、出现孤字行　`[V1 布局与对齐 / V3 可读性]`
- **位置**：学生端与教师端工作台"开始"卡片区。
- **可见现象**：四张卡片中"报表中心"的描述"按天看辅导、错题、检索与语料导入的汇总"折成 3 行，其他卡片 2 行；教师端有一处该描述被截断，只剩"汇总"孤立一行。
- **影响**：同排卡片文案行数不一、孤字成行，对齐与阅读节奏被破坏。
- **建议**：统一描述的字数上限或固定行数 + 省略号，保证同排卡片文案等高。
- **复核条件**：四张卡片描述行数一致，无孤字行。
- **标注副本**：`annotated/teacher_15-dashboard-cards__anno.png`、`student_03-dashboard__anno.png`

### P5　教师端工作台"近期辅导"缺空态提示　`[V4 可见状态]`
- **位置**：教师端工作台"近期辅导"区。
- **可见现象**：只有表头、没有数据行，下方大片空白，没有"暂无记录"之类的提示。
- **影响**：用户无法判断是"确实没有记录"还是"没加载出来"。
- **建议**：补一条明确空态文案（如"本账号暂无辅导记录，发起一次辅导后将显示在这里"）。仅评空态的呈现缺失，不涉及加载流程。
- **复核条件**：无记录时显示明确空态提示。
- **标注副本**：`annotated/teacher_02b-dashboard-empty__anno.png`

### P6　管理后台表格列被截断、首屏即横向滚动　`[V3 可读性 / V1 布局]`
- **位置**：平台用户页、Skill 目录页。
- **可见现象**：用户页显示名"平台生命周期管理员（开发）"折成三行，邮箱 `plat-\nsuperadmin@example.com` 被折行，表格底部出现横向滚动条；Skill 页 ID 列被截断并带复制图标，同样有横向滚动条。
- **影响**：关键字段折行/截断，需要横向滚动才能看全，扫读效率低。
- **建议**：关键列给足宽度或用省略号 + 悬停显示全文；精简非必要列；尽量避免进入页面就要横向滚动。
- **复核条件**：常用字段在一屏内完整可读，无异常折行。
- **标注副本**：`annotated/admin_M02-users__anno.png`、`admin_M07-skills__anno.png`

### P7　状态徽章样式与配色语义跨页不统一　`[V5 视觉一致性]`
- **位置**：租户注册表、平台用户页、Skill 目录页。
- **可见现象**：租户生命周期用绿色描边英文 `ACTIVE`；用户状态用绿/灰中文"启用/停用"，角色用多色描边中文标签；Skill 风险上限用红色描边英文 `WRITE_EXTERNAL`，状态用绿色"已发布"。红色同时承担"风险标签"和"失败态"两种语义。
- **影响**：同为"正常/启用"的状态，中英文、描边/实心、配色都不一致；红色语义混淆，用户难以形成稳定预期。
- **建议**：统一状态徽章组件（语言、形状、配色映射）；风险标签与错误态使用不同色系。
- **复核条件**：跨三页对比，同类状态外观一致。
- **标注副本**：`annotated/admin_M01-tenants__anno.png`、`admin_M02-users__anno.png`、`admin_M07-skills__anno.png`

### P8　管理后台列表页表格下方大面积空白　`[V6 留白与信息密度]`
- **位置**：租户注册表、平台用户页。
- **可见现象**：租户表仅 2 行数据，表格卡片下方约六成区域纯白；用户表 7 行数据，下方仍有约四成空白。
- **影响**：数据量少时留白失控，页面显得空旷、不精致。
- **建议**：数据少时让卡片高度随内容收缩，或在空白区补充统计概览/引导内容。
- **复核条件**：卡片高度贴合内容，或空白区有实质内容。
- **标注副本**：`annotated/admin_M01-tenants__anno.png`、`admin_M02-users__anno.png`

### P9　会话页顶部技术说明字号小、密度高、视觉权重错配　`[V7 色彩与对比 / V6 信息密度]`
- **位置**：学生端 Agent 编排对话、教师端 Agent 真实对话。
- **可见现象**：对话区上方一段红色"这条链路的验证边界"四条项目符号，字号明显小于正文、行距紧，含 `/api/knowledge/agent/chat/stream`、`404/501`、`SSE` 等术语。
- **影响**：对目标用户（学生）是无意义的干扰信息，低对比小字难读，却占据显眼位置。
- **建议**：折叠为"技术说明"或移到帮助区；若保留则提高字号与对比，降低其视觉权重。
- **复核条件**：默认视图不再用小字堆砌技术说明。
- **标注副本**：`annotated/student_16-agent-chat__anno.png`、`teacher_12-agent-real__anno.png`
