## 2. 测试范围与策略

**覆盖目标（用户要求）**：全部功能、页面、入口、操作流程、角色与权限、异常场景及边界条件；逐项执行并记录；对照实现与文档；记录实际结果与"通过/失败/阻塞/不适用"；失败项给可复现步骤；输出完整文档与证据。

**执行矩阵**：
1. **鉴权与会话**：6 角色登录、无令牌/错口令/不存在账号、身份域隔离、过期回跳（令牌 900s）。
2. **页面渲染走查**：30 个路由（超管视角）逐项导航 + 截图 + 健康扫描（错误/空态/403/白屏检测）。
3. **角色与权限**：6 角色 × 11 个只读端点矩阵 + 前端导航显隐 + 低权限角色越权访问行为。
4. **关键写链路**：用户新建（校验→提交→列表出现→停用）、RAG 治理票据领取→写门（403→200）。
5. **异常与边界**：未登录深链、角色守卫 403、404 兜底、忘记密码、表单校验、空态、诚实边界提示。

**不覆盖项（已声明）**：
- 物理删除端点（设计上不存在，仅状态机迁移）。
- RAG `VERIFIED` 双签完整写流（需"非登记人 + 第二复核人"两个真实主体；平台仅 `plat-superadmin` 一个凭据，违反 SoD，环境限制；票据门与单签前置已实测，双签逻辑见 §5 FINDING 备注）。
- 租户生命周期 `suspend/resume/decommission/...` 动作：仅后端 API 存在，**前端 router 未挂载对应按钮**（见 §5 FINDING-04），故仅 API 层验证可达性，UI 走查标记为不适用。

### 4.4 关键写链路（真实浏览器 + 真实请求）
工具：`write_flows.py` → `write_log.jsonl` + `screenshots/w0*.png`。

**用例 W-01 新建平台用户（超管）**
1. 打开 `/users` → 点击「新建用户」→ 弹窗出现（截图 `w01_create_modal.png`）。
2. **边界-校验**：用户名填 `ab`（过短）、密码填 `123`（过弱）→ 提交 → 捕获校验文案：
   - "格式非法：4-20 位字母/数字/下划线，以字母开头"
   - "密码长度至少 10 位"
   （截图 `w02_validation.png`）→ **通过**（前端校验生效）。
3. **正常提交**：`username=e2ewalk11140014`、`password=Walktest123`、`displayName=E2E Walk`、`email=e2ewalk@example.com` → 列表出现该用户（`APPEARED`）→ **通过**。
4. **API 核验**：`GET /users` 返回 `status: ACTIVE`、含该记录（`createdAt` 本轮时间）→ **通过**（数据库真实写入）。
5. **停用**：行内「停用」→ 确认弹窗「确 定」→ API 核验 `status: DISABLED`、`authzVersion` 由 1→2 → **通过**。
   - 测试账号已置 `DISABLED`（同既有 e2e 账号处理惯例，无物理删除）。

**用例 W-02 RAG 治理票据门（写闸门）**
- 浏览器：`/rag/dashboard` 点击「领取治理票据」→ 按钮变「重新领取治理票据」、出现标签"票据 5b77ec86… · 剩余 299 秒"（截图 `w08_rag_after_ticket.png`）→ **通过**。
- 真实请求（直连 8081，附 `X-Rag-Scope: PLATFORM`）：
  - `POST /platform/v1/rag/governance-ticket` `{"scope":"PLATFORM"}` → **200**（返回票据 JWT）。
  - `POST /management/reindex?limit=1` **不带票据**（以平台 JWT 作 Authorization）→ **403** `"平台全局语料的写动作需要治理票据（scope=PLATFORM），当前票据声明：无票据"`。
  - 同端点 **带票据** → **200** `{"indexedChunks":1,"scannedChunks":1,"durationMs":5252}`。
  - `GET /management/statistics`（读，平台 JWT）→ **200**（读不需票据）。
  → **通过**：写门 fail-closed（无票 403，有票放行）。

## 5. 缺陷清单

### FINDING-01（中危 · 一致性/UX · 非安全阻塞）菜单过度暴露：导航可见性与后端 RBAC 不一致
- **类型**：前端导航与后端授权不一致（一致性/可用性），**安全影响：无**（后端 fail-closed，越权请求一律 403）。
- **现象**：`navConfig.tsx` 对除审计外的所有页面 `requiredRoles: PLATFORM_SCOPE_ROLES`（=全 6 角色均可见）。但后端 RBAC 为细粒度：`/users`、`/roles`、`/permissions` 仅超管可读；`/tenants` 拒绝 `resource`/`security`；`/capabilities/*` 拒绝 `lifecycle`/`security`；`/model-catalog` 拒绝非 `resource`/`super`。结果：低权限角色（如 `plat-support`）侧边栏可见 `平台用户 / 角色权限矩阵 / 模型配置` 等，点击后却得到内联 403 错误。
- **与文档冲突**：README §3 标注 `/users` 为"可写"，§5 与 Explore 笔记（DEF-06）称"非超管渲染**只读**入口"——但实测非超管对 `GET /users` 直接 **403**（非只读），与"只读"设计意图相悖。属**实现与文档不一致**。
- **可复现步骤**：
  1. 测试数据：以 `plat-support / Plat#2026!` 登录。
  2. 操作：左侧菜单点击「平台用户」（或「角色权限矩阵」「模型配置」）。
  3. 预期：要么菜单对该角色不可见，要么页面以只读模式展示数据。
  4. 实际：菜单可见，页面内联错误 Alert「无权执行该操作」（403）。
  5. 影响范围：全部非超管角色（lifecycle/resource/security/auditor/support）在 5+ 个菜单项上都会遇到"看得见打不开"。
  6. 严重程度：**中**（用户体验与预期不符、易误判为故障；不涉及越权或数据泄露）。
- **建议修复（二选一，推荐前者以贴合 DEF-06 只读意图）**：
  (a) 后端对 `GET /users`、`/roles`、`/permissions` 授予对应平台角色只读权限，前端按现有"非超管只读"渲染；或
  (b) 收紧 `navConfig.requiredRoles` 使其与后端 RBAC 对齐（如 `/users`、`/roles` → 仅 `PLATFORM_SUPER_ADMIN`）。
- **是否阻塞发布**：否（fail-closed，无安全风险）。

### FINDING-02（低危 · 文档/实现不一致）`/metrics-entry` 页面标题与导航标签不一致
- **现象**：导航标签为"效果数据录入"，但页面 `<title>` 为"Agent 效果指标 · Agent 管理控制台"（与 `/metrics` 相同），易让用户混淆两页。
- **证据**：`walk_log.jsonl` 中 `效果数据录入` 记录 `title=Agent 效果指标 · Agent 管理控制台`。
- **严重程度**：低。**建议**：修正 `/metrics-entry` 页面标题/文档标题为"效果数据录入"。

### FINDING-03（信息 · 环境观察）RAG 子系统就绪标签含"失败"
- **现象**：领取治理票据后，Dashboard 就绪标签出现若干"失败"项（如某些 RAG 子系统在本环境未就绪）。
- **判读**：反映**本测试环境** RAG 子系统运行态，非控制台缺陷；控制台已如实呈现（不掩盖）。
- **严重程度**：信息（环境相关）。**建议**：发布前在准生产环境确认 RAG 各子系统就绪。

### FINDING-04（信息 · 实现说明）租户生命周期动作按钮未在 router 暴露
- **现象**：`suspend/resume/decommission/finalize-decommission/cancel` 仅有后端 API（`/tenants/{id}/...`），前端 `router.tsx` 未挂载对应按钮/页（仅列表只读 + 开通入口）。
- **判读**：属带外运维或后续迭代缺口，非回归故障。
- **严重程度**：信息。**建议**：若需控制台自助运维，补充生命周期操作入口与双确认。

### FINDING-05（信息 · 边界）平台令牌打 `/api/chat/stream` 返回 400 而非 401
- **现象**：平台令牌（带合理 body）打租户链 SSE 端点返回 `400 INVALID_REQUEST`，而非身份域隔离期望的 `401`。
- **判读**：功能上仍被阻断（不可达），但隔离信号落在"校验层 400"而非"鉴权层 401"。该端点本就非 admin-console 使用（AI 实验室走 `/api/agent/chat/stream`）。
- **严重程度**：信息（低）。**建议**：若需严格一致，可在鉴权层先于 body 校验返回 401。
