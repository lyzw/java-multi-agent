## 〇、评审结论先行（一句话）

**这是一个"教学理念正确、界面诚实、但核心学习闭环在当前状态下无法成立"的产品。** 讲解内容本身有真实教学价值，失败提示的诚实度也明显高于同类原型；但有 **4 个会直接挡住普通用户的问题**（数字编号提交不了、公式不可读、薄弱点从未被记录、模型失败时永久卡在"执行中"），在它们解决前，它是一位老师**不敢推荐给学生独立使用**的演示原型，而不是可用的教学工具。

## 二、各环节是否易理解

### 做得好的（✅）

1. **页面语言是学生话，不是研发话**。登录页用"把错题变成下一次的分数"，工作台用"从一道做错的题开始，看它错在哪一步"——作为一名老师，我认为这种表达降低了学生的心理门槛，方向完全正确。
2. **隐私边界反复讲清楚**。"不收姓名/学校/班级""会话只存内存、刷新即清空""反馈不影响账号和成绩"——这些声明具体、可信，符合教育场景对未成年人的保护要求。
3. **Agent 对话把黑箱打开了**。样例回放模式把路由→RAG→Skill→Tool→回传→用量的每一步都摊开，并明确标注"非真实模型输出"——这是很好的**教学透明化**设计，学生能看到 AI 是怎么想的。
4. **失败提示的诚实度值得表扬**。通用问答遇到模型限流时显示"模型调用过于频繁 / RATE_LIMITED / 稍后重试；本页不做自动重试，避免继续消耗配额"；403 页面明确写"这是账号权限范围，不是登录失效或网络问题；重新登录、刷新或重试都不会改变结果"——**不骗学生、不给无效重试**，这两点做得很专业。
5. **预置示例问题降低了操作成本**。通用问答和 Agent 对话都给了 3–4 个现成问题，学生点一下就能开始，不必自己想怎么问。

### 不易理解的（🔴/⚠️）

1. **🔴 "学生匿名编号"字段是个陷阱**。字段说明写"请填写平台生成的匿名编号"，我按常理填了数字编号 `20261116001`（这就是平台发给学生的最常见编号形态），提交时被一句红字挡回："内容中疑似包含学号或连续数字标识，请移除"。**这个字段明明就是让我填编号的，为什么编号又被当成学号拦掉？** 我最后靠猜改成 `stu_a1b2c3d4e5f6g7h8` 才成功——普通学生绝不会想到这一招，页面也没有任何格式提示。（截图 `04`）
2. **🔴 结果页公式看不懂**。归因讲解里大量 `$$2(x+3)=2x+2\times3=2x+6$$`、`| 维度 | 判断 |` 表格、`## 📌`、`### 一、` 等符号**原样显示**，只有粗体和行内代码被渲染。对初中生这就是乱码。经检查页面有 0 个公式渲染节点。更糟的是，模型输出本身也有 `\fracbax` 这类缺花括号的错误写法，前端不渲染反而把错误暴露出来。（截图 `07`）
3. **🔴 结果页自相矛盾**。同一页先说"这次分析没有记录到错因""这次分析没有写入薄弱点"，紧接着小字又说"分析完成后，这道题会写入薄弱点清单"——**到底有没有写？** 我查了数据库确认：薄弱点表确实 0 条，即"没写入"是真的，"会写入"是假承诺。
4. **⚠️ 知识检索的失败没有说法**。我按默认版本检索，按钮先显示"检索中…"，最后既没答案也没来源，只回到"提交问题后这里会显示……"这句初始提示。**学生无法判断是没搜到、搜到了被拦、还是系统坏了**——只能反复换说法，浪费时间。（截图 `09b`）
5. **⚠️ 年级叫法不统一**。发起辅导页默认"初一"，知识检索页默认"七年级"。老师都知道是一回事，但学生容易以为是两个不同的设置。
6. **⚠️ 内部术语外露**。Agent 对话真实模式底部仍写"通用 Agent 编排 · 真实端点 · **尚未完整收口**"；结果页有"待核对""合规扫描违规""JSON 校验"等研发口径。样例回放模式的同类文案已改成"已收口"，真实模式还没同步。
7. **⚠️ 工作台给学生看无权入口**。侧边栏已经正确隐藏了"学习画像/报表中心"，但工作台正文里还留着这两张卡片；学生点进去直接吃 403。（截图 `15` → `14`）

## 三、操作成本与体验感受

| 环节 | 操作步骤 | 学生实际感受 |
|------|---------|------------|
| 登录 | 手填 36 位 UUID + 账号 + 密码 | UUID 是最大障碍，学生不知道自己的租户码从哪来；无"记住上次租户" |
| 发起辅导 | 填 5 个字段 | 本来 1 分钟的事，因编号格式不明**卡了 3 次提交**被迫猜格式 |
| 等待分析 | 提交后科学步进度页 | 正常情况下几十秒；本次因模型限流**无限期卡住**，学生只能盯着"执行中" |
| 看结果 | 滚动阅读 | 内容本身值得读，但公式看不懂，体验被打断 |
| 知识检索 | 选 5 项版本坐标 + 提问 | 版本坐标对普通学生过于专业；默认还是个库里没有的组合 |

**总体感受**：界面漂亮、反馈及时、决策成本低（几乎不用思考就能找到功能），但**在关键节点上会突然要求用户提供他不可能知道的信息**（租户 UUID、匿名编号格式），这是最伤体验的操作成本——它不是"多点点几下"，而是"直接卡死"。

## 四、发现的问题与卡点（按对教学的伤害排序）

### 🔴 P0 — 直接阻断核心学习任务

**P0-1｜模型失败后 Run 永久卡在"执行中"，重试无上限（本次新发现，最严重）**
- 现象：提交辅导后，模型调用返回 429（套餐用量耗尽），Run 进入重试循环。我观察了 10 分钟，重试次数从 4 次涨到 **14 次仍不停**，Run 状态始终 `RUNNING`，进度页永远显示"执行中 / 正在同步最新状态…"，检索记录里显示"分析中 · 领取 14 次"。
- 测试配置写着 `max-attempts: 3`，但实际未被遵守——这是**无限重试 + 假进度**双重缺陷。
- 作为老师，这是最不能接受的一条：学生会一直等一个永远不会来的结果，或反复提交制造更多失败。**它直接违背了产品自己写下的"不伪造进度"承诺。**
- 证据：`06-run-stuck-rate-limit.png`、`08-runs-list.png`，DB 实查 attempt=14、MODEL_CALL_ERROR=14。
- 建议：① 区分可重试错误（网络抖动）与配额/套餐耗尽（`RATE_LIMITED`/`QUOTA_EXHAUSTED`），后者**立即终态失败**；② 给重试设硬上限并在此后转 FAILED；③ 进度页必须显示明确的失败原因与"稍后再试/联系管理员"，绝不显示"执行中"。

**P0-2｜数字型匿名编号无法提交**
- 现象见第二节。"匿名编号"字段与学号扫描规则语义冲突，学生按直觉填写必被拦。
- 建议：把格式引导写进字段提示（` stu_ 开头 + 16 位`），提供"一键生成匿名编号"按钮（前端本地生成 `stu_`+随机串即可，无需后端签发）；**绝不能简单豁免学号扫描**（会让真实学号随 Prompt 出境，违反零保留承诺）。

**P0-3｜公式与 Markdown 零渲染**
- 现象见第二节。核心交付物（数学讲解）不可读，直接决定学生能不能看懂。
- 建议：前端引入 KaTeX 渲染（`admin-console` 已有整套依赖可复用），把 `\[...\]`/`\(...\)`/`$$...$$` 渲染成图形；同时在模型指令里约束公式花括号完整，修掉 `\fracbax` 类错误。

**P0-4｜薄弱点从未被记录，学习闭环断裂**
- 现象：结果页说"没写入薄弱点"，DB 实查 `weakness_record` 对该学生编号 0 条。根因不是代码坏了，而是这两个工具（`record_weakness`/`get_student_profile`）**从未被纳入 Agent 的能力目录**，模型根本不知道有这个工具，从不调用。
- 对教师而言这是**产品价值层面的问题**：一款"错题归因辅导"产品如果不能积累薄弱点，就只是"一次性问答机"，学生用一百道题也不会得到"下一步该补哪块"的建议——而这正是产品名称承诺的核心。
- 建议：把两个工具纳入能力目录（能力表 + Skill 声明 + Agent 绑定 + 指令指引），并以"薄弱点表里真的多了一行"为验收标准，而不是"接口返回 200"。

### 🟠 P1 — 严重伤害可信度与效率

**P1-1｜知识检索空结果无归因**：默认版本坐标（七年级/人教版）在语料库中无对应内容；页面没有"跨版本查找"选项；检索结束只回到初始提示，学生误以为是自己问得不好。（建议：按漏斗计数区分"该版本无语料/未搜到/被门禁拦下"三类提示；默认改为有语料的组合或"回退同册"；增加跨版本开关。）

**P1-2｜Agent 真实链路 RAG 读取失败**：真实端点报"RAG 响应读取失败（不可达或超出大小上限）: host=127.0.0.1"，同时召回 0 片段。跨进程地址契约需按对端真实绑定值核对。（证据 `13-agent-real-failed.png`）

**P1-3｜工作台 403 陷阱卡片**：侧边栏已隐藏无权入口，正文卡片未同步。（建议：卡片与导航用同一份能力清单渲染，单一真相源。）

**P1-4｜模型用量在 Run 链路显示 0**：Agent 对话样例回放显示"输入 186·输出 142"，但真实链路的模型用量因流式 usage 判空缺陷恒为 0——关心额度的学生/家长会得到错误数字。

### 🟡 P2 — 体验与打磨

- P2-1 登录要手填 UUID 租户标识，无记忆/学校码替代。
- P2-2 登录失败不区分"密码错"与"账号被锁"，被锁时学生只会反复重试越锁越久。
- P2-3 `navigate(state?.from ?? '/')` 未做站内路径白名单，若历史 `from` 指向某个已完成 Run，登录后会落到旧进度页（本次新会话未复现，代码层面仍存在）。
- P2-4 年级"初一"vs"七年级"术语不统一。
- P2-5 真实模式内部术语"尚未完整收口"未随样例模式一起改掉。

## 五、对目标达成度的影响

用教师视角，我把产品的目标拆成三级来评判：

| 目标层级 | 是否达成 | 依据 |
|---------|:---:|------|
| **L1 能独立提交一道错题** | ❌ | 编号格式不明，直觉填法 100% 被拦（P0-2） |
| **L2 能稳定拿到一次高质量归因讲解** | ⚠️ | 讲解内容质量真不错，但公式看不懂（P0-3），且模型失败时永久卡住（P0-1）——**不稳定** |
| **L3 能积累薄弱点并指导下一步学习** | ❌ | 薄弱点从未写入（P0-4），画像对学生关闭，学生看不到自己的薄弱点 |
| 附加：知识检索可溯源 | ❌ | 默认空、无归因、无跨版本（P1-1） |

**结论**：产品目前只能**不稳定地达成 L2**（能讲对，但看不懂、且随时可能卡死）；**L1 和 L3 完全未达成**。而 L3 恰恰是"错题归因辅导"区别于普通 AI 问答的立身之本。**按教学有效性评估，当前版本不具备让学生独立使用、并把学习过程沉淀下来的条件。**

## 七、优点与不足总清单

**优点（值得保留与发扬）**
- ✅ 教学理念正确：从"错在哪一步"出发，不是只给分数；内容有真实讲解深度与针对性练习。
- ✅ 视觉完成度高、交互清晰、状态反馈及时。
- ✅ 隐私与边界诚实：不收身份信息、会话不留痕、区分真假输出。
- ✅ 失败提示不骗人（通用问答、Agent 对话、403 页）——这是同类原型普遍做不到的。
- ✅ 流程透明化设计（Agent 过程逐帧可见）有教学价值。

**不足（必须修复）**
