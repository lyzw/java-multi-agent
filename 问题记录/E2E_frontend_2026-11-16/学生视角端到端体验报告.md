## 二、作为学生，我觉得好的地方

1. **页面好看、不吓人**。登录页用「把错题变成下一次的分数」这种人话，而不是「智能体平台」；工作台卡片、状态徽章（已完成/执行中）一眼看懂。
2. **归因讲解是真的有内容**。它准确指出我是「去括号漏乘系数」，还给了重新做题的建议，不是敷衍的一句「你算错了」。
3. **通用问答是我最喜欢的功能**。问我「为什么天空是蓝色的」，4.4 秒就逐字流式出来，用初中生能懂的话讲了瑞利散射、晚霞，还明说「模型生成，未经教材语料核验」——诚实。
4. **Agent 对话把过程摊开给我看**。路由命中、RAG 检索、用量、完成，每一步都有时间戳；还明确区分「样例回放（假数据）」和「真实端点」，没有拿假流冒充真实。
5. **隐私交代得清楚**。反复强调不收姓名、学校、班级，会话只存内存、刷新即清空。
6. **反馈按钮有状态**。点「有帮助」后按钮变选中态，我知道点到了。

## 三、我遇到的问题（按严重程度）

### 🔴 问题 1：数学公式全是乱码一样的源码，我看不懂

**截图**：`07-result.png`、`16-agent-chat-live.png`

归因结果页和 Agent 回答里，所有数学公式都长这样：

```
\[
\begin{aligned}
y&=ax^2+bx+c\\
&=a\left(x^2+\fracbax\right)+c
\end{aligned}
\]
其中顶点为\(h=-\frac{b}{2a}\)，最后\boxed{y=a(x-h)^2+k}
```

对一个初一学生来说，这跟天书没区别。更糟的是 Agent 回答里还出现了 `\fracbax` 这种缺花括号的写法（应该是 `\frac{b}{a}x`）——**模型输出本身也有格式错误**，前端不渲染反而把错误原样暴露出来。

- **原因**：前端 `ModelText.tsx` 只处理 `**粗体**` 和 `` `代码` ``，完全不支持 LaTeX；而模型被引导输出大量 LaTeX。两边约定对不上。
- **影响**：数学、物理等学科的核心内容**不可读**，这是整个产品最核心的交付物，直接决定学生能不能看懂。
- **建议**：引入 KaTeX/MathJax 渲染 `\[...\]` 和 `\( ... \)`；同时在模型 prompt 里约束公式语法，避免 `\fracbax` 这类错误。

### 🔴 问题 2：「学生匿名编号」填数字就被拦，我根本提交不了

**截图**：`05-new-run-filled.png`

字段说明写的是「请填写**平台生成的匿名编号**，不要填姓名」，我填了 `20261116001`（11 位数字，和学号一样是平台发的编号格式），点「开始分析」没反应，页面底部飘出一句红字：

> 内容中疑似包含学号或连续数字标识，请移除

我完全懵了：这个字段本来就是让我填编号的，为什么编号又被当成学号拦掉？

- **原因**：前端合规扫描把任何 8–12 位连续数字判为「学号」并拦截；后端 `DataClassification` 的 `STUDENT_ID` 规则也是 `(?<![0-9])[0-9]{8,12}(?![0-9])`。规则本身没错，但**和「匿名编号」这个字段的语义直接冲突**。
- **我的绕过方式**：改成 `S2026-4f8a2b` 才提交成功。普通学生不会想到这一招。
- **影响**：如果平台真的给学生发数字型匿名编号，学生**永远无法提交作业**；而且题目里出现大数字（如 `12345678+87654321`）也会被误杀。
- **建议**：匿名编号字段应豁免学号扫描，或改为下拉选择/扫码/自动带入，不让学生手填。

### 🔴 问题 3：知识检索永远搜不到东西，提示还把我往错路上带

**截图**：`10-rag.png`、`11-rag-result.png`

我用「去括号时乘法分配律怎么用？一元一次方程怎么解？」检索，反复换说法、换版本范围，永远只有一句：

> 没有检索到可引用的教材语料，因此无法生成讲解。可以换个说法，或把版本范围改成「优先本版，可回退同册」再试。

我照做了，还是空。后来我从技术侧查到三个叠加原因：

1. 页面默认版本是「七年级·数学·上册·人教版·2024」，但**语料库里根本没有这个组合**（公共语料集中在六年级）。
2. 就算切到存在的「数学·六年级·下册·沪教版·2024」，检索候选只有 5 条，最后**全被相关性门禁 0.38 拦掉**——因为公共语料 8891 块里有 **2145 块的正文是 `[图]` 占位符**，没有文字可供检索。
3. 我所在租户 `t-e2e-fe` **自己一块语料都没有**，只能靠公共库。

**最能说明问题的是**：同一个问题在「Agent 对话」里走真实端点，RAG 却能召回 3 个片段。说明独立检索页传的 `edition` 参数把候选过度收紧了。

- **影响**：学生以为是自己问得不好，反复改说法浪费时间；实际上这个功能对他不可用。
- **建议**：① 空结果时区分「该租户/版本无语料」和「未搜到相关内容」，分别给准确提示；② 默认版本不要硬编码成一个库里没有的组合；③ 图片型语料要么做 OCR，要么明确标注不可检索。

### 🔴 问题 4：Agent 找的「依据」跑题了，却标着「直接匹配」

**截图**：`16-agent-chat-live.png`（点开「展开核对 3 个片段原文」）

我问「二次函数的顶点式怎么推导？」，它翻出来三条出处：

- `[1] 相关度 0.49 · DIRECT_MATCH` → 内容是**圆锥的底面和顶点**（"顶点"两个字撞上了）
- `[2] 相关度 0.57 · DIRECT_MATCH` → 内容是**一元一次方程两边同除以 x 的系数**
- `[3] 相关度 0.54 · DIRECT_MATCH` → 同上

还标注 `DIRECT_MATCH`（直接匹配）。学生点开「核对」一看，出处跟问题完全是两回事，会直接摧毁对系统的信任。片段里还有 OCR 乱码（`犘 叫作圆锥的顶点`、`两边同除以狓`）。

- **建议**：对召回片段做学科/知识点一致性校验，别只靠字面相关度；把 `DIRECT_MATCH` 留给真正命中的片段。

### 🟠 问题 5：结果页说「没记录错因」「没写入薄弱点」，又自相矛盾

**截图**：`07-result.png`

- 「解题步骤」区块：`这次分析没有记录到错因` + 小字 `错因需要模型实际调用记录工具才会产生`
- 「薄弱点回执」区块：`这次分析没有写入薄弱点` + 小字 `分析完成后，这道题会写入薄弱点清单`

前面说没写入，后面说完成后会写入——到底有没有？而且学生账号本来就看不了画像页。我花了时间做题，结果系统没把我的薄弱点记下来，也没地方看。

- **建议**：要么把结构化错因/薄弱点真正落库并给学生看，要么明确说明「本版本暂不提供薄弱点跟踪」，别用矛盾文案。

### 🟠 问题 6：明明调用了模型，用量却显示 0 tokens

**截图**：`16-agent-chat-live.png`

Agent 对话真实跑了 16.8 秒，回答了一大段，但时间线「用量统计」写的是 `输入 0 · 输出 0 tokens`，底部也是 `用量：输入 0 · 输出 0 tokens`。对一个会关心「我是不是快用完额度」的学生（或家长），这是误导。

### 🟠 问题 7：登录失败不分「密码错」和「账号被锁」，我也不知还要等多久

我探测密码时连错几次，账号被直接锁 15 分钟。但页面只提示「租户、账号或密码不正确」，我完全不知道是被锁了、还要等多久，只会反复重试——越试越锁。

- **建议**：明确提示「账号已锁定，请于 XX:XX 后重试」或提供自助解锁。

### 🟡 问题 8：登录要手填一长串 UUID 租户标识

普通学生不知道自己的租户 UUID 是什么。没有示例、没有「记住上次租户」、没有学校码/二维码替代。这是每次登录的第一道坎。

### 🟡 问题 9：登录后落在历史 run 进度页，不是工作台

我登录后直接看到 `a96630d4...` 这个旧 run 的进度页，愣了一下才找到「工作台」。建议登录后默认回工作台。

### 🟡 问题 10：面向学生的页面露出内部术语

- Agent 对话底部：`通用 Agent 编排 · 真实端点 · 尚未完整收口`
- 结果页「待核对」区块：`合规扫描违规`、`JSON 校验`
- Agent 名称直接叫 `E2E 错题归因辅导 Agent`

这些是研发/测试口径，学生看不懂也不该看。

### 🟡 问题 11：年级叫法不一致

发起辅导页默认「初一」，知识检索页默认「七年级」。虽然是一回事，但学生容易以为是两个不同的设置。

## 四、总体评价

**一句话**：这是一个**设计取向很诚实、视觉完成度高、讲解质量不错**的产品，通用问答和 Agent 过程透明化是亮点；但目前有四个会直接挡住学生的问题——**公式看不懂、匿名编号提交不了、知识检索永远空、Agent 依据跑题**——在这些问题解决前，它更像一个「演示得很好的原型」，而不是学生能独立用起来的产品。

**分维度打分（学生主观感受，满分 5）**

| 维度      | 评分  | 说明                   |
| ------- | --- | -------------------- |
| 视觉与交互   | 4.0 | 好看、清晰、状态反馈到位         |
| 核心归因质量  | 3.5 | 讲解内容好，但公式不可读严重扣分     |
| 功能完整性   | 2.5 | 检索不可用、薄弱点未落库、画像无权限   |
| 提示与可理解性 | 2.0 | 多个错误提示错误归因或暴露内部术语    |
| 隐私与诚实度  | 4.5 | 明确不收身份信息、区分真假输出，值得表扬 |

**发布建议**：不建议面向真实学生规模开放。建议按 P0（问题 1–4）→ P1（问题 5–7）顺序修复后，再做一轮单租户试点。
