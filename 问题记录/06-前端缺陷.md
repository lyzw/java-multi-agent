## FE-01 · 401 与 403 语义混同 → 正常业务被拒也被踢回登录页

**问题描述**
前端对 401 一律清会话跳登录，把「未登录」「业务无权限」「跨身份域 401」三类情形混为一谈，
导致正常业务被拒也被踢回登录页、**丢失操作现场**。

**产生原因**
前端只按 HTTP 状态码分支，而 401 在本项目里不只表示「未登录」。

**相关解决方案**
详见 [API-06](05-API契约与错误语义.md#api-06--401-与-403-语义混同--前端误清会话跳登录)。
前端改为**严格按 `code` 分支**：仅 `UNAUTHENTICATED` 清会话跳登录；
`ACCESS_DENIED` 与跨域 401 绝不跳登录，交页面提示或渲染无权限整页。

**来源**：`git log fd63fa2`（2026-11-01）
**状态**：✅ 已修

## FE-03 · `SkillCatalogPage` 表单加载状态与过滤数据不一致

**问题描述**
在 `renderTable` 函数中，`loading` 状态设置为 `loading && data === filtered`。
用户搜索过滤时，`filtered` 数据可能已加载完成，但 `loading` 仍为 `true`，
导致**表格显示加载状态而实际数据已可用**。

**产生原因**
```typescript
const renderTable = (data: SkillCatalogItem[]): JSX.Element => (
  <Table<SkillCatalogItem>
    rowKey="skillId"
    loading={loading && data === filtered}  // 问题所在
```
`data === filtered` 为 `true` 时 `loading` 仍可能为 `true` → 持续显示加载。

**相关解决方案**
```typescript
loading={loading && data.length === 0}  // 仅当数据为空时显示加载
```

**来源**：[`记录-2026-10-30.md`](记录-2026-10-30.md) 问题 1
**状态**：✅ 已修

## FE-05 · `AgentMetricsPage` 布尔值显示与未采集状态不一致

**问题描述**
`yn` 函数在值为 `null` 时返回 `'—'`（NOT_COLLECTED），
而 `pct`/`ms`/`count` 也使用同一常量 → 显示不一致。

**产生原因**
```typescript
function yn(v: boolean | null): string {
  if (v === null) { return NOT_COLLECTED }   // '—'
  return v ? '是' : '否'
}
```
用户可能期望看到「未采集」或更明确的提示。

**相关解决方案**
```typescript
if (v === null) { return '未采集' }  // 更明确的提示
```
> ⚠️ 这条与本项目核心铁律「**未采集 ≠ 0**」直接相关 ——
> 治理纪律类断言在 admin-console 只有 1–2 个测试守护（见 FE-19）。

**来源**：[`记录-2026-10-30.md`](记录-2026-10-30.md) 问题 3
**状态**：✅ 已修

## FE-06 · `MetricEntryPage` Form 实例重复创建

**问题描述**
`EntryCard` 组件内部使用 `Form.useForm()` 创建表单实例，每次渲染都会创建新的表单实例，
可能导致**表单状态丢失**。

**产生原因**
```typescript
function EntryCard({ title, description, status, onFinish, children }: EntryCardProps) {
  const [form] = Form.useForm()  // 每次渲染创建新实例
```
父组件不必要的重新渲染会连带丢掉表单状态。

**相关解决方案**
用 `useMemo` 包裹表单元素，并约束依赖：
```typescript
const formElement = useMemo(() => (
  <Form form={form} layout="vertical" disabled={submitting} onFinish={...}>...</Form>
), [form, submitting, onFinish, children])
```

**来源**：[`记录-2026-10-30.md`](记录-2026-10-30.md) 问题 4
**状态**：✅ 已修

## FE-07 · `AgentLabPage` 轮询定时器潜在内存泄漏

**问题描述**
`poll` 函数使用 `window.setInterval` 创建定时器，但组件卸载时可能无法正确清理 → **内存泄漏**。

**产生原因**
```typescript
useEffect(() => stopPolling, [stopPolling])  // 仅在 stopPolling 变化时清理
```
`stopPolling` 的引用变化时 effect 的清理函数不会在卸载时兜底执行。

**相关解决方案**
```typescript
useEffect(() => {
  return () => {
    if (pollTimer.current !== null) {
      window.clearInterval(pollTimer.current)
      pollTimer.current = null
    }
  }
}, [])
```

**来源**：[`记录-2026-10-30.md`](记录-2026-10-30.md) 问题 5
**状态**：✅ 已修（首批记录中优先级最高项）

## FE-09 · `PublishCenterPage` useEffect 依赖项不必要触发

**问题描述**
`useEffect` 依赖 `load` 与 `tab`，但 `load` 是 `useCallback` 记忆化的、不依赖 `tab`，
导致 effect 不必要地触发。

**产生原因**
```typescript
const load = useCallback(async (state?: string) => { ... }, [])  // 不依赖 tab
useEffect(() => { void load(...) }, [load, tab])  // tab 变化时也会触发
```

**相关解决方案**
把状态查询移入 effect 内部，依赖收敛到 `[tab]`；或加注释说明为什么需要 `tab` 依赖。

**来源**：[`记录-2026-10-30.md`](记录-2026-10-30.md) 问题 7
**状态**：✅ 已修

## FE-11 · `RagManagementPage` 作用域切换时可能中断用户操作

**问题描述**
用户切换作用域（TENANT/PLATFORM/ALL）时，`useEffect` 会清空选中项、重置维护面板、
作废票据等操作。若用户正在编辑或查看某个语料来源，这些操作会**中断用户的工作**。

## FE-12 · `DictionaryAdminPage` 自动选择逻辑可能覆盖用户选择

**问题描述**
`useEffect` 在字典列表变化时自动选择第一个字典；当 `list` 被清空后重新加载时，
`selectedCode` 可能不会被正确重置。

**产生原因**
```typescript
useEffect(() => {
  const first = list[0]
  if (selectedCode === null && first) { setSelectedCode(first.dictCode) }
}, [list, selectedCode])
```
只处理了「没选过」，没处理「选过但已不在列表里」。

**相关解决方案**
```typescript
useEffect(() => {
  const first = list[0]
  if (selectedCode === null && first) {
    setSelectedCode(first.dictCode)
  } else if (selectedCode !== null && !list.some(d => d.dictCode === selectedCode)) {
    if (first) { setSelectedCode(first.dictCode) }
  }
}, [list, selectedCode])
```

**来源**：[`记录-2026-10-30.md`](记录-2026-10-30.md) 问题 10
**状态**：✅ 已修

## FE-23 · RAG 管理面全量 500（前端表现为「后端挂了」）

**问题描述**
RAG 管理面所有请求（含 404 与 health）一律 500。

**产生原因**
两层叠加：
1. **RAG 进程的 classpath 指向已被删除的 `rag/*/target/classes`**，
   类初始化失败被 JVM 标记为**错误类** → 所有路径一律 500；
   **重新编译回原路径也无法恢复**（错误类不可重新初始化），**只能重启进程**；
2. **平台实例未加载 `jwt.env`** → dev profile 临时生成密钥对，与 RAG 配置的验签公钥不同源
   （指纹 `0deff367522fc36f` ≠ `340be45292284d01`）→ 管理面全部 401。

**相关解决方案**
1. 后端在生成临时密钥对时**打启动告警并点名对端验签键名**；
2. 前端按 4xx/5xx **分流文案**（401 归因「令牌没验过」，不再误说成「身份域隔离」）。

**来源**：`git log af01b33`（P0-2）
**状态**：✅ 已修

## FE-24 · 会话过期无提示 + 「重新登录」被裸 `/login` 兜底覆盖

**问题描述**

**产生原因**

**相关解决方案**

2. 「重新登录」改为**只清存储、不翻转认证态** ——
   同步的认证态更新必须先于 `transition` 落地，否则会被兜底路由接管。

**来源**：`git log af01b33`（P1-5）
**状态**：✅ 已修
