## 二、环境前置的关键纠偏（写进流程，避免下次误判）

1. **业务库不是本地容器**。本地 `agent-pg17` 只承载 IT；platform 8480…8080 连的是阿里云 RDS
   `rm-cn-hhf50fbhh0001uzo.rwlb.rds.aliyuncs.com:5432/agent_dev`。上一轮"目录有 15 对象"结论取自本地
   ，对业务链路不成立——经 RDS 实查，`cap_tool_def` 仅 7 行且 learning-loop 工具 0 行。
   ✅ 以后凡"活库生效性"断言，必须连 `platform.env` 指向的 RDS。
2. **登录必须带 `tenantId`**（`/api/auth/token`）：`request.tenantId()` 为 null 直接判失败；
   离线用 PBKDF2 复算确认 `e2estudent` 口令为 `E2e-Admin-2026`（避免反复试错触锁）。
   ✅ 返回体新增 `studentId=stu_f7f82201ee6906ca`，登录态派生生效。
3. **能力目录纳管 ≠ 可用**。完整可达链是：
   `principal.student_id 补丁` → `cap_tool_def×2 + cap_skill_def×1` →
   `cap_agent_def 新版本行（不可变，禁用 UPDATE）` → `agent_version 旧路径同源` →
   **`execution_snapshot`（Run 绑定的是快照，没有它外键违约）** →
   `PLATFORM/TENANT 发布头 + 指针 CAS`。
   任缺一环，表现都是"Run 成功但 `tools: 0`"。
4. **Agent 版本不可变**：`forbid_published_def_mutation` 触发器禁止改已发布行 → 每次改提示词/参数只能发
   v+1（v3 加技能 → v4 工具优先+提额 → v5 LaTeX 契约），每次都要重新生成发布头并 CAS 指针。

## 三、本轮新发现并修复的 P0（真实交互驱动）

### P0-A 画像外键断链：新学生必然写不进薄弱点
- **现象**：`record_weakness` 调到了，但 `tool_operation.state=UNKNOWN`、`weakness_record` 无行。
- **根因**：`weakness_record.weakness_student_fk → student_profile(tenant_id, student_id)`，
  而**全仓生产代码没有任何创建 `student_profile` 的入口**（只有 IT fixture 写），
  `get_student_profile` 对学生不存在时按设计返回空画像。以 `app_agent` + 租户 GUC 复现：
  `violates foreign key constraint "weakness_student_fk"`。
- **修复**：`StudentDataRepository.insertWeakness` 写入前按**本次 Run 输入里学生自己声明的
  grade/subject** 幂等建档（`ON CONFLICT (tenant_id, student_id) DO NOTHING`，首次登记为准不覆盖）；
  无法合法建档时抛 `ProfileUnavailableException`，工具映射为 `definitelyFailed`（前置检查失败，
  不是"写入后结果未知"）。
- **验收**：`f570490d` → `record_weakness SUCCEEDED`，
  `weakness_record = stu_f7f82201ee6906ca | 二次函数一般式转顶点式 | 公式记错 | 0.80`，
  `student_profile = stu_f7f82201ee6906ca | 初二 | 数学`。

### P0-B 1024 token 截断吞掉工具调用
- **现象**：旧指令下，模型先写长讲解再发工具调用，`finish_reason=length`，正文被截断、
  `record_weakness` 调用丢失，学生只看到半截答案。
- **实验**（直连 MiniMax-M2.5，18 会话对照，见下表）：

  | 指令/预算 | 发起 `record_weakness` |
  |---|---|
  | 旧指令 @1024 | **1/3 ❌** |
  | 旧指令 @4096 | 3/3 |
  | 工具优先指令 @1024 | 3/3 |
  | 工具优先指令 @4096 | 3/3 |

- **修复**：提示词改为「先完成工具调用、**不要在工具调用之前写任何正文**，两个工具都返回后再讲解」；
  `maxOutputTokens` 1024 → 4096。活库发 v4，种子 math-tutor 同步同一份契约。
- **验收**：浏览器 `a20b51bc` → SUCCEEDED，`weakness_record` 落行。

### P0-C 幂等键遇 `/` 打崩整个 Run
- **现象**：浏览器 `25025ec2` → `RUN_FAILED / INTERNAL_ERROR`，前端显示"这次分析临时未能完成"。
- **根因**：模型把知识点写成 `h=-b/2a…`（含 `/`），`IdempotencyKey.requirePart` 拒绝分隔符 →
  `IllegalArgumentException` 从 `ToolInvocationGate` ③ 幂等键构造处逃逸到 `RunExecutionLoop`
  → 整个 Run 判 INTERNAL_ERROR。
- **修复（双保险）**：
  1. `IdempotencyKey`：组成部分改为**可逆百分号编码**（`%`→`%25`、`/`→`%2F`），
     唯一分解性不变（`%252F` 与 `%2F` 不撞），三处解析点同步 `decodePart`；
  2. `ToolInvocationGate`：幂等键构造纳入 try/catch → 降级为 `recordRejected`（工具级拒绝），
     任何未来的键构造异常都不再打崩 Run。
- **验收**：`IdempotencyProtocolTest` 38 用例全绿（3 个原"拒绝分隔符"用例改为"编码+唯一分解"断言）；
  浏览器 `a20b51bc` 全流程 SUCCEEDED。

## 四、本轮补齐的验收缺口（上一轮只做了实现，没做契约守卫）

1. **公式渲染契约测试**：新增 `frontend/tests/markdownAnswer.math.test.tsx`（5 用例）——
   A 行内/块级 `$…$`、`B` 单独占行 `\[…\]`（教师评审实测原始形态）、C 裸 LaTeX 命令、
   D 公式不得变成 HTML 执行通道、E 非法公式不崩页。
   - 断言"源码不残留"必须**剥掉 `.katex` 子树**后再比：KaTeX 的 MathML `<annotation>` 合法保留源码。
   - **反向验证**：撤掉 `rehypeKatex` 插件 → A/B/C 三个用例变红；恢复后 `cmp` 逐字节一致、5/5 绿。
2. **种子内容指纹漂移**：上一轮改了 math-tutor 的 `enabled_skills` 与提示词却**没重算
   `config_fingerprint`**（存储 `10bf887c…`，实算不符）→ 闭包失效检测/缓存判定失真。
   本轮按 `CapObjectFingerprint` 算法重算并与双写旧路径 `agent_version.definition` 同步；
   用 Python 复刻算法先对活库 v2 做**同值校验**再用同一实现重算，避免手算错。
3. **模型输出格式契约**（方案 §1 写明但上一轮漏落）：math-tutor 与 E2E Agent 的提示词均加入
   「所有数学公式一律 LaTeX：行内 `\(...\)`，独立成段 `\[...\]`，花括号成对，严禁纯文本拼公式」。
   活库发布 v5。
