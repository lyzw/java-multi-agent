# Admin Console 平台身份与租户身份分离 — 彻底改造方案

> 适用范围：Java SaaS Agent 平台（模块化单体 + 独立 Worker，Spring Boot 4.1.1 / Security 7.1 / Jakarta 11 / Jackson 3 / Java 21 / PostgreSQL 17+ / RabbitMQ）。
> 决策前提：**项目尚未上线**，因此本方案作为全新基线设计，不迁就现有 `principal` / `PLATFORM_ADMIN` 实现；现有 dev/test 库可整体重置，无需生产数据迁移。
> 核心结论：`admin-console` 必须是独立的 **Platform Control Plane**（独立主体、独立令牌、独立授权域、独立数据域），而不是"拥有全租户权限的超级租户控制台"。

---

## 0. 关键设计决策（先拍板）

| 决策点 | 本方案选择 | 理由 |
|---|---|---|
| 物理部署 | **保持模块化单体**（单 deployable），但安全边界严格分离 | 提案明确"不是必须拆成两个后端"；先以逻辑+安全边界隔离，未来可平滑切物理部署 |
| 令牌 | 平台/租户两套 JWT，**不同 `aud`**，可共用 issuer 但**独立密钥轮转** | 令牌层即可拒绝跨域调用，满足验收清单第 1 条 |
| 数据库角色 | 三套连接角色：`platform_ops`（平台域，可管理 platform schema）、`app_tenant`（租户域，RLS）、`app_agent`（Worker，可信任务上下文） | 延续既有 RLS 铁律与 BYPASSRLS 双通道纪律 |
| 主体模型 | `PlatformPrincipal` 与 `TenantPrincipal` 两类独立 record，无共享角色表 | 提案原则 #1 |
| 授权 | 两个独立 `AuthorizationService` 接口 + 两个权限命名空间 | 提案 §4 / §7.2 |
| 平台赋权 | 平台角色**仍走带外运维通道授予**，应用层不提供"创建超级管理员/自授平台角色"端点 | 防自举回路（既有 `04_platform_admin_grant.sql` 纪律保留并升级） |
| 租户业务执行 | 平台管理权 ≠ 业务执行权；Worker 执行仍过 `ToolInvocationGate` | 提案执行分离原则 |

```
┌──────────────────────────── Platform Control Plane ────────────────────────────┐
│  admin-console (React)                                                                 │
│      │  /api/platform/v1/*  (aud=admin-console-api)                                  │
│      ▼                                                                                │
│  PlatformAuthentication ─▶ PlatformAuthorizationService ─▶ Platform Management Svc   │
│      │                                  │                                            │

│      ▼                                                                                │
│  platform schema (platform_user / role / tenant lifecycle / quota / capability /    │
│                    policy / platform_audit_event)  ◀── platform_ops DB 角色           │

                                     │ 仅"租户管理元数据"（不含业务内容）

┌──────────────────────────── Tenant Control Plane ───────────────────────────────┐
│  租户控制台 / 业务 API  (/api/tenant/v1/*  aud=tenant-api)                           │
│      ▼                                                                                │
│  TenantAuthentication ─▶ TenantMembership ─▶ TenantAuthorizationService ─▶ 业务 Svc  │
│      │                                  │ tenant.* 权限命名空间 + RLS                 │
│      ▼                                                                                │
│  租户表 (tenant_user / membership / agent / run / session / tenant_audit_event)      │
│  强制 tenant_id + RLS  ◀── app_tenant DB 角色                                         │
└───────────────────────────────────────────────────────────────────────────────────┘
                                     │ 共享执行基础设施
                                     ▼
        Shared Execution：Worker / MQ / Outbox / execution_capability_snapshot
        Worker 从可信任务记录建立 TenantContext，重校验租户状态+授权版本+执行快照
```

两条访问路径可共用底层业务服务与 Worker，但**不能共用一个无身份域校验的通用管理接口**。

## 2. 模块与包结构（platform/）

保留现有模块化单体布局，新增/重构如下：

```
platform/
├── platform-identity/                 # 【新增】平台身份域
│   └── src/main/java/.../identity/
│       ├── PlatformPrincipal.java          # record(sub, sessionId, roles, authzVersion, mfaVerified)
│       ├── PlatformAuthentication.java      # 平台登录/会话校验
│       ├── PlatformAuthorizationService.java# 平台授权接口（Decision 返回）
│       ├── PlatformJwtTokenService.java     # 签发/校验 aud=admin-console-api
│       ├── port/  PlatformUserRepository / PlatformRoleRepository / PlatformAuditRepository
│       └── infra/ Jdbc* 实现（platform_ops 角色）
├── agent-core/                        # 租户身份域（重构 TenantContext → 显式 TenantPrincipal）
│   └── .../tenant/
│       ├── TenantPrincipal.java            # record(sub, tenantId, membershipId, roles, authzVersion)
│       └── TenantContext.java              # 由 TenantPrincipal + 校验后派生
├── agent-ports/                       # 授权端口（拆分两个接口）
│   └── .../security/
│       ├── PlatformAuthorizationService.java
│       ├── TenantAuthorizationService.java
│       ├── AuthorizationDecision.java       # {allowed, reasonCode, policyVersion, decisionId}
│       └── Namespaces.java                  # platform.* / tenant.* 常量冻结
├── agent-infrastructure/              # 安全实现：两套 JWT、RLS 上下文、Repository
├── agent-api/
│   ├── platform/   # /api/platform/v1/* 控制器（用户/角色/租户/资源/审计）
│   └── tenant/     # /api/tenant/v1/* 控制器（成员/角色/agent/run...）
└── platform-bootstrap/
    └── config/SecurityConfiguration.java    # 【关键】两条独立 SecurityFilterChain
```

**两条过滤器链**（platform-bootstrap）：

```java
// 链 1：平台管理 API
securityFilterChainPlatform(http) {
  http.securityMatcher("/api/platform/**")
     .addFilterBefore(PlatformBearerTokenFilter, UsernamePasswordAuthFilter)
     .sessionManagement(STATELESS)
     .authorizeHttpRequests(a -> a.anyRequest().authenticated())
     .csrf(disabled).httpBasic(disabled);
}
// 链 2：租户业务 API
securityFilterChainTenant(http) {
  http.securityMatcher("/api/tenant/**")
     .addFilterBefore(TenantBearerTokenFilter, ...)
     .sessionManagement(STATELESS)...;
}
```

`PlatformBearerTokenFilter` 校验 `aud=admin-console-api` 且 `principal_type=PLATFORM_USER`；`TenantBearerTokenFilter` 校验 `aud=tenant-api` 且 `principal_type=TENANT_USER`。**任何一链收到对方 `aud` 的令牌直接 401/403**，从令牌层实现身份隔离。

## 3. 身份数据模型（DDL 蓝图）

### 3.1 Platform Schema（平台域，无 RLS，platform_ops 管理）

```sql
CREATE SCHEMA IF NOT EXISTS platform;

CREATE TYPE platform.user_status  AS ENUM ('ACTIVE','DISABLED','LOCKED');
CREATE TYPE platform.auth_source   AS ENUM ('LOCAL','OIDC','SSO');

CREATE TABLE platform.platform_user (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username      VARCHAR(128) NOT NULL UNIQUE,
    email         VARCHAR(256) UNIQUE,
    display_name  VARCHAR(128),
    status        platform.user_status NOT NULL DEFAULT 'ACTIVE',
    auth_source   platform.auth_source  NOT NULL,
    mfa_required  BOOLEAN NOT NULL DEFAULT FALSE,
    last_login_at TIMESTAMPTZ,
    authz_version BIGINT NOT NULL DEFAULT 1,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    version       BIGINT NOT NULL DEFAULT 0          -- 乐观锁
);

CREATE TABLE platform.platform_role (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(64) NOT NULL UNIQUE,          -- PLATFORM_SUPER_ADMIN ...
    description VARCHAR(256),
    built_in    BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE platform.platform_permission (
    id   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code VARCHAR(128) NOT NULL UNIQUE                 -- platform.tenant.create ...
);

CREATE TABLE platform.platform_role_permission (
    role_id       UUID NOT NULL REFERENCES platform.platform_role(id),
    permission_id  UUID NOT NULL REFERENCES platform.platform_permission(id),
    PRIMARY KEY (role_id, permission_id)
);

CREATE TABLE platform.platform_user_role (
    platform_user_id UUID NOT NULL REFERENCES platform.platform_user(id),
    role_id          UUID NOT NULL REFERENCES platform.platform_role(id),
    granted_by       UUID NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (platform_user_id, role_id)
);

CREATE TABLE platform.platform_session (
    id            UUID PRIMARY KEY,
    platform_user_id UUID NOT NULL REFERENCES platform.platform_user(id),
    revoked       BOOLEAN NOT NULL DEFAULT FALSE,
    mfa_verified  BOOLEAN NOT NULL DEFAULT FALSE,
    expires_at    TIMESTAMPTZ NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE platform.platform_mfa_credential (
    id              UUID PRIMARY KEY,
    platform_user_id UUID NOT NULL REFERENCES platform.platform_user(id),
    type            VARCHAR(32) NOT NULL,             -- TOTP / WEBAUTHN / SSO_BIND
    ext_subject     VARCHAR(256),                     -- 外部 IdP subject
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 租户生命周期 / 配额 / 能力授权（平台对租户的管理关系，不把平台用户加入租户）
CREATE TABLE platform.tenant (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name                VARCHAR(128) NOT NULL,
    slug                VARCHAR(64)  NOT NULL UNIQUE,
    status              VARCHAR(32)  NOT NULL,         -- 状态机见 §7
    plan                VARCHAR(32),
    lifecycle_state     VARCHAR(32)  NOT NULL,
    effective_policy_version BIGINT NOT NULL DEFAULT 1,
    tenant_authz_version     BIGINT NOT NULL DEFAULT 1,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE platform.tenant_quota (
    tenant_id           UUID NOT NULL REFERENCES platform.tenant(id),
    agent_limit         INT,
    run_concurrency_limit INT,
    budget_limit        NUMERIC(14,2),
    PRIMARY KEY (tenant_id)
);

CREATE TABLE platform.tenant_capability_grant (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id   UUID NOT NULL REFERENCES platform.tenant(id),
    resource_code VARCHAR(128) NOT NULL,              -- cap.tool:xxx / cap.mcp:yyy
    scope       VARCHAR(32) NOT NULL,                  -- ALLOWED / DENIED
    status      VARCHAR(32) NOT NULL DEFAULT 'ACTIVE',
    version     BIGINT NOT NULL DEFAULT 1,
    UNIQUE (tenant_id, resource_code)
);

CREATE TABLE platform.platform_audit_event (           -- 【无 tenant_id】
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    actor_id      UUID NOT NULL,
    actor_type    VARCHAR(32) NOT NULL DEFAULT 'PLATFORM_USER',
    action        VARCHAR(128) NOT NULL,
    target_type   VARCHAR(64),
    target_id     UUID,
    decision      VARCHAR(16) NOT NULL,                -- ALLOW / DENY
    reason_code   VARCHAR(64),
    correlation_id UUID,                               -- 跨域调查关联
    ip            INET,
    occurred_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

> 约束：`platform_user` 不设 `tenant_id`；平台权限/租户权限分别建表；平台角色外键指向 `platform_role`，与租户角色表物理隔离。

### 3.2 Tenant Schema（租户域，强制 RLS）

```sql
-- 身份主体与成员关系分离（支持"用户可加入多租户"或"单租户"两种形态）
CREATE TABLE tenant_user (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username      VARCHAR(128) NOT NULL,
    status        VARCHAR(32) NOT NULL,
    authz_version BIGINT NOT NULL DEFAULT 1,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (username)                                         -- 邮箱唯一性仅在本域定义
);

CREATE TABLE tenant (
    id   UUID PRIMARY KEY,                                    -- 与 platform.tenant.id 关联（逻辑外键，跨 schema）
    name VARCHAR(128)
);

CREATE TABLE tenant_membership (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id      UUID NOT NULL REFERENCES tenant(id),
    tenant_user_id UUID NOT NULL REFERENCES tenant_user(id),
    status         VARCHAR(32) NOT NULL,
    authz_version  BIGINT NOT NULL DEFAULT 1,
    UNIQUE (tenant_id, tenant_user_id)
);

CREATE TABLE tenant_role (
    id   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenant(id),
    name VARCHAR(64) NOT NULL,
    UNIQUE (tenant_id, name)
);

CREATE TABLE tenant_permission (
    id   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenant(id),
    code VARCHAR(128) NOT NULL,
    UNIQUE (tenant_id, code)
);

CREATE TABLE tenant_user_role (
    membership_id UUID NOT NULL REFERENCES tenant_membership(id),
    role_id       UUID NOT NULL REFERENCES tenant_role(id),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (membership_id, role_id)
);

CREATE TABLE tenant_role_permission (
    role_id        UUID NOT NULL REFERENCES tenant_role(id),
    permission_id  UUID NOT NULL REFERENCES tenant_permission(id),
    PRIMARY KEY (role_id, permission_id)
);

-- 业务表（agent / run / session / 会话 / 凭据引用）一律带 tenant_id 并 RLS
-- 例：
CREATE TABLE agent (
    id UUID PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenant(id),
    ...
);
ALTER TABLE agent ENABLE ROW LEVEL SECURITY;
ALTER TABLE agent FORCE ROW LEVEL SECURITY;
CREATE POLICY agent_tenant_isolation ON agent
  USING (tenant_id = current_setting('app.tenant_id')::uuid);
```

### 3.3 共享执行元数据（Worker / MQ / Outbox）

保留 `execution_capability_snapshot`（执行时不可变配置快照）、`outbox`、`task` 等。Worker 仅以 `app_agent` 角色连接，从**可信任务记录**取 `tenant_id`，绝不信任消息体传入的 `tenant_id`；执行前重校验 `tenant.status`、`tenant_authz_version`、`capability_grant.status` 与快照版本。

### 3.4 RLS 铁律（沿用并强化）

1. `set_config('app.tenant_id', ?, true)` 必须位于事务内。
2. RLS 依赖服务端可信上下文，`tenant_id` 不得来自请求参数。
3. 平台身份**无法**通过将 `tenant_id` 置空/通配符绕过 RLS——平台域本就无 RLS、且平台主体不持有 `tenant_id`。
4. 禁止常规业务连接使用 `BYPASSRLS`；仅 `platform_ops`（平台域写）与受控运维例外，且隔离。
5. 适用版本使用 `FORCE ROW LEVEL SECURITY`，并核对表所有者/连接角色/函数权限。

## 4. 认证与会话契约

### 4.1 平台令牌（示例 claims）

```json
{
  "sub": "platform_user_001",
  "principal_type": "PLATFORM_USER",
  "aud": "admin-console-api",
  "session_id": "platform_session_001",
  "roles": ["PLATFORM_SUPER_ADMIN"],
  "authz_version": 7,
  "mfa": true,
  "iss": "java-multi-agent",
  "exp": 1700000000
}
```

### 4.2 租户令牌（示例 claims）

```json
{
  "sub": "tenant_user_001",
  "principal_type": "TENANT_USER",
  "tenant_id": "tenant_123",
  "aud": "tenant-api",
  "session_id": "tenant_session_001",
  "membership_id": "mem_456",
  "authz_version": 12,
  "iss": "java-multi-agent",
  "exp": 1700000000
}
```

### 4.3 规则

- 两套 JWT 独立密钥轮转；校验 `iss` / `aud` / `exp` / 签名 / `principal_type`。
- **令牌层互拒**：平台 `aud` 的令牌被租户 API 接收 → 401；反之亦然。
- 角色/权限声明不作撤权后长期有效依据；高风险操作重校验 `authz_version`、租户状态、审批状态。
- 不允许前端提交 `principal_type` / `tenant_id` / `role` 自行切换身份。
- 两套会话的登出/撤销/过期/MFA 分别管理；`platform_session.revoked` 与 `tenant_session` 独立。
- 高权限平台角色强制 MFA；敏感操作重认证。
- 同一自然人兼任平台运营与租户业务 → **两个独立主体**，不因邮箱相同合并权限（外部 IdP 用 `issuer+subject+identity_domain` 映射隔离）。

## 5. 授权模型

### 5.1 两个接口

```java
interface PlatformAuthorizationService {
    AuthorizationDecision authorize(PlatformPrincipal p, String action, Resource r);
}
interface TenantAuthorizationService {
    AuthorizationDecision authorize(TenantPrincipal p, String action, Resource r, TenantContext ctx);
}
```

`AuthorizationDecision { boolean allowed; String reasonCode; long policyVersion; UUID decisionId; }` —— 返回明确结果与拒绝原因，供审计。

### 5.2 权限命名空间（冻结清单）

**平台域 `platform.*`**

| 前缀 | 动作 |
|---|---|
| `platform.user.*` | `read` `manage` |
| `platform.role.*` | `read` `assign` `revoke` |
| `platform.tenant.*` | `create` `read` `update` `suspend` `resume` `decommission` |
| `platform.tenant.quota.*` | `read` `update` |
| `platform.tenant.capability.*` | `grant` `revoke` `read` |
| `platform.resource.*` | `read` `manage`（全局 Tool/MCP/模型目录） |
| `platform.policy.*` | `read` `publish` |
| `platform.audit.*` | `read` `export` |
| `platform.support.*` | `diagnostics.read` |

**租户域 `tenant.*`**

| 前缀 | 动作 |
|---|---|
| `tenant.member.*` | `read` `invite` `remove` |
| `tenant.role.*` | `read` `assign` |
| `tenant.agent.*` | `read` `edit` `publish` |
| `tenant.skill.*` | `read` `manage` |
| `tenant.tool.*` | `use` `configure` |
| `tenant.mcp.*` | `read` `configure` |
| `tenant.run.*` | `create` `read` `cancel` |
| `tenant.audit.*` | `read` |

> 正式契约须冻结完整清单、资源类型与操作定义（写入 `Namespaces.java` + OpenAPI）。

### 5.3 平台角色目录（最小特权 + 职责分离）

| 角色 | 权限范围 | 明确禁止 |
|---|---|---|
| `PLATFORM_SUPER_ADMIN` | 全部平台动作 | 不因此获租户业务数据/凭据明文/任意 Agent 执行 |
| `TENANT_LIFECYCLE_ADMIN` | `platform.tenant.*` + quota/capability | 不管理租户内部用户角色或业务数据 |
| `PLATFORM_RESOURCE_ADMIN` | `platform.resource.*` `platform.policy.read` | 不读租户私有配置/秘密 |
| `PLATFORM_SECURITY_ADMIN` | `platform.policy.*` `platform.role.read` | 普通情况不可改自身角色/建超级管理员/读业务数据 |
| `PLATFORM_AUDITOR` | `platform.audit.read`(脱敏) | 不读租户业务内容 |
| `PLATFORM_SUPPORT` | `platform.support.diagnostics.read` | 不读凭据明文/完整提示词/会话内容 |

### 5.4 租户角色目录

`TENANT_OWNER` / `TENANT_ADMIN` / `TENANT_SECURITY_ADMIN` / `TENANT_DEVELOPER` / `TENANT_OPERATOR` / `TENANT_AUDITOR` / `TENANT_MEMBER`（权限与禁止项见提案 §3.2，本方案原样采用）。

### 5.5 授权判定公式（服务端确定身份与范围）

```
Allow_platform = Authenticated_platform ∧ Active_platform ∧ Permission_platform ∧ Policy_platform
Allow_tenant   = Authenticated_tenant ∧ Active_tenant ∧ Membership_tenant
                 ∧ Permission_tenant ∧ Scope_tenant ∧ Policy_effective(含租户 status)
```

平台角色**不能**替代 `Membership_tenant`；租户角色**不能**替代平台权限。默认拒绝、显式授权、服务端定身份与数据范围。

### 5.6 非 RBAC 能解决的边界（执行时校验）

- 平台可暂停租户，但不可直接改租户 Agent 发布版本。
- 平台资源管理员发布平台级 Tool，租户能否用仍须经 `tenant_capability_grant` 授权。
- 租户开发者有 `agent:edit` ≠ 可调用所有 Tool/MCP（仍过 `ToolInvocationGate`）。
- 租户管理员有 `member:invite` ≠ 可把平台角色授给自己。
- 平台支持看脱敏诊断 ≠ 可读完整提示词/会话/凭据明文。
- Agent/Skill/Tool/MCP 实际执行仍过现有执行安全门禁。

## 6. 数据访问与隔离矩阵

| 数据类型 | 平台管理员 | 租户管理员 | 租户普通用户 |
|---|---|---|---|
| 平台用户/角色 | 按平台权限 | 禁止 | 禁止 |
| 租户列表/生命周期 | 按平台权限（仅管理元数据） | 仅自身租户基础信息 | 仅授权可见 |
| 套餐/配额/能力授权 | 管理配置 | 看自身，不可破上限 | 按业务只读 |
| 租户内部用户/角色 | 默认禁止直接管理 | 本租户 | 按授权 |
| Agent/Skill 配置 | 不直接改租户私有资源 | 本租户 | 按授权 |
| 平台级 Tool/MCP 注册 | 按平台权限 | 看获授权目录 | 按授权用 |
| 租户私有 Tool/MCP 配置 | 默认禁止 | 本租户，秘密受控 | 按授权 |
| 业务会话/提示词/执行结果 | 默认禁止 | 按租户权限 | 按资源授权 |
| 凭据明文 | 禁止默认读取 | 仅受控凭据流程 | 禁止读不必要明文 |
| 平台审计 | 按平台审计权限 | 禁止全平台日志 | 禁止 |
| 租户业务审计 | 仅脱敏管理元数据/受控视图 | 本租户 | 按审计授权 |

"默认禁止"≠平台永不协助：生产事故走**独立受控支持流程**（明确目的、指定租户、最小范围、短时授权、审批、留痕、自动失效，高风险双人审批）——不是普通平台角色的隐式超级权限。

## 7. 租户生命周期状态机

```
PENDING_SETUP ──▶ ACTIVE
ACTIVE ──▶ SUSPENDED ──▶ ACTIVE
PENDING_SETUP ──▶ CANCELLED
ACTIVE ──▶ DECOMMISSIONING ──▶ DECOMMISSIONED
（可选扩展 EXPIRED / DELETING，但各服务须统一状态枚举）
```

### 创建租户（关键：不自动建租户管理员）

1. `PLATFORM_SUPER_ADMIN` / `TENANT_LIFECYCLE_ADMIN` 经 `platform.tenant.create` 发起。
2. 服务端校验权限、slug 唯一、套餐/资源上限。
3. 事务内建 `platform.tenant` + 初始 quota + capability grant + `effective_policy_version`。
4. 进入 `PENDING_SETUP`，经**独立邀请流程**建首位 `TenantUser`（平台不知其密码，不以平台主体冒充）。
5. 租户管理员完成验证与安全初始化 → `ACTIVE`。
6. 记 `platform_audit_event`；创建失败不留半初始化租户。

### 暂停/恢复

- 拒新业务请求与新任务提交；按策略取消/暂停在跑任务。
- Worker 执行时重校验租户状态，不只信入队时检查。
- 按 `tenant_authz_version` / 状态版本使旧授权上下文失效。
- 保留审计/计费/任务终态/恢复所需元数据；恢复后重检权限/配额/任务状态，不盲目恢复过期任务。
- 暂停**不**自动删用户/角色/Agent/历史业务数据。

## 8. 审计分离

- `platform_audit_event`（无 `tenant_id`，`actor_type=PLATFORM_USER`）+ `tenant_audit_event`（带 `tenant_id`，RLS）。
- 通过 `correlation_id` 支持必要跨域调查，但不混库、不互授权。
- 敏感操作记录：操作者、目标、结果、审批、关联请求（可追踪）。
- 脱敏：平台审计员看租户生命周期/授权变更，默认不展开业务内容；`tenant_audit_event` 经 RLS 仅本租户可见。

## 9. API 分区契约

| 分区 | 路径 | 身份要求 |
|---|---|---|
| 平台认证 | `/api/platform/v1/auth/*` | 平台身份认证 |
| 平台用户 | `/api/platform/v1/users/*` | `PlatformPrincipal` |
| 平台角色 | `/api/platform/v1/roles/*` | `PlatformPrincipal` + `platform.role.*` |
| 平台租户管理 | `/api/platform/v1/tenants/*` | `PlatformPrincipal` + `platform.tenant.*` |
| 平台资源 | `/api/platform/v1/resources/*` | `PlatformPrincipal` + `platform.resource.*` |
| 平台审计 | `/api/platform/v1/audit-events/*` | `PlatformPrincipal` + `platform.audit.*` |
| 租户认证 | `/api/tenant/v1/auth/*` | 租户身份认证 |
| 租户成员/角色 | `/api/tenant/v1/members/*` `/api/tenant/v1/roles/*` | `TenantPrincipal` |
| 租户 Agent 等资源 | `/api/tenant/v1/agents/*` 等 | `TenantPrincipal` + `tenant.*` |
| 租户运行任务 | `/api/tenant/v1/runs/*` | `TenantPrincipal` + `tenant.run.*` + 执行授权 |

- API 路径本身不是安全边界，但清晰命名减少误用、稳定契约。
- 写操作验证请求状态、资源版本、授权版本；敏感操作需审批/重认证不因"可信后台"而跳过。
- 平台租户管理 API 接受显式 `target_tenant_id` 作资源标识，但**不**解释为调用者已取得该租户业务身份。

## 10. Admin Console 功能范围（前端 admin-console）

**菜单模块**：平台总览 / 租户管理 / 平台用户与权限 / 平台资源与能力目录 / 全局安全策略 / 运行监控与审计。

支持人员协助须走独立受控访问入口，不复用平台登录态。

## 13. 风险与回退

- **范围风险**：双域拆分体量大，P0 必须先把契约与负向测试冻结，避免后期返工。
- **自举回路风险**：平台角色若开放应用层赋权端点，会重现"谁赋权谁自封管理员"；必须保留带外 `platform_ops` 授予纪律（升级版 `04_platform_admin_grant.sql` 写入 `platform.platform_user_role`）。
- **RLS 绕过风险**：平台域虽无 RLS，但 `platform_ops` 仅用于平台 schema；任何租户表访问必须经 `app_tenant` + RLS。
- **回退**：因未上线，采用特性开关（feature flag）灰度两套认证链；旧 `principal` 体系在 P0 重置时整体清空，无需兼容迁移。

---

## 14. 与现有执行门禁的衔接

现有 `ToolInvocationGate`、Outbox/MQ 唤醒、Worker 执行循环、三版本（config/授权/执行快照）分离**全部保留并强化**：
- Worker 从可信任务记录建 `TenantContext`（由 `TenantPrincipal` 派生），重校验 `tenant.status` + `tenant_authz_version` + `capability_grant.status` + 快照版本。
- 平台管理权不进入执行授权路径；Agent/Skill/Tool/MCP 运行时授权仍由租户授权 + 执行门禁决定。
- `execution_capability_snapshot` 记录不可变配置快照，旧快照不能绕过当前强制策略与租户暂停状态。

---

*本方案为全新基线，落地前需经 P0 架构评审与威胁模型复审。当前 dev/test 库可随本方案重置。*
