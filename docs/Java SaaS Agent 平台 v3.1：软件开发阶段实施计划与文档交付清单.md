# Java SaaS Agent 平台 v3.1：软件开发阶段实施计划与文档交付清单

> **版本**：v1.0  
> **架构基线**：《Java SaaS Agent 平台：规划与技术架构设计方案 v3.1（最终实施版）》  
> **用途**：把架构基线拆解为可排期的工作包、阶段门禁、责任分工、测试证据和文档交付物。  
> **计划口径**：约 18 周的初始估算，适用于一个具备后端、执行引擎、测试和平台工程能力的团队；实际排期需根据人数、已有基础设施和外部系统接入情况调整。  
> **约束**：本计划不替代 v3.1 架构协议。若实施中改变状态机、租户安全边界、幂等、预算、审批或恢复语义，必须先更新 ADR、架构文档和测试，再合并实现。

---

## 1. 执行原则与完成标准

1. **按可验证增量交付**：每阶段必须有可运行软件、测试结果、文档和明确的退出门禁，不以代码提交数或文档完成度代替验收。
2. **先验证高风险协议**：先验证 PostgreSQL + Outbox、MQ 重复投递、Worker 租约/fencing、模型网关、工具调用 UNKNOWN、租户上下文和 SSE 续传，再大规模开发。
3. **以数据库作为执行事实源**：Run、Step、ToolOperation、Approval、RunEvent、Usage/Budget、Audit 和 Outbox 的权威状态落在 PostgreSQL；MQ 用于通知和唤醒，不作为业务状态唯一来源。
4. **分清三层尝试语义**：Run attempt、ToolOperation 逻辑操作、工具调用 attempt 分开建模和计数；重试不得模糊为同一个“次数”。
5. **副作用先记账、后调用、可对账**：外部调用超时或响应丢失时按 UNKNOWN 处理；在确认结果前，不盲目重放，不把超时等同于取消，也不随意释放预算预留。
6. **安全不是后置阶段**：身份认证、服务端授权、TenantContext、对象存储每次读取授权、Prompt Injection 边界、Egress/SSRF、脱敏和审计从 MVP 开始实现；P3/P4 补齐强度与证据。
7. **文档与实现同版本**：OpenAPI、DDL/迁移、状态机、ADR、配置、Runbook 和测试用例随代码变更更新。
8. **生产门禁必须有证据**：关键门禁应能关联 CI 报告、测试记录、演练记录、指标截图或批准的风险接受单。

### 1.1 建议的研发工作流

需求登记 → 业务验收标准 → 技术拆解与依赖分析 → ADR/接口/数据设计 → 任务估算 → 实现 → 自动化测试 → Code Review → 测试环境验收 → 文档同步 → 发布与观测 → 复盘。

每个工作项必须至少包含：`需求/任务 ID`、背景、范围、依赖、负责人、验收标准、测试用例、涉及文档、风险/回滚策略。

### 1.2 单项 DoD（Definition of Done）

- [ ] 验收标准满足，或未完成项已登记并由授权人批准。
- [ ] 代码已合并并通过非作者 Review；安全、状态机、迁移和权限改动有领域负责人 Review。
- [ ] 相关单元/集成/契约/E2E 测试通过，测试证据可追溯。
- [ ] 涉及 API、DDL、状态机、配置或权限的文档同步更新。
- [ ] 关键路径具备日志、指标、Trace、审计和可定位错误信息；不记录密钥或不必要的敏感内容。
- [ ] 涉及副作用时，幂等、超时、重试、UNKNOWN 和对账语义明确且有测试。
- [ ] 涉及权限时，既有正向授权测试，也有越权拒绝测试。
- [ ] 涉及数据库迁移时，迁移、失败处理及回滚/前向修复路径已在目标版本验证。

### 退出门禁

- ADR-001 至 ADR-010 中影响实施的关键决策已决定，或有明确 owner、截止时间和禁止进入生产的标记。
- v3.1 附录 E 的 PoC 验收项均有数据证据；未通过项有修复任务和复测日期。
- 新成员按文档可启动项目、运行迁移和测试。
- 模块依赖、状态机、租户安全边界和 API/数据协议已冻结；后续变更走 ADR。

## 5. P2：核心闭环 MVP（第 3–7 周）

### 目标

按垂直切片构建可运行的最小平台：Agent 版本可发布，Run 可创建和查询，Worker 可异步执行模型和只读工具，结果、事件、错误与审计可追踪。

### Sprint 1（第 3 周）：工程骨架、租户上下文、Agent/Version

| 任务 ID | 实施任务 | 具体内容 | 验收点 |
|---|---|---|---|
| P2-S1-01 | 模块骨架 | 按 v3.1 包结构创建 api/application/domain/ports/infrastructure/worker/testkit | 依赖方向符合架构约束，无循环依赖 |
| P2-S1-02 | 身份与租户上下文 | 从可信认证上下文生成 TenantContext；客户端传入 tenant_id 不作为授权依据 | 未授权租户请求拒绝；上下文不串租户 |
| P2-S1-03 | Agent CRUD 与版本 | 草稿、版本、发布状态和不可变版本标识；校验发布配置 | 已发布版本可追溯；版本内容不可原地变更 |
| P2-S1-04 | DDL 与迁移流水线 | 建立版本化迁移、测试库初始化和失败检测 | 空库可建库；迁移可在 CI 自动执行 |

### Sprint 2（第 4 周）：Run API、幂等创建、状态机、事件和 Outbox

| 任务 ID | 实施任务 | 具体内容 | 验收点 |
|---|---|---|---|
| P2-S2-01 | 创建 Run | 创建 Run、初始事件、幂等记录、Outbox 在同一事务提交；初始状态为 QUEUED | 事务失败时不留下半成品；重复请求返回一致结果 |
| P2-S2-02 | Run 查询与状态迁移 | 通过迁移守卫更新状态；禁止任意字段直接改状态 | 非法迁移拒绝；并发迁移有确定结果 |
| P2-S2-03 | Run/Step/Event 持久化 | 写入可追踪事件、关联 run_id/tenant_id/correlation_id | 从 Run 可还原主要执行轨迹 |
| P2-S2-04 | API 契约与错误模型 | 定义参数错误、无权限、不存在、冲突、限流和下游失败 | OpenAPI 与实现/契约测试一致 |
| P2-S2-05 | Outbox Publisher 初版 | 可靠发布、重复投递允许、失败重试有记录 | DB 成功但发布失败时可恢复发布 |

### Sprint 3（第 5 周）：Worker、租约、ModelGateway

| 任务 ID | 实施任务 | 具体内容 | 验收点 |
|---|---|---|---|
| P2-S3-01 | Worker 消费与领取 | MQ 只作为唤醒；Worker 按数据库状态和租户上下文领取任务 | 重复消息不导致重复创建 Run |
| P2-S3-02 | lease/heartbeat 基础版 | 领取后建立租约、周期续租、记录 fencing token；支持取消轮询 | 失联任务可被识别；旧 token 不能写入 |
| P2-S3-03 | ModelGateway | 统一模型请求、超时、限流、错误映射和 usage 采集 | 模型错误分类明确；敏感信息不进入日志 |
| P2-S3-04 | 执行快照 | Run 绑定不可变 Agent/Prompt/策略/工具契约快照 | 后续编辑 Agent 不改变已创建 Run 的配置 |
| P2-S3-05 | 执行状态与失败分类 | 记录成功、失败、超时、取消等状态和错误分类 | 失败原因可查询，不只靠日志判断 |

### Sprint 4（第 6 周）：Tool SPI、权限、工具操作账本

| 任务 ID | 实施任务 | 具体内容 | 验收点 |
|---|---|---|---|

## 11. 生产准入检查表（阶段验收汇总）

### 功能与契约

- [ ] Agent 草稿、版本、发布与不可变快照可用。
- [ ] Run 创建、查询、取消、受控重试和结果读取可用。
- [ ] OpenAPI 与实际行为一致；幂等键范围、请求摘要冲突和保留期明确。
- [ ] 工具输入/输出 Schema、执行时授权、审计和错误分类完整。
- [ ] SSE 支持续传、授权校验、保留期与游标重置语义。

### 一致性与恢复

- [ ] Run + 初始事件 + 幂等记录 + Outbox 原子提交。
- [ ] Run attempt、ToolOperation 逻辑操作和调用 attempt 的字段/指标含义分离。
- [ ] 重复消息、重复发布和重复结算安全。
- [ ] Worker 租约续期、取消轮询、接管和 fencing 有故障注入证据。
- [ ] UNKNOWN 有对账与人工处置流程，禁止未经确认盲目重放。
- [ ] Approval 消费与取消检查处于同一短事务；外部调用在事务之外；消费后崩溃可恢复。
- [ ] 预算有原子预留和唯一预留记录，UNKNOWN 不会错误释放不确定成本。
- [ ] 旧 Run 恢复会校验契约兼容性并重新验证当前授权。

### 安全与隐私

- [ ] 跨租户 Run、Step、Event、Conversation、ToolOperation、Approval、文件、缓存和审计访问均有拒绝测试。
- [ ] RLS、TenantContext、连接池复用和共享 MQ 租户校验通过。
- [ ] Prompt Injection、SSRF/Egress、秘密泄漏和工具权限绕过测试通过。
- [ ] 对象存储每次读取重新授权；预签名 URL 的范围、有效期和撤权风险已评审。
- [ ] 日志、Trace、事件和对象内容分别有脱敏、访问和保留策略。
- [ ] 指标标签基数受控，不把用户输入、Run ID 或高基数标识作为普通标签。

### 运营与发布

- [ ] 5–10 个基础 Agent 评测用例进入 CI 或发布门禁，高风险工具有专属契约测试。
- [ ] PoC 数据、未通过项、风险接受人和复测记录可追溯。
- [ ] 关键仪表盘和告警已验证通知路径与责任人。
- [ ] 容量目标、SLO、RPO/RTO 由业务/技术确认并有测试证据。
- [ ] 备份恢复、迁移、发布和回滚已演练。
- [ ] 运维手册、值班、支持升级路径和试点交接已完成。

## 14. 变更管理与决策规则

1. 若改变 Run/ToolOperation/Approval 状态、事务边界、幂等键、预算预留、取消优先级、RLS 或对象授权，必须提交 ADR 或更新已有 ADR。
2. ADR 需包含背景、备选方案、决定与理由、风险、负责人、验证测试、迁移/回滚方式和复审触发条件。
3. 不允许把“暂时没有实现”写成“已支持”。PAUSED、WAITING_EXTERNAL、复杂补偿状态等不在 MVP 范围的能力，只有在协议、状态迁移、恢复和测试完整后才可启用。
4. 不为追求架构完整而提前拆分独立 BudgetService；MVP 可在 agent-core 内实现预算能力，但必须保持原子预留、唯一预留记录、幂等结算和可对账语义。
5. 不强制每租户单独创建物理 MQ 队列；共享 MQ 可行，但消息必须包含可信任务标识并在数据库领取时验证租户、任务归属和当前状态。
6. PoC 并发数字仅是初始验证样本，不是生产吞吐承诺；容量结论必须来自目标环境压测和可复现数据。
7. 未满足高风险门禁时不得直接进入生产；例外必须记录限制措施、风险 owner、批准人和到期复审日期。
