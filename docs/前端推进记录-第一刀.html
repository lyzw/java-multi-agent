前端结构重设计 · 第一刀推进记录

2026-10-23 · 角色分面导航（B1 闭合）+ 两处已确认缺陷修复 · 前后端均已编译/测试通过

一句话结论：此前评审发现的根因——登录响应不含 roles 导致导航不分层、RAG 需手填租户——本刀在后端真正闭合（登录一次往返回带 roles），前端据此把导航按角色显隐、顶栏显示身份，并修掉两处会直接报错的缺陷。安全边界仍在后端（执行时重授权），前端角色判定仅作 UI 引导（fail-closed）。

① 后端（B1 真正闭合）

文件改动
agent-infrastructure/.../security/AuthenticationService.javaAuthResult 新增 roles 字段，取自库登记值 rolesOf(record)（与 JWT 声明同源）。
agent-api/.../auth/AuthController.javaTokenResponse 新增 roles 并透出；登录一次往返即得角色，免去 /api/auth/roles 二次调用（端点保留供续期重校验）。

⚠️ /api/auth/roles 在 SecurityConfiguration 中受保护（需 Bearer），前端登录后即可调用，无需改接线。RAG 管理页此前已预填 session.tenantId。

② 前端（消费 roles + 修缺陷）

文件改动
api/types.tsLoginResponse 增加 roles?: string[]。
auth/tokenStorage.tsStoredSession 增加 roles 并持久化/加载（旧会话回落空数组）。
auth/session.tsx暴露 roles；signIn 接收 roles。
pages/LoginPage.tsx登录后透传 response.roles ?? []。
auth/RequireRole.tsx去掉 void area 空操作，改用 hasRoleAccess(session.roles, area) 真实判定。
layouts/AppShell.tsx导航按角色显隐（学生/家长/老师仅见「辅导」组）；顶栏身份条显示「角色 + 租户短 ID」。
App.tsx移除 /runs、/rag 的 area 守卫（学生侧页面，任何已登录可见，避免生效后被误锁）；新增 /profile 查询路由。
pages/DashboardPage.tsx缺陷①：/profile/current 死链 → /profile（输入学号跳转）。
api/client.ts / features/rag/useRagSearch.ts缺陷②：generateRagAnswer 增加 tenantId 并透传 X-Tenant-Id；生成调用补传租户（上线即不再 400）。
pages/rag/RagSearchPage.tsxB2：检索租户预填 session.tenantId，消除手填 UUID。
