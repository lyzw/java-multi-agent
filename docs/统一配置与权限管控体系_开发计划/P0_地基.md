# W-PERM-P0 · 地基：数据模型、authzVersion 与迁移双写

> **阶段目标**：建立统一配置与权限管控的持久化地基——不可变版本对象表、`cap_authz_version` DB 强一致版本、迁移双写可回退、结果事件表与执行意图记录。这是后续所有阶段（P1–P5）的硬依赖。  
> **设计文档落点**：§6.1 核心表、§6.2 引用与快照职责、§6.4 闭包指纹（结构就绪，算法在 P1 实现）、§5.4 四类版本、§8.4 迁移。

---

## 1. 目标与范围

| 范围 | 内容 |
|---|---|
| 入库 | `cap_tool_def` / `cap_skill_def` / `cap_mcp_server_def` / `cap_agent_def`（不可变版本行 + RLS）、`cap_authz_version`、`execution_capability_snapshot`、`cap_config_release`、`结果事件表`、`执行意图记录` |
| 版本服务 | `cap_authz_version` 原子自增仓库；初始值 1；读写权威主库/线性一致源 |
| 迁移 | 现有 `agent`/`agent_version`/`execution_snapshot` 双写接入；可回退到旧读路径 |
| 不在此阶段 | 任何 Phase A 校验逻辑、Gate 改造、审批/预算/账本改造（留 P1–P3） |

## 6. 风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 双写导致旧路径写入性能下降 | 双写开关默认 false；灰度开启；失败切回旧读/写路径 |
| RLS 策略误伤跨表 join | P0-T8 事务契约测试 + 现有 RLS 17 表回归 |
| 迁移脚本在目标库失败 | 前向修复脚本 + 回滚脚本随迁移同版本提交 |

## 7. 退出门禁

- [ ] 所有核心表 DDL 在目标 PostgreSQL 版本应用成功，含不可变版本行与 RLS。
- [ ] `cap_authz_version` 原子自增 IT 通过（并发自增单调无丢失，初始值 1）。
- [ ] RLS 租户隔离 IT 通过（tenant A 不可见 tenant B 的 agent/快照/审批/账本）。
- [ ] 迁移双写可回退：开关切 false 后旧路径完全接管，无数据丢失。
- [ ] 双写一致性比对在抽样数据上差异为 0（或已登记并获批的差异清单）。
- [ ] 事务契约测试通过（版本行插入 + authzVersion 自增 + RLS 同事务）。

**出口**：M0 数据地基就绪。
