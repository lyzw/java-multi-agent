# 统一配置与权限管控体系 · 开发计划总览

> **工作流编号**：`W-PERM`（独立工作流 / 单独阶段）  
> **对标设计文档**：`docs/Agent - Skill- Tool -MCP 统一配置与权限管控体系.md`（V1 基线 · 第四轮修订定稿）  
> **版本**：v1.0 · 计划口径：以「可验证增量」交付，不以后端代码行数或文档页数代替验收  
> **与整体平台计划的关系**：本计划是《Java SaaS Agent 平台 v3.1 软件开发阶段实施计划》中「安全治理 / 权限管控」切片的**独立细化阶段**；整体计划 P0–P5 关注平台大闭环，本 W-PERM 在其之上把「Agent→Skill→{Tool,MCP} 统一配置与权限管控」拆成 7 个内部阶段（W-PERM-P0 ~ W-PERM-P6），各自具备独立门禁、责任分工与测试证据。

---

## 1. 定位：为什么是「单独阶段」

| 维度 | 说明 |
|---|---|
| 独立版本线 | 设计契约以 `docs/Agent - Skill- Tool -MCP 统一配置与权限管控体系.md` 为唯一事实源；本计划只消费它，不反向改写其规则（§5 安全决策 / §8 冻结门槛 / §9 验收矩阵 为权威）。 |
| 独立依赖门 | 仅依赖平台 **P2 核心闭环 MVP**（已有 `ToolInvocationGate` / `AuthorizationService` / RLS / 审批·预算·账本 Port）与 **P3 可靠性基座**（UNKNOWN·幂等·对账语义）。不阻塞平台其它工作流。 |
| 独立验收门槛 | 以设计文档 §8.3 三类门槛 + §9 行为/不变量/故障注入 + 附录 A 检查清单为冻结依据；Demo 永不等于平台验收（§9 / §13）。 |
| 独立追踪 | 状态枚举 `DESIGNED→DEMO_IMPLEMENTED→PLATFORM_IMPLEMENTED→UNIT_TESTED→INTEGRATION_TESTED→SECURITY_ACCEPTED→ACCEPTED`（§10）；每个 P0 保证至少 1 个实现落点 + 1 个测试 ID。 |

## 3. 关键依赖图

```text
平台 P2（ToolInvocationGate / AuthorizationService / RLS / 审批·预算·账本 Port）
        │
        ├──▶ W-PERM-P0 地基（cap_* 表 + authzVersion DB + 结果事件 + 执行意图）
        │         │
        │         ├──▶ W-PERM-P1 解析校验（PermissionResolver / InvocationValidator / Phase A）
        │         │         │
        │         │         ├──▶ W-PERM-P2 闸门与准入线性化（Gate 扩展 / 执行意图 / 防绕过）
        │         │         │         │
        │         │         │         └──▶ W-PERM-P3 审批与故障恢复（双哈希 / 状态机 / COMP-1~6）
        │         │         │
        │         └──▶ W-PERM-P4 MCP 安全接入（与 P1 并行，依赖 P0 表 + P1 校验框架）
        │         │
        │         └──▶ W-PERM-P5 发布审计（依赖 P0 表 + P3 审批终态）
        │
        └──▶ W-PERM-P6 冻结与全量验收（汇聚 P2/P3/P4/P5，执行 §8.3 三类门槛）
```

**关键路径**：P0 → P1 → P2 → P3 → P6。P4、P5 为可并行支线，但 P6 须等其汇合。

## 4. 里程碑与冻结门禁

### 4.1 里程碑

| 里程碑 | 触发阶段完成 | 判定 |
|---|---|---|
| M0 数据地基就绪 | P0 | authzVersion 原子自增 + RLS + 迁移双写可回退通过 |
| M1 授权语义闭环 | P1 | §9 Phase A 全拒绝场景四字段 + 原因码稳定 |
| M2 闸门与防绕过 | P2 | S1/S3b/S3f + 防绕过 0 通过 |
| M3 恢复可证 | P3 | COMP-1~6 + S6/S7/S8/S9 全绿 |
| M4 MCP 可信 | P4 | S5* 具名安全用例全绿 |
| M5 发布可审计 | P5 | PUB-* + 审计 100% |
| **M6 V1 冻结候选** | P6 | §8.3 三类门槛 + 附录 A 检查清单达成 |

### 4.2 冻结门禁（§8.3，V1 冻结唯一依据）

1. **功能**：§9 行为测试四字段 + 具体原因码全绿（含 S3*、S4a/b/c、S5、S6、S8、S9）。  
2. **安全**：RLS、防绕过 0、审批一次性与范围绑定、MCP 具名安全用例、fail-closed。  
3. **工程**：迁移双写可回退、发布 CAS/回滚、审计完整、COMP-6 / PUB-1 等故障注入与不变量通过。  
4. **硬约束**：**Demo ≠ 验收**（设计文档 §9 / §13）；平台 `cap_*` 自动化与故障注入全绿方为冻结。

## 5. 通用执行原则（沿用整体计划 §1）

1. 每阶段必须有可运行软件、测试结果、文档、明确退出门禁。  
2. 先验证高风险协议：authzVersion 强一致、CAS 发布、执行意图先于副作用、COMP-6 崩溃恢复。  
3. 数据库为执行事实源；MQ 仅通知/唤醒。  
4. 副作用先记账、后调用、可对账；UNKNOWN 不得盲目重放。  
5. 安全不是后置阶段；越权拒绝测试与正向授权测试成对出现。  
6. 文档与实现同版本：DDL/迁移、状态机、原因码表、ADR、测试用例随代码变更更新。

### 5.1 单项 DoD（Definition of Done）

- [ ] 验收标准满足，未完成项已登记并获批。  
- [ ] 代码合并并通过非作者 Review；权限/状态机/迁移/安全改动有领域负责人 Review。  
- [ ] 单元/集成/契约/E2E 测试通过，证据可追溯（关联 §9 测试 ID）。  
- [ ] 涉及 API/DDL/状态机/配置/权限的文档同步更新。  
- [ ] 关键路径具备日志/指标/Trace/审计；不记录密钥或多余敏感内容。  
- [ ] 涉及副作用时，幂等/超时/重试/UNKNOWN/对账语义明确且有测试。  
- [ ] 涉及权限时，正向授权 + 越权拒绝测试成对。  
- [ ] 涉及迁移时，迁移/失败/回滚（或前向修复）路径已在目标版本验证。

## 6. 风险登记（摘要）

| 风险 | 影响 | 缓解（落点） |
|---|---|---|
| authzVersion 强一致读延迟/抖动 | 撤权阻断不及时（§5.5） | 读权威主库/线性一致源；缺失 fail-closed（`AUTHZ_UNAVAILABLE`） |
| 发布 CAS 并发回滚半成品 | 当前指针错乱（§6.3） | 同事务版本+release+CAS；失败整事务回滚；PUB-1/PUB-2 注入 |
| 执行意图未先于副作用写入 | 崩溃窗口重复/丢失副作用（§5.3.4） | 13a 强制先于 execute；COMP-6 硬门槛 |
| 审批参数替换重放 | 越权执行（§5.3.1） | approvalScopeHash + effectiveArgsHash；消费时范围重验 |
| MCP SSRF / DNS rebinding / 重定向 | 内网/元数据泄露（§6.5） | endpoint 防 SSRF、DNS 后 IP 校验、禁重定向至内网、凭据仅 `credential_ref` |
| 嵌套 Skill / 动态发现提前引入 | V1 非目标越权面（§3.2 N1/N4） | 代码层显式拒绝 `inherits`、关闭 `dynamicDiscovery` |

## 7. 追踪与证据要求（§10）

- 状态枚举：`DESIGNED → DEMO_IMPLEMENTED → PLATFORM_IMPLEMENTED → UNIT_TESTED → INTEGRATION_TESTED → SECURITY_ACCEPTED → ACCEPTED`。  
- Demo 与平台分列；每项附**证据路径**（代码落点 / 测试类 / 执行结果 / 构建或 commit id）。  
- 进入各态须满足：实现落点存在、对应 §9 用例通过、可审计日志就绪。  
- **当前无需求达到 `PLATFORM_IMPLEMENTED` 即冻结未达成**——本计划各阶段门禁以平台 IT/安全/故障注入为准。
