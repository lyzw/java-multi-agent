# W-PERM-P3 · 审批与故障恢复：双哈希审批、状态机、补偿与 COMP 故障注入

> **阶段目标**：实现「防参数替换重放」的审批双哈希绑定（§5.3.1）、审批状态机（§5.3.3）、跨系统补偿（§5.3.4/§5.3.5），并以 **COMP-1~6** 故障注入验证崩溃窗口与 UNKNOWN/对账闭环。补齐 S6/S7/S8/S9 与 §7.4 双维度结果。  
> **设计文档落点**：§5.3.1 审批绑定契约、§5.3.2 参数规范化、§5.3.3 状态机、§5.3.4/§5.3.5 恢复、§7.4 双维度结果与对账、§9.2 COMP-1~6。

---

## 1. 目标与范围

| 范围 | 内容 |
|---|---|
| 审批双哈希 | `approvalScopeHash`（范围定义摘要）+ `effectiveArgsHash`（全部有效参数 `effectfulParams` 或默认全部）；消费时范围重验，失败 `APPROVAL_SCOPE_MISMATCH` |
| 参数规范化 | `args_norm_v1`（§5.3.2）：字段字典序、UTF-8 NFC、十进制、缺失与 null 区分、Schema default 先展开、SHA-256 |
| 状态机 | PENDING→RESERVED→INTENT_SUBMITTED→CONSUMED（+EXPIRED/CANCELLED）；补偿幂等入队 |
| 补偿 | 预算/PRE/准入失败 → CANCELLED（幂等）；补偿失败 → 持久化补偿任务 |
| 双维度 | `executionStatus`（副作用结果是否已知）+ `ledgerPersistenceStatus`（终态是否可靠落账）；确定成功但 POST 失败 → SUCCEEDED + ledger RETRYING，只重试落账 |
| 故障注入 | COMP-1~6 全绿；COMP-6 为硬门槛（确定成功→结果持久化失败→重启→落账 SUCCEEDED 且外部只执行一次） |

> 不在本阶段：CAS 发布（P5）、MCP 传输（P4，但审批不区分 native/mcp）。

## 6. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 审批 hash 被绕过（参数替换重放） | P3-T1 消费时范围重验；禁止「参数未出现在某条 paramPolicy 即默认允许变化」 |
| 补偿任务丢失 | 补偿失败持久化任务 + 独立调度重放 |
| 重启后重复副作用 | COMP-6：结果事件先于落账；恢复先查意图/下游幂等/账本，禁止盲目重试（`atMostOnceRecovery=manual` 工具禁自动重试） |
