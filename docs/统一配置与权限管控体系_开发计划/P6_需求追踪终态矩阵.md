# W-PERM-P6 · 需求追踪终态矩阵

> **定位**：把设计期的 `docs/权限管控体系/09_需求追踪矩阵.md`（**基线**，写于设计期）填成**实现期终态**。
> **状态枚举**：§10 七态 `DESIGNED → DEMO_IMPLEMENTED → PLATFORM_IMPLEMENTED → UNIT_TESTED → INTEGRATION_TESTED → SECURITY_ACCEPTED → ACCEPTED`。
> **硬约束**：**Demo ≠ 验收**（§8.3 / §9 / §13）—— Demo 验证与平台成熟度**分列**，Demo 一列**不参与**冻结证据。
> **证据要求**：每项附**可核对的证据路径**（测试类#方法）。本矩阵的每一条证据路径都由
> `Section9ScenarioCoverageTest` / `FreezeGateEvidenceTest` **回源码核对存在性**，
> 不存在「手工勾选代替」（P6 §6 风险登记的缓解措施）。

## 1. 状态口径

| 状态 | 含义 | 本矩阵中的判定口径 |
|---|---|---|
| `DESIGNED` | 仅文档设计，未实现 | 无实现落点 |
| `DEMO_IMPLEMENTED` | Python Demo 已验证逻辑可行性 | **仅记录，不构成验收**（硬约束） |
| `PLATFORM_IMPLEMENTED` | Java 平台已实现（cap_* 对象 / 闸门集成） | 有实现落点，尚未被测试锁定 |
| `UNIT_TESTED` | 通过单元 / 组件测试 | 至少 1 条单测断言该需求的关键行为 |
| `INTEGRATION_TESTED` | 通过集成测试（含 DB / RLS / 并发） | 至少 1 条 IT 在**真实 PG** 上断言 |
| `SECURITY_ACCEPTED` | 通过安全验收（脱敏 / 审计 / 越权 / 撤权全绿） | 安全专项证据齐备且全绿 |
| `ACCEPTED` | 已冻结验收 | **本阶段无需求达到** —— 见 §5 未达项与 §6 冻结结论 |

> ⚠️ **「整体状态」取「Demo 验证 ∩ 平台成熟度」可达的最高态**，
> 但**「Demo 验证」一列永不参与冻结判定**。

## 6. 冻结结论摘要

| 判定项 | 结论 |
|---|---|
| 功能门槛（§8.3 第 1 条） | **达成** —— §9 全部 37 条（24 行为 + 13 不变量/故障）均有证据落点，四字段与原因码对着设计文档逐字核对通过 |
| 安全门槛（§8.3 第 2 条） | **达成** —— 防绕过 0 四层证据齐备；RLS 用非特权角色验证；审批双哈希 + 一次性；MCP 具名安全用例；fail-closed 含真·存储不可用 |
| 工程门槛（§8.3 第 3 条） | **达成** —— 双写可回退 / CAS 发布与回滚 / 审计 100% / COMP-1~6 与 PUB-1/PUB-2 全绿 |
| 硬约束（Demo ≠ 验收） | **达成** —— 本矩阵 Demo 与平台分列；无需求误标 `PLATFORM_IMPLEMENTED`；每条证据路径机器可核对 |
| 单项状态是否达 `ACCEPTED` | **未达** —— 24 项需求中 21 项达 `SECURITY_ACCEPTED` / `INTEGRATION_TESTED`，**R-15 止于 `DESIGNED`**、**NFR-03 止于 `UNIT_TESTED`** |
| **总体结论** | **M6 V1 冻结候选（带 12 项登记限制，其中限制 6 为上线阻塞项）** |

> 逐条证据与门槛核对见 `P6_V1冻结判定报告.md`。
