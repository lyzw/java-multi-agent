### 1.3 新增一条正向断言（防止「守卫被改空」）

在 `sqlResourcesAreCentralizedAndGuardIsLive()` 之后新增，确保 MP **确实**被使用且**只**在数据库模块：

```java
@Test
@DisplayName("✅ MyBatis-Plus 依赖与 Mapper 只在 agent-persistence（架构决策变更后新增）")
void mybatisPlusStaysInDatabaseModule() {
    String dbPom = read(platformRoot().resolve(DB_MODULE + "/pom.xml"));
    assertThat(dbPom).contains("mybatis-plus-spring-boot4-starter");

    long mapperFiles = mainJavaFiles().stream()
            .filter(p -> p.toString().contains("/mapper/"))
            .filter(p -> stripComments(read(p)).contains("com.baomidou.")
                      || stripComments(read(p)).contains("org.apache.ibatis."))
            .count();
    assertThat(mapperFiles).as("Mapper/MyBatis 类型必须真实存在于 agent-persistence，防止守卫空转")
            .isGreaterThan(0);
    // FORBIDDEN_IMPORTS 已保证其他模块 0 命中
}
```

> 同步：`@DisplayName` 里的「具体 ORM/JDBC 实现包只在 agent-persistence」措辞可保留，
> 但需要把 `TEST_FIXTURE_ALLOWED_PREFIXES` 的说明补一句：
> 「连库夹具仍只用原生 JDBC，不引入 MyBatis，换 ORM 时夹具不受影响」。

## 3. 落地注意事项

1. **一次性提交**：两个守卫 + 两个 persistence POM + 父 POM 版本锁定在同一提交内完成，避免中间态红灯持续太久。
2. **ADR 补齐**：新增 `docs/adr/ADR-0xx- adopt-mybatis-plus.md`，记录「决策：批准 / 动机四项 / 回滚条件 / RLS 红线」，守卫改动引用该 ADR 编号。
3. **守卫不是放松而是收紧**：新增 `com.baomidou.` 与 MP artifact 后，约束从「禁止一切 ORM」变成「ORM 只能在数据库模块，且必须是 MP」——比原来更精确，符合「换 ORM 时改动收敛在本模块」的原始设计意图。
4. **POC 阶段**：在 W0 冒烟通过前，可先用 `@Disabled("待 W0 MP 依赖落地")` 临时标注 `mybatisPlusStaysInDatabaseModule`，但**不得**删除或注释掉原有断言。
