P0 · 阻断级

P0-1

移动端整页横向滚动：9 个页面里 6 个在手机上左右晃

根因 src/styles/layout.css:67-71（.shell__body align-items:flex-start）＋ :636-638（≤767px 改 column 方向）
现象
≤767px 时 .shell__body 变成纵向 flex，但 align-items:flex-start 还在——在纵向容器里这会让子项按内容最大宽度收缩，而不是撑满。于是 .main 宽度由内容决定，超出视口。
实测
390px 视口下 document.scrollWidth：/config 935px、/reports 881px、/runs 678px、/ 586px、/audit 487px、/agents 441px（视口仅 390）。
根因验证
注入 align-items:stretch + max-width:min(72ch,100%) 后，/、/runs、/reports 三页 scrollWidth 立刻回到 390；/config、/audit、/agents 仍溢出，因为那 9 张表没有套 .table-wrap（见 P1-E）。
修法
/* src/styles/layout.css —— 移动断点补 3 行 */
@media (max-width: 767px) {
  .shell__body { flex-direction: column; align-items: stretch; }  /* ← 关键 */
  .main { width: 100%; max-width: 100%; }
}
/* 72ch 的 max-width 在窄屏必须收敛，否则 p/lead/panel__note 会顶出容器 */
p, .page-head__lead, .panel__note, .marked { max-width: min(72ch, 100%); }

P0-3

治理处置：点一下 radio 就永久归档，零确认

src/pages/governance/GovernancePages.tsx:411-414
现象
onChange={() => void submit(item.operationId, opt.value)}——radio 的 change 事件直接触发提交，而三项处置选项全是不可逆的终态归档（"副作用已发生/未发生/无法判定"）。同一文件里的"拒绝"流程却做对了：理由必填 + 独立的"确认拒绝"按钮。
影响
误点一次即把一次工具操作永久记成结论。误判为"已发生"会让平台跳过合法重试——该学生的辅导请求永久无解，且页面没有补救入口。这是本页自己标注的 Sev-0 级语义。
修法
const [disposition, setDisposition] = useState<Disposition | null>(null)
<input type="radio" checked={disposition === opt.value}
       onChange={() => setDisposition(opt.value)} />   {/* ← 不再直接提交 */}
<button type="button" className="btn"
        disabled={disposition === null || busy}
        onClick={() => void submit(item.operationId, disposition!)}>
  确认归档为「{labelOf(disposition)}」
</button>

另需把"处置说明"输入框移到 radio 之上——否则它现在排在不可逆选项后面，实际不可用。

P0-4

「上传文件」的 input 被 display:none，键盘与读屏用户完全够不着

src/pages/rag/RagManagementPage.tsx:1252-1258
现象
<label className="btn btn--quiet">上传文件<input type="file" style={{ display: 'none' }} /></label>。display:none 会让 input 同时退出无障碍树与焦点序列，外层 label 本身不可聚焦——于是这个"看起来像按钮"的东西永远 Tab 不到、读屏完全感知不到、点击也没有焦点环。
影响
批量导入语料（CSV/JSON）在键盘与读屏用户下只剩粘贴文本一条路，实际不可用。
修法
<label className="btn btn--quiet" htmlFor="bulk-file" tabIndex={0}
       onKeyDown={(e) => { if (e.key === 'Enter' || e.key === ' ') bulkFileRef.current?.click() }}>
  上传文件
  <input id="bulk-file" type="file" ref={bulkFileRef}
         accept=".json,.csv,application/json,text/csv"
         className="sr-only" onChange={onFile} />
</label>

.sr-only 已在 layout.css:8 定义（clip 方案），既视觉隐藏又保留在无障碍树。

P0-5

768–1023px（iPad 横屏区间）：16 个导航入口只剩裸图标

src/styles/layout.css:626-628（≤1023px 隐藏标签）＋ :1155-1158（折叠态）　实测区间 1023px / 900px / 820px / 768px
实测
视口 1023 / 900 / 820 / 768 时：.nav__label 的 display 均为 none，.nav__group-title 同样为 none，侧栏宽 64px，链接内容为空（innerText 为空串），仅剩 16 个 63×40px 的图标。
影响
链接名靠 title 属性兜底（读屏仍能念出），但触屏没有 hover、键盘不弹 tooltip——这两个用户群看到的是 16 个无法辨识的图标，且分组标题也一并消失，连"这些图标属于哪一组"都不知道。这正好覆盖 iPad 768–1023px 区间。
附带
代码注释写着"DOM 保留以保无障碍名"，但 display:none 会把元素移出无障碍树——注释与实际效果不符，容易让人以为这块已经处理过了。
修法：把"隐藏"改成"视觉隐藏"
/* layout.css —— 626 与 1155 两处统一替换为视觉隐藏 */
.nav__label,
.shell[data-collapsed='true'] .nav__label {
  position: absolute; width: 1px; height: 1px; padding: 0; margin: -1px;
  overflow: hidden; clip: rect(0,0,0,0); white-space: nowrap; border: 0;
}
/* ≤767px 的横向标签条要恢复显示 */
@media (max-width: 767px) { .nav__label { display: static; } }

触屏用户仍需要 tooltip 之外的方案——建议图标栏在触屏下展开为抽屉，或至少在长按/首次进入时显示一次分组说明。

P1 · 明显影响体验与可达性

19 条，按主题归并。这里只展开最有代表性的几条，其余给定位与一句话修法。

A · 视觉一致性：浏览器默认蓝漏了进来

检索记录页的运行标识是 rgb(0, 0, 238) + 下划线——浏览器默认链接蓝。这与设计系统自己的纪律直接冲突：tokens.css:140 连 ::selection 都特意改掉了默认蓝，理由是"那会像另一个系统的残留"，而正文链接却漏了。

/* tokens.css —— 补一条全站链接规则 */
main a { color: var(--ink-2); text-decoration: underline; text-underline-offset: 2px; }
main a:hover { color: var(--ink); }

同类：RunResultPage.tsx:133 结果页显示原始枚举 SUCCEEDED、步骤显示 SUCCESS/FAILED，而工作台显示"已完成"——features/run/runState.ts:44 已有中文映射函数，页面没用。

B · 文案质量：工程口吻和 emoji 漏进了用户界面

13 处用户可见文案里带着 ⚠️ emoji 或 **粗体** markdown 标记——JSX 不解析 markdown，界面上会出现裸星号（它们**不会**混进…），而彩色 emoji 在"墨+纸"两色纪律里像外来物。典型位置：

  • RunSearchPage.tsx:107 —「⚠️ 这里只有状态筛选：后端的 run 表没有学科与耗时列（P4-D09 实测）…」工程推理直接写给了学生看
  • RagSearchPage.tsx:212 —「⚠️ 检索按租户隔离（RLS）：已自动填入登录租户…留空将无法检索。」
  • ReportsPage.tsx:263,361、HealthPage.tsx:116、ConfigPages.tsx:437、RagManagementPage.tsx:619,1709,1844 — 同类 emoji
  • RunResultPage.tsx:250、RagMaintenancePanels.tsx:565,852 — markdown 星号漏出

修法：删 emoji；markdown 改 <b>（同项目 ReportsPage.tsx:259 已是正确写法）；工程口吻说明移出界面，或降到 hover 提示与折叠区。

C · 信息架构：列表只有 UUID，没有题目摘要

工作台与检索记录的首列都是 36 字符的 runId。老师/学生看到"775cf7db-e65a-496c-9ed9-6b4469981090"无法判断这是哪道题；"领取次数 0/1"也没有任何解释。这两个表是这个产品的主入口，却按机器可读的形态在呈现。

C2 · 报表中心：11,837px 单页，9 个区块，0 个锚点

这一页把统计区间、7 组图表、知识点排行、语料增长、相关页面全堆在一个文档流里，实测高 11,837px。想找"知识点薄弱排行"要滚过 10,000+px；页内没有任何区块导航（锚点 0、tabs 0），页面也没有面包屑。

修法：拆成 3~4 个 tab（概览 / 辅导 / 语料），或至少在页首加一排区块锚点；口径说明收进"?"折叠。

D · 结果页：最核心的「错在第几步」从来没显示过

CSS 里 .steps__item--done（绿点）、.steps__item--bad（红点）、.steps__wrong（删除线+红划线）三个类都已定义（layout.css:281/286/311），但全仓 TSX 中零引用——RunResultPage.tsx:177 只写了 className="steps__item"。设计好的"老师划掉那一步"效果，从未接到数据上。

<li className={`steps__item${step.state === 'SUCCESS' ? ' steps__item--done'
    : step.state === 'FAILED' ? ' steps__item--bad' : ''}`}>
  …
  {step.output && <p className={`steps__body${step.state === 'FAILED' ? ' steps__wrong' : ''}`}>
    {step.output}</p>}</li>

这是全表最值钱的一条 P1——错题归因页的价值就是"指出错在哪一步"，而现在每一步的节点都是同一个中性灰方块。

E · 审批台：文案承诺"只能拒绝"，界面上却没有拒绝按钮

同一张卡片上先后写着「这条审批已过期，只能拒绝或等待系统清理」和「已过期，不可批准。」——两句提示、零个可点按钮。另外每张卡片顶部的「待审批 · 已过期」都用批改红，20 张卡片连成一片红墙，让"红=错"的语义贬值（tokens.css:7 的 R1 纪律）。

修法二选一：① 让过期项也可拒绝（仅禁用"批准"）；或 ② 文案改成「已过期，不能批准也不能拒绝，等待系统清理」。另外把"待审批"改为中性药丸、只保留"已过期"用红。

F · 移动端：导航条被裁在半个字上，表格按钮被压成 30px

≤767px 时侧栏变成横向滚动标签条，16 个入口总宽 1918px（实测 nav.scrollWidth），首屏只能看到 3.5 个，而且第 4 个被裁在「知」字中间——一个点不动的半截元素。

另外 Agent 配置页的「发布新版本」按钮在 390px 下被压成 30px 宽（文字挤成两行）——这是全站唯一低于 40px 触控目标的实交互元素。

修法：移动端改抽屉式菜单（汉堡按钮），或至少给横向滚动条加渐隐边缘提示 + 首屏提示语；表格操作列在窄屏改为整行点击而非按钮。

G · 可达性：必填项对读屏不存在，tabs 没有 tabpanel

· shared/Field.tsx:45 必填星号带 aria-hidden，input 又不带 required／aria-required → 读屏不播报"必填"（登录页反而是对的，用了原生 required）。
· NewRunPage.tsx:278 提交按钮 disabled → 点击后焦点掉回 body，读屏用户永远走不到提交按钮，也就听不到"还差 4 项"的提示（该提示在按钮下方、无 live region）。
· tabs 有 role=tab／aria-selected，但没有 tabpanel、没有方向键、没有 roving tabindex——键盘用户要 Tab N 次才能从一个 tab 走到下一个。
· RagManagementPage.tsx 的表单有 aria-invalid 却没有 aria-describedby，错误只播报一次，重新聚焦输入框时不再复述。 

/* 1) 必填：让原生语义说话 */
<input required={required} aria-required={required} … />
<label>{label}{required && <span className="req" aria-hidden="true">*</span>}</label>

/* 2) 禁用按钮改成 aria-disabled，保留焦点可达 */

建议的修复顺序

  1. 第一批 · 布局与可达性底线 约 1.5 天

  2. 第二批 · 核心流程正确性 约 2 天

    涉及状态与交互语义，需要补回归测试。

    • P0-3 治理处置改为"选项 + 显式确认"两步
    • P1-D 结果页步骤状态挂上已定义的 --done/--bad/--wrong
    • P1-G 必填语义、提交按钮焦点、tabs 键盘模式

  3. 第三批 · 信息架构与文案 约 2~3 天
