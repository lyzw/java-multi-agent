### 1.4 RLS 策略（42 表开启 + FORCE，共 50 条策略）

租户上下文函数：`public.current_tenant_id()` 读会话 GUC `app.tenant_id`；未设置返回 NULL → 所有 RLS 策略拒绝访问（**fail-closed 默认拒绝**）。

**① 默认形状（38 表 × 1 策略 = 38 条）**：`<table>_tenant_isolation`，USING + WITH CHECK 均 `tenant_id = current_tenant_id()`。典型：student_profile（未成年人数据，Sev-0）、audit_record、principal、run、budget_*、tool_operation*、consent_withdrawal 等。

**② 特殊形状（4 表 × 3 策略 = 12 条）——「平台行 NULL 共享读 + 租户行只能自己写」**：

| 表 | SELECT | INSERT | UPDATE |
|---|---|---|---|
| cap_config_pointer | `tenant_id IS NULL OR = current`（PLATFORM 指针只读共享） | 仅 `tenant_id = current`（TENANT 指针；PLATFORM 指针须由 platform_ops 写） | 仅 `tenant_id = current` |
| cap_config_release | 同上（PLATFORM 作用域行只读共享） | 仅 TENANT 作用域；PLATFORM 发布须 platform_ops | 仅 TENANT |
| cap_decision_log | 同上（平台发布审计只读共享） | 仅租户作用域审计行；PLATFORM 发布审计须 platform_ops | 仅 TENANT |
| cap_config_publish_request | 仅 `tenant_id = current`（严格隔离，PLATFORM 行对应用角色不可见） | 仅 `tenant_id = current` | 仅 `tenant_id = current` |

> 这正是 platform_ops 必须存在且带 BYPASSRLS 的原因：任一租户若能单方面写 PLATFORM 行 = 直接越权替换全平台生效配置。

**③ 追加不可改（防篡改，触发器层）**：

- `audit_record`：`forbid_audit_mutation`（04_retention_role 版）——UPDATE 永远拒绝；DELETE 仅当 **连接凭据具备 agent_retention 成员身份**（`pg_has_role`，会话无法自封）且声明 `agent.retention.actor`（仅留痕）。旧版「会话 set_config 自声明即放行」的可构造绕过已闭合。
- `erasure_certificate`：`forbid_certificate_mutation` —— UPDATE/DELETE 一律拒绝，**无例外通道**（连 agent_retention 也不放行，删除凭证即销毁证据链）。
- 其他不变式触发器：run/审批/预算预留/配置发布 状态机守卫、fencing token 回退拒绝、execution_snapshot 不可变、已发布定义行不可改等（共 33 触发器）。

### 1.5 应用层角色绑定（非 DB 角色，带外 SQL 模板）

- `04_platform_admin_grant.sql`：向 `public.principal_role` 带外写入 PLATFORM_ADMIN（应用层无赋权端点，防自举回路；执行身份为 platform_ops 或超管）。
- `06_platform_grant.sql`：向 `platform.platform_user_role` 带外绑定平台角色（6 内置角色），并递增 authz_version。

### 2.3 表级权限矩阵

| 角色 | 权限 |
|---|---|
| **rag_app** | USAGE ON SCHEMA rag + public；SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA rag；序列 USAGE/SELECT；DEFAULT PRIVILEGES 同（rag + public 两 schema） |
| **rag_ops** | 先 **REVOKE ALL**（保证「最小授权」可重复达成，不是一次性愿望）再授：① SELECT ON ALL TABLES IN SCHEMA rag（11 表全可读，供跨租户盘点）；② 写仅 6 表且**一律无 DELETE**：`rag_source`(I/U)、`rag_document`(I/U)、`rag_chunk_embedding`(I/U)、`rag_dictionary`(I/U)、`rag_access_audit`(仅 I)、`rag_chunk`(仅 U)；③ DEFAULT PRIVILEGES 仅 SELECT（新表不会静默变成可全局写）；④ 角色级 `statement_timeout=30s`、`idle_in_transaction_session_timeout=15s`、`search_path=rag, public`；刻意**不设** app.tenant_id 角色级默认（池化连接会串作用域） |

BYASSRLS 的代价与补偿（04 脚本明确声明）：DB 层不再限制 rag_ops 写哪个桶，限长由 ① GuardedRagOpsDataSource（会话窗外取不到连接）② ops 事务入口不接收租户参数、哨兵桶由实现内部绑定 ③ A 档窗口只发 SELECT，三道应用侧结构约束 + 库内 CHECK（`scope='PLATFORM' ⇔ tenant_id=哨兵`，CHECK 不是策略，BYPASSRLS 绕不掉）承担。**本角色不得用于任何其他用途**：不给 rag_app 加成员、不给 DELETE、不给 schema 建对象权。

### 2.4 RLS 策略（35 条）

租户上下文：`rag.rag_current_tenant()` 读 `app.tenant_id`；未设置返回 NULL（只见全局行）；**显式把全局哨兵 `00000000-…-0000` 当会话身份 → RAISE 42501**（fail-loud 封堵越权企图）。全局行定义：`tenant_id = rag_global_tenant_id()` 且 `scope='PLATFORM'`。

**① 四操作分策略形状（8 表 × 4 = 32 条：rag_chunk, rag_chunk_embedding, rag_dictionary, rag_document, rag_edition, rag_knowledge_point, rag_knowledge_prerequisite, rag_source）**：

| 操作 | 谓词 |
|---|---|
| SELECT（`*_read`） | `tenant_id = ANY(ARRAY[rag_current_tenant(), rag_global_tenant_id()])` —— 本租户行 + 全局哨兵桶 |
| INSERT（`*_write`） | `tenant_id = rag_current_tenant() AND scope = 'TENANT'` —— **写不出全局行**（越权闸门本体） |
| UPDATE（`*_update`） | USING 本租户；WITH CHECK `本租户 AND scope='TENANT'` —— 不可把行改成全局 |
| DELETE（`*_delete`） | 仅本租户行 |

**② 严格隔离形状（3 表 × 1 = 3 条）**：rag_access_audit / rag_answer_citation / rag_ingest_job 均为 `tenant_isolation`，USING + WITH CHECK 均 `tenant_id = rag_current_tenant()`（无全局桶共享）。

**③ 追加不可改**：rag_access_audit 有 `trg_rag_audit_append_only`（`rag.forbid_rag_audit_mutation`，UPDATE/DELETE 一律拒绝）。

## 三、初始化顺序与验证纪律（两库通用，来自 README/脚本内铁律）

1. **顺序**：建库（owner）→ 01 DDL → 02 种子 → 03 角色授权 → 04（platform 为 retention；rag 为 ops）。**角色必须在 DDL 之后建**（ALTER DEFAULT PRIVILEGES 只覆盖此后新建的对象，顺序颠倒 = 应用角色全表无权限）。
2. 04 必须排在 03 之后：03 重跑会重授全表 GRANT，**静默覆盖** audit_record/erasure_certificate 的 DELETE 撤销。
3. **验 RLS 必须用非特权角色**（app_agent / rag_app 实连）：owner / BYPASSRLS 验隔离 = 假结论。
4. total 汇总：platform 65 表（platform 19 + public 46）/ 42 RLS / 50 策略；rag 11 表 / 11 RLS / 35 策略。
