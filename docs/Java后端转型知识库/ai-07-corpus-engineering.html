A7. RAG 语料工程化与数据流水线：从原始 PDF 到可检索向量

第 13 章讲的是「一次检索怎么走到答案」，A1 讲的是 pgvector / halfvec / RRF 的概念。本册补上中间最容易被 Java 后端忽略的一段：数据本身是怎么被造出来的。一份 162 页教材要变成可检索片段，经历解析 → 切分 → 角色判定 → 知识点挂接 → 嵌入 → 索引 → 检索准入七道工序，其间有两套解析后端、双切分策略、一条离线脚本路径和一套线上化流水线并存。这段工程化历史里藏着本项目最密集的「文档结论被代码反证」案例。

先建立时点轴：三处「矛盾」其实是版本漂移

本册材料跨 2026-10-28 至 11-10。三个关键时点：① 10-28 换 qwen3-embedding:8b（4096 维）+ halfvec(4096) 上线；② 11-04 D21/D24/D25 与交互验收，此时部分文档仍写「真实嵌入 Port 未接」「09/10/11 迁移未执行」；③ 11-10 批量 fix(rag) 落地真实嵌入端口、版权收紧、平台档摄取。凡遇「文档说没做、代码已有」或反之，先分清时点，再以代码 + 真库证据为准。文档冲突 集中在 A7.9。

两个真实缺陷及修复（同一文件注释）：

轴缺陷现象根因修复
版权轴2026-11-10 六年级物料导入实测：全库常驻 PENDING，检索却照单全收旧谓词 <> 'RESTRICTED' 把 PENDING 当可用，且版权轴没有任何写入路径收紧为显式白名单 IN ('LICENSED','FAIR_USE_QUOTATION')

A7.8 数据模型：三层来源、4096 维、五轴版本与 8 值状态机

唯一权威是 deploy/sql/rag/01_rag_ddl.sql（pg_dump 终态快照）。Java 后端需要注意「文档基线 11 表」已经过时，现库约 15 张表。

三层来源模型

rag_source（作品）→ rag_document（物理载体）→ rag_chunk（片段）。rag_chunk 无 source_id 列，来源须经 rag_document 中转（JdbcRetrievalRepository 类注释行 73–78）。

向量与 ANN 缺口

rag_chunk_embedding.embedding public.halfvec(4096) NOT NULL（DDL 行 389）。halfvec 的 HNSW/IVFFlat 只支持到 4000 维，所以 DDL 行 960–961 明写「本索引刻意不存在」，稠密检索退化为全表精确扫描。未解决：语料规模上去会先撞延迟。

版本五轴

EditionCoordinate(subject, grade, term, publisher, revision_code)；rag_edition_unique 五轴唯一 + effective_from/effective_to。出版社 ≠ 出版机构：rag_source.publisher 是出版机构（上海教育出版社），rag_edition.publisher 是版本体系（沪教版），不可互换。12 号回填脚本把占位修订码改为「历史存量（未标注版次）」。

状态机与角色

rag_ingest_status 8 值：PENDING/PARSING/CHUNKING/EMBEDDING/INDEXING/SUCCEEDED/FAILED/REJECTED（无 CANCELLED，取消 = REJECTED + error_detail='SOURCE_REVOKED'）。rag_chunk_role 10 类，部分索引 rag_chunk_retrievable_idx 排除答案类防泄题。

locator / chunkId 引用：Chunk.Locator(pageNumber, sectionPath, exerciseNo, charStart, charEnd) 与 chunkId = UUID.nameUUIDFromBytes("chunk:{documentId}:{page}:{charStart}")（在线）；离线脚本 scripts/rag_import_pdf.py 用 uuid5(NS, "chunk|{isbn}|{page}")（行 40、302），两套派生规则并存——同一教材经两条路径入库会得到不同 chunkId，文档冲突 不是「单一算法」。离线脚本 classify() 只产出 5 类角色，与 DDL 的 10 类枚举也不一致。

离线脚本路径：线上化方案要替代的对象

scripts/rag_import_pdf.py 文件头行 2–26 说得很直白：「RAG 服务没有文件上传通道（object_ref 只存引用、正文不入库），所以真实教材入库走这条离线路径；本脚本只生成 SQL，不连库、不写库」。流程：本地抽取 → 生成 SQL → DBA 执行 → 管理端签发 → /reindex 补向量。关键规则：strip_boilerplate()（跨页重复页眉，threshold=max(3, len(pages)//3)）、classify() 五类角色、toc_units()、page_offset() 众数自标定、appendix_pieces() 词表按单元重切状态机；剪枝 DELETE 只删未被 rag_answer_citation 引用的片段。这是「两代工程形态」并存的实证：Python 离线脚本 vs Java SPI + 多后端 + 分块桥。
