```markdown

## 一、维度定义与评估坐标系
- 1.1 这个维度到底解决什么问题（问题陈述，不谈实现）

## 二、理论体系（必须引用真实出处）
- 2.1 该领域的核心理论/概念框架（≥3 个），逐一给出定义、原始出处（论文名+年份+作者/机构，或官方文档 URL）
- 2.2 理论给出的「设计张力」（trade-off）清单：每个张力给出「A 方案 vs B 方案」的取舍

> 硬性要求：理论必须有真实出处。论文给真实标题/作者/年份/arXiv 号或会议名；框架能力给官方文档 URL。禁止编造论文、作者、年份或 URL。若某理论无法核实，明确写「未能核实官方出处，以下为本报告基于公开工程实践的归纳」。
```

## 撰写纪律

1. **本项目证据必须可复核**：每条「我们的实现」都要给出 `文件路径:行号` 或 `类名/方法名`。不确定的不要写。
2. **竞品信息必须来自官方文档**：给 URL。若抓不到官方页，写明「官方未明示」而非猜测。
3. **理论必须真实**：论文/书/规范给真实出处；核实不到就降级标注。
4. **改进点必须可执行**：不许写「加强测试」「完善监控」这类无信息量的条目。必须写到文件/表/配置/接口级别，并给验收口径。
5. **诚实优先于漂亮**：我们的短板要写根因（设计取舍 vs 能力缺失），不要粉饰。
6. **篇幅**：每份 800-1500 行 Markdown 区间为佳；宁可信息密度高，不要注水。
7. **不要写空泛的"建议加强"**，每个建议要有验收门禁。
8. **文末必须附「诚实边界声明」**：明确本报告哪些部分基于源码实证、哪些部分基于官方文档、哪些部分是工程判断（推断）。

## 项目已知铁律速查（改进方案的红线）

1. RLS 的 GUC 必须在事务内、业务 SQL 前绑定；验隔离用 `app_agent`(NOBYPASSRLS)；FORCE RLS 不绑租户静默 0 行。
2. 枚举须 `?::enum`；`INSERT…RETURNING` 需 SELECT 且走 executeQuery；`authz_decision_log` 禁 RETURNING；`run_step` 必填 fencing_token；终态后禁补 attempt。
3. 组件扫描类 ≥2 构造 ⇒ `@Autowired`；多 Bean 注入点 `@Qualifier`，勿 `@Primary`。
4. 各一个 persistence 模块（ADR-011）；main 侧 JDBC import 只许 persistence。
5. 双通道消息按 eventType 分流，否则终态 Run 被重跑（Sev-0）；采集绝不复用 `agent.run.execute`。
6. 验收三级（单元/API/角色×任务）+ 反向验证；「有一行」≠「数字算对了」；守卫必问「撤掉修复点会红吗」。
7. 业务 SQL 用 `app_agent` 绝不 `agent_retention`；新表同步 `03_platform_roles.sql`；`ON CONFLICT DO UPDATE` 需 UPDATE 授权 + SchemaDriftIT。
8. fail-closed；无物理删除端点；`AgentOverrides` 唯一权限解析；judge 成本绝不混 `usage_record`。
9. `scenario` 只认 `run.input_payload.scenario`；平台 JWT `PLATFORM_JWT_PRIVATE_KEY`，租户域 `JWT_PRIVATE_KEY`。
10. record 兼容构造器静默清空后加字段 ⇒ 转换全参构造逐字段带过。
11. 事务内 SQL 失败禁 fail-soft 后 COMMIT；`TransactionalConnectionHolder` 用 POISONED。
12. SSE：平台链 `/api/agent/chat/stream` / 租户链 `/api/knowledge/agent/chat/stream`（禁带 tenantId）；13 事件 + 第 14 checkpoint、`done` 终帧；不写 outbox、不发 MQ。
13. FORCE RLS 下 `IN (SELECT…LIMIT…FOR UPDATE SKIP LOCKED)` 的 LIMIT 静默失效 ⇒ `WITH candidates AS MATERIALIZED`。
14. 跨进程 HTTP 契约按对端真实校验取值。
15. 终态/权限错误不得伪装成临时故障：404/403/401 须显式终态 + 停轮询 + 不给重试。
16. `run_step.state` 恒 `'RUNNING'`＝「步骤已发生」，完成看 `completed_at`。
17. 静态源码守卫 / 渲染快照 ≠ 运行时成立：必须真实交互驱动 + 撤点反证。
18. 前端必须顶层 ErrorBoundary + 全局未捕获错误安全网。
19. 前端错误/状态隔离 D1/D2/D3/D6/D7 五条。
20. jspecify `@NonNull` 不能用于全限定类型名，须用简单名。
21. RE2/J 不支持环视断言与反向引用 ⇒ 含 lookbehind 的正则必须留 JDK 引擎。
22. 静态常量声明顺序：flag 常量须声明在使用它的静态字段之前。
23. Sonar「异味」≠ 真缺陷；删改前须拿既有验收契约反证。
24. SpotBugs `NP_NULL_ON_SOME_PATH_FROM_RETURN_VALUE` 定位法：读 `spotbugsXml.xml`。
25. S6218 诉求是 `toString`，非 equals/hashCode。
26. re2j 批量校验须做 Java 字符串反转义。
