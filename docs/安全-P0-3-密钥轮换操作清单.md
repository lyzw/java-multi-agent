# 安全运维清单 · P0-3：BYPASSRLS 明文口令轮换与密钥管理迁移

> 来源：《系统优化建议-全量评审》§5.2 / §9 表 #3（P0）。
> 性质：**运维执行项**——代码侧无法替你轮换 RDS 口令，本文档给出可逐步勾选的执行清单。
> 建议执行时机：**立即**（轮换）/ 下一迭代（密钥库迁移）。
> 最后更新：2026-10-27。

---

## 0 · 为什么紧急

`platform_ops` 账号持有 **BYPASSRLS**——拿到它即绕过全部行级租户隔离，
可读写**所有租户**的全部数据。该口令当前以明文形式存在于多份本地 env 文件中
（虽被 `.gitignore` 排除、未入库，但明文落盘 + 无 KMS 仍属评审定级的高危）。
凡明文口令出现过的机器（开发机、聊天记录、终端历史）都应视为暴露面，
**轮换是唯一可靠的止损手段**（删除文件不等于撤销泄露）。

## 1 · 敏感资产盘点（2026-10-27 实测）

| # | 资产/账号 | 权限级别 | 明文出现位置 | 风险 |
|---|---|---|---|---|
| 1 | `platform_ops`（`AGENT_PLATFORM_OPS_DATASOURCE_PASSWORD`，platform.env） | **BYPASSRLS**，绕过全部 RLS | platform.env | 🔴 极高 |
| 2 | 主应用库账号（`SPRING_DATASOURCE_USERNAME/PASSWORD`，platform.env） | 非特权，RLS 生效 | platform.env | 🟡 中 |
| 3 | `rag_app`（RAG 库应用账号，非特权） | 非特权，RLS 生效 | rag.env / **多份文档与终端历史**（IT 命令行明文） | 🟡 中（暴露频率最高） |
| 4 | RabbitMQ（`RABBITMQ_USER/PASSWORD`，platform.env） | 消息通道 | platform.env | 🟡 中 |
| 5 | JWT 私钥（租户域 + 平台域两对） | 令牌签发根 | jwt.env（由 `scripts/gen-jwt-keys.sh` 生成） | 🔴 高（签发权=一切） |
| 6 | RAG IT 凭证（`IT_RAG_PG_PASSWORD`） | 与 #3 同账号 | 终端历史 / 项目记忆 / 会话记录 | 🟡 中 |

## 2 · 轮换操作清单（按账号逐个执行）

### 2.1 🔴 `platform_ops`（最高优先级）

1. [ ] **选窗口**：platform_ops 仅被带外运维任务使用，低峰期轮换无业务影响。
2. [ ] 阿里云 RDS 控制台（或 psql 特权会话）执行：
       `ALTER ROLE platform_ops WITH PASSWORD '<新强口令>';`
       （更稳妥：新建 `platform_ops_v2` + 同权限 → 应用切换 → 删除旧账号，
       避免 `ALTER ROLE` 后旧连接池残留会话仍持旧凭证。）
3. [ ] **同步更新**所有引用点：`platform.env`、任何部署机/CI 的对应 env、密钥库（见 §3）。
4. [ ] 重启使用 `AGENT_PLATFORM_OPS_*` 的进程，验证带外任务可跑。
5. [ ] **验证 RLS 仍被绕过（预期行为）且仅此账号可绕过**：
       用非特权账号连库执行跨租户查询应被 RLS 拦截（复用既有 RLS 验证用例）。
6. [ ] 确认旧口令在所有历史泄露面（终端历史等）失效——用旧口令连库必须被拒。

### 2.2 🟡 `rag_app`（RAG 应用 + IT 账号）

1. [ ] 同法轮换（`ALTER ROLE rag_app WITH PASSWORD '...'`）。
2. [ ] 更新 `rag.env` 与 CI 环境变量（`IT_RAG_PG_PASSWORD`）。
3. [ ] 重跑 RAG 全模块 IT 验证：
       `JAVA_HOME=/opt/homebrew/opt/openjdk@21 IT_RAG_PG_URL=... IT_RAG_PG_USERNAME=rag_app IT_RAG_PG_PASSWORD='<新>' mvn -o clean verify`（8 模块全绿）。
4. [ ] **流程整改**：IT 凭证此后只经环境变量注入，**不再出现在**命令行、文档、聊天与项目记忆中
       （本次评审后项目记忆中的旧口令一并视为已轮换失效）。

### 2.3 🟡 主应用库账号 / RabbitMQ

1. [ ] 主应用账号轮换后重启 agent-api 等全部 Spring 进程；跑平台侧 IT/冒烟。
2. [ ] RabbitMQ 口令在 RabbitMQ 管理台轮换；更新 platform.env 后重启 worker，
       验证 Quorum 队列收发正常（消息通道可切换开关双向各验一次）。

### 2.4 🔴 JWT 签发密钥

1. [ ] RS256 密钥对标识别强行轮换意义有限（公钥可验证私钥持有者），
       但**若私钥曾以明文落盘或进入聊天记录，视为已泄露，必须轮换**。
2. [ ] 轮换采用 **kid 双密钥滚动**：新 kid 上线 → 旧 kid 保留于 JWKS 至存量令牌过期（900s TTL）→ 摘除旧 kid。
3. [ ] 轮换后所有在线令牌仍有效（TTL 内），无需强制下线；如需立即失效，配合 P1 项 #10（jti 黑名单/登出）。

## 3 · 密钥管理迁移建议（本轮或下迭代落地）

### 3.1 目标结构（本仓库 · 2026-10-28 已按此收敛，文件名按属主分开）

```
仓库根/
├── platform.env.example      # 入库模板：只有键名与占位符（<MUST-FILL>），零真实值
├── rag.env.example           # 同上（RAG 侧：PG + 嵌入运行时）
├── jwt.env.example           # 同上（说明由脚本生成，勿手填）
└── …────────────────────────────────────────────────────────
    platform.env              # 平台 8080 真实值（原 config.env），chmod 600，不入库
    rag.env                   # RAG 8081/worker 真实值（原 rag-online.env + rag-local.env 合并）
    jwt.env                   # 两域 JWT 公私钥（scripts/gen-jwt-keys.sh 生成，平台签+RAG验同源）
```

- **命名按属主**：平台与 RAG 的配置不共用一个文件（库不同、角色权限不同），
  唯一共用的是 `jwt.env` —— 签发与验签同源才不会出现「登录正常、调 RAG 全 401」。
- **为什么放仓库根而不是 `deploy/env/`**：IDEA 的 EnvFile 插件要按路径挂文件，
  且插件只做 `KEY=VALUE` 逐行解析（不认 `source`/`if`/引号），根目录最省心。
- **入库模板**让新成员/CI 知道需要哪些键，而真实值只存在于密钥库。
- 补一条守卫（P2 项 #20 可并入）：CI 检测仓库 diff 中出现
  `jdbc:postgresql://[^ ]*:[^ ]*@` 或 `PASSWORD=.+` 的非 example 文件即失败。

### 3.2 密钥库选型（按接入成本升序）

| 方案 | 适用 | 说明 |
|---|---|---|
| **macOS Keychain / pass（GPG）** | 个人开发机 | 零成本止血：env 文件值改为引用，真实值 `security add-generic-password` 存 Keychain，启动脚本 `security find-generic-password -w` 注入 |
| **阿里云 KMS 凭据托管** | 部署在阿里云（当前 RDS 即在阿里云） | RDS 凭据可托管 + 自动轮换；应用经 KMS SDK/环境变量注入取值 |
| **Vault / Nacos 加密配置** | 多环境多实例 | 迁移成本最高，待多实例部署（P1 #10 authzVersion 迁 DB 同期）一并评估 |

### 3.3 卫生习惯（立即生效）

1. [ ] env 文件 `chmod 600`；目录不进 IDE 全局搜索索引（标记 excluded）。
2. [ ] 终端历史处理：`export HISTCONTROL=ignoreboth` + 轮换后 `history -c`；
       含口令的历史命令（如本机 IT 运行命令）不再复用。
3. [ ] 轮换完成 checklist 全部勾选后，在本文件头部标注轮换日期与执行人。
