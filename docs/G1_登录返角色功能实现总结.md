## 📌 一、G1 功能背景

### 需求概述
为已登录用户提供一个接口，查询其当前拥有的角色列表。作为 JWT token 验证与授权的基础组件，该功能需要能够：
1. 从有效 JWT token 中提取 user principalId
2. 查询数据库中用户的实际角色集合
3. 与 token 声明的角色取交集返回

### G1 vs G2 策略对比

| 特征 | G1 临时方案 | G2 正式方案 |
|------|-----------|------------|
| 认证来源 | JWT token manual parsing(SecurityContextHolder) | SecurityContext.getAuthentication() |
| 延迟抖动风险 | ⚠️ fail-fast | ✅ 零延迟（自动注入） |
| 实现复杂度 | 🟢 低 | 🟡 中（需完整配置依赖） |
| 维护成本 | 🟢 简单 | 🔴 需与 Spring Security 保持同步 |

### G1 设计决策点

1. **fail-fast 策略**：避免使用缓存，确保多实例一致性
2. **JWT manual parse**: 在 Spring Security 启用前，确保功能可用
3. **fail-safe fallback**：无效 token 返回空 set，不泄露信息

## 📋 二、API 端点说明

### G1 临时实现

```java
@GetMapping("/roles")
public ResponseEntity<Map<String, Set<String>>> queryRoles() {
    try {
        // G1: 从 JWT token 提取 principalId，查询角色
        TenantContext context = tokens.verify(...)
        return ResponseEntity.ok(Map.of("roles", context.roles()));
    } catch (RuntimeException e) {
        // fail-safe: 无效 token → 空 set
        return ResponseEntity.ok(Map.of("roles", Set.of()));
    }
}
```

## 🔜 四、后续计划 (G2)

### Phase 2: 正式接入 Spring Security

```java
// G2 方案 - AuthSecurityController.java
@Component
public class AuthSecurityController {
    @GetMapping("/roles")
    public ResponseEntity<Set<String>> roles() {
        // ⚠️ 从 SecurityContext 自动获取（无延迟）
        Authentication auth = SecurityContextHolder.getAuthentication();
        return ResponseEntity.ok(auth.getAuthorizedAuthorities().stream()
                .map(GrantedAuthority::getRole).collect(Collectors.toSet()));
    }
}
```
