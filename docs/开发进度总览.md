### 3.1 本轮抓到的真实缺陷（实测，非推断）

| # | 位置 | 缺陷 | 危害形态 |
|---|---|---|---|
| **1** | `JdbcRunEventQueryRepository.parsePayload` | `body.split(",")` 不识别字符串内逗号 | `errorCode="E1,E2"` 被读成 `{errorCode=E1, E2=null}` → **错误码被静默改写** |
| **2** | 同上 | `unquote` 只处理 `\"` 与 `\\` | 含换行的值回读为**字面量两字符 `\n`** |
| **3** | 同上 | 手写 `coerce` 把整数全当 `Long` | 写入 `Integer` / 读取 `Long` 不对称，下游 `==` 静默失败 |
| **4** | `JdbcRateLimiter` | 全局单一限额，无桶级覆盖 | 治理桶与学生桶互相蚕食；按**租户**限流 → 多个运维互相限流 |
| **5** | `ApprovalQueryPort` | 「拒绝未填理由」抛 409 类异常 | 前端提示「已被别人处理」，真相是「少填一个字段」→ 改 400 |

> 三条 1～3 的共同形态：**不抛异常、不断言报错，只是值悄悄变了**。
> 与 P4-D08 R-1（工具未注册为 Bean → 表永远为空）同源——
> **静默失效靠「逐行看断言」抓不到，只能靠「针对可疑行为的专项用例」抓。**

### 3.2 ⛔ 反证工具自身的 2 个假阴性（比产品缺陷更危险）

| # | 根因 | 后果 |
|---|---|---|
| **CP-1** | `mvn -q` 连带抑制 `[INFO] Tests run:` 汇总行 | grep 永不匹配 → **5/7 反证被误报为「如期保持绿」** |
| **CP-2** | `failsafe:verify` 读上一轮遗留的 `failsafe-summary.xml` | reactor 中途中断，误判为有效 |

> **两者都是 P4-D04 F-14 的同形态**：「测试没跑起来」被当成「测试通过」。
> **反证工具自身的假阴性比产品缺陷更危险**——它会让整套反证退化成「永远全绿」的仪式。
> 脚本现已内置「本轮确实跑了用例」断言，否则一律判**无效**而非**绿**。

### 3.3 ⛔ 3 类「假不变式」（测试自身的缺陷）

| 写法 | 为何错 | 改为 |
|---|---|---|
| `list(tenantB).isEmpty()` | 隔离 IT 库**跨运行累积**，tenantB 自己也有数据 | 断言「B 看不到 A 的**任何一行**」+ 管理连接对照 |
| 夹具用 `snapshot_id LIMIT 1` | `execution_snapshot` 有 `tenant_id`，跨租户复用会撞约束，而失败现场指向 Run 代码 | 按租户取快照并缓存 |
| 端点 IT 用注入的 `DataSource` 造夹具 | Spring 注入的是**非特权 app_agent + 强制 RLS**，读不到快照 | 夹具另开**管理连接** |

## 六、环境备忘（踩坑清单）

1. **Maven / JDK 不在 PATH**：用 IntelliJ 内置 JBR 25（`/Applications/IntelliJ IDEA.app/Contents/jbr/Contents/Home`）+ `plugins/maven-plugin/lib/maven3/bin/mvn`。
2. **集成测试必须用隔离库** `./scripts/dev-it-db.sh`（`agent_it`）+ `RABBITMQ_VHOST=agent-test`。
3. **`source config.env` 必须配 `set -a`**，否则 `RABBITMQ_PASSWORD` 为空 → `ACCESS_REFUSED`。
4. **`-pl <module>` 单跑会用到本地仓库旧 jar**：新增端口后必须带 `-am`。
5. **端点 IT 须用 `RANDOM_PORT`**：`MOCK` 下不装配 Security 过滤器链，401 断言永远红。
6. **反证脚本每轮前须清 `failsafe-reports` 与 `failsafe-summary.xml`**（见 §3.2）。
7. **数用例数 XML 的 `<testcase>`**，不要读 `.txt` 的 `Tests run`。
