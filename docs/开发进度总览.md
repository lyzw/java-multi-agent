## 五、✅ RAG 的 3 项真实缺陷（已修 + 附反证）

> 三个缺陷是「测试编译失败 → 一项都跑不了」掩盖的，修复后**当场暴露**。
> 本轮已全部修复并补齐反证；RAG 测试 **66 项 / 3 失败 → 74 项 / 0 失败**。

| # | 缺陷 | 根因 | 危害形态 | 修法 |
|---|---|---|---|---|
| **R-D1** | 知识点挂接恒为空 | `KnowledgePoint.matches` **方向反了**：原为 `normalize(canonicalName).contains(normalizedQuery)`，应为 `normalizedQuery.contains(normalize(canonicalName))` | **静默零召回**——正文含知识点名也挂不上，检索侧永远拿不到知识点关联，**且系统表面完全正常**（与 P4-D08 的 R-1 同构）| 反转方向 + **方向判别用例**（「抛物线顶点的坐标是 (h,k)。」应命中 / 「抛物线顶」不应命中）|
| **R-D2** | 章节路径恒为空 | `IngestionPipeline` 只从 **heading 块**累积路径，**不读** `LayoutBlock.sectionPath()` | 定位信息不完整 → 引用溯源定位不到具体小节 | 明确取值规则：**标题累积优先**（§5.3 的层级截断只存在于它上面），**无标题上下文时回退解析器路径**（否则定位退化为空串，引用无法核对）|
| **R-D3** | 答案区无题号判错 | `resolveRole` 未按 RAG-D04 §3.1 判定表处理「答案区 + 无题号」，且**只看块自身题号**、不看**继承题号** | ⛔ **泄题（Sev-0）**：`EXPLANATION` **不是**答案类角色 → **会被讲解模式召回** → 答案内容直接进学生上下文 | 按 §3.1 判定表重写 + 引入**有效题号**（块自身，否则继承上文最近题号）|

> ⚠️ **更正上一版的错误判断**：上一版把 R-D3 判为「方向安全的功能缺口」——**错了**。
> `RetrievalPolicy.allowsRole` 在 `EXPLAIN` 模式下放行**全部非答案类角色**，
> 所以「把答案判成讲解」正是**泄题方向**。RAG-D04 §3.1 原有的代价说明同样写反，已加**勘误**。
> 另发现**继承题号**同样漏判：答案册里的答案块通常不带自身题号，
> 归属的是上文那道题——按原实现会被判成 `EXPLANATION` → **同样泄题**。

### 5.1 反证（注入缺陷 → 期望精确转红）

| 反证 | 注入的缺陷 | 转红项 |
|---|---|---|
| **A** | `matches` 方向改回「名称.contains(文本）」 | **3 项**：`matchesWhenTextContainsNameOrAlias` / `knowledgePointAttached` / `knowledgePointAttachmentIsDirectional` |
| **B** | 章节路径只认标题累积（忽略解析器路径）| **2 项**：`locatorComplete` / `sectionPathFallsBackToParser` |
| **C** | 角色判定回退到「答案区无题号 → `EXPLANATION`」| **3 项**：`answerZoneWithoutExerciseNumberIsExampleSolution` / `answerBlockInheritsExerciseNumber` / **`answerZoneContentNeverSurvivesExplainMode`** |

> ⚠️ **反证 C 的第三项是本轮新增的最关键用例**：
> `answerZoneContentNeverSurvivesExplainMode` 把「**角色判定 → 检索期过滤**」串成一条端到端断言——
> 不只测角色（那只是判据），而是证明「被判错的答案内容**不会进入学生的上下文**」。
> 修复前它转红：答案区段落被判为 `EXPLANATION` → 不是答案类 → **被召回**。

## 九、环境备忘（踩坑清单，供后续接手者）

1. **Maven 与 JDK 不在 PATH**：用 IntelliJ 内置的 JBR 25 + maven3（路径见 §三）。
2. **集成测试必须用隔离库** `./scripts/dev-it-db.sh`（`agent_it`）：
   开发库 `agent_dev` 被运行中的实例持续写入，上千条僵尸 `run` / `outbox` 占满
   `ORDER BY created_at LIMIT 1000` 的窗口 → 后来者报「任务未被领取」。
   **这已是 F-9 同形态的第二次出现**，失败现场指向错误方向（看起来像代码回归）。
3. **RabbitMQ 用 `agent-test` vhost**：`agent` vhost 上有 IntelliJ 调试实例的 4 个消费者在抢消息。
4. **`source config.env` 必须配 `set -a`**，否则 `RABBITMQ_PASSWORD` 为空 → `ACCESS_REFUSED`。
5. **`spring-boot-maven-plugin` 必须挂 `<classifier>exec</classifier>`**（本轮 P4-D09 修复）：
   否则 fat jar 布局会让 failsafe **整个模块**的集成测试无法引导。
