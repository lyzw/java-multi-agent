## 🎯 一、G1 功能背景

### G1「登录返角色」需求概述

在开发过程中，多个端点需要获取当前用户拥有的角色信息。由于此时 Spring Security 尚未启用，采用**临时实现方案**通过手动解析 JWT token 获取角色。此功能待正式接入 Spring Security 后，将改为无状态的 `SecurityContextHolder` 查询，避免延迟抖动和 fail-fast 限制。

## 🔧 三、技术实现

### 代码位置

```java
// platform/agent-api/src/main/java/cn/studykid/multiagent/api/auth/AuthController.java
@GetMapping("/roles")
public ResponseEntity<Map<String, Set<String>>> queryRoles() {
    // G1: 从 JWT token 提取 principalId
    TenantContext context = tokens.verify(
            RequestContextHolder.currentRequestAttributes().getRequest().getHeader("Authorization"),
            Clock.systemUTC().instant(),
            java.util.Set.of(...role_list...));
    return ResponseEntity.ok(Map.of(\"roles\", context.roles()));
}
```

### 核心逻辑

1. **提取 Authorization header**：从请求头中获取 JWT token
2. **验证 token**：调用 `JwtTokenService.verify()` 进行签名校验和字段解析
3. **取交集**：以数据库角色为准，与 token 声明的角色取交集
4. **fail-safe**：任何异常情况下返回空 set（不暴露信息）

## 🔄 五、G1 临时方案的限制

### 当前依赖

- ❌ `RequestContextHolder.currentRequestAttributes().getRequest()` 手动提取 token
- ⚠️ JSON 手解析（`tokens.verify()`）而非 Spring Security 自动处理

### 正式集成后收益（G2）

| 项目 | G1 临时方案 | G2 正式方案 |
|------|-------------|-------------|
| 状态传递 | fail-fast，手动获取 | 自动注入，无延迟 |
| 安全模型 | 手动验证 JWT | Spring 统一授权 |
| 并发处理 | 需手动处理上下文 | 自动 `SecurityContextHolder` |
