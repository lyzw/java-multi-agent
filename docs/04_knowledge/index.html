这套知识库解决什么问题

你已经会 Spring Boot、JPA/MyBatis、MySQL、REST 接口与单元测试。但在这个仓库里，「启动一个服务」涉及两套 Maven reactor、两套数据库、三个角色体系、一份跨进程 JWT 密钥、若干 fail-closed 开关；「测试全绿」也不等于「功能正确」。本知识库把这两段距离拆成可循序渐进执行的章节，并把 AI 相关知识点、开发过程中的选型决策、特殊 AI 问题处理、多级 Agent 编排、配置治理与权限、真实事故案例、RAG 语料工程、数据源合规、测试与质量保障、对话质量评估与归因、租户级成本治理与 Token 计费、可观测性与运维 Runbook、跨 Run 记忆、模型网关、流式输出、MCP 运行时单独编成十六册，并把项目里真实踩过的坑整理成现象 → 原因 → 定位 → 解决 → 验证五段式案例。

阅读前必须接受的一条约定

本知识库只陈述仓库里可查证的事实。凡是文档之间互相矛盾、只有注释提及而代码未落地、或本次勘察无法核实的内容，一律用 未确认 / 文档冲突 标注，并在 第 20 章 汇总。不做推测性补全。命令中的口令、密钥一律写占位符。

0.2 事实来源与标注图例

本手册的事实按以下优先级取用，冲突时以更靠近可执行物的一方为准，并在正文标注：

  1. 源码与构建产物：pom.xml、*.java、application.yml、*.sql、可执行 jar 的 MANIFEST；
  2. 可执行脚本：scripts/*.sh、.github/workflows/ci.yml；
  3. 配置模板与结构 README：*.env.example、deploy/sql/README.md；
  4. 设计/复盘文档：docs/**、rag/docs/**、问题记录/**、审查文档/**（其中不少是历史快照，可能滞后）。
标注含义
可直接复用传统 Java 后端的既有经验在这里依然成立，照做即可
需调整概念相似但语义、边界或默认值不同，照搬会出错
需补充传统 Java 后端通常不涉及，必须新建立的心智模型
未确认仓库中没有可核实依据，或本次勘察未逐项验证；需现场核对
文档冲突两份权威材料给出的结论不一致，已列出双方口径
为什么专门标「未确认」

这个项目有大量历史设计文档和实测记录，部分写于早期基线（例如 21 张表、Flyway 迁移链、普通 jar 启动）。把过时文档当成现行事实，正是本项目多起「静默失真」事故的根因。第 20 章集中列出全部已知冲突，遇到命令跑不通请先查那里。

0.3 代码块与示例的约定

  • 所有命令行、SQL、Java 片段统一使用同一套代码块样式；标题栏标注语言与真实文件路径（路径相对仓库根）。
  • 示例中的 <口令>、<host>、<MUST-FILL> 是占位符，不是可复制的真实值；仓库内真实的 *.env 均为 0600 权限且被忽略，手册不复现其中任何密钥。
  • 命令大多以仓库根目录为当前工作目录；需要进入 platform/ 或 rag/ 时会显式写出。
  • 凡引用真实事故，均给出问题记录/文档的路径与原文编号（如 TST-01、P8），便于回溯。

0.4 维护说明

本知识库为多文件 HTML，共 28 个页面 + 3 个共享资源，全部位于 docs/Java后端转型知识库/，无外部 CDN 依赖，双击 index.html 即可离线使用，也可逐页用浏览器「打印为 PDF」。样式与全站目录集中在 assets/handbook.css / assets/site-data.js / assets/handbook.js，改一次全站生效；新增章节只需保持 <section class="chapter" id="…"> 与带 id 的 h3 结构，并把新条目登记进 site-data.js。结构基线、配置键、脚本清单发生变化时，应同步更新 第 5 章、第 6 章、第 18 章 与 第 20 章。
