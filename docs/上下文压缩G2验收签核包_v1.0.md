## 3. G2-b：L1 真跑压缩闭环

### 3.1 入口与夹具口径

- 测试类：`ContextCompactionL1RealRunIT`，`@EnabledIfEnvironmentVariable(named = "IT_PG_URL", matches = ".+")`，本地隔离库 `agent_it`。
- 同一个 `agent.context.enabled=true` 的 Spring 上下文，两个冻结 Agent 由 `cap_agent_def.generation_params.context` 区分：`strategy=OFF` 为关闭等价对照，`strategy=TIERED` 为实验组。
- 挤出压力：5 轮只读工具 `get_student_profile` 大输出回灌 + 1 轮终答；`maxInputTokens=16000`、`triggerRatio=0.70`、`targetRatio=0.40`、`recentTurns=6`；OFF 末轮仍全发，TIERED 越过触发线。
- 模型桩：使用 `BeanDefinitionRegistryPostProcessor` 在所有配置解析完成后强制替换 `observableModelGateway` BeanDefinition；内部仍复用生产 `ModelCallObserverChain`。
  - 不能只写 `@Bean(name = "observableModelGateway") + @Primary`：实测被生产 `ObserverConfiguration` 反向覆盖，Worker 退回 `FakeModelGateway` 固定 usage 10:20，压缩发生也看不出账上 token 下降。
- 计费：`long inputTokens = TOKEN_COUNTER.count(RequestContextProjection.project(request));`，usage 严格按真实送出的 `ModelRequest` 全窗口投影计算；固定 usage 属 Sev-0 假绿，已被守卫与反证禁止。

### 3.2 关键断言

| 维度 | 断言 |
| --- | --- |
| Run 闭合 | OFF / TIERED 各 6 次模型调用、6 行 `usage_record`；Run 状态 `SUCCEEDED` |
| 账本同源 | `assertUsageMatchesRequests` 逐轮断言 `usage_record.input_tokens` 等于真实请求的 `RequestContextProjection.project(request)` 估算 |
| 回放底座 | `run_message` 角色计数 `USER=1 / ASSISTANT=6 / TOOL=5`；压缩后 TOOL 正文最小长度与 OFF 完全相等 |
| 行为分流 | OFF 压缩事件为空；TIERED 非空且至少一条 `tier>=1`、`droppedTokens>0`、`afterTokens<beforeTokens` |
| 核心效果 | TIERED 末轮与全 Run 累计 `input_tokens` 均严格小于 OFF |
| 稳定前缀 | `systemPrompt` / `toolSchemas` / `modelId` / `temperature` / `maxTokens` / `timeout` / `userContent` 跨轮逐字一致 |
| 首轮锚 | 每轮 `effectiveMessages()` 中首轮用户问题精确出现一次，不重复发送 |
| 工具配对 | 每轮 assistant `tool_calls` 与 TOOL `tool_call_id` 闭合，W1 / W2 不拆散配对 |
| 生产入口 | `RunExecutionLoop` 中 `ModelRequest request = assembly.request();` 唯一，禁止回退 `legacyRequest` |

## 4. G2-c：双通道重投边界

### 4.1 S2 可证伪边界

计划 §8.1 写「Rabbit + DB 两通道重投 / 恢复，checkpoint 不重复写入」。当前 `checkpoint` 表、`ContextCheckpointPort`、compaction 幂等键均尚未落地，因此本阶段只能验「同一输入重投 -> 输出确定、无副作用、不二次计费」；不把「重复采集不翻倍」冒充「压缩态不重复落库」。该边界已写入两个 IT 的 Javadoc，并由 `ContextCompressionG2GuardTest#doubleChannelReplayEvidenceIsNonVacuous` 锁定。

### 4.2 Rabbit 通道

- 入口：`TraceCollectEndToEndIT#collectEventProducesMetricRowThroughRealBroker`，1/1，`skipped=0`。
- `@BeforeAll` 先 purge `agent.trace.collect.it`，避免上轮遗留消息污染 ack 增量。
- 同一 `OutboxMessage` 发送两次；非空转证据：
  - `awaitAckCount(acksBefore + 1)`；
  - `awaitAckCount(acksAfterFirst + 1)`；
  - `awaitMetricRecomputedAfter(computedAfterFirst)` 且 `metricComputedAt().isAfter(computedAfterFirst)`；
  - `metricRowCount() == 1`；
  - `retriedCount()` / `deadLetterCount()` 不增；
  - `captureExecutionFacts()` 与 `captureSideEffectFacts()` 与首次投递后逐位相等；
  - `productionExecuteQueueDepth()` 不变，证明采集重投没有复活执行通道。
- 夹具补非零 `usage_record` / `run_step`，避免「0 与 0 相等」的弱断言；`review_task` 等副作用按 `tenant_id` / `trace_id` 谓词清理，避免 FORCE RLS 下静默 0 行。

### 4.3 DB / PG 队列通道

- 入口：`TraceMetricContentAccuracyIT#repeatedCollectIsIdempotent`（1/1）与 `#metricValuesAreComputedCorrectly`（1/1），类合计 2/2，`skipped=0`。
- 同一事件二次投递；非空转证据：
  - `awaitPgProcessedAtLeast(processedBefore + 1)`：基线在首次采集后取，第二次只需 `+1`；
  - `awaitMetricRecomputedAfter(computedAfterFirst)` 且 `computed_at` 前移；
  - `metricRowCount() == 1`；
  - `metricLong("input_tokens") == 120`、`output_tokens == 45`、`tool_rounds == 2`，证明数字仍算对；
  - `captureExecutionFacts()` / `captureSideEffectFacts()` 冻结；
  - `pendingQueueRows()` / `deadLetterRows()` 均为 0。
- `TraceCollectDatabaseChannelEndToEndIT#collectEventProducesMetricRowThroughDatabaseChannel` 1/1 保证 DB 通道单次闭合仍成立。
