## 1. 端到端验收场景（冻结 V1 的前置条件）

> 每个场景给出：前置、调用、预期 `authorizationDecision` / `executionDecision` / `executionStatus` / `reasonCode`、实现位置、自动化用例。
> **决策状态模型以 05 §0 为准**：授权失败 = `authorizationDecision=DENY`；审批/预算失败 = `authorizationDecision=ALLOW, executionDecision=DENY`。

| # | 场景 | 前置 | 调用 | authzDecision | execDecision | execStatus | reasonCode | 实现位置 | 用例 |
|---|---|---|---|---|---|---|---|---|---|
| **S1** | 已授权工具 | homework_tutor 启用 student_profile_reader，含 get_student_profile | Agent→Skill→Tool(READ) | ALLOW | ALLOW | SUCCEEDED | — | validator+native | test_S1 |
| **S2** | 未授权工具 | homework_tutor 未启用 notifier | Agent→Skill(notifier)→Tool(WRITE_EXTERNAL) | DENY | DENY | NOT_STARTED | SKILL_NOT_ENABLED | validator | test_S2 |
| **S3** | 主体撤权后 | S1 同上下文，`authzVersion` bump | 同 S1 | DENY | DENY | NOT_STARTED | AUTHZ_STALE | AuthorizationService+validator | test_S3 |
| **S4** | Skill 被收紧 | 运行时 overrides 移除 student_profile_reader | 同 S1 | DENY | DENY | NOT_STARTED | SKILL_NOT_ENABLED | resolver+validator | test_S4 |
| **S5a** | MCP 配置指纹变化 | notify_mcp 固定清单/配置变更，快照指纹陈旧 | Agent→Skill→MCP(send_mail) | DENY | DENY | NOT_STARTED | CONFIG_FINGERPRINT_STALE | 06 §4 指纹失效 | test_S5a |
| **S5b** | MCP 操作级越界 | 工具不在 Skill/MCP allowlist（固定清单不含） | Agent→Skill→MCP(send_sms) | DENY | DENY | NOT_STARTED | MCP_OP_NOT_ALLOWED | validator | test_S5b |
| **S6** | 审批未通过/缺失/重放 | send_email WRITE_EXTERNAL，无/无效 approval | Agent→Skill→MCP | ALLOW | DENY | NOT_STARTED | APPROVAL_REQUIRED / APPROVAL_DENIED / APPROVAL_REPLAY_REJECTED | runtime[审批] | test_S6 |
| **S7** | 预算不足 | send_email，BudgetPort 余额不足 | 同 S6 带 approval | ALLOW | DENY | NOT_STARTED | BUDGET_EXCEEDED | runtime[预算] | test_S7 |
| **S8** | 外部执行结果未知 | send_email 审批通过+预算够，响应丢失 | 同 S7 执行 | ALLOW | ALLOW | UNKNOWN | EXEC_UNKNOWN | runtime[UNKNOWN→对账] | test_S8 |

**判定规则**：
- S1/S8 必须 `authorizationDecision=ALLOW`；S2–S7 必须 `authorizationDecision=DENY`（S2–S5）或 `executionDecision=DENY`（S6/S7），且 `reasonCode` 精确匹配。
- S8 关键：`executionStatus=UNKNOWN` **不**等同于执行成功；进对账队列。
- S6/S7 必须验证"授权通过、仅执行准入拒绝"——不得笼统记为 `authorizationDecision=DENY`（评审 §9.1）。
- 任一不符 → V1 不冻结（04 §4）。

## 2. 撤权竞态 / 并发 / 故障（评审 §9.3，强化 S3）

| 测试 | 操作 | 预期 |
|---|---|---|
| **S3a** 跨实例失效 | A 实例撤权提交（bump authzVersion），B 实例随后发起调用 | B 读取新版本 → `authorizationDecision=DENY(AUTHZ_STALE)` |
| **S3b** 执行准入点阻断（撤权先提交） | 调用通过 Phase A 授权后、撤权事务提交，再尝试启动外部副作用（执行准入点重验在撤权之后） | 执行准入点重验（07 §2[10]/05 §5）→ `executionDecision=DENY(EXEC_ADMISSION_STALE)`，不启动新副作用 |
| **S3f** 在途操作不承诺绝对阻断（准入先完成） | 执行准入点已通过、外部副作用已发出（或正在发出），随后撤权提交 | 该调用为已进入执行阶段的在途操作；记录 `executionStatus`（SUCCEEDED/FAILED/UNKNOWN）并按幂等/对账/补偿处理，**不承诺**撤销已发出的副作用（05 §5 契约 2） |
| **S3c** 并发单调递增 | 两实例并发修改授权 | `authzVersion` 单调递增，无丢失更新（DB 原子自增/乐观锁） |
| **S3d** 版本服务不可用 | 授权版本 DB 不可用 | fail-closed 拒绝无法确认授权状态的新调用 |
| **S3e** 重复撤权 | 重复处理同一撤权事件 | 版本继续递增，无版本回退、无丢失撤权 |
| **S3g** 准入竞态 vs 并发发布 | Run 通过执行准入点（读版本/指纹 Vn）后、新配置发布（seq Vn+1）前窗口；或反之 | 已通过准入的在途调用按既有结果执行（不撤销，05 §5 契约 2）；新调用读新版本/指纹按新配置生效；发布原子性保证无"部分新配置可见"（06 §3.2） |

> S3b 验证"撤权先提交 → 阻断"（05 §5 契约 1）；S3f 验证"准入先完成 → 在途不承诺绝对阻断"（05 §5 契约 2）；S3g 验证"并发发布 vs 准入判定"窗口下二者互不破坏（06 §3.2 原子发布）。三者共同覆盖执行准入点的线性化边界，不得只验证理想时序。

| 闭包计算 | 显式 enable / 移除 override / 收紧 ceiling | 闭包正确 |

## 5. 配置生命周期测试（评审 §9.4）

| 测试 | 预期 |
|---|---|
| 未发布配置不能被 Agent 引用 | DENY（状态机 06 §3） |
| 发布审批人与请求人相同 | 拒绝（双人复核 `approver_id <> requester_id`） |
| 多对象发布失败时 | 不暴露部分生效配置（PREPARING 不可读，06 §3.2） |
| 已发布配置不可原地修改 | 插入新不可变版本，旧行不变 |
| 回滚后历史版本/快照可追溯 | 新 release 指向旧 version，历史保留 |
| 被引用对象停用 | 新 Run 不可引用，存量按版本失效 |
| 迁移重复执行 | 幂等，无重复对象/错误覆盖 |
| 租户不能引用其他租户对象 | RLS 拒绝（NFR-02） |
| 无关对象配置变更 | **不**触发本 Run 快照失效：仅本 Run 依赖闭包内对象变化才触发失效（P0-6 / 06 §4 闭包级指纹）；其他 Agent/Skill/Tool/MCP 的变动不影响本 Run | 
| 并发发布 + 回滚 | 单调 `config_publish_seq` 无冲突；回滚生成新 PUBLISHED release 指向旧 version，旧 release 标记 ROLLED_BACK，当前指针稳定不破坏（P0-8 / 06 §3.2） | 
| 回滚不恢复主体授权 | 撤权状态独立（05 §5） |

### 5.1 执行前后故障恢复测试（评审 08-05）

| 测试 | 预期（四字段 / 账本 / 预算） |
|---|---|
| 审批端口超时/不可用 | fail-closed：`authorizationDecision=ALLOW, executionDecision=DENY(APPROVAL_DENIED)`，不启动副作用（05 §5.2） |
| 审批重放/并发消费冲突 | `executionDecision=DENY(APPROVAL_REPLAY_REJECTED)`，仅一个调用成功消费（05 §5.2） |
| 预算预留后执行失败 | 预算回滚释放；`executionStatus=FAILED`，不重复预留（05 §5.2） |
| 账本 PRE 写入失败 | 拒绝执行（不绕过账本发请求）；重试仍失败 → 标记待人工确认（05 §5.2） |
| 账本 POST 写入失败（副作用已发生） | `executionStatus=UNKNOWN`，进对账队列重查/补偿，不记为执行失败（05 §5.2） |
| 幂等键重复到达（已完成） | 返回首次结果，不重复执行/不重复预留（05 §5.2） |
| 外部响应丢失 | `authorizationDecision=ALLOW, executionDecision=ALLOW, executionStatus=UNKNOWN`，进对账队列，不得盲目重试（05 §5.2 / S8） |

## 6. MCP 安全测试（评审 §9.5）

| 测试 | 预期 |
|---|---|
| 固定清单 + 工具下线 | DENY(MCP_OP_NOT_ALLOWED / CONFIG_FINGERPRINT_STALE) |
| Server 身份映射冲突 | 同名不同 server 区分，禁止冲突 |
| Schema 变更后旧配置调用 | DENY(CONFIG_FINGERPRINT_STALE) |
| DNS 解析到禁止 IP | 连接级 DENY（SSRF，06 §5） |
| HTTP 重定向到禁止目标 | 重校验拒绝（06 §5） |
| 凭据轮换失败/认证不确定 | 连接级 DENY / fail-closed |
| 超时/响应超限/并发超限/熔断 | 失败隔离，不拖垮全局 |
| MCP 输出含恶意指令 | 不转化为可信系统指令（不可信边界） |

## 7. 性能与审计测试（评审 §9.6）

| 维度 | 指标 | 目标 | 测试条件 |
|---|---|---|---|
| 本地权限判定 | `InvocationValidator` 单跳（闭包查表+版本比对+策略） | **p99 < 1ms** | 数据集/闭包规模/并发量明确；**不含**授权 DB 读取的端到端耗时 |
| 端到端调用 | 授权+审批+预算+网络+执行 | 另行设定（不与本地判定混用） | — |
| MCP（V2）发现 | 缓存 TTL/刷新/失效/失败 | 失效且无法校验→拒 | — |
| 配置发布→生效 | 强一致读取 + 缓存重验 | 新调用实时读；旧缓存命中须重验 | 非"异步 ≤1s" |
| 决策日志 | 四字段完整率 | 100% | runId/invocationId/authzDecision/execDecision/execStatus/reasonCode/fingerprint |
| 审计分类 | 非笼统 DENY 占比 | 100% | 按 05 §8 reasonCode |
| 防绕过 | 直接调用 ToolHandler | 0 通过 | 静态+运行时+架构测试 |
| 撤权 SLA | 提交后新调用失效 | 强一致读取达成 | S3a/S3d |

**审计双重验收**：
1. 每次调用（允许/拒绝/失败/未知）均可通过 `runId` + `invocationId` 追踪。
2. 日志不含明文凭据与不必要的敏感参数。
3. 授权拒绝/审批拒绝/预算不足/执行失败/执行未知可准确区分（reasonCode）。
