## 0. 状态模型（7 态枚举）— 评审 P0-9

> **核心修正**：原矩阵将「已实现(Demo)」「设计中」「待 PoC」混用，易把 **Demo 验证**误读为 **平台验收**。本版显式拆分三线状态，杜绝混淆。

**需求成熟度 7 态枚举（单向递进）**：

| 状态 | 含义 | 是否构成 V1 验收 |
|---|---|---|
| `DESIGNED` | 仅文档设计，未实现 | 否 |
| `DEMO_IMPLEMENTED` | Python Demo 已验证逻辑可行性（非生产代码，不可上线） | 否 |
| `PLATFORM_IMPLEMENTED` | Java 平台已实现（cap_* 对象 / 闸门集成） | 部分 |
| `UNIT_TESTED` | 通过单元/组件测试 | 部分 |
| `INTEGRATION_TESTED` | 通过集成测试（含 DB/RLS/并发） | 部分 |
| `SECURITY_ACCEPTED` | 通过安全验收（脱敏/审计/越权/撤权全绿） | 接近 |
| `ACCEPTED` | 已冻结验收 | 是 |

**三线拆分列说明**：
- **Demo验证**：Python Demo（`agent-permission-demo/`）是否覆盖该需求逻辑（✅ / 部分 / —）。Demo 仅为设计验证，不参与生产验收。
- **平台成熟度**：Java 平台当前落地程度（待建 / 部分 / 已有 / 待测 / 待验证）。
- **整体状态（7态）**：取「Demo验证 ∩ 平台成熟度」可达的**最高**态；因平台 cap_* 集成基本待建，**当前无需求达到 `PLATFORM_IMPLEMENTED` 及以上**。

> ⚠️ **冻结语义**：V1 冻结以「平台 `PLATFORM_IMPLEMENTED` + `UNIT_TESTED` + `INTEGRATION_TESTED` + `SECURITY_ACCEPTED`」为准；**Demo 实现仅证明设计可行，不构成任何验收**。凡标注 `DEMO_IMPLEMENTED` 的项，均须在平台侧重新实现并经测试后方可计入冻结证据（04 §4 / 冻结清单第 7 项）。
