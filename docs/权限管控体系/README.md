## 三、数据层迁移（12）速览

**目标**：解除权限逻辑与 PostgreSQL 的耦合，使后续可从容迁移到不同关系型数据库或向量库。

**核心思路**：RLS 不是要被「废除」，而是从「唯一权威」降级为「可拆卸的最内层兜底」。
迁移的实质是 —— 仓库里权限过滤**已经**在应用层写了一遍（每个 Repository 显式 `WHERE tenant_id`），
RLS 是叠加在上面的第二道。⇒ 迁移是**删除冗余**而非**从零新建**。

**枢纽对象**：`ScopeFilter` —— 只有 4 种形态、不含任何 SQL 方言的范围语义对象。

| 形态 | 语义 | 对应现役 RLS |
|---|---|---|
| `TenantOnly` | 仅本租户 | `tenant_id = current_tenant_id()` |
| `TenantWithShared` | 本租户 + 平台公开桶 | `tenant_id IN (rag_current_tenant(), rag_global_tenant_id())` |
| `Unrestricted` | 平台全域 | BYPASSRLS 运维通道 |
| `NONE` | 空集（恒假 → 0 行） | fail-closed 的显式表达 |

**六阶段路线**（详见 12 §3）：

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| P0 准备 | 导出策略、生成翻译对照表、补启动自检 | 对照表评审通过；主数据源确认非 BYPASSRLS |
| P1 影子 | 应用层只判不拦，与 RLS 谓词离线比对 | ≥2 周 `AUTHZ_MISMATCH = 0` |
| P2 双写 | 应用层过滤生效，RLS 保留兜底（两层取交集） | 全量 IT 绿 + 两份反证同时通过 |
| P3 逐表退役 | 按域分批 `DROP POLICY` | 每批跨租户用例仍红 + 回滚演练通过 |
| P4 收口 | 策略规则进配置中心 + 双人复核 | 新增表纪律反转（默认无 RLS） |
| P5 清理 | 删 `TenantSessionBinder` | 稳定运行一个季度后 |

> ⚠️ **P0 硬前置**：主数据源必须先切到 `app_agent`（NOBYPASSRLS）。
> 若仍用 BYPASSRLS 角色，**RLS 在主链路本就失效**，P1 影子比对直接失去意义。

## 四、配套工具

| 工具 | 用途 |
|---|---|
| [`scripts/export-rls-policies.sh`](../../scripts/export-rls-policies.sh) | 导出活库全部 RLS 策略 → 分类为 `ScopeFilter` → 生成翻译对照表（含缺口扫描 / 读写不对称检测 / 活库-vs-DDL 漂移检测） |
| [`docs/权限管控体系/authz/policy-mapping.yaml`](authz/policy-mapping.yaml) | 翻译对照表基线（由上述脚本生成） |

```bash
# 生成对照表
PG_CONTAINER=agent-pg17 PG_USER=agent PG_DB=rag_base DDL_DIR=deploy/sql \
  ./scripts/export-rls-policies.sh
```
