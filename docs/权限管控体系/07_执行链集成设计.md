# 07｜执行链集成设计

> 定位：定义新增校验组件与**现有 `ToolInvocationGate`** 的职责边界，避免重复校验与绕过路径。
> 评审依据：03 P0-2（授权校验与现有执行闸门缺少接口契约）、C4（职责未划清）、05（授权≠执行、顺序唯一）、G-01/G-03。
> **本文件不重定义安全规则，只定义组件分工与调用顺序；安全语义以 05 为准。**

---

## 1. 组件职责表（唯一真相）

| 组件 | 职责 | 输入 | 输出 | 失败语义 | 复用/新增 |
|---|---|---|---|---|---|
| **AuthorizationService** | **主体当前授权 + `authzVersion` 重授权（最先执行）** | `AuthContext`, action, resourceId | bool（实时，强一致读） | 陈旧/不足 → `authorizationDecision=DENY(AUTHZ_STALE)` | 已有（换 DB 实现，04 §1.1） |
| **PermissionResolver** | 无副作用只读：计算"有效能力闭包"（Agent→Skill→Tool/MCP），合并继承/覆盖/收紧 | Agent/Skill/Tool/MCP 配置 + 租户覆盖 | `EffectiveClosure`（含 `configFingerprint`） | 配置缺失/环/放宽为 CONFIG_ERROR DENY | 新增（复用 `EffectiveConfigResolver` 读取） |
| **InvocationValidator** | 调用期**能力链+配置约束**判定（Phase A 授权，不含预算/执行副作用） | `AuthContext` + `EffectiveClosure` + 本次调用目标 | `AuthorizationDecision(allow/deny, stage, reasonCode)` | 任一因子 false → `authorizationDecision=DENY`（05 公式/顺序） | 新增（实现 05 §1–§3） |
| **ToolInvocationGate** | **唯一执行入口**：调度 Phase A → Phase B → 执行；自身负责 Phase B 闸门 | `ToolHandler` + 调用参数 | `ExecutionResult(authorizationDecision, executionDecision, executionStatus, reasonCode)` | Phase B 各闸门独立 `executionDecision=DENY`（不混淆为授权 DENY） | 已有（ADR-011 禁绕过） |
| **ApprovalPort** | 风险驱动审批（REQUIRED/OPTIONAL），绑定操作+参数域+指纹+一次性消费 | 工具/风险/参数 | 审批态 | 缺失/拒/不可确认/重放 → `executionDecision=DENY(APPROVAL_*)` fail-closed | 已有（`RiskBasedApprovalPolicy`） |
| **BudgetPort** | 预算预留（幂等键） | tenant/run/tool | 预留成功/失败 | 不足 → `executionDecision=DENY(BUDGET_EXCEEDED)` | 已有 |
| **RunToolLedgerPort** | 账本登记（幂等，PRE/POST） | invocationId/结果 | 登记 | PRE 写入失败 → 重试/进入恢复流程（不得仅"告警"） | 已有 |
| **ToolHandler** | 原子执行（native 或 MCP-backed 统一接口） | 校验后参数 | 结果（含 UNKNOWN 对账） | 异常 → FAILED/UNKNOWN | 已有（MCP-backed 包装新增） |

> 组件名是**职责划分**，非认定当前已存在这些新类。`InvocationValidator` 与 `PermissionResolver` 为本次新增；其余复用既有。

## 2. 调用契约顺序（T3，无重复副作用，顺序与 05 §2 一致）

```
调用进入 ToolInvocationGate.invoke(agentId, skillId, toolId|mcp, params, ctx)

[0] 构建可信调用上下文：身份/租户/Run/目标来自可信认证上下文（TenantContext），绝不取客户端输入
[1] AuthorizationService.isAuthorized(ctx, TOOL_INVOKE, toolId)  → 实时主体授权（先判角色集合，再判 authzVersion 新鲜度）
        └ false → 写决策日志(authorizationDecision=DENY, AUTHZ_ROLE_MISSING / AUTHZ_STALE) → 返回（不执行）
[2] PermissionResolver.resolve(ctx)  → EffectiveClosure（命中缓存则校验 authzVersion/fingerprint 仍有效；
        仅当 [1] 通过后才用于判定，避免未授权主体读取敏感配置分支）
[3] InvocationValidator.validate(ctx, closure, target) → AuthorizationDecision（Phase A：Agent→Skill→Tool→risk→MCP→param→fingerprint）
        ├ false → 写决策日志(authorizationDecision=DENY, stage, reasonCode) → 返回（不执行）
        └ true  → authorizationDecision = ALLOW
[4] ToolHandler.validate(params)  → 结构校验（JSON Schema）  → 失败 executionDecision=DENY(PARAM_SCHEMA_FAIL)
[5] ApprovalPort.check(tool, params, fingerprint, approvalId)  → 风险审批（REQUIRED 且未满足/重放→DENY）
        → 失败 executionDecision=DENY(APPROVAL_*)  【authorizationDecision 仍 ALLOW】
[6] BudgetPort.reserve(tenant, run, tool, idempotencyKey)  → 预算（不足→DENY(BUDGET_EXCEEDED)）【仍 ALLOW】
[7] RunToolLedgerPort.record(invocationId, PRE)  → 账本"已登记未完成"（失败→重试/恢复流程）
[8] ExecutionAdmissionCheck（TOCTOU 执行准入点，线性化契约见 05 §5）：重验 authzVersion + closureFingerprint 仍新鲜
        → 失效 executionDecision=DENY(EXEC_ADMISSION_STALE)  【不启动新副作用】
        └ 契约：撤权先提交→阻断（05 §5 契约 1）；准入已完成且撤权后提交→在途操作不承诺绝对阻断，按对账处理（05 §5 契约 2）
[9] ToolHandler.execute(params)  → 执行；UNKNOWN → reconcile → 对账队列
[10] RunToolLedgerPort.record(invocationId, POST, executionStatus)
→ 返回 ExecutionResult(authorizationDecision=ALLOW, executionDecision=ALLOW, executionStatus, reasonCode)
```

**边界铁律（评审 G-01）**：
- `[1]` 主体授权**必须**在 `[2][3]` 能力链判定之前；`InvocationValidator` 只做能力链+配置约束判定，不得重复主体授权。
- `[5][6][7]` 的审批/预算/账本由既有闸门 Port 负责，**不得**在 `InvocationValidator` 内重复执行副作用（评审 G-02）。
- 顺序的安全语义由 05 §2 唯一规定，本文件仅做组件编排，不得改变其短路顺序与失败归属。
- **结构校验与业务参数策略分属不同阶段（05 §1）**：[3] 的 `param` 是**业务权限策略**（`paramPolicies`，如 `in_allowlist`/`lte`），属授权阶段（Phase A），**非结构校验**；[4] 的 `ToolHandler.validate` 是**仅一次**结构校验（JSON Schema），属执行准入（Phase B）。二者不得合并执行，也禁止在 [3] 重复做结构校验。

## 3. 唯一执行入口与防绕过

- **所有** Native Tool 与 MCP-backed Tool **必须**经 `ToolInvocationGate` 单一入口；ADR-011 禁止 Spring AI 自动执行、禁止直接调用 `ToolHandler` 实现类。
- **集成验收条件**（进入 PoC 强制）：
  - 静态：扫描确认无任何 `ToolHandler.execute()` 被业务代码直接调用（仅 `ToolInvocationGate` 调用）；Spring AI Tool 自动注册/执行路径检查。
  - 运行时：注入"绕过闸门直接调用工具"的测试 → 必须失败（无授权上下文即拒绝）。
  - 包边界：`agent-ports`/`agent-core` 包访问权限限制，禁止业务模块直接拿到 `ToolHandler` Bean。
  - 覆盖：每个 MCP-backed Tool 与 Native Tool 走同一 `invoke` 路径，决策日志格式一致。
  - 上述由**代码扫描 + 架构测试 + 运行时测试**共同验证（静态扫描无法单独证明闭环）。

## 4. 配置读取与缓存失效

- `PermissionResolver` 闭包结果按 `(tenantId, agentId, agentVersion, configVersion, closureFingerprint, authzVersion)` 缓存；其中 `closureFingerprint` 为**有效能力闭包指纹（Run 依赖闭包级，非全局聚合，05 §5）**。
- `authzVersion` / `configVersion` 变化 → 失效（**DB 强一致读取**，04 §1.1；非普通异步缓存刷新）。
- **仅当 Run 依赖闭包内的对象（Agent/Skill/Tool/MCP）发生版本或指纹变化**（含 MCP 固定清单变更）时，`closureFingerprint` 才变化并失效；**与当前 Run 无关的 cap_* 变更不触发失效**（05 §5 / 06 §4）。失效 → 新 Run 重新计算；已有 Run 快照 mismatch → 授权 DENY(CONFIG_FINGERPRINT_STALE)（06 §4）。
- 版本服务不可用 → fail-closed 拒绝新调用（05 §5）。
- 旧缓存可保留时长、命中后是否允许继续：命中必须重新校验版本新鲜度；无法确认版本 → 拒绝。

## 5. 预算/幂等/账本执行前后事务契约（评审 §8.2）

- 授权、参数校验和必要审批**必须在副作用执行前完成**（[1]–[5] 在 [9] 前）。
- 幂等检查（[6] 预算预留携带幂等键）必须在重复请求可能产生副作用前生效；重复消费同一幂等键 → IDEMPOTENCY_CONFLICT DENY。
- 预算预留具幂等键，支持失败释放或补偿；预留成功是执行前置条件。
- 执行前账本记录（[7] PRE）必须能识别"已登记但未完成"的调用。
- 执行后账本更新（[10] POST）必须记录 `SUCCEEDED` / `FAILED` / `UNKNOWN`。
- **账本 PRE/POST 写入失败的处理必须明确**：阻止执行 / 重试 / 进入恢复流程三选一并实现，**不得仅写"重试/告警"**。外部调用已发生后账本更新失败，须与外部响应丢失一样进入可恢复流程（UNKNOWN 对账），避免账本显示未执行而实际副作用已发生。
- **故障恢复契约（统一表，见 05 §5.2）**：审批端口不可用/超时、审批重放冲突、预算不足、账本 PRE 失败、账本 POST 失败（副作用已发生）、幂等键重复到达、外部响应丢失（UNKNOWN）——每种故障的前置状态、是否允许执行、账本状态、预算处理、重试条件、对账动作、最终审计均有确定规则；任一故障**不得**笼统"重试/告警"或绕过账本发请求。
