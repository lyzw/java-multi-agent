# 04｜V1 范围与非目标基线（冻结版）

> 目的：在 03 PRD 通过评审后，**冻结 V1 实施边界**，防止范围蔓延，使开发基线可设、验收可测。
> 关联：03 PRD §5/§7（演进路线）、05 分层授权决策规范、08 安全测试与验收矩阵。
> 评审依据：03 评审 P0-1（V1/V2 功能边界冲突）、P0-3 注记（分布式 authzVersion 若属多实例安全必要条件应前移至 V1）。

## 1. V1 必修（Must-Implement）

| 编号 | 能力 | 说明 | 验收落点 |
|---|---|---|---|
| **A1** | Agent 显式启用 Skill | `Agent.enabledSkills` 为 Skill id 显式列表；不允许任何隐式/标签传播启用 | 08 场景"未授权工具 DENY"、"Skill 被收紧 DENY" |
| **A2** | Skill 显式引用 Native Tool | `Skill.declaredTools` 为 Tool id 显式列表（单一事实源，非复制） | 08 场景"已授权工具 ALLOW" |
| **A3** | 基础 MCP 接入（最小可运行） | `McpServerDef` 定义 + 连接级授权 + 操作级 `toolAllowlist`（**固定工具清单 + 配置版本/指纹校验**，不支持运行期动态发现） | 08 场景"MCP 工具发生变化 DENY" |
| **A4** | 三段校验 + authzVersion 重授权 | T1 配置期 / T2 绑定期快照 / T3 调用期逐跳重验；每次调用校验 `authzVersion` 与配置指纹 | 08 场景"主体撤权后 DENY" |
| **A5** | Skill riskCeiling 上限 | `Tool.riskLevel ≤ Skill.riskCeiling`，超则拒（防 P4 高危透传） | 08 / 02 §3.1 P4 |
| **A6** | 收紧覆盖 | `Agent.overrides` + 租户 `tenant_config_override`；仅移除/调低，不新增/放宽（收紧棘轮） | 01 §1.6 / 03 §2.4 |
| **A7** | 决策日志 | 结构化四字段：`runId / invocationId / agentId / skillId / toolId / authorizationDecision / executionDecision / executionStatus / reasonCode / authzVersion / configVersion / configFingerprint / latencyMs` | 08 审计字段 |
| **A8** | 复用既有安全地基 | `ToolInvocationGate` / `AuthorizationService` / `EffectiveConfigResolver` / `ConfigTighteningPolicy` / RLS 不重建 | 07 执行链集成设计 |
| **A9** | 全局 fail-closed | 缺配置 / 缺授权 / 异常 / 超时 / 列举失败 → 拒；风险等级未知/非法/未登记 → 配置期拒发布、运行期 `authorizationDecision=DENY(RISK_LEVEL_UNKNOWN)`（05 §3.3，**不降级为 WRITE_EXTERNAL 后放行**） | 05 异常处理矩阵 |

### 1.1 关键前置修正：DB 化 authzVersion 前移至 V1

评审指出"分布式授权版本若是多实例安全正确性的必要条件，应前移 V1"。本平台为**多租户 SaaS、多实例部署**，单实例内存版 `RoleBasedAuthorizationService` 无法满足"撤权即时全实例失效"。

**V1 强制要求**：`authzVersion` 必须为 **DB 支撑、单调递增、全局一致** 的版本号（或等价逻辑时钟），且**经强一致读取（或具强一致保证的授权服务）**判定失效——**不依赖普通异步缓存刷新**来承诺即时撤权。撤权 → 同一事务内 bump 版本 → 所有实例下一次调用读取到新版本即失效旧授权。V1 **不要求**完整的策略即代码，但**必须**提供该版本的存储、并发自增、读取与失效判定契约（详见 06 §1.5、07 §2）。

> **可验证的撤权 SLA（评审 §5.1/§5.2）**：撤权事务成功提交后，任意实例发起的新工具调用，只要其授权判定发生在提交之后，必须读取到不早于该提交版本的 `authzVersion`；若无法确认版本新鲜度（版本服务不可用/读取超时），fail-closed 拒绝该调用。该 SLA 以 DB 强一致读取或强一致授权服务为技术契约，而非"异步缓存最终一致"。

## 2. V1 明确不做（Explicit Non-Goals）

| 编号 | 能力 | 归属 | 不做的原因 |
|---|---|---|---|
| **N1** | 嵌套 Skill / `Skill.inherits` | V2 | 传递闭包易抬权（P3）；V1 只显式 ID 引用，写 `inherits` 即拒 |
| **N2** | Capability Tag / Skill Bundle / Agent Profile | V2 | 缓解组合爆炸用（M1），但标签过宽有越界风险；V1 仅显式 ID，避免歧义 |
| **N3** | 通用参数策略引擎 | V2 | V1 仅在验收场景必需处做**手写参数约束**（`in_allowlist` / `lte` 两点判定），不形成可组合策略引擎 |
| **N4** | 动态 MCP 工具发现 | V2 | V1 用固定工具清单 + 配置版本/指纹校验；运行期实时列举属 V2 |
| **N5** | 策略即代码（OPA/Rego） | V3 | 本期声明式规则 + 闭包计算已够 |
| **N6** | 跨 Agent 委托（A2A 授权） | V3 | 本期单 Agent 内能力闭包 |
| **N7** | 共享参数策略库 / 标签化权限市场 | V2 | 依赖 N2/N3 |

## 3. V1 预留接口（Reserved, stubbed）

schema 中保留字段但 V1 **不实现语义**，写入时按以下规则处理，避免"预留即生效"的隐患：

| 字段 | V1 行为 | 理由 |
|---|---|---|
| `Skill.inherits` | 写入即**拒绝**（校验失败），不允许误用 | 防 P3 抬权 |
| `Agent.skillBundles` / `capabilityTags` / `Skill.requiredCaps` | 接受写入但**忽略语义**（等价于空），不用于任何启用判定 | 防 M1 标签越界；为 V2 留字段 |
| `Skill.paramPolicies` / `Tool.paramPolicies` | 仅支持 `in_allowlist` / `lte` 两点手写判定；其他 op 写入即拒 | 防 G2 参数越权 |
| `McpServer.dynamicDiscovery` | 固定为 `false`；写入 `true` 即拒绝 | V1 不动态发现 |
| `Tool.namespace = tenant:<id>` | V1 仅 `platform` 级定义；租户级自定义 Tool 留 V2 | 单一事实源治理 |

## 4. V1 冻结验收门槛（进入 PoC 的前置条件）

进入 PoC / 架构冻结前，**08 安全测试与验收矩阵**的场景必须**全部有明确预期行为、实现位置与验收方式**，且自动化测试通过。冻结门槛拆为三类（评审 §5.2），**任一不通过即不冻结 V1 基线**：

### 4.1 功能门槛（场景行为正确）
1. Agent 调用**已授权**工具 → `authorizationDecision=ALLOW, executionDecision=ALLOW, executionStatus=SUCCEEDED`
2. Agent 调用**未授权**工具 → `authorizationDecision=DENY`（stage=agent_skill / skill_tool）
3. **主体撤权后**再次调用 → `authorizationDecision=DENY`（AUTHZ_STALE，跨实例强一致生效）
4. **Skill 被收紧**（移除/调低 ceiling）后调用 → `authorizationDecision=DENY`
5. **MCP 工具发生变化**（配置版本/指纹不匹配或固定清单不含）→ `authorizationDecision=DENY`（CONFIG_FINGERPRINT_STALE / MCP_OP_NOT_ALLOWED，S5a/S5b 分别建模）
6. **审批未通过/缺失/重放** → `authorizationDecision=ALLOW, executionDecision=DENY`（APPROVAL_*）
7. **预算不足** → `authorizationDecision=ALLOW, executionDecision=DENY`（BUDGET_EXCEEDED）
8. **外部执行结果未知**（副作用已发生、响应丢失）→ `authorizationDecision=ALLOW, executionDecision=ALLOW, executionStatus=UNKNOWN`、进对账队列
9. **撤权竞态/并发**（S3a–S3e）：跨实例失效、执行准入点阻断、并发单调递增、版本服务不可用拒绝、重复撤权无回退

### 4.2 安全门槛（不变量成立）
- RLS 跨租户引用拒绝、执行入口防绕过（静态+运行时+架构测试 0 通过）
- 撤权并发单调性（无丢失更新）、MCP SSRF/DNS/重定向/凭据轮换测试通过
- 审批绑定+一次性消费（重放/并发消费冲突被拒）、fail-closed 全异常分类 100%

### 4.3 工程门槛（可运维）
- 数据迁移（双写→校验→切读→稳定期→停写）可回退、幂等
- 版本发布/回滚数据模型支持（不可变版本 + `cap_config_release`，回滚不恢复主体授权）
- 审计日志字段完整 100%、性能（本地判定 p99<1ms，端到端另行设定）、部署回退方案就绪

> 注：8 个核心端到端场景全绿**不等于**安全验收完成；须同时满足 4.2/4.3 方可冻结（评审 §5.2）。

> **与 09 追踪矩阵的联动（评审 P0-9）**：冻结前须确认 09 已显式区分 Demo 验证（`DEMO_IMPLEMENTED`）与平台验收（`PLATFORM_IMPLEMENTED`+测试），且所有 Must-Implement 项不再被"已实现(Demo)"误标即视作验收。当前 09 §5 状态总览显示**无需求达到 `PLATFORM_IMPLEMENTED`**，V1 冻结门槛（平台实现 + 单测 + 集成 + 安全验收）尚未达成；**Demo 实现仅证明设计可行，不构成验收证据**（04 §4 / 冻结清单第 7 项）。
