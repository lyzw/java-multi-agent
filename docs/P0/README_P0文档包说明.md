## 使用规则

1. 这是一套**项目启动草案**，不是对未知业务事实的断言。所有 `[待确认]` 必须由指定责任人补齐。
2. v3.1 架构基线中的技术约束可直接作为设计输入；具体业务场景、租户规模、SLO、预算阈值、保留期、供应商和容量目标不能凭空设定。
3. 任何范围变化都要更新 P0-D03、P0-D04，并评估对排期、风险、架构和成本的影响。
4. P0 完成后，签署版本应冻结为 `v1.0-baseline`；后续变更通过变更记录追踪，不覆盖历史批准版本。
5. 建议将本目录纳入项目仓库 `docs/project/p0/`，并在 Pull Request 中维护变更记录。

## P0 退出门禁

- [ ] 项目目标和首个真实业务任务已被业务负责人确认。
- [ ] MVP 范围和明确非目标已被产品、业务和技术负责人确认。
- [ ] 所有 P0/P1 需求均有可验证验收条件及责任人。
- [ ] 外部依赖有负责人、可用时间和替代/降级方案（若适用）。
- [ ] 高风险项有缓解措施、决策期限和风险接受人。
- [ ] 初始排期和 RACI 获得项目团队确认。
- [ ] 关键技术决策被登记到 P1 ADR backlog；不在 P0 假装已经完成技术验证。

## 本次编制边界

本包按 v3.1 预设的企业级、多租户、可审计 Agent 平台编制；未假设具体行业、客户、业务系统、模型供应商、MQ 产品、团队人数或正式 SLA。此类内容均留作评审输入。
