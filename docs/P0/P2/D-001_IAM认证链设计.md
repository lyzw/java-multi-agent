## 0. 为什么这一项优先级最高

D1 已实现 Run 创建端点与授权闸门，但**闸门没有可信输入源**：

| 检查项 | 当前状态 |
|---|---|
| Spring Security 配置类 | **0 个** |
| 端点认证注解 | **0 个** |
| `TenantContext` 来源 | Spring 按参数注入 —— **调用方可任意构造** |

攻击者可提交任意 `tenantId` 与 `roles`，`AuthorizationService` 收到的
是他伪造的上下文 —— **授权闸门形同虚设**。

这不是「未完成的功能」，而是「**不要部署**」的前提。D-001 是解除项。

## 1. 关键决策（zhouwei 已确认）

| # | 决策 | 备选 | 采用理由 |
|---|---|---|---|
| 1 | **平台自建认证** | OIDC 对接外部 IdP / 自建 | 用户决策。自建避免外部依赖与出境问题，但**安全负担由平台承担**（见 §7 风险） |
| 2 | **JWT 自带 tenant claim** | 服务端映射库表 | 无需每次请求查库；自建认证下服务端即签发方，声明可信 |
| 3 | **内嵌 mock IdP** | 手工构造 JWT | CI 无外部依赖可跑；且能测到真实 JWT 解析与 claims 映射 |

### 决策 1 的连带风险（必须显式承认）

自建认证意味着以下责任**全部落在本平台**，无外部方兜底：

| 责任 | 外部 IdP 方案 | 自建方案 |
|---|---|---|
| 密码存储与爆破防护 | IdP 负责 | **平台负责** |
| MFA / 异常登录检测 | IdP 负责 | **平台负责（P3+）** |
| 密钥轮换 | IdP 负责 | **平台负责** |
| 账号生命周期 | IdP 负责 | **平台负责** |
| 合规认证（如等级保护） | 可依赖 IdP 资质 | **需自行承担** |

> ⚠️ **未成年人场景的放大效应**：本平台账号对应初中生及其监护人，
> 凭据泄露后果重于普通系统。**P3 前不得接入真实用户**，
> 仅限合成数据与受控试点（`deployment.pilot.max-tenants=1`）。

## 2. 职责边界

### 本设计做什么

```
POST /auth/token        账号密码 → 签发 JWT
GET  /auth/jwks         公开验签公钥
（拦截器）              每次请求验签 → 构造 TenantContext
（过滤器）              未认证 → 401
```

### 本设计**不**做什么（比「做什么」更能防越权）

| 不做 | 理由 |
|---|---|
| 密码找回 / 注册自助 | 涉及监护人同意流程（P3+），本期只做受控发号 |
| 刷新令牌（refresh token） | 引入令牌状态存储与撤销复杂度；本期 access token 短时效（默认 15 分钟） |
| MFA | 依赖外部短信/认证器，P3+ |
| 授权撤销的实时推送 | 当前靠 `authzVersion` 在**执行时**校验，已满足红线 9 |
| 多因素 / 设备指纹 | 无依据的复杂度 |

## 3. 数据模型（新增 V3 迁移）

### 3.1 `principal`（账号主体）

| 列 | 类型 | 说明 |
|---|---|---|
| `principal_id` | uuid PK | 与 JWT `sub` 一致 |
| `tenant_id` | uuid FK | 归属租户 |
| `login_name` | text UNIQUE | 登录名，**全局唯一**（跨租户唯一防撞名） |
| `password_hash` | text | Argon2id，**永不返回给任何调用方** |
| `display_name` | text | 内部标识，**不得含真实姓名**（DEC-6） |
| `status` | text | ACTIVE / DISABLED / LOCKED |
| `failed_attempts` | int | 连续失败次数，达阈值锁定 |
| `locked_until` | timestamptz | 锁定到期 |
| `authz_version` | bigint | 撤销授权时递增（对接红线 9） |
| `created_at` / `updated_at` | timestamptz | |

**约束**：
- CHECK：`login_name ~ '^[a-z0-9][a-z0-9._-]{2,63}$'`
- CHECK：`failed_attempts >= 0`
- RLS：与其他租户表一致，`tenant_id` 必带
- **禁止列**：邮箱、手机号、身份证号、真实姓名（PIPL）

> ⚠️ 自建认证最大的诱惑是「顺手加个邮箱方便找回密码」。
> 本表**结构上不提供**该列 —— 需要时须走 CHG 评审，而非 ALTER 顺手加。

### 3.2 为什么登录名全局唯一而非租户内唯一

若租户内唯一，`alice` 可存在于多个租户 → 用户混淆 + 枚举面扩大 +
运维易误判。全局唯一使「撞名」在发号阶段即暴露。

## 4. JWT 设计

### 4.1 声明结构

```json
{
  "iss": "https://auth.studykid.cn",
  "sub": "<principal_id>",
  "aud": "agent-platform",
  "iat": 1760000000,
  "exp": 1760000900,
  "jti": "<uuid>",
  "tenant_id": "<tenant_id>",
  "roles": ["STUDENT"],
  "authz_version": 3
}
```

### 4.2 签名算法：RS256（非 HS256）

**关键理由**：`HS256` 用**对称**密钥。若公钥接口 `/jwks` 也用同一密钥签发，
任何能读公钥的人都能**伪造 token**。RS256 的私钥只在服务端，公钥可公开。

> ⚠️ 常见错误实现：「JWT 用 HS256，密钥放在配置里」+「校验时用同一个密钥」
> —— 这在单机自建场景看似可行，但一旦将来接入多方验证（如网关预验证）
> 立即退化为可伪造。**本期直接上 RS256，避免后续返工。**

### 4.3 校验清单（缺一即拒）

| 项 | 规则 |
|---|---|
| 签名 | 必须有效 |
| `alg` | **必须等于 RS256**（防 `alg=none` 与算法混淆） |
| `iss` | 必须匹配配置 |
| `aud` | 必须包含配置值 |
| `exp` | 未过期 |
| `nbf` | 若存在须已生效 |
| `tenant_id` | 必须在库中存在且 `status='ACTIVE'` |
| `roles` | **必须在库中登记的角色白名单内**，未登记的忽略 |

> ⚠️ **`alg` 显式校验是最易漏的一步**：不校验时，攻击者可把
> `alg` 改为 `none` 去掉签名要求，或改为 `HS256` 用公钥当密钥。

## 5. 认证失败的处理

| 情形 | 响应 | 理由 |
|---|---|---|
| 缺少/格式错误的 Authorization 头 | 401 | 未认证 |
| 签名无效 / 过期 / `alg` 不符 | 401 | 未认证 |
| **token 有效但租户已停用** | 403 | **已认证但无权** —— 与 401 区分，语义不同 |
| **token 有效但账号 LOCKED** | 403 | 同上 |

> **401 与 403 必须可区分**：把「已认证但无权」报成 401，
> 会让客户端误以为「重新登录就能解决」，从而反复重试；
> 反之把认证失败报成 403，会掩盖凭据泄露问题。

### 错误消息不得包含

- 具体失败原因（签名无效 / 过期 / alg 不符）—— 便于攻击者调优
- `principalId` / `tenantId` —— 防枚举
- 任何 token 片段

统一返回：`{"error":"unauthorized"}`。

## 6. 防爆破机制

自建认证必须自建防护，否则账号会被撞库。

| 措施 | 阈值 | 理由 |
|---|---|---|
| 账号级锁定 | 连续 5 次失败 → 锁 15 分钟 | 单账号撞库 |
| 计数持久化 | 存 `principal.failed_attempts` | 内存计数重启即失效 |
| **响应恒定耗时** | 无论账号是否存在都做一次哈希校验 | **防用户名枚举** |

> ⚠️ **恒定耗时是最容易漏的一条**：若「用户不存在」直接返回快、
> 「密码错误」返回慢（因为要多跑一次 Argon2），攻击者可据此枚举有效账号。
> 因此**用户不存在时也必须跑一次 dummy 哈希验证**。

## 7. 已知限制（编码前预判）

| # | 限制 | 影响 | 何时处置 |
|---|---|---|---|
| 1 | **私钥来源**：本地由代码生成，生产由环境变量注入密钥库 | 生产需 KMS 对接 | P4 |
| 2 | **无 refresh token** | 15 分钟需重新登录 | P3（结合监护人同意流程） |
| 3 | **无 MFA** | 账号撞库风险 | P3+ |
| 4 | **无令牌撤销列表** | 已签发 token 在有效期内不可撤回 | **接受**：access token 15 分钟窗口，且执行时重新授权可拦截 |
| 5 | **单密钥无轮换** | 密钥泄露需紧急重签所有 token | P4（加 `kid` 支持多密钥） |
| 6 | **登录端点无速率限制** | 仅靠账号锁定，防分布式撞库不足 | **P3 必做**（网关层） |
| 7 | **自建认证的合规资质** | 未成年人场景可能需等级保护 | **须 zhouwei 评估**，非技术可解 |

> ⚠️ 限制 7 是**管理层决策项**，技术手段无法消解。
> 建议 P3 前与法务确认自建认证的资质要求。

## 8. 测试覆盖计划

| 分组 | 命题 |
|---|---|
| 签发 | 正确密码签发；错误密码拒绝；不存在的账号**耗时相同** |
| **验签** | 无签名拒绝 / **alg=none 拒绝** / **HS256 混淆拒绝** |
| | 过期拒绝 / 错误 iss 拒绝 / 错误 aud 拒绝 |
| **claims 映射** | tenantId/roles/authzVersion 正确映射 |
| | **未登记角色被忽略**（不因 JWT 写任意角色而提权） |
| **租户状态** | 租户停用 → 403（不是 401） |
| **执行时授权** | `authz_version` 落后 → 拒绝（红线 9 端到端） |
| 防爆破 | 连续失败触发锁定；锁定期间即使密码正确也拒绝 |
| **端到端** | 真实 HTTP 请求：未认证 401 → 认证后 200 → 越权 403 |

> ⚠️ **最易漏的测试点**：伪造 JWT 里的 `roles` 数组塞入 `TENANT_ADMIN`。
> 若服务端不与库中登记角色交叉校验，**任何用户都能自封管理员**。
> 这必须有专门的证伪用例。

| 既有约束 | 本设计如何满足 |
