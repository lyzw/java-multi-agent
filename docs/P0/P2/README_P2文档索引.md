## 设计文档须包含的章节

| 章节 | 说明 |
|---|---|
| **职责边界** | 做什么、**不做什么**（不做什么更能防越权） |
| **决策与理由** | 为什么这样设计，而非代码做了什么 |
| **执行链** | 各步骤顺序，以及**为何是这个顺序** |
| **失败与边界** | 失败时怎么办、哪些情况拒绝 |
| **测试覆盖** | 断言针对「不可绕过的性质」 |
| **已知限制** | 遗留问题、阻塞项，**不隐藏** |

> 最后一条最重要：**已知限制必须写进文档**。
> D1 就有一条硬限制（未接安全链时 `TenantContext` 可被伪造），
> 若不记录，后人可能误以为闸门已完备。
