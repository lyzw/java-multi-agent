# P2 一周执行计划

> **决定**（2026-10-19，zhouwei）：P2 排期压缩为 **1 周**。
> 本文档给出可执行拆解与**明确的取舍清单**。
>
> **原则**：宁可少做功能，**不可放松安全机制**。
> 安全机制一旦跳过，P3 的验证将失去意义，且风险会带到生产。

**状态**：D1–D4 已完成（**80%**），D5 待启动　**依据**：P1-10 重估门禁结论

## 1. ⚠️ 一周的现实评估

### 1.1 必须先说清楚的前提

| 事实 | 数据 |
|---|---|---|---|---|
| `agent-worker` | **0 个类**，完全从零 |
| `agent-api` | **0 个类**，完全从零 |
| P2 验收条目 | **13 项**（FR-001/002/003/004/005/007/008/010/014/017/018/020） |
| P1 主体耗时 | 1.5 天（**且主要是搭底座，无生产代码**） |

**P1 的速度不可外推**：底座已就位，但 P2 要做的是
Spring Boot 4.1 组件拼装 + MQ 消费 + 授权闸门 + SSE —— 不同性质的工作。

### 1.2 一周能做什么

按实测吞吐（P1 期间约 10 项任务/1.5 天，但那些任务平均较小），
一周（5 天）理论可完成 **15–20 个中等任务**。

P2 的 13 个验收条目中：
- **6 项**在 P1 已有基础（FR-003/004/005/007/010 部分）
- **7 项**需新建（FR-001/002/008/014/017/018/020）

**结论：一周「可能」做到，但前提是接受明确的范围削减。**
本文档 §3 给出削减清单。

## 3. ⚠️ 取舍清单（关键）

### 3.1 🔴 绝不可压缩（即使延期也不做）

| 项 | 理由 |
|---|---|---|---|---|
| **执行时授权闸门** | 跳过 = 权限撤销无效，是 Sev-0 |
| **fencing 校验** | 跳过 = 旧世代可覆盖新世代结果 |
| **工具执行前授权** | 模型可越权调用工具 |
| **租户上下文传递** | 全链路隔离的根基 |
| **配置 fail-closed** | 否则配置缺失会放行 |

> 这些是 P1 已验证过的机制，**P2 只是接入而非新建**，
> 接入成本低（约半天），但跳过会导致 P3 全部验证失效。

### 3.2 🟡 可延至 P3（一周内做不完的部分）

| 项 | 验收条目 | 延后理由 |
|---|---|---|---|---|
| SSE 续传（完整实现） | FR-014 | 游标过期协议可后补；先做最简订阅 |
| 可观测性指标 | FR-017 指标部分 | 日志脱敏已在 P1 完成，指标可后补 |
| 业务验收（SB-01～07） | FR-018 | 需评测集，属 P2 收尾但可顺延 |
| 输出无编造出处评测 | FR-020 | 评测集构建成本高 |

### 3.3 🟢 本周只做 Mock，不等真实依赖

| 项 | 本周做法 | 何时补真实实现 |
|---|---|---|---|---|
| `get_student_profile` | **只读 Mock Tool**（P0-D05 已允许） | D-007 契约就绪后 |
| `record_weakness` | Mock + 幂等语义完整实现 | 同上 |
| 身份认证 | **开发态固定身份**（仅本地） | D-001 接入时替换 |

> P0-D05 明确：「只读 Mock Tool 用于 PoC；
> 业务验收仍需真实工具或批准的沙箱」。
> 故 Mock 不阻塞 P2 技术闭环，但**阻塞 FR-018 业务验收**。

## 4. 一周内的风险与应对

| # | 风险 | 概率 | 应对 |
|---|---|---|---|---|
| 1 | **Spring Boot 4.1 生态踩坑** | 高 | ADR-011 已列影响面。优先写最小可跑路径，不要一次做全 |
| 2 | `@Retryable` 与自研重试双重重试 | 中 | **本周明确只用自研重试**，不引入 `@Retryable` |
| 3 | `ToolCallingAdvisor` 绕过授权 | 中 | 禁用自动执行路径，只用 `ToolCallback` 注册 |
| 4 | D-001/D-007 延期 | 中 | 用 Mock 顶上（§3.3），业务验收顺延 |
| 5 | 范围失控（一周做太多） | **高** | 每日检查 §3.1 红线，宁可砍功能 |

### 4.1 ⚠️ 最需要警惕的：范围失控

一周的诱惑是「什么都想做一点」。但 P1 的教训是：
**看似小的问题会击穿安全机制**（正则锚定、事务未关）。

建议：**每日结束时对照 §3.1 清单核查**，
若某项红线未落实，砍功能而非砍红线。

## 7. 与原建议的差异说明

P1-10 建议 **4–8 周**，实际决定 **1 周**。差异原因与应对：

| 差异 | 应对 |
|---|---|---|---|---|

条件为 §3.2 的四项延后项在 P3 补齐。
