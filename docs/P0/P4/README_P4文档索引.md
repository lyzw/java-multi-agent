> 从"没发生"变成"发生了但记错账"，后者更难发现且直触 Sev-0。

**⚠️ 本片最重要的方法论发现**：A-2 / A-5 反证**首跑全绿**——
`IdempotencyProtocolTest` 测的是**类本身**，闸门测试用 `allowAll()` 替身**根本不检查上下文内容**。
即「**被测单元正确，调用方传错参数，全绿照旧**」。
补 `ToolIdempotencyKeyTest` + `ToolGateAuthorizationContextTest`（**直接断言调用方传了什么**）后方可精确转红。
**这两项测试是本片真正的产出**——缺陷修复可回滚，缺了它们下个人重构会再挖同一个坑。

**诚实边界**：代码对齐 yml 既有声明（`WRITE_PROFILE: OPTIONAL`）而非反向；
「只能收紧不能放松」的合并在**策略类内部**完成（不能只靠装配层）；
`WRITE_EXTERNAL: REQUIRED` 仍最严；`PolicyEngineApprovalSource` 仍恒 `FAIL_CLOSED`（真实审批台未接入，**设计内安全状态**）；

**⚠️ 本片定位到 P4-D08 遗留的「根因未定位」：F-15 fat jar**

`platform-bootstrap` 下**每一个** `*IT` 类在 failsafe 中都报「Failed to find merged annotation for @BootstrapWith」，
而同类走 surefire 完全正常。根因：`spring-boot-maven-plugin:repackage` 把主构件替换成 **fat jar**
（类在 `BOOT-INF/classes/`，普通 classloader 读不到 `PlatformApplication`）
→ `@SpringBootTest(classes=…)` 内省抛 `TypeNotPresentException` → 元注解无法内省。

修法：`repackage` 挂 `<classifier>exec</classifier>` → 主构件保持 thin jar，胖包另出 `-exec.jar`。
效果：**本模块集成测试整体复活**（127 → 143）。

> 危害等级：高。它使本模块集成测试**整体失效**，而构建仍把其它模块报 SUCCESS
> —— 极易被误判为「测试写得不对」而改测试代码。

**诚实边界**（详见文档 §6）：L-1 真实模型接入前 G6 必返空画像 · L-2/L-3 G5/G7 未做 ·
L-4 `weaknesses` 结构化待前端改造 · L-5 前端占位假数据须整体替换 · L-6 `profile:read` 未授予任何角色 ·
L-7 未做真实模型端到端验证 · **L-8 文档待补**（fat-jar 根因应正式补入 §6，当前 `ReadEndpointIT` Javadoc 已引用 L-8 但文档只列到 L-7）。
