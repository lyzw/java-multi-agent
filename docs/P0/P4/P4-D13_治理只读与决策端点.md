## 1. 横切决策（四个端点共同遵守）

### 1.1 租户与 RLS

沿用 `JdbcRunQueryRepository` 的**双层铁律**，四处不得例外：

1. SQL **显式**携带 `tenant_id = ?`（第一道，RLS 被误删时仍能挡）；
2. 表上强制 RLS 策略（第二道，应用侧条件被误删时仍能挡）。

> ⚠️ 四张表（`run` / `approval` / `tool_operation` / `audit_record`）
> 在 `agent_it` 中**均已启用 forced RLS**，实测有效。

### 1.2 404 与 403 必须合并

单资源操作（批准/处置）返回 **404**，不区分「不存在」与「无权限」——
区分即构成**存在性探测通道**（同 `RunQueryController` 的既有立场）。

### 1.3 游标分页（keyset），不用 offset

FE-01 §P7 明确建议「游标分页，与 `Last-Event-ID` 语义一致」。

| 方案 | 评价 |
|---|---|
| **`OFFSET n`（页码）** | ❌ 深翻页时数据库要扫描并丢弃前 n 行；且**并发插入会导致行重复/漏读** |
| **keyset（游标）**（本片采用）| ✅ 无论翻到第几页都是索引区间扫描；并发插入不会让已翻过的行重复出现 |

**游标编码**：`base64url("<createdAt ISO>\|<id>")`，**不透明**（opaque）。
前端**不得解析**游标内容，只做原样回传——编码格式变更才不会打破前端。

**排序键**必须是**全序**（唯一）：
`(created_at, <主键>)`——单靠 `created_at` 排序在同毫秒多行时**不稳定**，
会让同一页出现重复/遗漏的行。

### 1.4 载荷白名单与敏感字段

| 表 | ⛔ 绝不返回 |
|---|---|
| `run` | `input_payload`（学生题目与解答）、`error_message`（内部细节）、`tenant_id`、`idempotency_key`、`request_digest` |
| `approval` | `tenant_id` |
| `tool_operation` | `tool_arguments`、`result_payload`（工具入参/回包）、`tenant_id` |
| `audit_record` | `tenant_id` |

### 1.5 限流

新增独立桶 **`GOVERNANCE_QUERY`**（列表/审批/审计查询）与 **`GOVERNANCE_DECIDE`**（决策）。
> ⚠️ **不新增桶的后果**：复用 `EVENT_QUERY`（30 次/60 秒）会与 FE-D9 已算满的
> 进度页轮询链（20 + 6 = 26 次/分）**共用同一配额** → 打开治理页会直接把进度页打挂。
> 这是 FE-D9 §2.3 配额表里「余量只有 4 次/分」的**直接后果**，必须分开计量。

| 桶 | 限额 | 用途 |
|---|---|---|
| `GOVERNANCE_QUERY` | 60 次 / 60 秒 | 四个只读列表 |
| `GOVERNANCE_DECIDE` | 30 次 / 60 秒 | 审批决定 / UNKNOWN 处置 |

### 1.6 限流拒绝的 HTTP 语义

`429` + `Retry-After`。⚠️ 限流组件故障（`FAIL_CLOSED`）**同样返回 429**，
**不得**降级为「放行」或「500」（后者会让前端误判为系统故障而重试风暴）。

## 2. G7 — Run 列表（游标分页）

### 2.1 契约

```
GET /api/runs?limit=20&cursor=<opaque>&state=<run_state>&createdFrom=<ISO>&createdTo=<ISO>
```

```jsonc
{
  "items": [
    { "runId":"…", "state":"SUCCEEDED", "createdAt":"…",
      "completedAt":"…", "attempt":1, "errorCode":null }
  ],
  "nextCursor": "eyJ…"     // 无更多时为 null
}
```

| 参数 | 默认 | 上限 | 非法值处理 |
|---|---|---|---|
| `limit` | 20 | **100** | 超限 → **400**（不静默截断，静默截断会让前端以为只有那么多）|
| `cursor` | 无 | — | **解不开 → 400**（不是 500，也不是忽略）|
| `state` | 全部 | — | **不在 `run_state` 枚举内 → 400** |
| `createdFrom` / `createdTo` | 无 | — | 解析失败 → 400；`from > to` → 400 |

> ⚠️ `run_state` 枚举为 `QUEUED/RUNNING/CANCELLED/SUCCEEDED/FAILED/TIMED_OUT`
> ——**不含 `UNKNOWN`**（P4-D10 §1.4 实测）。
> 因此 `state=UNKNOWN` 必须 **400**，不得静默返回空列表——
> 返回空列表会让运维以为「该状态不存在」，而真相是「这个状态就不存在」。

### 2.2 索引（V10 迁移）

```sql
CREATE INDEX idx_run_tenant_created
    ON run (tenant_id, created_at DESC, run_id DESC);
```
> 现有索引（`idx_run_state_queued` 等）都是**部分索引**且不含 `created_at`，
> 无法支撑按时间倒序的全量列表扫描。

## 3. G8 — 审批台

### 3.1 列表

```
GET /api/approvals?state=PENDING&limit=20&cursor=<opaque>
```

```jsonc
{ "items": [ {
      "approvalId":"…", "operationId":"…", "runId":"…",
      "state":"PENDING", "requirement":"REQUIRED",
      "argumentDigest":"sha256:…",      // ⛔ 是摘要，不是参数原文
      "targetResource":"profile/…",     // FR-014 要求展示的目标资源
      "approverScope":"TENANT", "expiresAt":"…",
      "approverId":null, "decidedAt":null, "createdAt":"…",
      "expired": false                  // ⚠️ 服务端算的显式标志
  } ], "nextCursor": null }
```

> ⚠️ **`expired` 必须由服务端算**并显式返回，不能让前端自己比较 `expiresAt` 与当前时间。
> 理由：前端时钟不可信（用户可改），且「过期」是**服务端裁决**——
> 前端算出「没过期」而后端拒绝，是最难排查的一类不一致。

### 3.2 决策

```
POST /api/approvals/{approvalId}/decision
{ "decision":"APPROVE"|"DENY", "reason":"…" }   // reason 仅 DENY 必填
```

| 情形 | HTTP | 处置 |
|---|---|---|
| 正常批准 | 200 | `ApprovalPort.grant` → state=APPROVED |
| 正常拒绝 | 200 | `ApprovalPort.revoke` → state=REJECTED |
| **已过期** | **409** | ⛔ **拒绝，不得批准**（FE-01：「过期/撤销须拒绝而非静默通过」）|
| 已消费 / 已决定 | **409** | 幂等拒绝，返回当前状态 |
| 不存在 / 非本租户 / 无权 | **404** | 合并（§1.2）|

> ⚠️ `approval.state` 有 DB 触发器 `enforce_approval_state_guard`，
> 非法跃迁会被数据库拒绝 → 实现必须走 `ApprovalPort` 而非直接 UPDATE。

### 3.3 审计

批准/拒绝**必须**写审计（`APPROVAL_GRANT` / `APPROVAL_REVOKE`）——
`JdbcApprovalRepository` 已有该行为，本片沿用。

## 4. G9 — UNKNOWN 处置台

### 4.1 列表

```
GET /api/operations?state=UNKNOWN&limit=20&cursor=<opaque>
```

```jsonc
{ "items": [ {
      "operationId":"…", "runId":"…", "toolName":"…",
      "riskLevel":"WRITE_PROFILE", "state":"UNKNOWN",
      "createdAt":"…", "updatedAt":"…",
      "reconciliationSource": null,          // P3-D03 自动对账来源；人工处置后为 "MANUAL"
      "manuallyDisposed": false
  } ], "nextCursor": null }
```

### 4.2 处置

```
POST /api/operations/{operationId}/disposition
{ "disposition":"RECONCILED_SUCCEEDED"|"RECONCILED_ABSENT"|"MANUAL_DISPOSED",
  "note":"…" }
```

| 处置值 | 语义 | 目标 state |
|---|---|---|
| `RECONCILED_SUCCEEDED` | 人工核实：副作用**已发生** | RECONCILED_SUCCEEDED |
| `RECONCILED_ABSENT` | 人工核实：副作用**未发生** | RECONCILED_ABSENT |
| `MANUAL_DISPOSED` | **无法判定**，人工结案归档 | MANUAL_DISPOSED |

> ⛔⛔ **本片不提供任何形式的「重试」**（FE-01 §P9：「禁止提供一键重试
> （盲目重放 = Sev-0）」）。
> 三个取值全部是**终态归档**，没有一条会把操作退回 `PENDING`/`IN_FLIGHT`。
> 这不是能力缺失，是**刻意的产品边界**。

| 情形 | HTTP |
|---|---|
| 正常处置 | 200 |
| **操作不是 `UNKNOWN` 态** | **409**（重复处置 / 已被自动对账）|
| 不存在 / 非本租户 / 无权 | 404 |

### 4.3 落库字段

更新 `state`、`reconciled_at`、`reconciliation_source='MANUAL'`、
`manual_disposed_by`、`manual_disposed_at`，并写审计。

## 5. G10 — 审计查询

### 5.1 契约

```
GET /api/audit?action=&resourceType=&resourceId=&from=&to=&limit=50&cursor=<opaque>
```

```jsonc
{ "items": [ {
      "auditId":"…", "actorId":"…", "action":"APPROVAL_GRANT",
      "resourceType":"approval", "resourceId":"…",
      "createdAt":"…", "detail": { "…": "…" }
  } ], "nextCursor": null }
```

> ⚠️ **`detail` 是否返回的裁决**：**返回**。
> 理由：`detail` 在**写入时**已由 `JdbcAuditRepository` 做过
> 「可识别信息扫描，命中即拒绝写」（F-9：按键豁免平台标识符）。
> 既然写入侧已保证不含学生信息，读出侧再一刀切掉会让审计页失去意义。
> **前提**：读出侧**不得**再拼接任何其他列进 `detail`。

### 5.2 安全约束

- `audit_record` 上有触发器 `forbid_audit_mutation`（**追加只读**）——
  本片**只读**，不提供任何删除/修改端点。
- 审计查询**自身**也要写审计（`AUDIT_READ`）——「谁查了审计」同样需要留痕。
  ⚠️ 避免自递归：审计查询的审计写入走 `recordAccess`（fail-open），不参与查询结果。

## 7. 测试计划与反证

| 用例 | 断言 |
|---|---|
| **G-1** | Run 列表按 `(created_at, run_id)` **全序**返回，同毫秒多行不重复不遗漏 |
| **G-2** | 游标翻页不重不漏；**并发插入新行不影响已翻页的结果** |

## 9. 已知限制（诚实边界）

| # | 限制 | 说明 |
|---|---|---|
| **L-1** | ⚠️ **审批批准仍不能驱动工具执行** | `PolicyEngineApprovalSource` 恒 `FAIL_CLOSED`；本片只让**人能看到并记录决定**，Worker 侧仍不消费人工审批 |
| **L-2** | ⚠️ **`run.error_code` 仍无写入方** | 列表的 `errorCode` 字段恒为 `null`（承自 P4-D12 L-1）|
| **L-3** | ⚠️ **无操作者身份（`actorId`）之外的审批人授权范围细化** | 授权沿用 `approval:consume` 动作级，未做到「只能审批自己 scope 的审批」|
| **L-4** | ⚠️ **游标不绑定筛选条件** | 换筛选条件后继续用旧游标会得到空页或错页；前端须在改筛选时**丢弃游标**（本片以测试锁定该用法，而非服务端拦截）|
| **L-5** | ⚠️ **审计查询无全文检索** | 仅等值/时间过滤；数据量大后需另排切片 |
