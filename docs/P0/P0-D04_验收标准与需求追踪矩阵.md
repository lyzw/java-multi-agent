## 1. 验收原则

- 验收条件必须可观察、可重复，避免“体验良好”“性能足够”等不可测表述。
- 每条 P0 需求至少有一条正向路径和一条关键失败/越权路径。
- 安全、一致性和副作用治理需求必须有自动化证据；截图或口头说明不能替代测试结果。
- 性能、容量、SLO、RPO/RTO 的数值需在 P1/P4 基于业务输入和目标环境确认，P0 不虚构阈值。
- 未通过项需登记缺陷 ID、严重度、负责人、修复日期和风险接受人；严重安全/数据一致性缺陷不能靠普通豁免进入生产。

### 2.1 AI 审查约束（DEC-7）

本项目测试与安全结论由独立 AI Agent（AG-QA / AG-SEC）出具，须满足：

- 审查方上下文**不得包含**实现过程、推理记录或设计草案（ISO-1）。
- 审查方输入仅限：需求 ID、代码、测试结果、运行日志、数据库断言（ISO-2）。
- 同一 Agent 不得在同一任务中同时承担 R 与 C/A（ISO-3）。
- **Sev-0 / Sev-1 结论须项目负责人 zhouwei 外部抽检复核，覆盖率 ≥ 30% 且必须包含全部 Sev-0 项**（ISO-5）；抽检记录归档至 P4-D09 风险接受单。
- 同基座模型存在相关盲区，Sev-0 判定**不得仅依赖 AI**，必须有自动化测试证据。

测试 ID 是项目内建议编号；P1 阶段应建立正式测试管理系统中的用例，并把本表中的占位 ID 映射到实际自动化测试。

## 4. 缺陷与豁免规则

| 严重度 | 示例 | 处理规则 |
|---|---|---|
| Sev-0/阻断 | 跨租户数据泄露、未授权副作用、UNKNOWN 被盲目重放、预算/审批可绕过 | 禁止进入生产；必须修复并复测 |
