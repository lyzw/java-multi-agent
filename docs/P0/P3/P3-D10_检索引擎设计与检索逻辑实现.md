## 1. Retrieval Engine 核心目标

G3 作为多租户 Agent 平台的**检索引擎层**，是连接 `Workspace Context` ↔ `Vector Knowledge Base` 的核心枢纽。其设计目标不是"召回更多内容",而是确保**检索结果的零信任传递**。

### 🎯 核心使命

| 能力 | 实现要求 | P3-D1 关联故障注入用例 |
|------|----------|------------------------|
| Workspace Context Retrieval | 基于租户上下文精准定位 `Run` | FI-RLS-001 (RLS 隔离) + FI-IDEM-001 |
| Vector Retrieval | 多向量混合召回，RAG 融合 | - |
| Ranking Logic | BERT+TF-IDF+RLS 三元组排序 | - |
| Zero-Trust Guardrail | RLS+TTL+Authority 三验证 | FI-LEASE-001 (fencing/token) |

### 2.1 混合检索策略 (Hybrid Retrieval)

```
┌─────────────────────────────────────────────────────────────────────┐
│                        G3 Retrieval Engine                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Workspace Context Input: tenant_id, runs, workspaces               │
│           ↓                                                           │
│   RLS Context Check ─►──────────────────→ Authority Triple Gate      │
│   (verify tenant isolation)                                          │
│           ↓                                                        ┌───────┐ │
│   Vector Search          │    TF-IDF Ranking       → 融合          │ Guard |
│   (vector_db.query)    +| (tf-idf.score)       │      Combine     │
│           ↘            │                       ↓                 │
│      [Retrieval Result]  └────────────┐        │                │
│                                       ▼         │               │
│                                    [ContextRecord] ←── P3-D10   │
|                                          G3 Retrieval Engine   |
```

### 2.2 三元组验证门限 (Authority Triple Gate)

| 组件 | 职责 | 失败模式 | P3-D1 注入对应 |
|------|------|----------|----------------|
| RLS Context | tenant_id 隔离检查 | 跨租户泄露 → RLS 隔离失效 | FI-RLS-001 |
| Vector Score | BERT 向量子相似度召回 | 相似但有毒内容误召回 | - |
| TTL Check | 向量过期时间 | 未清理旧向量索引 | FI-LEASE-001 (TTL) |

**门限逻辑**:  
```java
// retrievalResult = {vectorScore=0.85, id="Run-A", tenant_id="tenant-X"}
// Authority Triple:
//   RLS Check: tenant_id matches -> TRUE (✓)
//   Vector Score: semantic_score >= 0.75 -> TRUE (✓) 
//   TTL Check: last_updated < now - 90d -> TRUE (✓)

// If ANY fails, result = null; else pass to workspace context
```

## 6. Authority Triple Gate Implementation Details

### 6.1 Gate Check Logic - RLS Isolation

```java
public class RlsIsolationValidator {
    // G3 Retrieval Engine Guardrail: validate tenant isolation
    public boolean rlsCheck(String recordId, String expectedTenant) {
        // If tenant mismatch = null content returned
        if (!recordId.equals(expectedTenant)) {
            return false;  // Authority Triple Gate FAILED: RLS
        }
        return true;  // All gates passed → safe to retrieve
    }
}

// Example usage:
// retrievalServiceAuthorityTripleCheck(ContextRecord record) 
```

### 6.2 Gate Check Logic - TTL Validation

```java
public boolean ttlValidationCheck(ContextRecord record) {
    Instant now = Instant.now();
    long ageMinutes = Duration.between(record.lastUpdated(), now).toMinutes();
    
    // Default TTL: 90 days worth of minutes (P3-D4 retention policy)
    if (ageMinutes >= 90L * 24 * 60) {
        return false;  // TTL expired → null return
    }
    return true;
}
```

### 6.3 Gate Check Logic - Vector+TF-IDF Threshold

```java
public double calculateHybridScore(double vectorScore, double tfIdfScore) {
    return (vectorScore * 0.5) + (tfIdfScore * 0.5); // G3 defaults: 0.5 Vector + 0.5 TF-IDF
    // ⚠️ 伪代码示例：return 之后的阈值判断不可达，真实阈值校验见 RetrievalService 的 gate 逻辑
}
```

## 8. Retrieval Service API Contract Specification

### 8.1 RetrievalService Method Signatures

```java
// Primary retrieval with RLS isolation & Authority Triple Gate check
public RetrievalResult retrieveFromWorkspace(ContextRecord context) {
    // Gate 1: RLS Context Check (tenant_id validation)
    if (!validateRlsIsolation(context)) {
        return RetrievalResult.failed("RLS_ISOLATION_MISMATCH");
    }
    
    // Gate 2: TTL Validation (content age check)
    if (!ttlValid(context.lastUpdated())) {
        return RetrievalResult.failed("TTL_EXPIRED");
    }
    
    // Gate 3: Vector+TF-IDF Score Threshold
    double combinedScore = calculateHybrid(
        getVectorScore(context.embeddings(), 0.75f), 
        getTfIdfScore(context.terms())
    );
    
    if (combinedScore < 0.5) {
        return RetrievalResult.failed("SCORE_BELOW_THRESHOLD");
    }
    
    // All gates passed → authority_triple_passed=true
    return new RetrievalResult(true);
}

// Alternative interface with explicit authority triple flag
public boolean evaluateRetrievalAuthorityTripleGate(ContextRecord record) {
    if (!validateRlsIsolation(record)) return false;
    if (!ttlValid(record.updatedAt())) return false;
    
    // Check vector & tf-idf scores (G3 defaults: 75% minimum each)
    if (record.semanticScore < 0.7 || record.tfIdfScore < 0.7) {
        return false;
    }
    
    return true;  // Authority Triple Gate FULLY PASSED
}
```
