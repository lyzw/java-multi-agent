### 1.1 DEC-4 补充：版本锁定理由

- **Spring Boot 4.1.1**（2026-08-20 发布，OSS 支持至 2027-07-31）。**不选 4.0.x**：其 OSS 支持 2026-12-31 到期，仅剩 2 个月。
- 依据 v3.1 架构文档第 83 行原文 `Spring Boot 3.x`，本次变更属**架构基线偏离**，必须在 P1 阶段以 **ADR-011** 记录理由、影响面与回滚方案。
- 配套版本基线（Spring Boot 4.1 依赖矩阵）：Spring Framework 7.0.x、Spring Security 7.1、Jakarta EE 11、Jackson 3、Hibernate 7、Flyway 12.x、jOOQ 3.21+（需 Java 21）、Tomcat 11。

### 1.2 DEC-9 补充：成本与容量配置化

**注意**：配置化解决的是「后续谁来调」，**不解决「初始值是多少」**。配置项必须有初值，而初值本身是决策——否则系统在上线首日就可能因缺省过大而失控。故本决策同时给出**保守初值**与**调优路径**。

| 配置项 | 配置键（建议） | 保守初值 | 依据 | 调优时点 |
|---|---|---|---|---|
| 单 Run 成本上限 | `agent.run.max-cost-per-run` | ¥2.00 | 错题归因为单轮短任务，按 7 次模型调用 × 混合单价估算 | P4 实测 usage 后 |
| 单 Run 模型调用上限 | `agent.run.max-llm-calls` | 12 | 覆盖 5 步 Loop + 重试余量 | P2 评测集实测 |
| 单 Run 最大步数 | `agent.run.max-steps` | 20 | 防止异常循环；超出即失败并可解释 | P2 |
| 租户并发 Run 上限 | `agent.tenant.max-concurrent-runs` | 5 | 保守起步，防下游过载 | P4 压测后 |
| 试点租户数 | `deployment.pilot.max-tenants` | 1 | 灰度起步 | P5 灰度扩量 |
| RPO | `dr.rpo` | 24 小时 | 无外部约束时的保守值 | P4 演练后确认 |
| RTO | `dr.rto` | 4 小时 | 同上 | P4 演练后确认 |

**配置化带来的三个必须处理的副作用**（否则配置化会变成新的风险源）：

| 副作用 | 处置 | 关联 |
|---|---|---|
| 配置错误导致预算失控或误拒 | 预算预留/结算仍以 **DB 原子条件更新**为准，配置只作上限输入；配置缺失时**拒绝而非放行**（fail-closed） | FR-012、R-007 |
| 运行中改配置导致同一 Run 前后不一致 | **Run 创建时快照配置值**并写入 ExecutionSnapshot，改配置只影响新 Run | FR-002 不可变快照 |
| 配置被当成绕过安全门禁的后门 | 高风险阈值（成本上限、并发上限）变更须走 **CHG 模板 + 审计留痕**；未成年人相关配置**禁止运行时下调保护强度** | P0-D03 §6、ISO-5 |

### 1.3 DEC-10 补充：零保留确认的延后与硬闸门

允许延后确认，但**延后不等于无约束**。设置以下硬闸门：

| 闸门 | 规则 | 违反后果 |
|---|---|---|
| GATE-1 | **P1 阶段全部使用模拟/合成数据**，禁止任何真实学生数据进入 Prompt | P1 门禁不通过 |
| GATE-2 | 真实学生数据接入前，**必须**取得供应商零保留书面条款或确认使用境内实例 | 禁止接入，业务验收延期 |
| GATE-3 | 确认截止点：**W2 D5（M1 门禁）**。逾期未确认则 P2 阶段仅用模拟数据做技术闭环，业务验收顺延至确认完成 | P2 退出条件记 `Accepted with conditions` |

> 该闸门设计与 P0-D05 R-017、A-009 联动；**不允许以「稍后确认」为由在 P1/P2 直接接入真实学生数据**。

### 1.4 DEC-11 补充：审批策略配置化

`record_weakness` 是否需审批，改为**由工具风险级别配置驱动**，而非硬编码：

| 配置项 | 配置键（建议） | 初值 | 说明 |
|---|---|---|---|
| 工具风险级别映射 | `agent.tool.risk-level-map` | `record_weakness=WRITE_PROFILE` | 风险级别枚举：`READ` / `WRITE_PROFILE` / `WRITE_EXTERNAL` |
| 审批触发矩阵 | `agent.approval.required-by-risk` | `WRITE_EXTERNAL=REQUIRED`，`WRITE_PROFILE=OPTIONAL`，`READ=NOT_REQUIRED` | 三档：REQUIRED / OPTIONAL / NOT_REQUIRED |
| 审批有效期 | `agent.approval.ttl` | 15 分钟 | 过期拒绝 |
| 审批人范围 | `agent.approval.approver-scope` | 家长或教师 | 与 DEC-6 角色一致 |

**配置化的关键约束**：审批策略**只能收紧、不能放松**。任何将 `WRITE_EXTERNAL` 从 `REQUIRED` 调为非 REQUIRED 的变更，属**安全门禁降级**，必须走 P0-D03 §6 范围变更模板 + ISO-5 外部抽检，不得作为普通配置调整处理。

> 这样设计的好处：首期 `record_weakness` 可按 `OPTIONAL` 快速跑通闭环（不阻塞 P2），同时 P3 验证审批/取消竞态时只需把配置切为 `REQUIRED` 即可，**无需改代码**。

### 1.5 DEC-12 补充：主 MQ 选型（轻量级诉求）

**RabbitMQ 4.3.6 社区版 + Quorum Queue**，不采用 Kafka、不采用 NATS，**禁止双栈**。

选型前提须先厘清：本项目 **MQ 只作唤醒信号**，Worker 按数据库状态与租户上下文领取任务，权威事实源永远是 PostgreSQL（P0-D03 §4 红线 1）。因此实际要求只有 at-least-once、幂等消费、死信、积压可观测、低资源占用五项，而非高吞吐日志流。

| 项 | 值 |
|---|---|
| 版本 | 4.3.6（当前唯一仍在社区支持期的 4.x 分支） |
| 队列类型 | **Quorum Queue**（唯一具备 Raft 复制能力） |
| Erlang/OTP | 25.0+ |
| 元数据存储 | Khepri（4.3 起唯一，Mnesia 已移除） |
| `x-delivery-limit` | **3**（显式设置；quorum 默认 20，对有副作用工具风险过高） |
| 社区支持截止 | **2026-11-30**，覆盖 P0～P3 |
| 商业支持截止 | 2028-04-30（未采购） |

**已接受的支持窗口风险**：项目负责人 DEC-12 决定采用社区版并接受该窗口。相应义务——P4 生产准入（2027-01）前须评估 RabbitMQ 4.4；停维后无免费 CVE 补丁，须在 P4 安全复核登记残余风险；跨大版本升级需停机窗口演练。

完整论证、队列拓扑与消息体规范见 **ADR-001**。

### 1.6 DEC-13 补充：PostgreSQL 版本

**PostgreSQL 17**（当前小版本 17.x），支持至 2029-11-08。

| 版本 | 状态 | 结论 |
|---|---|---|
| 18 | 最新（18.6），仅 13 个月 | 偏新，本项目用不上其新特性 |
| **17** | 主流，24 个月生产验证 | ✅ **选用**，项目 2027-02 结束后仍余 2.75 年 |
| 16 | 部署面广但窗口短 | 备选 |
| 15 | 2027-11 EOL | 排除 |
| 14 | **2026-11-12 EOL** | 排除 |

**本项目所需能力在 17 上全部具备**：`FOR UPDATE SKIP LOCKED`（Worker 领取）、RLS（租户隔离）、`MERGE`（PG 15+，状态迁移）、jsonb。

PG 18 的特性（并行 FULL/RIGHT OUTER JOIN、standby 逻辑复制）对本项目无直接价值：前者我们无此查询形态，后者仅 P4 做只读副本时才可能用到。

## 2. AI 全角色承担的责任模型（DEC-1 + DEC-7）

### 2.1 角色映射

每个角色由**独立 AI Agent 实例**承担，上下文与记忆互相隔离：

| 角色 | Agent 代号 | 职责 | 与实现工作的隔离要求 |
|---|---|---|---|
| 业务负责人 | AG-BUS | 业务价值、场景验收、风险接受 | 只读需求与验收证据，不参与实现 |
| 产品负责人 | AG-PO | 范围、优先级、验收口径 | 不参与实现 |
| 项目经理 | AG-PM | 计划、依赖、风险、会议、状态 | 不参与实现 |
| 架构负责人 | AG-ARC | 架构一致性、ADR、模块边界 | 可参与设计，**不审查自己的设计决策** |
| 后端负责人 | AG-BE | Java 服务、数据模型、执行引擎 | 实现方 |
| AI/模型接入 | AG-AI | ModelGateway、评测、模型策略 | 实现方 |
| 测试负责人 | AG-QA | 测试策略、追踪矩阵、验收证据 | **独立上下文，无实现过程可见性** |
| 安全负责人 | AG-SEC | 威胁模型、权限、租户隔离、密钥 | **独立上下文，无实现过程可见性** |
| 运维/平台 | AG-SRE | CI/CD、监控、部署、备份 | 实现方 |
| 外部系统/IAM | — | 由项目负责人直接提供资源 | 无独立 Agent |

**项目负责人（zhouwei）**：业务决策最终责任人、高风险风险接受人、生产准入批准、外部季度抽检执行人。

### 2.2 强制隔离规则（回应 P0-D06 §5 利益冲突条款）

| 规则 | 内容 | 违反后果 |
|---|---|---|
| ISO-1 | AG-QA / AG-SEC 的上下文**不得包含** AG-BE / AG-AI / AG-SRE 的实现过程、推理记录或设计草案 | 审查结论作废，任务退回 |
| ISO-2 | 审查方输入仅限：需求 ID、代码、测试结果、运行日志、数据库断言 | 同上 |
| ISO-3 | 同一 Agent 不得在同一任务中同时承担 R 与 C/A | DoD 不通过 |
| ISO-4 | AG-ARC 设计的协议由 AG-QA + AG-SEC 交叉审查，AG-ARC 不得自审 | 门禁不通过 |
| ISO-5 | **Sev-0 / Sev-1 结论每阶段需项目负责人外部抽检复核**，抽检比例 ≥ 30% 且必须包含全部 Sev-0 项 | 阶段门禁不通过 |

### 2.3 残余风险声明

同基座模型存在**相关盲区**：AG-SEC 与 AG-BE 若基于同一模型，可能共享同类错误。因此：

- Sev-0（跨租户泄露、未授权副作用、UNKNOWN 盲目重放、预算/审批绕过）的判定**不得仅依赖 AI**，须有自动化测试证据 + 项目负责人抽检。
- ISO-5 的季度抽检是**补偿控制**，不是形式要求；抽检记录须归档至 P4-D09 风险接受单。

## 3. 首个业务场景定义（DEC-2 + DEC-5）

### 3.1 场景定义：初中生错题归因与个性化辅导

> **无知识库依赖**：Agent 使用模型**参数内知识**（parametric knowledge）进行分析，**不做教材/题库向量检索**。这是 DEC-5「首期不做 RAG」的技术含义——不引入向量库、不做文档切分入库，模型不引用外部教材原文。

| 字段 | 内容 |
|---|---|
| 场景 ID | BR-01 / AT-BIZ-001 |
| 目标用户 | 初中生（12–18 岁），由家长/教师代为发起 |
| 触发方式 | 学生提交一道错题：题目文本 + 自己的解题过程 + 已知正确答案 |
| Agent 工作 | ① 读取学习画像 → ② 归因分析 → ③ 生成讲解 → ④ 记录薄弱点 → ⑤ 返回结构化结果 |
| 输出 | 归因结论、错因讲解、可执行解题步骤、薄弱点更新结果 |
| 失败后处理 | 学生重试；连续 3 次失败转人工教师；薄弱点记录进入待核对队列 |

### 3.2 工具清单

| 工具 | 类型 | 副作用 | 幂等键 | 授权要求 |
|---|---|---|---|---|
| `get_student_profile` | 只读 | 无 | — | 学生仅可读本人画像 |
| `record_weakness` | **有副作用** | 写入薄弱点 | `student_id + run_id + knowledge_point` | 仅本人；执行时重新授权 |

> **设计意图**：`record_weakness` 是首期**唯一的有副作用工具**，用于实证验证 P0-D03 §4 红线 4/5/7（Attempt 区分、fencing、UNKNOWN 对账）与风险 R-003/R-007/R-008。它使最高风险协议有真实场景承载，而非玩具验证。

### 3.3 成功判定（业务验收标准）

| 编号 | 指标 | 阈值 | 验证方式 |
|---|---|---|---|
| SB-01 | 错因归因准确率 | ≥ 80% | 人工评审 20 题标注样本 |
| SB-02 | 讲解可执行性 | 平均评分 ≥ 4/5 | 教师人工评分量表 |
| SB-03 | 薄弱点记录准确率 | ≥ 85% | 与人工标注对比 |
| SB-04 | 跨用户数据隔离 | 100% 拒绝 | 自动化安全测试 AT-TENANT-001/002 |
| SB-05 | 响应时延 | P95 ≤ 30s | 性能基线（P4 复核） |
| SB-06 | 幂等正确性 | 同键重复调用不产生重复薄弱点 | 并发集成测试 AT-IDEM-001/002 |
| SB-07 | UNKNOWN 不盲重放 | 0 次盲目重放 | 故障注入 AT-UNKNOWN-001 |

### 3.4 失败判定（触发 Sev-0/Sev-1）

- 编造不存在的知识点或引用不存在的资料出处
- 归因错误导致学生形成错误认知
- 画像数据泄露给其他学生
- 重复记录导致薄弱点虚高（污染后续推荐）
- 生成内容违反未成年人内容安全要求

### 3.5 明确排除

- 不做教材原文引用与页码定位（依赖 RAG，DEC-5 排除）
- 不做题目检索/推荐（依赖题库，DEC-5 排除）
- 不做作业批改与打分（涉及评分公平性与申诉链路，另立需求）
- 不做实时在线辅导（并发与延迟约束超出首期容量基线）

## 4. 未成年人数据合规基线（DEC-6）

### 4.1 采集白名单（仅此三类可采集）

| 数据项 | 用途 | 保留期 |
|---|---|---|
| 随机 `student_id`（不可反推身份） | 主体标识 | 账号存续期 + 12 个月 |
| 年级、学科 | 匹配学段讲解深度 | 12 个月 |
| 薄弱点（知识点 + 错误类型） | 个性化与归因 | 12 个月 |

### 4.2 禁止采集（硬红线）

姓名、学校、班级、身份证号、手机号、精确地理位置、面部/声纹、生物识别、社交账号、家庭经济状况。

### 4.3 法定义务（依据《个人信息保护法》第 31 条）

不满十四周岁未成年人的个人信息属于**敏感个人信息**，处理须满足：

| 义务 | 实现要求 | 证据 |
|---|---|---|
| 监护人单独同意 | 同意书留痕：时间、版本、范围、撤回方式 | 同意记录表 + 版本化文本 |
| 专门处理规则 | 本节即为专门规则，需随功能变更同步更新 | P4-D10 |
| 单独同意可撤回 | 提供撤回入口；撤回后 30 日内删除画像 | 删除工单 + 日志 |
| 不用于模型训练 | 供应商须支持零保留（zero-retention）或使用境内实例 | 供应商条款 + 配置证据 |
| 数据不出境 | 全链路境内，Prompt 与工具结果分离存储 | 架构说明 + 网络策略 |

### 4.4 数据保留与分离

| 数据 | 保留期 | 存储位置 |
|---|---|---|
| 学习画像 | 12 个月 | 主库（租户隔离） |
| Prompt / 工具结果 | 90 天 | 对象存储（每次读取重新授权） |
| 审计日志 | 180 天 | 审计库（脱敏，不含 Prompt 原文） |
| Trace / 指标 | 30 天 | 观测系统（不含高基数与敏感标签） |

> 数值需业务与安全负责人在 P0-C8 确认（P1-D07 冻结 ADR-007/009/010）。

## 5. 外部依赖提供方式（DEC-3）

D-001～D-010 全部由项目负责人直接提供。**提供即视为该依赖无外部排期风险**，但仍须登记版本、连接方式与容量边界，避免 ADR 缺少输入。

| ID | 依赖 | 需提供内容 | 需明确的边界 |
|---|---|---|---|
| D-001 | IAM/OIDC | issuer、客户端/服务账号、claims 结构、测试用户与角色 | 生产身份治理不可由本地测试身份替代 |
| D-002 | 模型服务 | API 访问、配额、数据处理条款、**零保留确认** | 须确认不用于训练、数据不出境 |
| D-003 | 主 MQ | Kafka/RabbitMQ 二选一、连接/权限、监控 | ADR-001 决策输入 |
| D-004 | PostgreSQL | 版本、HA、备份、连接池、迁移权限 | 本地容器仅开发验证 |
| D-005 | Redis | 版本、HA、访问策略 | 不作为唯一任务状态存储 |
| D-006 | 对象存储 | bucket、身份授权、签名 URL、生命周期 | 初期限制大文件功能 |
| D-007 | 业务 API/工具 | `get_student_profile` / `record_weakness` 契约 | 幂等与查询能力必须具备 |
| D-008 | 密钥服务 | 应用身份、注入方式、轮换流程 | 禁止提交仓库/日志 |
| D-009 | CI/CD | Runner、权限、镜像扫描、部署环境 | 本地构建不可替代上线流水线 |
| D-010 | 安全/合规评审 | 数据分类、威胁模型、隐私与保留要求 | 未确认前不接入真实学生数据 |

## 6. 技术基线变更影响（DEC-4 → ADR-011）

Spring Boot 4.1 相对 3.x 的变更对本项目有**正向复用**与**必须适配**两类：

### 6.1 可直接复用的能力（降低工作量）

| 能力 | 复用阶段 | 对应原计划任务 |
|---|---|---|
| `InetAddressFilter` HTTP 客户端 SSRF 防护（DNS 前拦截私网/元数据地址） | P3 | P3-09 Egress/SSRF |
| `@ConcurrencyLimit` 并发上限 | P3/P4 | P4-05 限流与过载保护 |
| `@Retryable` 内置重试 | P2 | ModelGateway 重试 |
| OpenTelemetry Starter（Kafka/RabbitMQ/JVM 自动装配） | P4 | P4-03 可观测性 |
| API 版本控制（MVC/WebFlux） | P2 | P1-D06 错误码与版本策略 |
| `RestTestClient` | P2 | P2-D07 测试计划 |
| JSpecify null-safety（全栈） | P2 | P1-D01 模块边界静态约束 |

### 6.2 必须适配的破坏性变更

| 变更 | 影响 | 应对 |
|---|---|---|
| **Jackson 3**（Jackson 2 移除） | 事件序列化、ToolOperation 账本、API 契约 | 序列化层统一适配；契约测试重写 |
| **Spring Security 7** 全组件化，`WebSecurityConfigurerAdapter` 移除 | 认证授权链、TenantContext 注入 | P1-04 重新设计安全配置 |
| 模块化 70+ starter | 依赖管理、classpath 假设 | 只引入显式模块 starter，禁依赖 classpath 扫描假设 |
| Hibernate 7 / JSpecify | 领域层空值语义 | 领域层用 `@NullMarked` 显式声明 |
| 内置 retry/concurrency | 与自研重试可能重复 | 明确单一重试点，禁止双重重试 |
| Flyway 12.x | 迁移脚本兼容性 | P1-08 迁移规范按新版重写 |

### 6.3 ModelGateway 与 Spring AI 2.0 的边界

Spring AI 2.0 要求 Java 21 + Spring Boot 4.x，与本基线**天然对齐**，且统一 `ChatClient` 抽象有利于满足 v3.1「领域层不依赖框架专属类型」。

**但必须遵守**：Spring AI 2.0 移除了内置工具执行循环，工具不再按 Bean 名自动解析，须显式注册 `ToolCallback`。本项目应**利用**该约束——在 `ToolCallback` 注册环节插入服务端授权、Schema 校验与 `ToolOperation` 账本写入，从架构上保证「模型不能绕过服务端授权直接执行工具」（P0-D03 §2 不可妥协边界）。

> 该设计决策须在 **ADR-011** 中与 ModelGateway 抽象边界一并记录。

## 7. 排期重估机制（DEC-8）

18 周基线基于人类团队估算，AI 全角色承担后**不直接沿用**，改为两段式：

| 段落 | 周期 | 产出 | 决策 |
|---|---|---|---|
| 段一：P0 收口 + P1 架构验证 | 第 1–2 周 | 六份基线文档 + PoC 量化数据 + ADR-001～011 | 保持原计划 |
| 段二：重估 | W2 D5 | 基于实测 AI 吞吐（任务/周、Review 耗时、返工率）重估 P2–P5 | **P1-10 门禁评审时决定** |

重估输入数据项：每角色 Agent 实际吞吐、单任务 Review 耗时、返工率、PoC 暴露的协议风险数、外部依赖实际就绪时间。

> 重估只允许**调整排期或资源**，不允许通过削减安全/一致性验收项追赶进度（P0-D06 §9）。
