5计划调整规则与升级机制

5.1 预测与纠偏（P0-D06 §9）

每周基于实际吞吐与依赖状态更新预测完成日期（周五站会后发布）
延迟 > 2 工作日关键路径任务延迟超 2 个工作日 → PM 组织影响评估，三选一：范围调整 / 资源调整 / 里程碑重排
硬性禁止不通过减少安全/一致性验收项「追赶进度」
门禁未过记 Blocked 或 Accepted with conditions，须写明批准人、限制范围、复审日期
1 个工作日发现重大阻塞后 1 个工作日内登记（P0-D01 §5）；超 SLA 未解则升级至项目负责人

5.2 立即升级 / 阻断条件（P0-D05 §5）

  • 高风险无 owner 或无到期日 → 升级为项目阻塞
  • 外部依赖预计延误超 2 个工作日 → PM 提出替代路径与排期影响
  • 发生跨租户泄漏 / 秘密泄漏 / 未授权副作用 / UNKNOWN 盲目重放 → 立即阻断相关路径并升级安全 + 技术负责人
  • 风险接受必须记录接受人、范围、补偿控制、到期日、复审条件，不得永久豁免
  • Sev-0（跨租户泄露、未授权副作用、UNKNOWN 盲重放、预算/审批可绕过）禁止进入生产

5.3 任务级 DoR / DoD 门禁（P0-D06 §7 / §8，沿用不修改）

Definition of Ready（开工前必须满足）

  1. 有任务 ID、目标、范围和唯一 DRI
  2. 有可验证验收条件与关联需求 ID
  3. 前置依赖、测试数据、权限和环境已准备或有明确计划
  4. API/DDL/状态机/安全影响已识别；涉未决架构决策先建 ADR/验证任务
  5. 估算和目标 Sprint 明确

Definition of Done（完成需同时满足）

  1. 代码合并且经过非作者 Review
  2. 单元/集成/契约/安全测试通过，证据可定位
  3. API、DDL、状态机、配置、运维文档同步更新
  4. 日志、指标、Trace、审计与错误分类满足需求
  5. 数据迁移已在目标版本验证，失败处理/前向修复明确
  6. 涉副作用时幂等、超时、重试、UNKNOWN/对账语义有测试
  7. 涉权限时含授权成功 + 越权拒绝测试
  8. 未完成项、风险、临时开关、回滚方式被明确记录
