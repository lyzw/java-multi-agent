## 1. 项目背景

建设一套基于 Java 的企业级 SaaS Agent 平台，为授权租户提供 Agent 配置与版本管理、异步任务执行、模型与工具调用、执行轨迹查询、权限与审批、预算计量和运行治理能力。平台以 PostgreSQL 中的持久化状态作为执行事实源，通过 Outbox/MQ 驱动异步任务，使用 Worker 执行任务，并以工具操作账本、幂等协议和 UNKNOWN 对账控制外部副作用风险。

**业务背景（DEC-2 已确认首个场景，详见 P0-D00 §3）：**
- **首个业务场景**：初中生错题归因与个性化辅导。学生提交错题（题目 + 自己的解题过程 + 正确答案），Agent 归因错因、生成可执行讲解、记录薄弱点。
- 当前业务痛点：错题归因依赖人工教师批改，成本高、时效低；通用答疑产品只给答案，不定位知识薄弱点，无法形成个性化改进路径。
- 目标用户：初中生（12–18 岁），由家长或教师代为发起。
- 当前替代流程与成本：教师人工批改 + 逐题讲评，按每题 3–5 分钟估算，无法规模化覆盖。
- 为什么需要 Agent 而非规则服务：错因归因需结合学生解题过程的语义理解与多步推理，规则无法覆盖；且需在读取画像、生成讲解、记录薄弱点之间保持上下文一致与授权正确。
- **明确不做（DEC-5）**：不做教材/题库向量检索（RAG），使用模型参数内知识，不引用外部资料原文。

**合规约束（DEC-6）**：场景涉及未成年人，采集白名单仅限随机 student_id、年级、学科、薄弱点；禁止姓名/学校/班级/联系方式等直接身份信息；须满足《个人信息保护法》第 31 条监护人单独同意。详见 P0-D00 §4。

## 2. 项目目标

### 2.1 产品目标

1. 提供 Agent 草稿、版本、校验、发布和不可变执行快照能力。
2. 提供异步 Run 的创建、查询、取消、受控重试、结果读取与事件轨迹。
3. 支持单 Agent Loop、模型接入抽象、上下文组装及至少一个经授权的业务工具。
4. 对工具参数进行 Schema 校验，并在执行时实施服务端授权。
5. 对有副作用的工具建立持久化操作账本、幂等约束、UNKNOWN 状态和可审计对账路径。
6. 建立多租户隔离、预算预留/结算、审批、事件续传和基本可观测性基础。

### 2.2 工程目标

- 新开发人员能依照工程文档在本地构建、运行测试。
- 核心执行链路可通过日志、Trace、Run/Step/ToolOperation 记录定位。
- 状态迁移有并发守卫；数据库迁移可重复执行并有失败处理方案。
- 高风险失败场景有自动化测试证据，而不是只依赖人工演示。

## 3. 项目范围概要

### 包含

- Agent 定义、版本、发布和执行快照。
- Run 创建/查询/取消/受控重试、步骤与事件持久化。
- 单 Agent 执行循环、ModelGateway、ContextAssembler。
- Tool SPI、输入输出 Schema 校验、执行时授权和调用记录。
- PostgreSQL + Outbox + 单一主 MQ + Worker 的异步执行链路。
- 基础租户上下文、资源授权、RLS 验证和跨租户测试。
- 预算预留、使用量结算、审批消费与取消竞态的设计和验证。
- UNKNOWN 对账、事件/SSE 续传、审计、指标和基础运维文档。

### 不包含（首期）

- 通用多 Agent 编排或通用 DAG 引擎。
- 插件市场、任意脚本执行和不可信插件沙箱。
- 完整商业账单/发票系统。
- 通用 BPM 审批中心。
- 未经容量测试承诺固定吞吐量或 SLA。
- 无业务证据支持的 RAG、知识库或复杂多模态能力。

具体范围以 P0-D03 批准版本为准。

### 决策机制

- 日常需求与任务优先级：产品负责人提出，项目经理协调。
- 架构/技术选型：形成 ADR，由架构负责人组织评审，技术负责人批准。
- 范围增加：必须说明业务价值、工期/成本影响、风险和被挤出的工作，经产品及项目负责人批准。
- 高风险安全例外：必须有书面风险接受人、期限、补偿措施，不允许以口头同意替代。
- 重大阻塞：责任人发现后 1 个工作日内登记；超过约定 SLA 未解决则升级到项目负责人。

## 6. 项目成功定义

项目成功需同时满足：

1. 业务：首个真实业务任务及目标用户得到明确确认，试点结果可衡量。
2. 功能：P0-D04 中列为首期必须的需求全部通过验收，或经正式批准豁免。
3. 安全：不存在未批准的严重/高危安全问题；跨租户、授权、秘密管理测试通过。
4. 可靠性：UNKNOWN 不被盲目重放；旧 fencing 世代不能提交结果；预算与审批竞态有验证证据。
5. 运维：告警、恢复、备份、回滚、责任人和升级路径已验证。
6. 交付：代码、测试、文档、部署配置和运维知识均有可追溯版本。
