# P1-08 威胁模型

> **范围**：P1 已实现的安全控制面。API 入口与 Worker 尚未实现（P2），
> 其攻击面按**设计约束**记录，不宣称已有防护。
>
> **方法**：STRIDE，信任边界显式标注。
>
> **原则**：只登记**已在代码或数据库中实际存在**的防护。
> 设计意图与已实现防护严格区分 —— 否则文档会给出虚假的安全感。

**版本**：v1.0　**更新**：2026-10-19　**阶段**：P1 退门前

---

## 1. 资产分级

按泄露后果排序，而非按技术类型：

| 级别 | 资产 | 后果 |
|---|---|---|
| **S0 极高** | 未成年人真实数据（题目、薄弱点、错题记录） | 合规违规 + 隐私泄露，**不可撤回** |
| **S0 极高** | 模型 API 凭据 | 冒用计费 + 可能用于探测模型安全策略 |
| **S1 高** | 跨租户数据 | 客户间数据泄露 |
| **S1 高** | 审批决策记录 | 合规流程失效 |
| **S2 中** | 预算与用量 | 成本失控 |
| **S3 低** | 运行指标与日志 | 运维可见性 |

> S0 之所以是「不可撤回」：数据一旦出境或被用于训练，
> 无论后续如何补救，都已发生。**这决定了缓解策略必须偏保守。**

## 2. 信任边界

```
┌─ 边界 B1：公网 / 租户 ──────────────────────────────────┐
│  [家长/教师客户端]                                       │
│      │ 不可信输入                                        │
└──────┼───────────────────────────────────────────────────┘
       ▼
┌─ 边界 B2：应用进程 ─────────────────────────────────────┐
│  agent-api  →  agent-application  →  agent-core         │
│  （未实现）    （用例编排）            （领域规则）        │
│                    ↕                                     │
│              agent-infrastructure                        │
└──────┼───────────────────────────────────────────────────┘
       ▼
┌─ 边界 B3：数据库（PostgreSQL 17）───────────────────────┐
│  RLS 策略 + 触发器 + CHECK 约束                          │
│  ⚠️ 权威安全边界 —— 应用层绕过也无法突破                 │
└──────────────────────────────────────────────────────────┘

┌─ 边界 B4：外部模型服务（deepseek/minimax/workbuddy）───┐
│  出站 HTTP —— 数据流向不可控区                           │
└──────────────────────────────────────────────────────────┘

┌─ 边界 B5：消息中间件（RabbitMQ 4.3.6 Quorum）───────────┐
│  消息一旦投递，难以精确删除                               │
└──────────────────────────────────────────────────────────┘
```

**关键判断**：**B3 是最后一道可信边界**。
B2 以上的所有防护都可能因代码缺陷失效，但 B3 由数据库强制执行，
不受应用逻辑正确性影响。这是本项目把安全不变量下沉到 DB 的根本理由。

## 3. STRIDE 分析

### 3.1 Spoofing（身份伪造）

| # | 威胁 | 场景 | 已有缓解 | 残余风险 |
|---|---|---|---|---|
| S-1 | 伪造 `tenant_id` | 客户端在请求中携带他人租户标识 | `TenantContext` 不可变；`tenant_id` 取自认证上下文而非请求参数；RLS 以 DB 会话变量为准 | **D-001 IAM 未接入**：当前无真实认证，接入前无法验证 |
| S-2 | 冒用模型凭据 | 泄露 API Key 后调用模型 | `CredentialRedactor` 脱敏日志与异常；口令经 `${ENV:}` 注入 | 凭据一旦进入日志即无法撤回 → **D-008 KMS 待接入** |
| S-3 | 提升权限 | 低权限主体执行高风险动作 | `AuthorizationService` 默认拒绝（未登记动作/角色一律拒）；执行时重新授权 | Spring Security 7 认证链待设计（ADR-011） |

> **S-1 的关键设计**：`tenant_id` 永不信赖客户端输入。
> 改用别的租户标识不会改变 RLS 判定结果 —— 因为 RLS 读的是
> 应用在事务开始时设置的会话变量，而非请求体。

### 3.2 Tampering（篡改）

| # | 威胁 | 场景 | 已有缓解 | 残余风险 |
|---|---|---|---|---|
| T-1 | 篡改 Run 状态 | 终态 Run 被改回中间态 | `enforce_run_state_transition` 触发器拒绝 | 低 |
| T-2 | 回退 fencing token | 旧世代 Worker 提交结果 | `enforce_fencing_on_write` + UPDATE 条件带 token（双保险） | 低 |
| T-3 | 篡改执行快照 | 修改配置使其绕过审批 | `forbid_snapshot_mutation` 触发器 | 低 |
| T-4 | 绕过 UNKNOWN 约束 | 盲目重试导致重复副作用 | `forbid_attempt_after_terminal` 触发器；类型层面禁止 `UNKNOWN → PENDING` | 低 |
| T-5 | 超发预算 | 并发下突破预算上限 | `budget_no_overspend` CHECK + 应用层原子预留 | 中：应用层逻辑待 P2 实现 |
| T-6 | 配置降级绕过门禁 | 运行时调低审批强度 | `ConfigFailClosedTest` 断言只能收紧不能放松 | **高**：配置化本身是风险源（R-020），需 CHG 流程 + ISO-5 抽检 |

> **T-6 是设计上的固有张力**：配置化解决「后续谁来调」，
> 但同时开了一条「运行时降低安全强度」的路。
> 缓解不能只靠代码，必须叠加变更管控。

### 3.3 Repudiation（抵赖）

| # | 威胁 | 场景 | 已有缓解 | 残余风险 |
|---|---|---|---|---|
| R-1 | 无法追溯审批决定 | 家长/教师否认批准过 | `approval` / `audit_record` 表已建 | **高**：写入逻辑未实现（P2） |
| R-2 | 无法追溯数据访问 | 跨租户访问无记录 | RLS 生效但**无访问日志** | 中：需补充审计（P3） |
| R-3 | 日志被篡改 | 事后修改审计日志 | 审计表未实现追加约束 | 中 |

> 当前 RLS 策略**只管「能不能看」，不管「看了什么」**。
> 事后追责需要审计链路，属 P3 范围。

### 3.4 Information Disclosure（信息泄露）

| # | 威胁 | 场景 | 已有缓解 | 残余风险 |
|---|---|---|---|---|
| I-1 | 学生数据出境 | Prompt 携带真实数据发送至模型 | `ZeroRetentionGate` 按供应商 fail-closed；三家已取得书面零保留承诺 | 中：境外实例需另做 A-009 评估 |
| I-2 | 凭据入日志 | 供应商异常含 API Key | `CredentialRedactor` + `safeMessage` 刻意不挂 cause | 低 |
| I-3 | 可识别信息入 Prompt | 即使已确认也不该传姓名/学号 | `DataClassification` 检测身份证/手机号/学号/邮箱 | 中：正则无法穷尽编码与隐写 |
| I-4 | MQ 消息携带敏感数据 | 消息难以精确删除 | `OutboxMessage` 类型层面白名单 + 禁止字段黑名单 | 低 |
| I-5 | 模型编造资料出处 | 输出不存在的教材引用 | 无引用字段约束；SB-01 纳入评测集 | 中：**P2 评测集未建立**（R-018） |
| I-6 | 错误信息泄漏内部结构 | 异常暴露表名/供应商类型 | 模型异常归一化为六类枚举，不泄漏供应商类型 | 低 |

> **I-3 的固有局限**：正则只能拦住**明显的**可识别信息。
> 编码、拼音、隐写无法穷尽。因此数据分级（fail-closed）才是主防线，
> 正则检测是纵深防御的第二道 —— 不可颠倒主次。

### 3.5 Denial of Service（拒绝服务）

| # | 威胁 | 场景 | 已有缓解 | 残余风险 |
|---|---|---|---|---|
| D-1 | 无限重试烧钱 | 不可重试错误被误判为可重试 | `ModelErrorKind.retryable` 区分；契约测试断言 | 中：Spring 内置 `@Retryable` 与自研重试**可能双重触发** |
| D-2 | 预算击穿 | 大量调用耗尽预算 | `budget_no_overspend` + Run 级预算上限 | 中：限流未实现 |
| D-3 | MQ 消息堆积 | 消费者停滞导致积压 | quorum queue + `x-delivery-limit=3` | 中：队列参数**由应用声明，尚未实测** |
| D-4 | 连接池耗尽 | 慢查询占满连接 | HikariCP 超时配置 | 低 |

> ⚠️ **D-1 特别说明**：Spring Boot 4.1 内置 `@Retryable` 与自研重试逻辑
> 若同时生效会**双重重试**。ADR-011 已记录此项，
> P2 实现 Worker 时须明确**唯一重试点**。对 `record_weakness`
> 而言，双重重试即重复写入 = **Sev-0**。

### 3.6 Elevation of Privilege（权限提升）

| # | 威胁 | 场景 | 已有缓解 | 残余风险 |
|---|---|---|---|---|
| E-1 | 未授权工具调用 | 模型请求调用未登记工具 | 未登记工具按 `WRITE_EXTERNAL` 兜底；执行时授权 | 中：Spring AI `ToolCallingAdvisor` 自动执行路径**必须禁用** |
| E-2 | 绕过审批执行副作用 | 直接调用有副作用工具 | `WRITE_EXTERNAL=REQUIRED` 起步 | 中：审批流程未实现（P2） |
| E-3 | 内部调用绕过租户隔离 | 直接用超级用户连接 | RLS `FORCE ROW LEVEL SECURITY`；`AgentCorePurityTest` 禁框架依赖 | **高**：若误用超级用户连接，FORCE 也拦不住 |

> **E-3 是运维层面最易踩的坑**：超级用户与 `BYPASSRLS` 角色
> 会绕过所有策略，`FORCE ROW LEVEL SECURITY` 对它们无效。
> 本项目已在集成测试中强制使用 `app_agent` 角色。

## 4. 残余风险汇总

按「是否可被代码缓解」分类，这决定了整改方式：

| 等级 | 风险 | 代码可解？ | 整改路径 |
|---|---|---|---|
| **高** | T-6 配置化成为降级后门 | 部分 | CHG 模板 + ISO-5 外部抽检（非纯代码） |
| **高** | E-3 误用超级用户连接 | ✅ | 连接工厂强制非特权角色 + 启动自检 |
| **高** | R-1 审批与审计未实现 | ✅ | P2/P3 实现 |
| 中 | S-1 IAM 未接入 | ✅ | D-001（P2 前） |
| 中 | S-2 凭据管理 | 部分 | D-008 KMS（P4） |
| 中 | I-1 出境评估 | ❌ | 合规流程，非代码 |
| 中 | I-3 正则检测局限 | ❌ | 主防线是数据分级，正则仅纵深 |
| 中 | I-5 模型编造 | 部分 | P2 评测集 |
| 中 | D-1 双重重试 | ✅ | P2 明确唯一重试点 |
| 中 | E-1 自动执行路径 | ✅ | ADR-011 已记录，P2 实现时遵守 |

### 4.1 ⚠️ 本模型无法覆盖的风险

**R-016（同基座模型盲区）**：本威胁模型由 AI 分析，
可能与 AI 自身的盲区相关 —— 即「AI 看不出来的漏洞，AI 也分析不出来」。

缓解措施：
- Sev-0/1 判定**不得仅依赖 AI**，须自动化测试证据 + 外部抽检（ISO-5）
- 本文档应在 P3 故障注入后**复审**
- 建议由 zhouwei 或外部人员独立复核本模型

## 6. P2 实施时的强制约束

以下为设计约束，**实现时必须遵守**，否则本模型的缓解措施失效：

| # | 约束 | 原因 |
|---|---|---|
| 1 | 应用连接必须用**非特权角色** | 超级用户绕过所有 RLS 策略 |
| 2 | **禁用** Spring AI `ToolCallingAdvisor` 自动执行路径 | 会绕过授权闸门 |
| 3 | 明确**唯一重试点**（自研或 Spring 二选一） | 双重重试 → `record_weakness` 重复写入 Sev-0 |
| 4 | 消息体不得含 Prompt/工具参数/学生数据 | MQ 消息难以精确删除 |
| 5 | `tenant_id` 一律取自认证上下文 | 永不信赖客户端输入 |
| 6 | 连接获取经统一入口（含事务与租户绑定） | `set_config(is_local)` 必须配合事务 |
| 7 | 审批策略只能收紧不能放松 | 配置降级 = 安全门禁降级 |
