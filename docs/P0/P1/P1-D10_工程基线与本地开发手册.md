## 2. 模块结构与依赖方向

```text
agent-core          领域层（零框架依赖）
    ↑
agent-ports         端口定义（ModelGateway / ToolHandler / Repository）
    ↑
agent-application   应用层（用例编排、授权闸门、预算、配置快照）
    ↑
agent-infrastructure 基础设施层（PG / Outbox / MQ / ModelGateway 适配）
    ↑
    ├── agent-worker   执行引擎（消费、租约、fencing、ToolOperation 账本）
    └── agent-api      接口层（REST/SSE、错误码、API 版本控制）
            ↑
    platform-bootstrap  启动与装配（可执行 fat jar）
```

**约束**：依赖只能自下而上，禁止反向与循环。

**自动化保障**：`AgentCorePurityTest` 校验领域层不出现 `org.springframework`、
`jakarta.*`、`org.hibernate`、MQ SDK、数据库驱动、日志实现等 import，违反即构建失败。

## 3.1 本地依赖启动

### PostgreSQL

```bash
./scripts/dev-postgres.sh start     # 启动 PG 17 + 自动执行迁移与种子
./scripts/dev-postgres.sh status    # 查看版本与连接串
./scripts/dev-postgres.sh verify    # 以非特权角色验证 15 项安全约束
./scripts/dev-postgres.sh migrate   # 重新执行迁移（幂等）
```

连接串：`jdbc:postgresql://127.0.0.1:5433/agent_dev`（用户 `agent`）

> ⚠️ **DEC-13：PostgreSQL 17.x**。当前实例为 **17.11**，15 项安全约束已在该版本
> 上全部实测通过。PG 17 强制要求 `POSTGRES_PASSWORD` 或
> `POSTGRES_HOST_AUTH_METHOD=trust`——本地用 trust 免凭据，**生产必须密码 + SCRAM**。
>
> ⚠️ **PG 14 已于 2026-11-12 EOL**，禁止使用；PG 15 于 2027-11 EOL。

### RabbitMQ

```bash
./scripts/dev-rabbitmq.sh start     # 启动并准备 vhost
./scripts/dev-rabbitmq.sh status    # 查看状态与端口
./scripts/dev-rabbitmq.sh verify    # 应用启动后校验队列参数
./scripts/dev-rabbitmq.sh stop      # 停止（保留数据）
./scripts/dev-rabbitmq.sh destroy   # 删除容器
```

AMQP `127.0.0.1:5672`，管理界面 <http://127.0.0.1:15672>。

#### 当前实例（2026-10-18 实测）

| 项 | 实测值 |
|---|---|
| 版本 | **4.3.6**（与 ADR-001 一致） |
| 元数据存储 | `khepri_db`（4.x 唯一存储，Mnesia 已移除） |
| Erlang/OTP | 27（4.3 要求 ≥ 25） |
| **vhost `agent` 默认队列类型** | **`classic`** ⚠️ |

> ⚠️ **实测确认了一个关键风险**：vhost 的 `default_queue_type` 是 **classic**，
> **不是** quorum。也就是说应用若不显式声明 `x-queue-type: quorum`，
> 队列会**静默退化为 classic**，在 4.x 下**失去复制能力**
> （classic mirrored queue 已在 4.0 彻底移除）。
> 本项目 `application.yml` 已显式声明，`verify` 会对此告警提示。

#### 镜像获取（Docker Hub 直连不可达时）

本机 Docker Hub 直连超时（context deadline exceeded），需经镜像加速器：

```bash
RMQ_MIRROR=docker.1ms.run ./scripts/dev-rabbitmq.sh start
```

脚本会拉取 `<mirror>/library/rabbitmq:4.3.6-management` 后 **retag 为标准名**，
使后续脚本与文档中的 `IMAGE` 取值保持不变。

限流时可用 `RMQ_PULL_RETRIES` 增加重试次数：

```bash
RMQ_MIRROR=docker.1ms.run RMQ_PULL_RETRIES=5 ./scripts/dev-rabbitmq.sh start
```

**加速器实测结果（2026-10-18）**：

| 加速器 | HTTP 响应 | 结论 |
|---|---|---|
| `docker.xuanyuan.me` | `403 TOOMANYREQUESTS` | ❌ 免费节点按出口 IP 限流，5 次重试全失败 |
| **`docker.1ms.run`** | `401 UNAUTHORIZED` → 拉取成功 | ✅ **可用**，约 2 分钟完成 |
| `docker.m.daocloud.io` | `401 UNAUTHORIZED` | ✅ 可用（备用） |

> **判别技巧**：registry 返回 **401** 表示「可达但需 token」（正常）；
> 返回 **403 TOOMANYREQUESTS** 表示「被限流」。用 `hello-world` 做对照可快速区分
> 限流与标签不存在。

临时用本地已有镜像开发（quorum queue 需 ≥ 3.8）：

```bash
RMQ_IMAGE=rabbitmq:3-management ./scripts/dev-rabbitmq.sh start
```

> ⚠️ **队列由应用启动时声明**，不由脚本预建。原因是队列类型与
> `delivery-limit` 来自应用配置（ADR-001 §4）；若由运维脚本预建，
> 应用声明参数不一致会抛 `PRECONDITION_FAILED`，且会造成
> 「配置改了但队列没变」的错觉。脚本 `verify` 用于事后确认参数生效。

> ⚠️ **单节点限制**：quorum queue 的 Raft 多数派 = 自身，功能正常但无高可用。
> 生产须起 3 节点集群，见脚本末尾「生产集群」段。

### 数据库应用角色

```bash
psql -U <超管> -d <库> \
     -v app_role=app_agent2 -v app_password='<密码>' \
     -f platform/agent-infrastructure/src/main/resources/db/migration/verify/V__manage_app_role.sql
```

脚本幂等，可重复执行；不传 `app_password` 时只调整权限不改密码。

**必须用非超级用户**——超级用户与 `BYPASSRLS` 角色会绕过所有 RLS 策略，
用超级用户跑跨租户测试会得到「隔离生效」的虚假结论。

运行 RLS 集成测试（**已验证可在 PG 17 上通过**）：

```bash
export IT_PG_URL='jdbc:postgresql://127.0.0.1:5433/agent_dev'
export IT_PG_USER='app_agent'
export IT_PG_PASSWORD=''
mvn -pl agent-infrastructure test -Dtest=TenantSessionBinderIT
```

未设 `IT_PG_URL` 时自动跳过，不影响常规 `mvn verify`。
`app_agent` 角色由 `dev-postgres.sh start` 自动创建并授权。

> ⚠️⚠️ **「跳过」与「跑过」在构建界面上长得一模一样**（F-14/CP-1/CP-2 同形态，W-PERM-P0 验收时再次实测踩中）：
>
> - 上面三条变量**必须逐条 `export`**。写成 `export A=1 && B=2 && mvn ...` 时，`B` 只是 shell 变量
>   而非环境变量，`System.getenv("IT_PG_URL")` 取到 `null` → 全部 IT 被跳过 → **构建仍报 BUILD SUCCESS**。
> - 判读结果先看 **Skipped 数**：`Tests run: 37, Skipped: 37` 是「一条没跑」，不是「全绿」。
> - 跑**全量** IT 时用隔离库 `agent_it`（`./scripts/dev-it-db.sh` 建库），不要用 `agent_dev` ——
>   后者有历史 run 残留，会挤占任务领取窗口，报「任务未被领取」。
> - CI 侧已有防线：`ci.yml` 的 integration-test job **断言跳过数必须为 0**，本地复现时无此断言，需自行核对。

## 4. 配置基线（fail-closed）

完整模板见 `platform-bootstrap/src/main/resources/application.yml`。

### 4.1 铁律

| # | 规则 | 自动化保障 |
|---|---|---|
| 1 | 配置**缺失或非法一律拒绝**，不取默认值放行 | `ConfigFailClosedTest` 8 项 |
| 2 | 审批策略**只能收紧不能放松** | `ConfigFailClosedTest#cannotRelaxBelowDefault` |
| 3 | 未登记工具按 `WRITE_EXTERNAL` 兜底 | `ConfigFailClosedTest#unregisteredToolFallsBackToStrictest` |
| 4 | 配置在 **Run 创建时快照**，改配置只影响新 Run | `ConfigFailClosedTest#snapshotIsImmutableAcrossConfigChanges` |
| 5 | 快照审计导出**不含学生可识别信息** | `ConfigFailClosedTest#snapshotAuditMapIsSafe` |

### 4.2 配置键与保守初值

| 配置键 | 初值 | 调优时点 |
|---|---|---|
| `agent.run.max-cost-per-run` | 2.00 | P4 实测 usage |
| `agent.run.max-llm-calls` | 12 | P2 评测集 |
| `agent.run.max-steps` | 20 | P2 |
| `agent.tenant.max-concurrent-runs` | 5 | P4 压测 |
| `deployment.pilot.max-tenants` | 1 | P5 扩量 |
| `dr.rpo` / `dr.rto` | 24h / 4h | P4 演练 |
| `agent.tool.risk-level-map` | `get_student_profile=READ`, `record_weakness=WRITE_PROFILE` | P3 可调整 |
| `agent.approval.required-by-risk` | `READ=NOT_REQUIRED`, `WRITE_PROFILE=OPTIONAL`, `WRITE_EXTERNAL=REQUIRED` | P3 切 REQUIRED |
| `agent.approval.ttl` | 15m | — |
| `agent.approval.approver-scope` | PARENT_OR_TEACHER | — |

### 4.3 ⚠️ 配置写法约束（踩过坑，勿改回）

| 约束 | 原因 |
|---|---|
| **数值/布尔值必须加引号** | `YamlPropertiesFactoryBean` 会**静默丢弃**裸标量。`delivery-limit: 3` 被丢弃 → 队列退回 quorum 默认 **20** → `record_weakness` 重复写入最多 20 次（Sev-0）。已由 `ApplicationConfigTest` 断言防护 |
| **YAML 只能有一个文档** | `---` 分隔符会使后续文档被忽略（该 Bean 只读首个文档） |
| **顶层键不可重复** | 重复 `agent:` 直接解析失败（`found duplicate key`） |
| **口令一律用 `${ENV:}` 占位** | 不得硬编码明文；`ApplicationConfigTest` 会检测 |
| **`x-queue-type` 必须显式声明** | RabbitMQ 4.x 未配置 vhost 默认类型时默认 classic，而 classic 无复制能力 |

## 5. 领域层核心概念

### 5.1 三层 Attempt（P0-D03 §4 红线 4）

```text
Run attempt              Run 的第 n 次整体执行尝试
ToolOperation            一个逻辑工具操作（对账与幂等的最小单位）
ToolOperationAttempt     该逻辑操作的第 m 次调用尝试
```

`UNKNOWN` 归属 **ToolOperation** 而非 attempt——它表达「这个逻辑操作结果未知」，
与「尝试了几次」正交。

### 5.2 UNKNOWN 语义（最重要的安全约束）

请求已发出但响应丢失时：

- ❌ 不得当作普通 `FAILED` 盲目重试（可能重复副作用 → Sev-0）
- ❌ 不得直接释放预算预留（成本可能已发生）
- ✅ 只能通过对账流程离开：`RECONCILED_SUCCEEDED` / `RECONCILED_ABSENT` / `MANUAL_DISPOSED`

已由 `ToolOperationState.legalTargets()` 在类型层面强制——`UNKNOWN → PENDING`
（等同重试）会抛 `IllegalStateTransitionException`。

### 5.3 三条红线当前实现状态

| 红线 | 实现 | 验证 |
|---|---|---|
| **3** 原子提交 | `insertRunAtomically` 在同一事务写入 Run + 初始事件 + 幂等记录 + Outbox | `RunCreationAtomicityIT`（11 项，含整体回滚后四者均不残留） |
| **5** fencing | `FOR UPDATE SKIP LOCKED` 领取 + token 递增；提交/续租/释放的 UPDATE 条件均带 token | `RunClaimFencingIT`（7 项，含旧世代提交被拒） |
| **7** UNKNOWN 治理 | DB 触发器 `forbid_attempt_after_terminal` 拒绝终态/UNKNOWN 操作新增 attempt | `V1_constraint_check.sql` U1～U4 |

> fencing token **单调递增且不从 1 重启**。断言应写「领取后 == 领取前 + 1」，
> 不要硬编码绝对值。

### 5.4 工具执行授权链

```
模型请求调用 → Schema 校验 → 执行时重新授权 → 审批检查 → 预算预留 → 执行 → 账本写入
```

授权发生在**执行时刻**而非快照创建时刻：权限可能已被撤销（P0-D03 §4 红线 9）。

> ⚠️ Spring AI 2.0 的 `ToolCallingAdvisor` 会自动执行工具循环并绕过上述闸门，
> **本项目禁止使用其自动执行路径**（ADR-011 §3.3）。

### 5.5 ⚠️⚠️ RLS 事务铁律（本项目最隐蔽的失效模式）

`set_config('app.tenant_id', ?, true)` 的「事务局部」语义，**前置条件是必须开启事务**。

实测（PG 17.11）：

| 模式 | 可见行数 |
|---|---|
| 自动提交 + `is_local=true` | **0**（绑定立即失效） |
| 事务内 + `is_local=true` | 114（正常） |

**症状**：写入成功但查询恒为 0 —— 极易被误判为功能缺陷或 RLS 配置错误，
实际是租户上下文根本没绑上。

本项目曾因此在 **6 处生产代码**埋雷。统一处置：

- 所有 DAO 方法一律经 `tenantConnection(tenantId)` 取连接
  （关闭自动提交 → 绑定租户 → commit/rollback）
- **禁止直接 `dataSource.getConnection()`**

另：PG 的 uuid 列用 `setString` 传值时，SQL 中必须写 `?::uuid`，
否则报 `column "run_id" is of type uuid but expression is of type character varying`。
