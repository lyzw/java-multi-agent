## 0. ⚠️ 首要事实：后端接口现状（2026-10-19 实测）

> **为什么把这段放在最前面**：页面规划的上限由后端实际暴露的接口决定，
> 而不是由需求文档决定。经代码实测，全项目**只有 3 个 `@RestController`、4 个业务端点**。

### 0.1 已实现端点（全量）

| # | 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|---|
| 1 | `POST` | `/api/auth/token` | `{tenantId, loginName, password}` | `{accessToken, tokenType:"Bearer", expiresIn:900}` |
| 2 | `GET` | `/api/auth/jwks` | — | `{kid, alg:"RSA", publicKeyBase64}`（**非标准 JWKS**，前端不可直接用） |
| 3 | `POST` | `/api/runs` | `{idempotencyKey, agentId, input:{...}, requestedBy?}` | `{runId, replayed, state:"QUEUED", correlationId}` |
| 4 | `GET` | `/api/runs/{runId}/events` | `Last-Event-ID` 头（可选） | `text/event-stream` |

- 无 OpenAPI/Swagger，无分页接口，无列表接口，无刷新令牌，无 `/me`，无登出。
- **CORS 被完全禁用**（`cors.disable()`）→ 前端必须与后端**同源部署**（反向代理补 CORS 头），详见 §6.2。
- 仅暴露 `actuator/health`（`show-details: never`）。

### 0.2 规划中但**尚无端点**的动作常量

`AuthorizationService.Actions` 已定义 10 个受控动作，其中 **9 个无对应 HTTP 端点**：

| 动作常量 | 值 | 端点 | 阻塞的页面 |
|---|---|---|---|
| `RUN_CREATE` | `run:create` | ✅ 有 | — |
| `EVENT_SUBSCRIBE` | `event:subscribe` | ✅ 有 | — |
| `RUN_READ` | `run:read` | ❌ 无 | Run 详情、列表 |
| `RUN_CANCEL` | `run:cancel` | ❌ 无 | 取消 |
| `RESULT_READ` | `result:read` | ❌ 无 | 结果页 |
| `APPROVAL_CONSUME` | `approval:consume` | ❌ 无 | 审批台 |
| `UNKNOWN_DISPOSE` | `unknown:dispose` | ❌ 无 | UNKNOWN 处置台 |
| `AUDIT_READ` | `audit:read` | ❌ 无 | 审计页 |
| `AGENT_MANAGE` | `agent:manage` | ❌ 无 | Agent 配置 |

> **结论**：业务闭环页面（发起→进度→结果）可做；**运营与治理页面（列表/管理/审批/审计）全部阻塞**。

## 1. 目标用户与角色

### 1.1 真实使用者（对齐 `P0-D00` §3.1）

首个业务场景为**初中生错题归因与个性化辅导**。目标用户 12–18 岁初中生，
**由家长或教师代为发起**（`P0-D02` BR-01）。

| 角色 | 典型动作 | 后端角色常量 |
|---|---|---|
| **学生** | 提交错题、查看归因结果 | `known-roles` 含 `STUDENT`（`Roles` 常量未列） |
| **家长** | 代为发起、查看孩子学习画像 | `PARENT` |
| **教师** | 发起、查看班级薄弱点、审批 | `TEACHER` / `APPROVER` |
| **租户管理员** | 成员/权限/配额管理 | `TENANT_ADMIN` |
| **Agent 作者** | 配置与发布 Agent | `AGENT_AUTHOR` |
| **观察者** | 只读查看 | `VIEWER` |
| **运维/SRE** | 排障、死信、UNKNOWN 处置 | `WORKER`（服务账号）/ 运维账号 |

> ⚠️ 令牌实际携带的角色来自 `principal_role` 表，与 `AuthorizationService.Roles`（5 个）
> 和 `application.yml` 的 `auth.login.known-roles`（8 个）取**交集**。
> 前端**不得**自行假设角色集，须以实际令牌声明为准（当前 `/api/auth/token` 响应**不含角色**，见 §5-G1）。

### P1 登录页 ✅ 可实现

| 项 | 内容 |
|---|---|
| 路由 | `/login`（未认证访问任意页均重定向至此） |
| 目标 | 换取访问令牌，进入工作台 |

**区块**

1. **登录表单**：`tenantId`（租户标识）、`loginName`、`password`。
2. **提交反馈区**：统一错误提示。

**关键约束（不可省）**

| # | 约束 | 原因 |
|---|---|---|
| L1 | **失败提示统一为「租户、账号或密码不正确」** | 后端所有失败路径耗时一致且不区分原因（`D-001` §3.2）。前端若自行区分「账号不存在」即**制造了后端刻意消除的枚举面** |
| L2 | 不做「忘记密码」入口 | 需邮箱/手机号，而 PIPL 要求我们**不采集**这些（`D-001` §7）。这是结构性约束，不是有意遗漏 |
| L3 | 不做「注册」入口 | 涉及监护人同意流程，本期只做受控发号 |
| L4 | 不做「多租户切换」 | 会让一次登录可访问多租户，风险过大 |
| L5 | 令牌存 `sessionStorage`（**不用** localStorage） | 降低 XSS 场景下的令牌存活时间；无 refresh token 故不需长期存储 |
| L6 | 提前 60s 感知过期并引导重新登录 | `expiresIn=900`（15 分钟）且**无刷新接口**，到期即硬跳登录 |

**接口**：`POST /api/auth/token`

**缺口**：`G1` 响应不含角色/用户信息 → 前端无法渲染"当前身份"，登录后只能显示通用文案。
建议后端在登录响应增加 `roles`/`displayName`（**只返角色名，不返任何个人身份信息**）。

| 项 | 内容 |
|---|---|
| 路由 | `/` |
| 目标 | 快速发起辅导、查看进行中的任务 |

### P3 发起辅导页（错题录入）✅ 可实现

| 项 | 内容 |
|---|---|
| 路由 | `/runs/new` |
| 目标 | 采集一道错题并创建 Run |

**表单字段**（对齐 `BR-01` 输入定义）

| 字段 | 必填 | 约束 | 对应 `input` 键 |
|---|---|---|---|
| 学科 | ✅ | 白名单枚举（数学/物理/化学/生物/语文/英语等） | `subject` |
| 年级 | ✅ | 白名单枚举 | `grade` |
| 题目文本 | ✅ | 长度上限；**前端即做可识别信息预检** | `questionText` |
| 学生解题过程 | ✅ | 同上 | `studentSolution` |
| 已知正确答案 | ✅ | 同上 | `correctAnswer` |
| 学生标识 | ✅ | **随机匿名 ID**，禁止填姓名 | `studentId` |

**⛔ 合规红线（前端硬约束）**

| # | 红线 | 落地方式 |
|---|---|---|
| C1 | **禁止字段**：姓名、学校、班级、身份证号、手机号、邮箱、定位、面部/声纹、生物识别、社交账号 | 表单**根本不提供**这些输入框；不是「校验后拒绝」，而是「不存在」 |
| C2 | 学生标识只能填**随机匿名 ID** | 输入框旁固定提示「请填写平台生成的匿名编号，不要填姓名」 |
| C3 | 提交前**客户端预检**可识别信息 | 与后端 `DataClassification.IdentifyingPattern` 同规则：身份证 / 手机号 / 邮箱 / 8–12 位纯数字。命中则**阻断提交并高亮**，不等后端 400 |
| C4 | 不展示、不缓存题目原文到 `localStorage` | Prompt/工具结果保留期 90 天且属受控数据；浏览器本地缓存不可控 |

> **为什么 C3 要在前端做**：后端已实现同样的扫描并返回 `400 INVALID_REQUEST`，
> 但让用户先提交再被拒，代价是一次无谓往返且体验差。**前端预检是体验优化，不是安全边界**——
> 后端那道扫描才是安全边界，两者都要有。

**幂等键生成（重要）**

| 项 | 规则 |
|---|---|
| 取值 | 前端生成 UUID v4，**存在 `sessionStorage`** |
| 重试策略 | 同一次表单提交在**网络失败/5xx**时**复用同一 key**；表单内容变更则**换新 key** |
| 理由 | 同一 key + 同一 input → `replayed:true`，返回原 `runId`；同一 key + 不同 input → `409 IDEMPOTENCY_CONFLICT`。若每次重试都换 key，重复创建 Run，**记录薄弱点会被重复写入**（Sev-0） |

**接口**：`POST /api/runs`

**已知限制**：`agentId` 目前由前端硬编码/配置注入 —— 后端无 Agent 管理接口，
真实 Agent ID 需运维提供或后端补 `GET /api/agents`（缺口 `G2`）。

### P4 辅导进度页 🟡 部分可实现

| 项 | 内容 |
|---|---|
| 路由 | `/runs/:runId` |
| 目标 | 展示执行过程，让用户知道"在跑、在哪一步、还要多久" |

**⚠️ 首要事实**：SSE 当前是**短连接 + 轮询续传**，非长连接推送（`P2-D05` §3.3）。
每次响应都会结束，客户端须携带 `Last-Event-ID` 重新请求。

**⚠️ 第二个事实（更关键）**：`run_event` 表**只有 `RUN_CREATED` 一条事件由生产代码写入**，
Worker 侧（`RunExecutionLoop` / `RunDispatchConsumer`）**不写该表**。

→ **这意味着当前进度页拿不到任何执行中事件**，只能拿到创建事件。
**页面必须能优雅降级为"处理中"占位，不能假装有进度条。**

**区块**

1. **状态区**：映射 `RunState` 六态 ——
   `QUEUED` 排队中 / `RUNNING` 执行中 / `SUCCEEDED` 已完成 / `FAILED` 失败 /
   `CANCELLED` 已取消 / `TIMED_OUT` 超时。
   ⚠️ **`TIMED_OUT` 是真实终态**，初稿曾漏判致连接永不关闭（`P2-D05` §4），UI 映射不得遗漏。
2. **时间线**：事件流渲染。事件 `data` 为**白名单字段**：`sequenceNo`/`at` +
   可选的 `state`/`attempt`/`stepType`/`toolName`/`operationState`/`errorCode`/`phase`。
   ⚠️ **不得**期望出现 Prompt 原文、学生数据、工具参数——不存在，前端若渲染即说明有安全缺陷。
3. **重连指示器**：明确显示"正在重连/已暂停更新"，`Last-Event-ID` 续传进度。

**轮询策略**

| 项 | 策略 |
|---|---|
| 间隔 | 进行中 3s；终态后停止 |
| 续传 | 维护 `lastEventId`，每次请求置于 `Last-Event-ID` 头 |
| 背压 | `MAX_EVENTS=200`/次，超出则下一轮继续拉 |
| 终止 | 收到 `: run-terminal` 注释行 → 关闭连接，停止轮询 |
| 401 | 立即停止并跳登录（令牌过期） |

**接口**：`GET /api/runs/{runId}/events`（`Last-Event-ID` 头）

**缺口**：
- ✅ **`G3` 已关闭**（后端 P4-D09；前端 FE-D9 已接线）——进度页现在以
  `GET /api/runs/{runId}` 的状态快照为**权威**，事件流退为时间线补充。
  ⚠️ 两者**共用限流桶**（30 次/60 秒）→ 状态轮询间隔取 **10 秒**（FE-D9 §2.3）。
- ⛔ **`G4` 仍未关闭**：Worker 不写事件 → 进度页**时间线**仍长期只有 `RUN_CREATED`。
  **这是 P3-D10 的依赖项**（后端切片 P4-D12）。
  ⚠️ FE-D9 **不假装**解决 G4：状态是真的，时间线仍短。

### P5 归因结果页 🔴 阻塞

| 项 | 内容 |
|---|---|
| 路由 | `/runs/:runId/result` |
| 目标 | 展示归因结论、错因讲解、可执行解题步骤、薄弱点更新结果 |

**规划区块**（结构先定，内容待接口）

1. **归因结论卡**：错因分类 + 置信度。
2. **讲解区**：分步骤讲解。
3. **解题步骤区**：可执行步骤列表。
4. **薄弱点更新回执**：写入结果；⚠️ 若工具进入 `UNKNOWN`，**必须显式呈现"待核对"而非常规成功**。

**⛔ 结果页合规红线**

| # | 红线 |
|---|---|
| C5 | **不得显示任何教材引用、页码、资料出处**（`DEC-5` 不做 RAG）。前端若做「来源」区块或渲染模型输出的引用，**编造出处即判失败**（`R-018`）。建议：UI 层**不设**引用展示位，从结构上杜绝 |
| C6 | 结果内容不得含学生身份信息；渲染前对模型输出做一次敏感词兜底扫描 |
| C7 | 结果**不落** `localStorage`；仅内存 + 可选用户主动导出 |

**缺口**：`G5` 无 `result:read` 端点 → **本页完全阻塞**。
`P0-D00` §3.4 明确：终态存在未决 `UNKNOWN`/`RECONCILIATION_REQUIRED` 时，
**必须通过独立操作状态明确暴露，不得隐藏在普通成功响应中**（v3.1 §224）。
故结果页的数据结构**必须预留"待核对"分区**，不能等接口来了再补。

## 4. 全局设计规范

### 4.1 错误处理（必须兼容两套响应形状）

后端错误响应**存在两套不兼容字段名**，前端适配层须同时处理：

| 来源 | 形状 |
|---|---|
| `ApiExceptionHandler` / `RunController` | `{code, message}` |
| Security 401 / 403、`AuthController` 401 | `{error: "unauthorized" \| "forbidden" \| "invalid_credentials"}` |

**已实现错误码与 UI 映射**

| HTTP | code | UI 行为 |
|---|---|---|
| 400 | `INVALID_REQUEST` | 表单字段级高亮 + 消息 |
| 401 | — | 清令牌 → 跳登录，附「登录已过期」 |
| 403 | `ACCESS_DENIED` / `{error}` | 「无权访问」，**不重试** |
| 404 | — | 「资源不存在」（跨租户亦返回 404，**不区分**） |
| 409 | `IDEMPOTENCY_CONFLICT` | 「该提交与之前的请求不一致，请刷新后重试」 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 通用错误 |
| 422 | `COMPLIANCE_BLOCKED` | **合规提示页**：说明数据合规限制，非程序错误 |
| 500 | `INTERNAL_ERROR` | 通用错误 + 显示 `correlationId` 供排障 |

> ⚠️ **不得**依赖 SSE 端点的 400/404：`ApiExceptionHandler` 的 `Exception` 兜底
> 可能吞掉 `ResponseStatusException`，实际返回 500。前端按 500 处理即可。

### 4.2 令牌与路由守卫

| # | 规则 |
|---|---|
| G-1 | 路由守卫仅做**体验优化**（未登录重定向），**不作为安全边界** |
| G-2 | 15 分钟过期无刷新 → 全局定时器，到期前 60s 提示、到期强制跳登录 |
| G-3 | 401 一律清空本地会话状态（含本设备 Run 记录），避免半登录态 |

### 4.3 状态展示铁律

| # | 规则 | 违反后果 |
|---|---|---|
| S1 | 不得编造进度百分比 | 无依据的进度条 = 假信息 |
| S2 | 失败必须显示可区分原因 | 笼统「出错了」使 SB-01～07 无法验收 |
| S3 | `UNKNOWN` / 待核对**独立呈现**，不并入成功态 | `P0-D00` §3.4 明令禁止隐藏 |
| S4 | 任何"暂无数据"须区分「确实没有」与「接口未开放」 | 否则用户以为系统坏了 |

## 6. 前端工程结构

### 6.1 目录

```
frontend/
├── src/
│   ├── app/            # 路由、布局、全局 Provider
│   ├── pages/          # P1~P13 页面组件
│   ├── features/       # run / auth / profile 领域切片
│   │   ├── auth/       # 登录、令牌存取、过期处理
│   │   ├── run/        # 创建、事件轮询、状态机
│   │   └── compliance/ # 敏感信息预检（白名单规则）
│   ├── shared/         # 错误处理、状态映射、UI 原子组件
│   └── api/            # 端点封装、错误归一化
├── tests/              # Vitest 单测 + MSW 契约 mock
└── vite.config.ts
```

### 6.2 部署形态（必须同源）

后端 `cors.disable()`，故**必须**由反向代理把前端与 `/api/*` 置于同源：

```
浏览器 ──► 反向代理（同源）
            ├── /            → 前端静态资源
            └── /api/*       → platform-bootstrap:8080
```

⚠️ 独立域名直连会被浏览器拦截，且**不得**为了绕过而给后端开 `cors.allowOrigins("*")`——
令牌在 `Authorization` 头，任意源可读将造成跨站数据窃取。

### 6.3 测试策略

| 层 | 工具 | 重点 |
|---|---|---|
| 单测 | Vitest | 状态映射（六态含 `TIMED_OUT`）、错误归一化（两套形状）、幂等键策略、敏感信息预检 |
| 契约 mock | MSW | 按**实测**响应形状 mock，含 401 `{error}` 与 403 `{code,message}` 两种 |
| 组件测试 | Testing Library | 表单校验、四态渲染 |
| E2E | Playwright（建议 P4） | 登录 → 发起 → 进度 完整链路 |

> 沿用项目铁律：**测试须主动破坏防护以证明其有效**。
> 例如：移除 `TIMED_OUT` 分支 → 进度页测试应精确失败；跳过敏感信息预检 → 合规测试应失败。
