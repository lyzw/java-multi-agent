# FE-D3 视觉设计规范

| 字段 | 内容 |
|---|---|
| 文档编号 | FE-D3 |
| 版本 | v1.0 |
| 依据 | FE-D2 页面体系、FE-01 页面规划、PIPL 未成年人数据要求 |
| 主题 | 错题归因辅导 |
| 受众 | **初中生**（使用者）、教师与管理员（审阅者）|

---

## 1. 设计主题与主张

### 1.1 主题从哪来

这个产品的真实材料不是"SaaS 仪表盘"，而是**老师批改作业的那张纸**：

| 材料 | 在产品中的对应 |
|---|---|
| 作业纸 / 方格纸 | 学生提交题目、解题过程的空间 |
| 老师的红笔批注 | 归因结论 —— **指出错在哪一步** |
| 墨与铅笔 | 系统陈述与学生书写 |

→ 主张：**做一张会批改的纸**，而不是一个管理后台。

### 1.2 关键判断

| 场景 | 结论 |
|---|---|
| 学生 | 12–15 岁，**不需要**童趣插画；需要"被认真对待"的体面感 |
| 审阅者（教师/管理员）| 需要**可信与克制**，花哨会削弱对结论的信任 |
| 综合 | **克制的纸感**，唯一用力处是"红笔指出错误"这一动作 |

> ⛔ 刻意**不做**儿童插画风。理由：产品核心是
> 「你的错因被找出来了」这一严肃结论，插画会削弱可信度。

## 2. 视觉规范

### 2.1 配色

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#FCFCFB` | 主背景（纸） |
| `--paper-sunk` | `#F5F6F7` | 次级区块底 |
| `--rule` | `#E3E5E8` | 分隔线（1px，**不用阴影**） |
| `--rule-strong` | `#C7CBD1` | 强分隔（表头、输入框边）|
| `--ink` | `#1A1D21` | 主文字、**主按钮** |
| `--ink-2` | `#5B6169` | 次级文字 |
| `--ink-3` | `#8A9099` | 占位、说明 |
| `--mark` | `#C8382D` | **批改红 —— 仅错误与批注** |
| `--mark-wash` | `#FDF2F1` | 红色浅底 |
| `--settled` | `#1D6B5C` | 已确认/通过（**低饱和青，非荧光绿**）|

**用色纪律**（可被测试检查）：

| 规则 | 说明 |
|---|---|
| R1 | `--mark` **只用于错误、待核对、阻止性提示**；不得用于按钮、链接、装饰 |
| R2 | 主按钮用 `--ink`（墨），不用彩色 —— 避免界面像玩具 |
| R3 | 状态色低饱和；禁止高饱和绿/蓝 |
| R4 | 前景与背景对比 ≥ 4.5:1 |

### 2.2 字体与字阶

| 角色 | 字族 | 说明 |
|---|---|---|
| 界面 | `-apple-system, "PingFang SC", "Microsoft YaHei"` | 黑体，用于控件与导航 |
| **学生内容** | `"Songti SC", "SimSun", serif` | ⚠️ **宋体** —— 教材本身就是宋体，用它把"题目区"与"界面区"在字体上分开 |
| 等宽 | `ui-monospace, "SF Mono", Menlo` | 运行标识、代码类数据 |

| Token | 尺寸 | 行高 | 用途 |
|---|---|---|---|
| `--t-display` | 26px | 1.3 | 页面主标题 |
| `--t-title` | 18px | 1.4 | 区块标题 |
| `--t-body` | 15px | 1.7 | 正文（**行宽 < 80 字符**）|
| `--t-note` | 13px | 1.6 | 次级说明 |
| `--t-mark` | 13px | 1.5 | 批注 |

> ⚠️ 中文正文行高取 1.7（高于英文惯例），宋体需要更松的行距。

### 2.3 间距与结构

| Token | 值 | 说明 |
|---|---|---|
| `--s-1` | 4px | 紧 |
| `--s-2` | 8px | 控件内 |
| `--s-3` | 12px | 元素间 |
| `--s-4` | 20px | 区块内 |
| `--s-5` | 32px | 区块间 |
| `--s-6` | 48px | 页面边距 |

**圆角**：仅 `4px`（输入框、按钮）。⚠️ 区块**不使用圆角或阴影** —— 用 1px 线与留白分隔，避免"卡片套件"观感。

### 2.4 版式原则

- **左对齐**，不用居中、不用两端对齐
- 行宽上限 **72 字符**
- 区块纵向节奏：标题 → 4px → 内容 → 32px → 下一区块

## 3. 布局结构

### 3.1 应用外壳

```
┌────────────────────────────────────────────────┐
│ 顶栏 56px：产品名 │ 租户 │ 退出                │
├────────────┬───────────────────────────────────┤
│ 侧栏 208px │ 内容区 max-width 880px            │
│ 分组导航   │  padding 32px                     │
└────────────┴───────────────────────────────────┘
```

**断点**

| 断点 | 行为 |
|---|---|
| ≥ 1024px | 侧栏常驻 |
| 768–1023px | 侧栏收窄至 64px，**仅图标 + 悬停展开** |
| < 768px | 侧栏转**顶部横向滚动标签条**；内容单列 |
| < 480px | 顶栏压缩，隐藏次要信息 |

### 3.2 批改纸区块（产品签名）

```
┌─ 2px 红边（仅错误时出现）
│
│  ← 内容区，缩进 20px
│
└─
```

- 左红边 = **老师批注栏**，只在"指出错误"时出现
- 红边内侧 20px 缩进，形成天然的注记关系
- 正确步骤用 `--settled` 小勾，不占版面

## 4. 状态设计（完整覆盖）

每个数据区块**必须**实现这 5 态：

| 状态 | 视觉 | 文案原则 |
|---|---|---|
| **默认** | 内容渲染 | — |
| **加载** | 骨架（**呼吸的纸面**，非灰色条）| — |
| **空** | 一句说明 + **一个下一步动作** | 空是邀请行动，不是道歉 |
| **错误** | 红边 + 原因 + 可执行的下一步 | ⛔ **不道歉、不写「出错了」** |
| **未开放** | 纸面 + 缺口编号 + 原因 | 与"空"区分：空=查了没有，未开放=没接口 |

### 4.1 加载：呼吸纸面

⛔ **不用灰色微光条**（AI 默认）。改为整块纸面做极缓慢的明度呼吸：

```css
@keyframes breathe { 50% { background: #F0F1F0; } }
@media (prefers-reduced-motion: no-preference) {
  .loading { animation: breathe 2.4s ease-in-out infinite; }
}
```

### 4.2 文案规范

| 场景 | ❌ | ✅ |
|---|---|---|
| 空列表 | 「暂无数据」| 「还没有发起过辅导。**发起第一道错题** →」|
| 错误 | 「请求失败」| 「连不上分析服务。**检查后端是否在运行**后重试」|
| 未开放 | 「功能开发中」| 「归因结果还没接后端。**已由 P3 阶段承接**」|
| 按钮→回执 | 提交 → 已提交 | 保存设置 → 设置已保存 |

> 动作词贯穿全流程：按钮说"发起辅导"，回执就说"辅导已发起"。

## 5. 可达性基线

| 项 | 要求 |
|---|---|
| 键盘 | 焦点环 **2px `--ink`** + 2px 偏移，全站可见 |
| 对比度 | ≥ 4.5:1（正文）/ ≥ 3:1（图形）|
| 动效 | 尊重 `prefers-reduced-motion` |
| 语义 | 表单 label 关联；错误用 `role="alert"` |
| 触摸目标 | ≥ 40×40px（学生可能用平板）|

## 6. 与现有实现的差异

| 项 | FE-D2 现状 | 本规范 |
|---|---|---|
| 区块分隔 | 等圆角卡片 + 微光骨架 | **1px 线 + 留白** |
| 强调色 | 蓝 `#0969da` 主按钮 | **墨色**主按钮，红色仅批改 |
| 字体 | 全站黑体 | **题目区宋体** |
| 加载 | 灰色微光条 | **纸面呼吸** |
| 响应式 | 单断点 | **3 断点**，含侧栏图标化 |
