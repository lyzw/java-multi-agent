## 0. 范围决策：为什么是 P5 + P6，而 P4 另立一片

| 页面 | 缺口 | 后端 | 本片 | 理由 |
|---|---|---|---|---|
| **P5 结果页** | G5 | ✅ P4-D10 已落地 | ✅ **接线** | ⛔ **当前渲染的是编造的解题过程**（见 §1.1）——最高优先级 |
| **P6 画像页** | G6 | ✅ P4-D09 已落地 | ✅ **接线** | 契约已冻结；且 `weaknesses` 的结构化形态**必须**在前端改造（FE-D09 L-4 遗留）|
| **P4 进度页** | G3 | ✅ P4-D09 已落地 | ❌ **不做** | 进度页已有 SSE 轮询链（FE-D6 刚做过生命周期审计）；再加一条状态轮询链会**引入第二条生命周期**，风险与收益不匹配 → 另立 **FE-D9** |

> ⚠️ **P4 不做的诚实理由**：不是「做不了」，是**「一次只引入一条轮询链」**。
> FE-D6 刚把 SSE 轮询的生命周期（`emit` 的 `stopped` 守卫、路由完整性）审干净，
> 此时再叠一条独立的状态轮询，会让「两个轮询谁先停、谁负责终态判定」变模糊。

## 1. 现状实测

### 1.1 ⛔ P5 当前渲染的是**编造内容**（逐条列出）

`RunResultPage` 的 `Unavailable` 组件结构是 `{children}` **在前**、提示框**在后**
（FE-D09 L-5）→ **假数据在提示之前就被用户看到**。被编造的内容有：

| # | 编造内容 | 位置 | 危害 |
|---|---|---|---|
| 1 | 「分子分母同乘 √3，把分母里的根式消掉。」 | 解题步骤 第 1 步 | 学生看到**不存在**的解题过程 |
| 2 | 「分母化为正，符号丢了」 | 解题步骤 第 2 步（标为「这里错了」）| 学生看到**不存在**的错因 |
| 3 | 「根式分母有理化时，若分母含 a−√b 且 b 大于 a，分母会变成负数。你这里漏了负号，符号就反了。」 | 第 2 步批注 | **编造的知识点讲解** |
| 4 | 「分子分母同时除以 √3，得到最简形式。」 | 解题步骤 第 3 步 | 编造步骤 |
| 5 | 「符号处理不当」 | 错因归类 chip | 编造的错因分类 |
| 6 | 「根式分母有理化」 | 涉及知识点 chip | 编造的知识点 |

> ⚠️ 这不是「占位不够优雅」，是**向学生展示不存在的内容**。
> 与「接口没接上」相比，**假数据是更坏的状态**：
> 它让系统**看起来能用**，而实际上什么都没发生。

### 1.2 P6 的两个具体问题

| # | 问题 | 说明 |
|---|---|---|
| 1 | `pickWhitelisted` 把 `weaknesses` 过滤成 `string[]` | 后端 G6 返回的是**结构化对象** `{knowledgePoint, errorType, confidence, createdAt}` → 现有过滤会**丢掉全部条目**（FE-D09 L-4）|
| 2 | 页面对 `notFound` 无感知 | 后端对不存在的学生返回 **200 + `notFound:true`**（不返回 404，避免枚举 studentId）→ 前端必须区分「没有这个学生」与「有但没数据」|

### 1.3 后端契约（已冻结，前端按此实现）

**P5** `GET /api/runs/{runId}/result`（P4-D10 §2）：

```jsonc
{
  "runId": "...", "state": "SUCCEEDED", "completedAt": "...", "errorCode": null,
  "explanation": "...",                 // 仅成功时有值
  "weaknesses": [ { "knowledgePoint": "...", "errorType": "...", "confidence": 0.8 } ],
  "steps": [ { "number": 1, "state": "...", "stepType": "...", "output": "..." } ],
  "reconciliation": { "pending": false, "operations": [] }
}
```

**P6** `GET /api/profiles/{studentId}`（P4-D09）：

```jsonc
{ "studentId": "stu_...", "grade": "初二", "subject": "数学",
  "weaknesses": [ { "knowledgePoint": "...", "errorType": "...", "confidence": 0.8, "createdAt": "..." } ],
  "notFound": false }
```

## 2. 前端契约与诚实边界

### 2.1 三态渲染（P5 / P6 通用）

| 态 | 条件 | 渲染 |
|---|---|---|
| 加载中 | 请求未完成 | `Loading` |
| 出错 | 请求失败 | `ErrorState`（**可重试**）+ 归一化原因 |
| 有数据 | 请求成功 | 真实内容 |

> ⚠️ **「出错」与「空」必须区分**（既有骨架测试 T1 已确立该纪律）：
> 「没读到」→ 可重试的错误；「读到了但没有内容」→ 诚实的空态 + 下一步。
> 把两者混同会让用户反复刷新等一个永远不会来的结果。

### 2.2 诚实边界（P5）

| 数据 | 生产实际状态 | 前端处置 |
|---|---|---|
| `explanation` | ✅ 有（模型输出）| 渲染；**渲染前做 C6 敏感词扫描** |
| `weaknesses` | ❌ 恒空（真实模型接入前）| **真实空态**：「这次分析没有记录到错因」+ 说明原因（模型尚未接入），**绝不编造错因** |
| `steps` | ❌ 恒空（`run_step` 无写入方）| **真实空态**：「没有步骤记录」+ 说明原因，**绝不编造步骤** |
| `reconciliation` | ✅ 恒存在 | 恒渲染该分区；`pending=true` 时**醒目**列出未决操作 |

> ⚠️ **「空态」与「占位」是两件事**：
> 占位 = 「功能没接上」（→ 用户不该来这个页面）；
> 空态 = 「接上了，确实没有」（→ 用户该知道下一步做什么）。
> 本片把 P5 从占位改成空态，**前提是空态文案必须诚实说明原因**。

### 2.3 诚实边界（P6）

| 数据 | 生产实际状态 | 前端处置 |
|---|---|---|
| `notFound=true` | 学生不存在 | 「找不到这个匿名编号」+ 不显示任何画像区块 |
| `grade` / `subject` | ✅ 有 | 渲染 |
| `weaknesses` | ❌ 恒空 | **真实空态**：「还没有记录到薄弱点」+ 说明原因 |

### 2.4 C5 / C6 / C7 三条红线的落实

| 红线 | 本片处置 |
|---|---|
| **C5** 不显示教材引用/页码/出处 | **结构上不设**该区块（沿用现状）；且后端响应**不含**任何引用字段（P4-D10 K-9），双重保证 |
| **C6** 结果不得含学生身份信息 | **渲染前**对 `explanation` 做敏感词扫描（复用既有 `findLeakedFields` + `scanText`）；命中则**拦截该字段并提示**，**不静默删除内容** |
| **C7** 结果不落 localStorage | 仅内存（既有纪律，不变）|

> ⚠️ **C6 扫描命中时的处置**：**拦截该字段 + 明确提示**，
> **不是**静默删掉（静默删会让用户以为模型没提这件事），**也不是**整页报错
> （那会让「模型偶然复述了学号」变成整页不可用）。

### 5.2 顺带修正的两处「契约之外的东西」

| # | 问题 | 处置 |
|---|---|---|
| 1 | ⛔ 界面文案提到 **`RECONCILIATION_REQUIRED`** | 该状态**不在 `run_state` 枚举里**（P4-D10 §1.4 实测）→ 在界面提它等于告诉用户一个**永远不会出现的状态**。文案改为只提 `UNKNOWN`；骨架测试同步改为「**必须提 UNKNOWN，且不得提 RECONCILIATION_REQUIRED**」|
| 2 | ⚠️ `pickWhitelisted` 遇 `null` 元素会 **TypeError 白屏** | 加对象判定：非对象元素降级为 `{knowledgePoint:'', errorType:'', confidence:null}`，不崩、不原样透传 |

> ⚠️ 第 2 项是**白名单实现自身的健壮性缺口**——
> 「白名单」的本意是抵御脏数据，但实现本身先被脏数据打死了。
> 与 P4-D09 L-4 是同一处契约变更（`string[]` → 结构化对象）的**下游后果**。
