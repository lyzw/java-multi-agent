## 1. 三条硬约束（不可协商）

### 1.1 ⛔⛔ P9 没有「重试」，而且**永远不会有**

FE-01 §P9 原文：「禁止提供一键重试（盲目重放 = Sev-0）」。
UNKNOWN 的定义是「副作用是否已经发生**不知道**」——
重放就是在「可能已经改了学生数据」之上再改一次。

本片的三重锁：

| 层 | 手段 |
|---|---|
| 类型 | `Disposition` 类型里**没有** `RETRY`（编译期拒绝） |
| 后端 | `UnknownOperationPort.Disposition` 枚举里**没有** `RETRY`（协议层拒绝，400） |
| UI | 处置面板只列三个**终态归档**选项；页面顶部常驻「为什么没有重试」说明 |

### 1.2 ⛔ 过期审批**不提供**批准按钮

后端对过期审批返回 409。让用户点一个**注定失败**的按钮是产品缺陷——
正确的做法是按钮不存在 + 常驻说明「已过期，不可批准」。

### 1.3 ⛔ 不得编造后端没有的东西

| 曾经的编造 | 处置 |
|---|---|
| FE-01 §P7 列了「学科」「耗时」两列 | ⛔ `run` 表**没有** `subject` / `duration` 列 → 本片**不渲染**这两列，并在页面上写明原因 |
| FE-01 §P9 要求区分 `UNKNOWN` / `RECONCILIATION_REQUIRED` | ⛔ 实测 `tool_operation_state` **没有** `RECONCILIATION_REQUIRED` → 改为展示真实枚举（见 §2.3） |
| `errorCode` 字段 | ✅ 展示，但当前生产无写入方（P4-D12 L-1）→ 恒为 `null`，页面不因此说「无失败原因」 |

> 与 FE-D8 同源纪律：**向用户展示不存在的内容，比不展示更糟**。

## 2. 契约消费要点

### 2.1 游标分页（keyset），不是页码

后端冻结的是 `limit + cursor`（`nextCursor` 为 `null` 即没有更多）。

| 规则 | 实现 |
|---|---|
| 只有 `nextCursor !== null` 才显示「加载更多」 | 否则点了必然得到空列表，白烧治理桶配额 |
| **改筛选条件必须丢弃游标** | 拿旧筛选的游标查新筛选的下一页 → 空页，而空页看起来像「这个租户没数据」 |
| 游标**不透明** | 前端只原样回传，不解析、不构造 |

### 2.2 五态不可混淆

沿用 FE-D3 五态：加载 / 空 / 错误 / 数据 / 未开放。
本片把 P7~P10 从「未开放」推进到前四态，**「未开放」态在这四页不再出现**。

### 2.3 `UNKNOWN` 与「已核对」的区分方式（实测更正）

FE-01 §P9 写的是「区分 `UNKNOWN` / `RECONCILIATION_REQUIRED`」，但实测枚举是：

```
PENDING · IN_FLIGHT · SUCCEEDED · FAILED · UNKNOWN
RECONCILED_SUCCEEDED · RECONCILED_ABSENT · MANUAL_DISPOSED
```

**没有 `RECONCILIATION_REQUIRED`**（P4-D10 已对 `run_state` 记录过同一问题）。

真实区分是：**`UNKNOWN`（尚未核对） vs 三个已核对终态**。
故页面同时展示中文标签与**原始枚举名**——后者是搜索、导出、跨系统对齐的依据。

## 3. 限流纪律

| 链 | 桶 | 频率 |
|---|---|---|
| 治理列表查询 | `GOVERNANCE_QUERY`（独立，120 次/60 秒） | **不自动轮询**，仅用户操作时请求 |
| 治理决策 | `GOVERNANCE_DECIDE`（独立，30 次/60 秒） | 仅点击时 |

> ⚠️ FE-D9 的配额表（进度页占 26 次/分，`EVENT_QUERY` 余量仅 4 次/分）
> **不受本片影响**——治理流量走独立桶。
> 但治理桶**按租户限流、多个运维共享**，故本片**不做任何自动轮询**。

### ⛔ 反证过程抓到的两件事

| # | 现象 | 结论 |
|---|---|---|
| **CP-1** | 首轮反证 T-A（拆掉页面的 `reset()`）→ 用例**仍绿** | 拆掉 {@code deps} 后 `reset()` 独立生效；拆掉 {@code reset()} 后 {@code deps} 独立生效——**二者是冗余双保险**。真正的反证必须**两道全拆** |
| **CP-2** | 骨架测试要求页面出现 `RECONCILIATION_REQUIRED` | ⛔ **该状态在 `tool_operation_state` 里根本不存在** → 断言自身是错的。已更正，并把命题交给治理页测试用真实 mock 重新断言 |

> **CP-1 的教训**：当两道保险**互相独立生效**时，
> 只拆一道的反证**必然是绿的**——它测的是「哪一道在起作用」，不是「机制是否承重」。
> **反证必须拆到「机制完全失效」为止。**
