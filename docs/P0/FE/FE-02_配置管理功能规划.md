## 0. ⚠️ 首要事实：后端配置体系几乎完全不存在

> **这是本文档最重要的结论**。配置管理页**不是"对接既有能力"，而是"从零新建"**。
> 以下全部为 2026-10-19 代码实测，非文档推断。

|---|---|
| `@ConfigurationProperties` 类 | **0 个**（`@ConfigurationPropertiesScan` 已开启但无目标类） |
| 配置读取方式 | 全部 `@Value` **逐个注入**，生产代码只读 **7 个键**，且全部集中在 `AuthConfiguration` |

### 0.3 ⚠️⚠️ 零保留配置是「配置与代码脱节」的最严重案例

yml 写 `confirmed-providers: "deepseek,minimax,workbuddy"`（三家已确认），
但生产装配用的是**硬编码空注册表**：

```java
// ApplicationConfiguration.java
return new ZeroRetentionGate(ZeroRetentionRegistry.empty(), Clock.systemUTC());
```

类注释坦承：「这意味着**所有供应商调用当前均被拒绝**，这是设计内的 fail-closed 行为」。

> **对前端的直接约束**：配置页**绝不能**展示"当前已确认供应商：deepseek/minimax/workbuddy"。
> 那是在展示一个 yml 里的字符串，而非系统真实行为。**展示即误导。**

### 0.4 三条治理约束的真实强制状态

| 文档约束 | 代码强制程度 | 位置 |
|---|---|---|
| **审批策略只能收紧不能放松** | 🟡 **算法已实现但未接入运行时**。`ApprovalRequirement.isRelaxationTo()` / `maxWith()` 存在，但 `PlatformConfig.Resolver` 生产零调用点 | `ApprovalRequirement.java` L43–54 |
| **高风险阈值变更须走 CHG 模板 + 审计留痕** | ❌ **仅文档约定，代码零实现** | — |
| **未成年人相关配置禁止运行时下调保护强度** | ❌ **仅文档约定，代码零实现**。`ZeroRetentionGate` 只做单点 fail-closed，无"单调性"比较逻辑 | — |

> ⚠️ **前端措辞红线**：不得写"后端会拦截放松操作"。
> 真实情况是——**后端目前不会拦，靠流程和人工**。
> 前端能提供的是**流程提示**，不是技术强制。

### 0.5 配置契约测试的保护范围

| 测试类 | 实测项数 | 保护对象 | 性质 |
|---|---|---|---|
| `ConfigFailClosedTest` | **19** | 3 个 run 配置键 + 审批收紧算法 + 快照隔离 | **算法语义**（测试自建 HashMap，不读 yml） |
| `ApplicationConfigTest` | **12** | 16 个 yml 键的文本快照 + 口令占位符 | **yml 文本不被误改**（非运行时校验） |

> ⚠️ 这两个测试**都不是运行时配置校验器**。
> 改了 yml 只要同步改测试就能通过。**前端不得把它们当作"后端会拒绝非法配置"的证据。**

## 1. 配置功能的目标与边界

### 1.1 目标

让配置从"改 yml + 重启"逐步演进为"**受控、可审计、fail-closed 的管理界面**"，
且**任何时候不降低安全强度**。

### 1.2 配置域全景（四区）

| 区 | 配置内容 | 归属 | 变更影响 |
|---|---|---|---|
| **A. 运行与容量** | 单 Run 成本/调用/步数上限、租户并发上限、试点租户数 | DEC-9 | 影响成本与过载 |
| **B. 工具与审批** | 工具风险级别映射、审批触发矩阵、审批 TTL、审批人范围 | DEC-11 | **安全门禁** |
| **C. 合规与零保留** | 零保留供应商登记、条款有效期、临期告警、数据分类策略 | DEC-10 | **未成年人保护** |
| **D. Agent 配置** | Agent 定义、版本、Prompt 模板、工具契约、发布校验 | FR-001/002 | 业务行为 |

> 四区中 **B/C 为安全高危区**，其 UI 约束最强（§4）。

### 1.3 明确不做

| 不做 | 理由 |
|---|---|
| MQ 队列拓扑在线修改 | `x-queue-type`/`x-delivery-limit` 一经声明不可更改，改类型需删队列重建（yml L44）。**误操作会丢消息** |
| 密钥/私钥管理 | 私钥走 KMS（P4），前端永不可见、不可编辑 |
| 直接编辑 yml 原文 | 绕过结构化校验；且多数键本就无人读取，改了也没用 |
| 前端本地"草稿配置" | 配置生效必须由服务端裁决，前端存草稿会给人"已配置"的错觉 |

## 2. 配置项清单与可写性分级

> **L1 只读** = 仅展示，不提供编辑入口
> **L2 可写（安全）** = 可编辑，仅能收紧
> **L3 可写（高危）** = 可编辑，须走审批/CHG 流程

| 区 | 配置项 | 当前 yml 值 | 生产是否生效 | 前端分级 | 理由 |
|---|---|---|---|---|---|
| A | `max-cost-per-run` | `2.00` | ❌ | **L3** | 成本上限，放宽=烧钱 |
| A | `max-llm-calls` | `12` | ❌ | **L3** | 同上 |
| A | `max-steps` | `20` | ❌ | **L3** | 防异常循环 |
| A | `max-concurrent-runs` | `5` | ❌ | **L3** | 放宽=下游过载 |
| A | `pilot.max-tenants` | `1` | ❌ | **L3** | 灰度控制 |
| B | `tool.risk-level-map` | 2 项 | ❌ | **L1 锁定** | 风险级别是**代码事实**（`ToolHandler.riskLevel()` 硬编码），配置仅是**校验镜像** |
| B | `approval.required-by-risk` | 3 项 | ❌ | **L2 只能收紧** | DEC-11 明令 |
| B | `approval.ttl` | `15m` | ❌ | **L2** | 延长 TTL=审批失效风险 |
| B | `approval.approver-scope` | `PARENT_OR_TEACHER` | ❌ | **L1 锁定** | DEC-6 合规边界 |
| C | `zero-retention.confirmed-providers` | 三家 | ❌ | **L3 + 证据强制** | 须 `evidenceRef` 非空 |
| C | `zero-retention.validity-months` | `12` | ❌ | **L3** | 直接影响闸门时效 |
| C | `zero-retention.expiry-warn-days` | `30` | ❌ | **L2** | 告警提前量 |
| D | Agent 定义/版本/Prompt | — | ❌ | **L3 + 发布校验** | 改配置影响业务行为 |
| — | `auth.jwt.*`（7 项） | — | ✅ | **L1 只读** | 认证链，改动=全员掉线风险；建议仅运维经 yml 修改 |
| — | `agent.mq.*` | — | ❌ | **不在配置页** | 见 §1.3 |
| — | `dr.rpo` / `dr.rto` | — | ❌ | **L1 只读** | 需演练后确认，非运行时调 |

### 2.1 ⚠️ 关于 `tool.risk-level-map` 为何是 L1 锁定

代码实测：工具风险级别是**工具实现类硬编码返回**的常量：

- `GetStudentProfileTool.riskLevel()` → `ToolRiskLevel.READ`
- `RecordWeaknessTool.riskLevel()` → `ToolRiskLevel.WRITE_PROFILE`

配置里的 `risk-level-map` **不是权威来源**。真实权威来源是 Java 代码。

> **因此前端只读展示配置值，并在页面上明示**：
> 「工具风险级别由服务端代码定义，配置项为校验镜像，两者不一致时以服务端为准」。
> ⚠️ 绝不能让管理员在这里改风险级别——那会给人"已降低风险"的错觉，而实际未生效。

## 3. 页面结构

### 3.1 路由与权限

| 路由 | 页面 | 所需动作 | 目标角色 |
|---|---|---|---|
| `/config` | 配置总览（四区导航 + 健康摘要） | — | `TENANT_ADMIN` `AGENT_AUTHOR` |
| `/config/runtime` | A 运行与容量 | `AGENT_MANAGE` | `TENANT_ADMIN` |
| `/config/tools` | B 工具与审批 | `AGENT_MANAGE` | `TENANT_ADMIN` |
| `/config/compliance` | C 合规与零保留 | `AGENT_MANAGE` | `TENANT_ADMIN` |
| `/agents` | D Agent 列表 | `AGENT_MANAGE` | `AGENT_AUTHOR` |
| `/agents/new` | D Agent 编辑器 | `AGENT_MANAGE` | `AGENT_AUTHOR` |
| `/agents/:id/versions` | D 版本与发布 | `AGENT_MANAGE` | `AGENT_AUTHOR` |
| `/config/audit` | 配置变更审计 | `AUDIT_READ` | `TENANT_ADMIN` |

### 3.2 页面详规

#### P14 配置总览 `/config`

| 区块 | 内容 |
|---|---|
| 四区导航卡 | 每区显示：项数、可编辑数、**是否存在"仅文档约定未强制"的约束** |
| 生效状态横幅 | ⚠️ 醒目提示：「当前多数配置项**尚未接入运行时**，修改后不会改变系统行为」 |
| 配置健康度 | fail-closed 自检结果、临期告警（如零保留条款到期倒计时） |

> ⚠️ **生效状态横幅是本页面最重要的元素**。没有它，管理员会以为改了就生效——
> 而实测是多数配置改了也没用。这是**诚实性要求**，不是免责声明。

#### P15 运行与容量 `/config/runtime`

每项一张卡片：当前值 / 状态标签 / 编辑入口。

| 状态标签 | 含义 |
|---|---|
| 🟢 已生效 | 后端有读取点，改后即时或下次生效 |
| 🟡 **仅配置未接线** | yml 有值但**生产无读取点** |
| 🔒 高危 | L3，须走 CHG 流程 |

**编辑交互（L3）**

1. 点击编辑 → 弹窗显示**当前值 + 新值 + 影响说明**。
2. 必须填写**变更理由**（不少于 10 字）。
3. 提交前展示 **CHG 模板摘要**（`P0-D03 §6` 九字段），引导补全。
4. 提交后进入**待审批**，而非立即生效。

**约束**：⚠️ 后端当前**无变更拦截**。若放宽成本上限，服务端**不会拒绝**。
因此前端须在放宽时**二次确认 + 醒目风险提示**，并在提交记录中标注
「本次变更未经服务端强制校验」。

#### P16 工具与审批 `/config/tools`

**B1 工具风险级别表**（只读）

| 列 | 内容 |
|---|---|
| 工具名 | `get_student_profile` / `record_weakness` |
| 服务端声明级别 | **从代码读取的真实值**（若接口提供） |
| 配置镜像值 | yml 中的值 |
| 一致性 | ✅ 一致 / ⚠️ **不一致（以服务端为准）** |

⚠️ **不得提供"添加工具"入口**。工具注册是**硬编码 Java 类**，
新增工具需写 `implements ToolHandler` + Spring 装配 + 加入 `ToolInvocationGate` 的 `handlers` List，
**不是页面上填个名字能解决的**。页面须明示这一点，避免误导。

**B2 审批触发矩阵**（L2 可写）

| 风险级别 | 当前配置 | 可选值 | 可写性 |
|---|---|---|---|
| `READ` | `NOT_REQUIRED` | `NOT_REQUIRED` / `OPTIONAL` / `REQUIRED` | ✅ 只能收紧 |
| `WRITE_PROFILE` | `OPTIONAL` | 同上 | ✅ 只能收紧 |
| `WRITE_EXTERNAL` | `REQUIRED` | 同上 | 🔒 **锁定** |

> **UI 必须实现"单向棘轮"**：
> 下拉框中**只会出现比当前更严格的方向**（`NOT_REQUIRED` → `OPTIONAL` → `REQUIRED` 单向）。
> 放宽方向**不在选项中**，而非"选了才报错"。
>
> 理由：`ConfigFailClosedTest` 已固化 `maxWith()` 语义
> （「配置试图放松 → 取更严格者」）。前端应与后端契约**同构**。

**B3 审批 TTL 与范围**

| 项 | 控件 | 约束 |
|---|---|---|
| TTL | 数字输入（分钟） | ⚠️ 建议**仅允许调小**（缩短有效期=更安全）。放宽须 CHG |
| 审批人范围 | 只读 | 🔒 `PARENT_OR_TEACHER` 由 DEC-6 冻结 |

#### P17 合规与零保留 `/config/compliance`

⚠️ **本页是全站合规要求最高的页面**，必须做到"宁可显示不出，不可显示错"。

**区块**

1. **⚠️ 生效状态警示**：若后端 `ZeroRetentionRegistry` 为空 →
   横幅「**当前所有供应商调用均被拒绝（设计内 fail-closed）**」。
   **不得**展示 yml 里的三家供应商名单作为"已确认"。
2. **供应商登记表**：`providerId` / 状态（`PENDING`/`CONFIRMED`/`REJECTED`/`EXPIRED`）/ 证据引用 / 到期日。
3. **新增登记表单**：`evidenceRef` **必填且非空**。
4. **临期倒计时**：距到期 < `expiry-warn-days` 时高亮。

**⛔ 合规红线（页面级）**

| # | 红线 | 理由 |
|---|---|---|
| CM-1 | **`evidenceRef` 为空则禁止提交** | `ZeroRetentionGate.confirm()` 强制非空，**口头承诺不构成证据** |
| CM-2 | 状态流转仅允许 `PENDING → CONFIRMED/REJECTED`；`EXPIRED` 由系统判定 | 防止手工把 `REJECTED` 改回 `CONFIRMED` |
| CM-3 | 页面**永不显示**学生个人信息 | PIPL 白名单仅 3 类字段 |
| CM-4 | 显示供应商状态时须区分"**配置声明值**"与"**运行时实际值**" | 依 §0.3，两者可能不一致 |

## 4. 配置红线的 UI 落地方式

> 原则（沿用项目经验「序列化敏感数据用白名单不用黑名单」）：
> **约束要落在"控件不存在"或"选项不可选"，而不是"选了会报错"。**

| 约束 | ❌ 错误做法 | ✅ 正确做法 |
|---|---|---|
| 审批只能收紧 | 下拉框列出全部值，提交时校验 | **下拉框只列收紧方向**，放宽值不在选项中 |
| 风险级别不可改 | 可编辑文本框，提交时报错 | **纯只读文本**，无编辑控件 |
| 审批人范围锁定 | 可下拉选择 | **只读展示** + 锁定图标 |
| `evidenceRef` 必填 | 可空提交，后端报错 | **输入框即必填**，空值时提交按钮 disabled |
| 高危项须审批 | 直接保存生效 | **保存=提交变更申请**，状态显示"待审批" |
| 配置未接线 | 像正常配置一样展示 | **状态标签 + 横幅明示未生效** |

## 5. 配置生效机制（前端须如实呈现）

| 配置形态 | 生效方式 | 前端呈现 |
|---|---|---|
| yml + 重启（当前唯一方式） | 改文件 → 重启 | 「**修改后需重启生效**」+ 提交后生成变更工单 |
| DB 存储（**待建**） | 保存即生效（或需显式发布） | 「保存后即时生效」 |
| 快照隔离（Run 级） | Run 创建时冻结 | 「本次变更不影响已创建的 Run」 |

> ⚠️ **不得**在未接线的情况下显示"保存成功即生效"的文案。
> 宁可显示"需重启"也不要误导——**误导性文案比功能缺失更有害**。

## 6. 后端配置侧缺口清单

### 6.1 ⚠️ C8/C9 的特殊性

这两项**不是"缺接口"，而是"已有配置与代码脱节"**。

| 项 | 现状 | 影响 |
|---|---|---|
| C8 | 16 个 yml 键无生产读取点 | 配置页即使建好，**展示和修改的值都不影响系统行为** |
| C9 | 零保留用硬编码空注册表 | 合规页**无法展示真实状态**；yml 的三家名单是摆设 |

> **优先级建议**：C8/C9 应**先于** C1/C3（建表建接口）完成。
> 否则会建出一套"看起来能配置、实际改了没用"的系统——
> **这比没有配置页更危险**，因为它会让管理员误以为已调整了安全参数。

> ✅ **C8 已由 P4-D11 关闭**（2026-10-20）。实测更正本节的过时数字：
> 「16 个键无生产读取点」**已过时**——P4-D03/D04/D05 已把限流、背压、保留期、
> Worker、试点租户数等真正接到了运行时。
> **P4-D11 实测基线**：`application.yml` 业务域共 **56 个叶子键**，
> 其中 **46 个有读取点、10 个无**；本片关闭其中：
> ① **3 个运行上限**（成本/步数/调用）——此前生产快照**硬编码**
> （成本上限 10.00），yml 的 2.00 无任何生产读取点，**声明比真实敞口紧 5 倍**；
> ② **风险映射**——由「惰性镜像」升级为**启动守卫**（与工具代码声明不一致即拒绝启动）；
> ③ **1 项虚构声明**（`reconcile` 队列在代码中从未落地）→ 已删除。
> 详见 [P4-D11](../P0/P4/P4-D11_C8配置接入运行时.md)。
