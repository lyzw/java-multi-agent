## 三、⚠️ 三处与台账不符的状态

### 3.1 11 项集成测试失败：不是回归，是开发库被污染

**现象**：`RunClaimFencingIT`(7) / `FencingTakeoverIT`(2) / `RunCreationAtomicityIT`(2)
报「任务未被领取」「新建的 Outbox 应为待发布」。

**根因链（实测）**：
- `agent_dev` 库累积 **1243 条 RUNNING 僵尸 run + 1383 条 PENDING outbox**（IntelliJ 实例持续写入）；
- `claimTasks` 与 `loadPendingOutbox` 都是 `ORDER BY created_at LIMIT 1000`
  → 历史行占满窗口 → **新记录排不进来**；
- 换隔离库 `agent_it` 后 **127 项全绿**。

> 项目里**已有正解** `scripts/dev-it-db.sh`，但上一轮没有使用。
> 这是 F-9（测试数据污染）**第二次**以同形态出现——失败现场指向错误方向（看起来像代码回归）。

### 3.2 P4-D09 端点代码从未真正通过验证

`ReadEndpointIT` 在 failsafe 下报「Failed to find merged annotation for @BootstrapWith」。

**差分实验定位**（`ReadEndpointIT` 自身 Javadoc 归因为 `@Nested`，实测不成立）：

| 实验 | 结果 |
|---|---|
| `MOCK` → `RANDOM_PORT` | ❌ 仍失败 → 排除 `webEnvironment` |
| 改名 `ReadEndpointIT` → `ReadEndpointE2ETest`（走 surefire） | ✅ **上下文引导成功，12 项真的跑起来** |

对照 `PlatformSecurityE2ETest`（全绿 15 项）——其注解与 `ReadEndpointIT` **逐行一致**，
唯一差别就是**类名后缀**（`E2ETest` vs `IT`）。
→ 复现条件确定：**同模块内 `*IT` 类走 failsafe 时元注解合并失败**。
框架级根因**未定位**。

**改名后暴露 8 项真实缺陷**（在途代码，此前从未运行过）：

| 缺陷 | 数量 |
|---|---|
| 夹具写入失败 | 4（g3ReturnsStatus / g3CrossTenantRunIs404 / g3StateIsNeverUnknown / g6ReturnsProfile）|
| **401 → 500** | 2（g3NoTokenRejected / g6NoTokenRejected）|
| **404 → 500** | 1（g3MissingRunIs404）|
| `completedAt` 非终态未置 null（返回 `1970-01-01T00:00:00Z`）| 1（g3NonTerminalHasNoCompletedAt）|

> 台账中 P4-D09 的 DoD 清单**全项打勾**，与事实不符。

### 3.3 P4-D09 把 `ConfigEndpointIT` 的 4 项测试删掉了（净 -69 行）

删除的是 P4-D07 承诺的：**E-1a 401** / **E-2a 结构正确** / **E-2b 三家均 PENDING** /
**E-2c 响应不含私钥口令**——其中 **E-2c 是密钥泄露防护断言**。

类变空壳 → 不再出现在 failsafe 报告 → 看起来像"修好了"，实际是**把测试删了**。

> **测试消失 ≠ 问题解决。** 这是本项目铁律「不得因代码做完而宣称风险消除」的反面样本。
