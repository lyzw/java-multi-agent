## 1. 目的与约定

本文把 v3.1 架构能力转换为可评审的产品/系统需求。具体行业场景尚未提供，因此业务流程和业务验收指标以 `[待确认]` 标记；技术需求按 v3.1 约束建立初始基线。需求状态：`Draft`、`In Review`、`Approved`、`Deferred`、`Rejected`。

优先级：
- **P0**：首期闭环/安全/一致性所必需；不满足不得进入下一阶段。
- **P1**：首期需要，但可在不破坏核心安全与数据一致性的前提下按阶段交付。
- **P2**：明确延期或后续增强。

## 2. 产品概述

系统为多租户 SaaS 平台。已认证用户在其授权租户范围内创建和发布 Agent；平台根据不可变执行快照创建异步 Run，由 Worker 执行单 Agent Loop；模型通过 ModelGateway 接入，工具调用通过 Tool SPI 并经过参数校验、执行时授权、必要审批及预算检查。运行状态、步骤、事件、工具操作和计量记录持久化，可查询、审计和恢复。

## 4. 业务流程需求

### BR-01 首个真实业务场景

业务方必须指定一个边界清晰、可评测的首期场景。
- 输入数据/触发方式：[待确认]
- Agent 预期完成的工作：[待确认]
- 可使用的工具和数据范围：[待确认]
- 期望输出及成功判定：[待确认]
- 人工介入/审批节点：[待确认]
- 失败后业务如何处理：[待确认]

### BR-02 Agent 生命周期

Agent 应支持草稿、版本化、发布校验和发布后执行快照追溯。每次 Run 绑定不可变执行快照，避免运行期间配置变化造成行为不可解释。

### BR-03 Run 执行与追踪

用户提交 Run 后获得可查询的 Run 标识；平台异步执行，用户可查看状态、步骤、事件和最终结果。取消为协作式停止，不承诺撤销已发出的外部副作用。

### BR-04 工具副作用治理

平台必须在工具执行前完成权限、参数、审批和预算检查；记录逻辑 ToolOperation 与调用 attempt。若外部调用结果不确定，进入 UNKNOWN 并通过对账或人工处理解决，不将 UNKNOWN 当作普通失败盲目重试。

## 6. 非功能需求（NFR）

| ID | 维度 | 要求 | 数值/策略 |
|---|---|---|---|
| NFR-001 | 安全 | 认证与资源授权分离；租户 ID 不以客户端输入作为授权依据 | 具体 IAM 映射待确认 |
| NFR-002 | 数据隔离 | 关键表有租户归属和隔离测试；RLS 与连接池事务上下文需验证 | P1 PoC 冻结策略 |
| NFR-003 | 一致性 | PostgreSQL 是 Run/事件/Outbox/操作账本的权威事实源 | 不以 Redis/MQ 为唯一事实源 |
| NFR-004 | 幂等 | 请求幂等键有操作域、请求摘要冲突语义和保留期 | 保留期待 ADR/业务确认 |
| NFR-005 | 可恢复性 | UNKNOWN 不盲目重放；租约/fencing 可测试 | 测试场景见 P0-D04 |
| NFR-006 | 性能 | 建立并发、时延、队列积压、事件吞吐基线 | 数值待容量评估，禁止预先承诺 |
| NFR-007 | 可观测性 | 关键链路具备 correlation/run ID、日志、指标和 Trace | 指标标签不使用高基数敏感字段 |
| NFR-008 | 隐私 | Prompt、工具结果、日志、Trace 和对象内容有独立脱敏/保留策略 | 数据分级/保留期待确认 |
| NFR-009 | 可维护性 | 模块边界清晰，接口契约与自动化测试同步 | 代码评审与 CI 门禁待 P1 定义 |
| NFR-010 | 灾备 | RPO/RTO、备份频率和恢复验证需有业务批准 | 数值待确认，不作为当前承诺 |

## 7. 错误与异常需求

- 参数校验失败、认证失败、授权失败、资源不存在、状态冲突、限流、下游不可用需有稳定错误分类。
- 模型/工具调用需有超时与错误映射；重试策略按错误类型和副作用语义决定。
- MQ 重复投递、延迟、乱序或消费者崩溃不能导致不受控副作用。
- 取消、超时、Worker 崩溃与外部响应丢失必须有确定状态或 UNKNOWN 处理路径。
- 未解决的 UNKNOWN、死信和预算对账差异必须可观测、可分派责任人、可审计处置。

## 8. 数据与审计需求

核心对象至少包括 Tenant、Agent/AgentVersion、ExecutionSnapshot、Conversation（如启用）、Run、RunStep、ToolOperation/Attempt、Approval、RunEvent、OutboxEvent、Usage/BudgetReservation、AuditRecord。字段、约束、索引和生命周期以 v3.1 数据模型及 P1 领域模型/数据字典为准。

需要业务确认：数据分类、敏感字段、数据区域、保留期、删除/导出请求、审计可见角色及人工对账权限。

## 9. 业务规则待确认清单

1. 首个真实业务任务及其成功/失败定义。
2. 租户、组织、用户、服务账号的关系与权限模型。
3. 高风险工具清单、审批规则、是否要求职责分离。
4. 每租户并发、单 Run 时长、最大步数、模型调用次数和成本上限。
5. 取消后已发起的外部动作由哪个业务系统负责查询/冲正。
6. UNKNOWN 的人工处理角色和允许的处置动作。
7. 事件、Prompt、工具输入输出和附件的保留、脱敏、删除要求。
8. 目标部署环境、可用区、RPO/RTO 与支持时段。

## 10. 需求变更流程

新增或修改需求需提交：变更原因、业务价值、优先级、影响模块/API/DDL/状态机、安全与隐私影响、测试证据、排期影响、回滚方案。经产品负责人和技术负责人评审后更新需求 ID、验收矩阵及对应 ADR/设计文档。

## 变更补充（v0.2）：多级 Agent 编排需求

### 新增业务流程 BR-05：Agent 委派
RouterAgent 根据已发布路由策略选择允许的业务 Agent；业务 Agent 可在其发布定义允许的范围内委派子 Agent。每次委派产生独立 `AgentInvocation` 记录，关联父子执行、调用链、目标固定版本、预算与终态。子 Agent 结果按声明的输出契约返回，不允许把任意子 Agent 输出直接提升为系统指令。

### 新增功能需求
| ID | 需求 | 优先级 | 初始验收条件 | 状态 |
|---|---|---|---|---|
| FR-021 | 多级 Agent 定义 | P0 | `AgentDefinition` 可声明编排模式及固定子 Agent 引用；旧配置无字段时默认 `LEAF` | Draft |
| FR-022 | AgentInvocation 契约 | P0 | 输入/输出 Schema、父子关系、trace、超时、状态、失败策略和目标 release 可校验、可审计 | Draft |
| FR-023 | 发布闭包与环路检测 | P0 | 发布时递归解析固定版本，拒绝循环引用、缺失引用、跨租户引用和未发布版本 | Draft |
| FR-024 | 委派运行时约束 | P0 | 强制最大深度、最大子调用数、超时与预算；越界请求在调用前拒绝 | Draft |
| FR-025 | 逐跳授权 | P0 | 每次委派重新校验调用方委派权限、主体/租户授权和 `authzVersion`；不得继承父 Agent 权限 | Draft |
| FR-026 | 委派可观测与恢复 | P1 | 父子执行可追踪；超时/取消/子调用结果不确定有明确状态，不盲目重放副作用 | Draft |
| FR-027 | 编排结果聚合 | P1 | `SEQUENTIAL` 按确定顺序执行并按契约聚合；失败策略明确，输出通过父 Agent Schema | Draft |

### 新增非功能要求
- `NFR-011` 可追溯性：每个子调用关联 `parentExecutionId`、`invocationId`、`traceId`、目标 release 和闭包指纹。
- `NFR-012` 有界性：每次 Run 具备最大委派深度、子调用次数、总超时和预算上限；默认值必须由配置显式给出或使用经过批准的平台默认值。
- `NFR-013` 安全：路由模型输出仅是候选选择，不是授权依据；服务端校验后才可委派。
