## 1. MVP 定义

MVP 的目标不是做完所有 Agent 平台能力，而是交付一条**可被真实业务验证、可授权执行、可追踪、失败可解释**的单 Agent 闭环：

> 创建/发布 Agent → 绑定不可变执行快照 → 创建 Run → Outbox/MQ 投递 → Worker 执行 → ModelGateway 决策 → 通过 Tool SPI 调用受控工具 → 持久化步骤/事件/结果 → 查询轨迹与审计。

首个业务场景及工具由业务方在 P0 冻结；在此之前，工程可用模拟业务数据和只读工具进行技术验证，但不能将模拟场景视为业务验收完成。

## 2. 首期必须包含

| 能力域 | 首期范围 | 不可妥协的验收边界 |
|---|---|---|
| Agent 管理 | 草稿、版本、校验、发布、不可变快照 | Run 可追溯至准确配置/版本 |
| 执行引擎 | 单 Agent Loop、步骤持久化、检查点/结果交付的最小实现 | 任务状态可查询，失败有明确结果 |
| Run 生命周期 | 创建、查询、协作式取消、受控重试 | 状态迁移合法且并发安全 |
| 异步执行 | PostgreSQL + Outbox + 单一主 MQ + Worker | DB 状态与 Outbox 原子；消费幂等 |
| 模型接入 | ModelGateway 抽象、超时、错误映射、基础用量采集 | 领域层不依赖供应商专属类型 |
| 工具系统 | Tool SPI、Schema 校验、执行时授权、工具记录 | 模型不能绕过服务端授权直接执行工具 |
| 副作用治理 | ToolOperation 账本、稳定幂等语义、UNKNOWN/对账路径 | 未知结果不盲目重放 |
| 租户安全 | TenantContext、RBAC/资源授权、RLS 方案验证 | 跨租户访问拒绝并有自动化证据 |
| 审批 | 针对具体 operation、参数摘要、目标资源和有效期的基础审批 | 消费审批前检查状态/取消；恢复路径明确 |
| 预算计量 | 原子预留、结算、幂等 usage 事件 | 并发不能超发；UNKNOWN 不随意释放预留 |
| 事件 | Run Event 持久化、SSE/Last-Event-ID 基础续传 | 授权校验和游标过期语义明确 |
| 可观测性 | 核心指标、日志、Trace 关联、告警/死信最小闭环 | 指标基数受控，日志不泄漏秘密 |
| 工程质量 | CI、迁移脚本、单元/集成/契约/E2E 测试 | 代码合并不等于阶段验收 |

## 3. 首期明确不做

| 非目标 | 原因 | 重新纳入的条件 |
|---|---|---|
| 通用多 Agent 协作 | 增加调度、上下文和故障语义复杂度 | 单 Agent 业务价值被验证并形成独立需求 |
| 通用 DAG/工作流引擎 | 超出首期闭环必要范围 | 有明确业务流程、用例和产品负责人 |
| 插件市场 | 涉及分发、版本兼容、供应链与租户治理 | 插件治理模型和安全沙箱经过专项评审 |
| 任意脚本执行/不可信插件沙箱 | 高风险执行面，不属于 Tool SPI 的默认能力 | 独立威胁模型、隔离方案和安全批准 |
| 完整商业账单、发票与支付 | 首期只需要预算和 usage 一致性 | 商业计费需求及财务口径被确认 |
| 通用 BPM 审批中心 | 首期仅约束具体工具操作 | 多业务线复用需求成立且另立项目范围 |
| 未经验证的复杂 RAG/知识库 | 尚无业务需求和数据边界输入 | 有数据 owner、评测集、访问模型和收益指标 |
| 无限期保存所有 Token 流 | 隐私、成本和存储压力不可接受 | 明确业务理由、保留策略与费用审批 |
| 固定吞吐/SLA 承诺 | 尚未完成目标环境容量评估 | 完成压测并由业务/运维批准 SLO |
| 自动重试所有失败工具 | 可能重复执行外部副作用 | 仅允许针对幂等/可查询且策略明确的操作 |

## 4. 关键约束与验收红线

1. PostgreSQL 是 Run、事件、Outbox、ToolOperation、Approval、Usage 等关键状态的权威事实源。
2. 只使用一种主 MQ；Kafka/RabbitMQ 的最终选择进入 P1 ADR，不在本文件中提前假定。
3. Run 创建、初始事件、幂等记录和 Outbox 应按 v3.1 规定在同一事务中提交。
4. Run attempt、ToolOperation 逻辑操作和工具调用 attempt 必须区分。
5. Worker 租约过期后可接管；旧 fencing 世代不得提交状态或结果。
6. 取消是协作式停止；外部副作用已发出后不承诺自动撤销。
7. UNKNOWN 必须对账；不得当成普通失败盲目重试或直接释放预算。
8. 对象存储每次读取重新授权；预签名 URL 必须限定对象、权限与有效期。
9. 当前授权仍需在旧 Run 恢复和工具执行时重新验证。
10. 高风险例外必须登记责任人、补偿措施、到期日和正式风险接受人。

## 5. MVP 分批交付建议

- **MVP-A：** Agent 草稿/版本、认证上下文、Run 创建与查询、持久化状态和基础事件。
- **MVP-B：** Outbox/MQ/Worker、ModelGateway、只读 Tool SPI、结果持久化。
- **MVP-C：** 端到端轨迹、SSE、授权测试、基本预算/审批路径。
- **MVP-D：** UNKNOWN、fencing、故障注入、跨租户测试和生产准入补充门禁。

此分批仅用于迭代管理，不表示可以在未满足安全门禁时把有副作用工具提前开放给真实用户。

## 变更补充（v0.2）：多级 Agent 的 MVP 边界

### 纳入范围
- 单个 RouterAgent 在静态、发布时固定的 `childAgentRefs` 中路由。
- `LEAF`、`ROUTER`、`SEQUENTIAL` 三种模式；V1 首个可运行实现优先完成 `LEAF` 与 `ROUTER`，`SEQUENTIAL` 需通过 P1 ADR/估算后纳入 P2 或明确排至 P3。
- 子 Agent 固定版本、递归发布闭包、循环检测、最大委派深度/调用数/超时/预算限制。
- AgentInvocation 审计、父子关联、逐跳授权和执行快照绑定。

### 明确非目标
- 动态发现任意 Agent、模型任意生成目标 Agent ID 后直接调用。
- 并行委派、复杂 DAG 调度、跨 Agent 分布式事务/自动补偿。
- 跨租户委派、无界递归、子 Agent 自动继承父 Agent 的 Skill 或权限。
- 以 RouterAgent 的角色或提示词作为授权依据。
- 未经 ADR 审批的新增传输类型或对 MCP 支持范围的扩张。

### 范围决策门禁
若首期业务不依赖多级委派，可将运行时委派排为 P1，但契约兼容、Schema、发布闭包及安全边界必须在 P1 冻结；不得因排期删除固定版本与逐跳授权约束。
