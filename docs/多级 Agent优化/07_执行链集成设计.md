# 07｜执行链集成设计

> 定位：定义新增校验组件与**现有 `ToolInvocationGate`** 的职责边界，避免重复校验与绕过路径。
> 评审依据：03 P0-2（授权校验与现有执行闸门缺少接口契约）、C4（职责未划清）、05（授权≠执行）。

---

## 1. 组件职责表（唯一真相）

| 组件 | 职责 | 输入 | 输出 | 失败语义 | 复用/新增 |
|---|---|---|---|---|---|
| **PermissionResolver** | 计算"有效能力闭包"（Agent→Skill→Tool/MCP），合并继承/覆盖/收紧 | Agent/Skill/Tool/MCP 配置 + 租户覆盖 | `EffectiveClosure`（含 `configFingerprint`） | 配置缺失/环/放宽为 CONFIG_ERROR DENY | 新增（复用 `EffectiveConfigResolver` 读取） |
| **InvocationValidator** | 调用期**能力链+配置约束**判定（不含预算/执行副作用） | `AuthContext` + `EffectiveClosure` + 本次调用目标 | `Decision(allow/deny, stage, code)` | 任一因子 false → DENY（05 公式） | 新增（实现 05 §1–§4） |
| **AuthorizationService** | 主体当前授权 + `authzVersion` 重授权 | `AuthContext`, action, resourceId | bool（实时） | 陈旧/不足 → DENY(stale_authz) | 已有（换 DB 实现，04 §1.1） |
| **ToolInvocationGate** | **唯一执行入口**：输入校验→重授权→幂等→账本→审批→预算→执行→账本更新 | `ToolHandler` + 调用参数 | 执行结果 + `executionStatus` | 各闸门独立拒绝（不混淆为授权 DENY） | 已有（ADR-011 禁绕过） |
| **ApprovalPort** | 风险驱动审批（REQUIRED/OPTIONAL），绑定操作+参数域+指纹 | 工具/风险/参数 | 审批态 | 缺失/拒/不可确认 → DENY(approval) fail-closed | 已有（`RiskBasedApprovalPolicy`） |
| **BudgetPort** | 预算预留（幂等键） | tenant/run/tool | 预留成功/失败 | 不足 → DENY(budget) | 已有 |
| **RunToolLedgerPort** | 账本登记（幂等） | invocationId/结果 | 登记 | 写入失败 → 重试/告警 | 已有 |
| **ToolHandler** | 原子执行（native 或 MCP-backed 统一接口） | 校验后参数 | 结果（含 UNKNOWN 对账） | 异常 → FAILED/UNKNOWN | 已有（MCP-backed 包装新增） |

> 组件名是**职责划分**，非认定当前已存在这些新类。`InvocationValidator` 与 `PermissionResolver` 为本次新增；其余复用既有。

## 2. 调用契约顺序（T3，无重复副作用）

```
调用进入 ToolInvocationGate.invoke(agentId, skillId, toolId|mcp, params, ctx)

[1] PermissionResolver.resolve(ctx)  → EffectiveClosure（命中缓存则校验 authzVersion/fingerprint 仍有效）
[2] InvocationValidator.validate(ctx, closure, target) → Decision
        ├ false → 写决策日志(DENY, stage, code) → 返回（不执行）
        └ true  → 继续
[3] AuthorizationService.isAuthorized(ctx, TOOL_INVOKE, toolId)  → 实时主体授权（不允许以快照代替）
[4] ToolHandler.validate(params)  → 结构校验（JSON Schema）
[5] ApprovalPort.check(tool, params, fingerprint)  → 风险审批（REQUIRED 且未满足→DENY）
[6] BudgetPort.reserve(tenant, run, tool, idempotencyKey)  → 预算（不足→DENY）
[7] RunToolLedgerPort.record(invocationId, PRE)  → 账本
[8] ToolHandler.execute(params)  → 执行；UNKNOWN → reconcile → 对账队列
[9] RunToolLedgerPort.record(invocationId, POST, executionStatus)
→ 返回 Decision(ALLOW) + executionStatus
```

**边界铁律**：
- `[2] InvocationValidator` **只做能力链+配置约束判定**，不预留预算、不写账本、不执行——避免与 `[6][7]` 重复副作用。
- `[3]` 主体授权**必须用实时 `authzVersion`**，禁止用 `[1]` 的闭包快照代替（评审 02 §3.3）。
- `[5][6][7]` 的审批/预算/账本由既有闸门 Port 负责，**不得**在 `InvocationValidator` 内重复执行。

---

## 3. 唯一执行入口与防绕过

- **所有** Native Tool 与 MCP-backed Tool **必须**经 `ToolInvocationGate` 单一入口；ADR-011 禁止 Spring AI 自动执行、禁止直接调用 `ToolHandler` 实现类。
- **集成验收条件**（进入 PoC 强制）：
  - 静态：扫描确认无任何 `ToolHandler.execute()` 被业务代码直接调用（仅 `ToolInvocationGate` 调用）。
  - 运行时：注入"绕过闸门直接调用工具"的测试 → 必须失败（无授权上下文即拒绝）。
  - 覆盖：每个 MCP-backed Tool 与 Native Tool 走同一 `invoke` 路径，决策日志格式一致。

---

## 4. 配置读取与缓存失效

- `PermissionResolver` 闭包结果按 `(tenantId, agentId, agentVersion, configFingerprint, authzVersion)` 缓存。
- `authzVersion` 变化 → 失效（DB 一致源，04 §1.1）。
- `configFingerprint` 变化（含 MCP 固定清单变更）→ 失效 → 新 Run 重新计算；已有 Run 快照 mismatch → `config_stale` DENY（06 §4）。
- 版本服务不可用 → fail-closed 拒绝新调用（05 §5）。

## 变更补充：AgentInvocation 运行时委派（v1.1）

### 执行链
`Run → Root Agent → AgentInvocation → Child Agent → Skill → ToolInvocationGate → Tool/MCP`。子 Agent 仍使用原 Tool 执行链，不允许绕过 `ToolInvocationGate` 或直接调用 MCP Client。

### 委派时序
1. RouterAgent 输出候选目标及结构化委派输入；模型输出仅为候选决策。
2. 服务端验证目标是否在当前 Agent release 的 `childAgentRefs` 中，且目标 release 与 `execution_snapshot` 一致。
3. 校验深度、剩余调用次数、剩余时间、预算、父调用状态及取消标志。
4. `AuthorizationService` 对当前主体/委托凭证、租户、目标 Agent 资源和当前 `authzVersion` 重新授权。
5. 持久化 AgentInvocation 与父子关联，再调度子 Agent；重复投递按 invocationId 幂等。
6. 子 Agent 结果按输出契约校验，作为不可信业务数据返回父 Agent；失败按声明的 `failurePolicy` 处理。
7. 子 Agent 内 Tool 调用继续执行 T3 门禁、审批、预算、幂等、账本和 UNKNOWN 对账流程。

### 状态与失败语义
AgentInvocation 至少区分 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`TIMED_OUT`、`UNKNOWN`（仅当子操作/委派结果确实不确定且无法证明未执行时使用）。不得把父 Run 失败自动解释为所有已发起副作用均已撤销。

V1 采用有界串行委派；子调用取消传播规则需明确：停止新委派、通知运行中的子调用协作式取消、等待已启动 ToolOperation 进入可解释状态。取消不能保证撤销外部副作用。

### 上下文与安全
子 Agent 仅收到通过输入 Schema 的最小必要上下文，不继承父 Agent 的全部 Prompt、工具集或权限。父 Agent 不得将子 Agent 输出提升为系统/开发者指令。日志仅记录摘要和关联 ID；敏感输入/输出按数据分级存储。
