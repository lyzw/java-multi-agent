## 1. 八个端到端验收场景（冻结 V1 的前置条件）

> 每个场景给出：前置、调用、预期 `decision` / `stage`(error_code) / `executionStatus`、实现位置、自动化用例。

| # | 场景 | 前置 | 调用 | 预期 decision | 预期 stage / error_code | 预期 executionStatus | 实现位置 | 用例 |
|---|---|---|---|---|---|---|---|---|
| **S1** | 已授权工具 | homework_tutor 启用 student_profile_reader，含 get_student_profile | Agent→Skill→Tool(READ) | **ALLOW** | ok | SUCCEEDED | validator+native | test_e2e_s1 |
| **S2** | 未授权工具 | homework_tutor 未启用 notifier（send_email） | Agent→Skill(notifier)→Tool(WRITE_EXTERNAL) | DENY | agent_skill / SKILL_NOT_ENABLED | （不执行） | validator | test_e2e_s2 |
| **S3** | 主体撤权后 | S1 同上下文，但 `authzVersion` bump（撤权/角色变） | 同 S1 调用 | DENY | stale_authz / AUTHZ_STALE | （不执行） | AuthorizationService+validator | test_e2e_s3 |
| **S4** | Skill 被收紧 | 运行时将 homework_tutor.overrides.removeSkills 加入 student_profile_reader（收紧） | 同 S1 调用 | DENY | agent_skill / SKILL_NOT_ENABLED | （不执行） | resolver+validator | test_e2e_s4 |
| **S5** | MCP 工具发生变化 | notify_mcp 固定清单移除 send_mail（config_fingerprint 变） | Agent→Skill(notifier)→MCP(send_mail) | DENY | config_stale / CONfig_FINGERPRINT_STALE（或 mcp_tool_not_allowed） | （不执行） | 06 §4 指纹失效 | test_e2e_s5 |
| **S6** | 审批未通过/缺失 | send_email 为 WRITE_EXTERNAL，无 approval_id | Agent→Skill(notifier)→MCP | DENY | approval / APPROVAL_REQUIRED | （不执行） | runtime[审批] | test_e2e_s6 |
| **S7** | 预算不足 | send_email 调用，但 BudgetPort 余额不足 | 同 S6 但带 approval_id | DENY | budget / BUDGET_EXCEEDED | （不执行） | runtime[预算] | test_e2e_s7 |
| **S8** | 外部执行结果未知 | send_email 审批通过+预算够，执行时外部响应丢失 | 同 S7 执行 | **ALLOW** | ok | **UNKNOWN** | runtime[UNKNOWN→对账] | test_e2e_s8 |

**判定规则**：
- S1/S8 必须 `decision=ALLOW`；S2–S7 必须 `decision=DENY` 且 stage/code 精确匹配。
- S8 关键：`decision=ALLOW` 但 `executionStatus=UNKNOWN`，**不**等同于执行成功；进对账队列。
- 任一不符 → V1 不冻结（04 §4）。

### 变更补充：工具幂等键分域的验收补充（第十七批）

| 用例 ID | 类别 | 场景 | 预期 | 证据 |
|---|---|---|---|---|
| MA-T10b | 幂等 | 父 Agent 与子 Agent 调用**同名工具 + 同名 model call id** | 产生**不同**的幂等键 —— 后者不得被当成前者的重放（那次调用根本没发生，且模型拿到的是另一个 Agent 的结果） | `NestedToolIdempotencyTest#parentAndChildProduceDifferentKeys` + `#siblingAgentsProduceDifferentKeys` |
| MA-T10c | 幂等 | **同一 Agent** 的同一次调用**重复投递** | 产生**同一个**键（幂等语义未被修复破坏 —— 键若每次都变，幂等就退化成「每次都执行一遍」） | `NestedToolIdempotencyTest#sameAgentRepeatDeliveryKeepsSameKey` + `IdempotencyProtocolTest#sameAgentRepeatDeliveryStaysIdempotent` |

⚠️ **「不同 Agent 必须不同键」与「同一 Agent 必须同键」必须成对断言**：
只断言「键里含 agent 字样」在「所有调用都塞进同一个键」时同样会绿 —— 那不是证据。

CAP 链路自行派生 → 恰 1 条红；所有 Agent 共用同一个 Agent 段 → 3 条红。

⚠️ **本批未覆盖的路径**：CAP 链路的**子 Agent 工具执行**本身
（步骤 13 执行准入会拒 —— 已登记为缺口，见 00「未实现」同名条）。
