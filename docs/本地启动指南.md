## 4. 启动后端

### 4.1 命令

```bash
cd /Users/zhouwei/code-workspace/ai-tech/java-multi-agent
java -jar platform/platform-bootstrap/target/platform-bootstrap-0.1.0-SNAPSHOT.jar \
  --spring.profiles.active=dev \
  --server.port=8080 \
  --spring.datasource.url=jdbc:postgresql://127.0.0.1:5433/agent_dev \
  --spring.datasource.username=agent \
  --spring.datasource.password= \
  --spring.datasource.driver-class-name=org.postgresql.Driver
```

### 4.2 ⛔ 四个必踩点

| # | 坑 | 症状 | 处置 |
|---|---|---|---|
| 1 | **不传 `dev` profile** | 启动失败：`auth.jwt.private-key 未配置` | 必须传 `--spring.profiles.active=dev`。代码 `AuthConfiguration.java:40` 的 `DEV_PROFILES = {dev, local, test}` 允许启动生成密钥，**生产禁止**（会致全员掉线）|
| 2 | **不传 datasource** | 上下文启动失败（无 bean）| 必须显式传 url/username/driver |
| 3 | **端口未固定** | 随机端口，前端代理连不上 | 必须 `--server.port=8080` |
| 4 | 旧实例未退 | `Port 8080 already in use` | `lsof -ti:8080 \| xargs kill -9` |

### 4.3 验证启动成功

```bash
# ⛔ 用 JWKS 判断后端存活（实测可靠，返回 200）
curl -s http://localhost:8080/api/auth/jwks
# → {"kid":"...","alg":"RSA","publicKeyBase64":"..."}
```

> ⚠️ **`/actuator/health` 当前返回 500**（实测）。
> **本机运行的后端实例启动参数不可读，根因未诊断**——
> 可能是旧的 D5 前构建产物（该 jar 仅含 9 个 bootstrap 类，缺 API/Worker 层），
> 也可能是 health 探针依赖的组件未就绪。
>
> **排查方法**：查看启动该实例的终端输出中的异常栈；
> 或用 `mvn clean package -DskipTests` 重新构建后重启。
>
> **在根因明确前，请用 `/api/auth/jwks` 作为存活判据**——
> 它不依赖探针组件，且实测返回 200。

## 6. 登录凭据（本地开发）

> ⚠️ 以下均为**本地开发账号**，生产走受控发号（D-001 §7）。

### 6.1 已内置的账号（2026-10-19 实测可登录）

| 账号 | 口令 | 租户 | 角色 |
|---|---|---|---|
| `e2e_student01` | `e2e-correct-password` | t-a | `STUDENT` |
| `tadmin` | `Tadmin-4505x` | t-a | **`TENANT_ADMIN`** |
| `agentauthor` | `Author-4505x` | t-a | **`AGENT_AUTHOR`** |
| `tadminb` | `Tadminb-4505x` | t-b | **`TENANT_ADMIN`**（另一租户，用于验证隔离）|

> 四个账号的 JWT payload 中 roles 均与库中一致（实测解码核对）。

**查租户 ID**：

```bash
./scripts/dev-seed.sh --lookup tadmin     # → 6f5d33fc-723e-4f64-beda-9e4435c72691
# 或
docker exec agent-pg17 psql -U agent -d agent_dev -tAc \
  "SELECT tenant_id FROM principal WHERE login_name='tadmin';"
```

### 6.2 ⚠️ 造管理员前必读：角色能做什么

`TENANT_ADMIN` 权限最全（10 个动作），但**多数动作没有对应端点**：

| 角色 | 动作数 | 有端点可用的 |
|---|---|---|
| `TENANT_ADMIN` | 10（含 `AGENT_MANAGE` `AUDIT_READ`）| ⚠️ 仅 `RUN_CREATE` / `EVENT_SUBSCRIBE` |
| `AGENT_AUTHOR` | 8 | ⚠️ 同上 |
| `APPROVER` | 4 | ❌ 0 |
| `VIEWER` | 3 | ❌ 0 |
| `STUDENT` / `PARENT` / `TEACHER` | **0**（默认拒绝）| — |

> ⚠️ **登录响应不含 `roles`**（缺口 G1），前端无法从登录结果知道当前身份。
> 但 **JWT payload 里是有的**（实测可 base64 解码得到）。

### 6.3 验证登录链路（实测可用）

```bash
TENANT_ID=$(docker exec agent-pg17 psql -U agent -d agent_dev -tAc \
  "SELECT tenant_id FROM principal WHERE login_name='e2e_student01';" | tr -d ' ')

curl -s -X POST http://localhost:5173/api/auth/token \
  -H "Content-Type: application/json" \
  -d "{\"tenantId\":\"$TENANT_ID\",\"loginName\":\"e2e_student01\",\"password\":\"e2e-correct-password\"}"
# → {"accessToken":"eyJ...","tokenType":"Bearer","expiresIn":900}
```

**错误凭据**应返回 `401 {"error":"invalid_credentials"}`（实测确认）。

> ⚠️ **令牌 15 分钟过期且无 refresh token**（缺口 G13），
> 过期即硬跳登录页。这是已知限制，非 bug。

### 6.4 ⛔ 查询为空？先查连的是哪个库

**本机并存两个 PostgreSQL**，连错会得到"查询为空"的假象：

| 端口 | 容器 | 版本 | 状态 |
|---|---|---|---|
| **5433** | `agent-pg17` | **PG 17.11** | ✅ **正确的库**，21 张表全在此 |
| 5432 | `agent-local-postgres-1` | PG 16.15 | ⚠️ 旧环境，**无 `agent_dev` 库** |

```bash
# ⚠️ 端口是 5433，不是 5432
docker exec agent-pg17 psql -U agent -d agent_dev \
  -c "SELECT login_name, tenant_id FROM principal;"
```

### 6.5 初始化脚本（推荐）

```bash
./scripts/dev-seed.sh --list                    # 查看现有租户/账号/角色
./scripts/dev-seed.sh --lookup e2e_student01    # 查某账号的 tenant_id

# 建新租户与账号（默认 t-dev / devstudent）
./scripts/dev-seed.sh

# 自定义
./scripts/dev-seed.sh --slug t-x --login alice \
  --password 'Alice-2026' --roles TEACHER,APPROVER
```

> ⚠️ **查账号用 `--lookup` 而非 `--login`**：
> `--login` 是 seed 的「设账号名」选项，
> 若复用为子命令会造成歧义（实测：子命令分支会抢走参数，
> 导致 seed 的格式校验形同虚设）。

脚本解决了两个实际卡点：

| 卡点 | 处置 |
|---|---|
| `password_hash` 有 CHECK 约束，而生成它的 `PasswordHasher.hash()` **无 CLI 暴露** | 脚本用 **jshell 调用 Java 真实实现**生成，**不复现算法**（复现即漂移风险，症状是"密码对却登不进去"）|
| 幂等 | 全部 `ON CONFLICT DO NOTHING`，重复执行不覆盖已有口令 |

> ⚠️ **口令只能用字母、数字与 `. _ -`**。
> 含 `!` `$` `'` 等字符时脚本会出现
> **「报成功但实际未入库」的静默失败**（实测踩到）。
> 脚本现已前置拦截 + **事后回查数据库**双重防护。

> ⚠️ **`login_name` 唯一性由索引而非约束实现**，
> 故用 `ON CONFLICT (login_name)` 列推断；
> 用 `ON CONFLICT ON CONSTRAINT uq_principal_login_name` 会报
> 「constraint does not exist」（实测踩过）。

### 6.6 手工建号的格式约束

若不用脚本，手写 SQL 时须满足（**实测自 `pg_constraint`**）：

```sql
-- login_name: ^[a-z0-9][a-z0-9._-]{2,63}$（小写起始，3–64 位）
-- slug:       ^[a-z0-9][a-z0-9-]{1,62}$
-- role:       ^[A-Z][A-Z_]{1,31}$（大写字母 + 下划线）
-- password_hash: 须匹配 $pbkdf2-sha256$i=%$%（PBKDF2-HMAC-SHA256，600000 次迭代，16 字节盐，标准 Base64 无填充）
```

**可用角色**：`auth.login.known-roles` 白名单为
`STUDENT, PARENT, TEACHER, TENANT_ADMIN, VIEWER, APPROVER, AGENT_AUTHOR, WORKER`。

> ⚠️ 清理测试数据须**按依赖顺序**删除（外键约束会拦截）：
> `principal_role` → `principal` → `tenant`。

## 9. 故障排查

| 症状 | 原因 | 处置 |
|---|---|---|
| **SQL 查询返回空 / 数据库不存在** | **连到 5432 旧 PG16**（无 agent_dev 库）| 用 **5433**，见 §6.2 |
| **`zsh: command not found: npm`** | `.zshrc` 未加载 nvm | 见 §1.2（已修复）|
| 建号时报 `password_hash` 违规 | 手写哈希格式不对 | 用 `./scripts/dev-seed.sh` |
| 建号时报 `constraint uq_principal_login_name does not exist` | 唯一性是**索引**非约束 | 用 `ON CONFLICT (login_name)` |
| 删租户报 foreign key violation | 依赖顺序错误 | 先删 `principal_role` → `principal` → `tenant` |
| 后端启动失败：`private-key 未配置` | 未传 `dev` profile | 加 `--spring.profiles.active=dev` |
| 后端启动失败：`Port 8080 in use` | 旧实例未退 | `lsof -ti:8080 \| xargs kill -9` |
| 前端 502 | 用了 `127.0.0.1` 访问 | 改用 `localhost` |
| 前端代理 502 | 后端未启动 | 先启后端 |
| 登录 401 | 凭据错 / 租户 ID 错 | 见 §6.1 自查命令 |
| 登录后立刻掉线 | 令牌 15 分钟过期 | 重新登录（无 refresh）|
| `mvn` 编译失败 | 并行开发的未完成改动 | `git status` 查看，**勿回退他人改动**|
| vitest 报 exit 137 | 内存不足 | 确认 `singleFork` 配置未被改 |
| 数据库连接失败 | PG 未启动 / 端口错 | `./scripts/dev-postgres.sh status`，端口是 **5433** 不是 5432 |
