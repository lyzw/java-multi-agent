# W-ADMIN-P2 · 发布与审批中心（M6）：三步工作流、双复核、回滚与生命周期迁移

> **阶段目标**：将既有 `ConfigPublishWorkflowService`（三步：申请→审批→执行）与 `CapConfigPublishController`（5 端点）接入控制台 UI，实现 M6 发布中心：申请队列、审批（双复核）、发布时间线、回滚、生命周期迁移（DEPRECATED）。  
> **设计文档落点**：§2 M6、§5.1 创建并发布 Agent（7 步）、§5.2 发布审批时序（双复核）、§5.3 回滚/删除守卫要点、§6 复用端点、§9 高危强制审批。

## 0. 落地记录（2026-10-24）

**设计转向（与 P0.5 / P1 红线一致）**：原稿拟建 `AdminPublishQueryService` 新聚合服务。落地前核查发现三步工作流已在 `ConfigPublishWorkflowService` / `CapConfigPublishController` 完整落地（5 端点 + 平台级 403 闸门 + 双人复核 409 + CAS 基线）。故收敛为：**复用既有工作流，仅补两个最小读端点**（申请详情深链、发布时间线），不建并行 admin 控制器。

### 0.4 边界与不在本阶段（及原因）

- **P2-T6 生命周期迁移 UI**：`LIFECYCLE_TRANSITION` 申请通道已就绪（`lifecycle` 参数经 `submitPublishRequest` 提交），但控制台缺 `cap_lifecycle_state` 读端点，无法展示 Agent 当前生命周期态 → 独立表单入口留待补读端点后追加；删除守卫（物理删除拦截）按计划留 P3。
- **P2-T7 平台级「申请→运维受理」占位**：后端对 PLATFORM 作用域**显式 403**（不是静默失败）——控制台不提供平台级发布表单，Tool/Skill/MCP 目录保持只读 + 带外运维提示（P0.5 红线延续）。
- **高危强制审批提示**（`trustTier=public` / `WRITE_EXTERNAL`）：这两类字段属**平台级对象**，本通道只服务租户级 Agent；且**所有**租户级发布均已强制双人复核（无高低之分），故无额外分支。
- **E2E（ADMIN-P2-\*）**：真实 DB 的发布-审批-回滚端到端由既有 `ConfigPublishManagementIT` 覆盖（三步状态机 + 双人复核 + CAS），本阶段新增 Mockito 单测锁定端点契约。

## 6. 风险与回滚

| 风险 | 缓解 / 回滚 |
|---|---|
| 平台级写发布经租户身份暴露 | 闸门联动：平台级仅申请占位，运维通道执行（延续 P0.5 红线） |
| 双复核被同人绕过 | `approver_id<>requester_id` 后端强校验 + 前端提示 |
| 回滚误恢复已撤销授权 | 回滚仅指向旧版本指针，明确不恢复主体授权（P2-T5） |
| CAS 并发回滚半成品 | 复用既有 CAS 发布（P5 已有），失败整事务回滚 |
