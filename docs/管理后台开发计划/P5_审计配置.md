## 8. 落地记录（2026-10-24 实施完成）

### 8.1 设计收敛：**复用优先，最小新增**

P5 后端三项经核查**均有既有实现**，刻意不建并行控制器：

| 任务 | 计划 | 实际落地 | 说明 |
|---|---|---|---|
| P5-T1 审计查询 | 新建 `GET /api/admin/audit/logs` | **复用既有** `AuditQueryController`（`GET /api/audit`） | 已含 ledger 维度筛选（action/resourceType/resourceId/from/to）+ 游标分页 + `recordAccess` 查询留痕（fail-open）；audit_record 有 forbid_audit_mutation 触发器 |
| P5-T2 角色矩阵 | 新建矩阵服务 | **复用既有** `GET /api/admin/tenants/self/principals`（含 roles、authzVersion，无凭据） | 租户内自服务视图，RLS 限定本租户 |
| P5-T3 凭据引用 | 新建凭据登记服务 | **既有目录端点即视图**：`McpResponse` 增补 `hasCredentialRef` 布尔（`credentialRef() != null`），**定位符与材料均不入响应** | 登记与轮换本身走带外运维通道（MCP 定义是平台级对象，无应用层写入口）——「仅存引用、不碰明文」由「根本没有写入口」达成，比表单校验更强 |

### 8.2 本阶段真实新增

**后端（platform/）**：

1. **`GET /api/admin/dashboard` 后端实现**（补 P0 以来一直由前端空态降级的缺口）：
   `DashboardViewService`（application 层聚合：tenantCount/agentCount/tool/skill/mcp/pendingApprovals/activeAlerts=24h 内 CRITICAL 拒绝数）+ `AdminDashboardController`。
   ⚠️ **刻意不做 fail-closed**：仪表盘是导航入口而非决策依据，各计数源独立 try/catch 记 0，与 `MonitoringViewService` 的严格 fail-closed（503）口径**相反**——两者语义不同。
2. **PLATFORM_ADMIN 授权通道三层打通**（默认拒绝 → 带外解锁）：
   - 权限矩阵：`RoleBasedAuthorizationService` 登记 `PLATFORM_ADMIN → Actions.all()`（仅映射，不默认授予）；
   - 签发白名单：`application.yml` known-roles 追加 `PLATFORM_ADMIN`（否则令牌签发时剥离该角色，永远 403）；
   - **带外赋权落点**：`deploy/sql/platform/04_platform_admin_grant.sql`（幂等写 `principal_role` 权威表 + 前后快照 + 生效链路提醒 + 注释态回收段）。
   ⚠️ **刻意不建应用层赋权端点**：赋权入口若挂在某个既有角色上即成自举回路（TENANT_ADMIN 自授 PLATFORM_ADMIN）；带外 SQL 让赋权者必须是能直连生产库的人，与「平台级对象变更走带外通道」红线同构。
3. **真实告警分发通道（Webhook 最小实现）**：
   - 端口 `AlertWebhookPort`（ports/monitoring）+ 实现 `HttpAlertWebhook` / `NoopAlertWebhook`（infrastructure/monitoring）；
   - 触发点：`JdbcDecisionAuditRepository.append` 事务返回后，`isCriticalDeny`（DENY 且 `DenySeverity.of(reasonCode)==CRITICAL`）→ best-effort `sendAsync` POST；
   - 三红线：异步不阻塞主链路 / 异常全吞只留 WARN / **载荷最小化**（仅租户/主体/工具/原因码/调用标识/时刻，无凭据无参数无指纹，JSON 手工转义）；
   - 配置 `agent.alerts.webhook-url` **默认空白 = 关闭**（Noop）：不配置目标就不外发，避免「悄悄把审计内容发给没人审过的地址」。

**前端（admin-console/）**：

4. `/audit` 审计日志页（P5-T4）：时间窗 + action/resourceType 筛选、游标翻页（无跳页——追加只读）、详情抽屉（detail JSON 原样呈现，双人复核字段含于 CONFIG_APPROVE 留痕）、不可篡改 + 查询留痕双提示。
5. `/roles` 角色矩阵页（P5-T5）：主体×角色 Tag 矩阵、角色分布统计、撤权水位告警（authzVersion>1 主体数）、只读明示。
6. `/settings` 配置中心（P5-T6）：凭据引用页签（仅「已登记/未登记」布尔标识，无明文框无回显）+ 全局参数占位页签（fail-closed：带外授权流程建立前不提供写入口）。
7. 导航：新增「角色矩阵」节点（TENANT_SCOPE）；audit/settings 占位替换为真实页；路由移除 `placeholderFor`（全部导航节点已无占位）。

### 8.4 诚实边界

- 审计页的「双人复核留痕」以 detail JSON 原样呈现（CONFIG_APPROVE 的 approverId/requesterId/decision 在其中），未做结构化复核时间线——留 V2。
- Webhook 为最小实现：无重试/退避/死信队列——外发丢失时权威事实仍在审计表，可经审计页回查。
- 凭据「登记」动作本身不在应用层（带外通道），控制台只呈现登记结果布尔。
- 角色矩阵的授权变更仍走带外 SQL；应用层「我的租户」自服务不含角色管理写入口。
