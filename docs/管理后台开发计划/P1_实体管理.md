# W-ADMIN-P1 · 实体管理（M2–M5）：Agent / Tool / Skill / MCP 的 CRUD 与版本历史

> **阶段目标**：为四类实体（Agent 租户级、Tool/Skill/MCP 平台级）提供列表、详情、创建/编辑草稿、版本历史能力，落于 M2–M5。所有写发布在 P2 接入工作流；本阶段只完成**草稿态**CRUD 与版本查看，不触碰发布语义。  
> **设计文档落点**：§2 M2–M5、§3 实体关系模型、§4.1 通用页面模式、§6 只读/编排端点、§9 收紧棘轮 / null≠[] / V1 边界。

---

## 0. 落地记录（P1 实际，2026-10-24）

> ⚠️ **设计转向（安全相关，与 P0.5 红线一致）**：本计划原稿拟建 `AdminEntityQueryController`（`/api/admin/{agents|tools|skills|mcps}`）+ 草稿保存服务。落地前发现共享后端已有成熟能力：
> - **Agent（租户级）**已有完整 CRUD 于 `/api/agents`（list/create/publishVersion），仅缺**详情**与**版本历史**两个读端点；
> - **Tool / Skill（平台级）**已有**只读**目录于 `/api/cap/catalog`，且该控制器刻意 GET-only——平台级对象变更走**带外运维通道**（`CapConfigPublishController` 对 PLATFORM 作用域显式 403）；
> - **MCP Server（平台级）**有 `cap_mcp_server_def` 表与 `CapMcpServerDefPort`，但**尚无目录端点**。
>
> 若照搬原稿，会**重复**既有端点、并**重新打开 P0.5 已关闭的平台级写边界**。故 P1 收敛为：**复用既有端点 + 仅补最小缺失读端点**，不建并行 admin 控制器，平台级写仍走带外通道。

### 后端（`platform/agent-api` 内扩展，不新建后端工程）
- **Agent 详情 / 版本历史**：`AgentQueryPort` 增 `listVersions(tenantId, agentId)`；`JdbcAgentQueryRepository` 实现（`tenantConnection` 绑 RLS，`ORDER BY version_number DESC`）；`AgentController` 增 `GET /api/agents/{id}`（`findAgent`→404）与 `GET /api/agents/{id}/versions`（复用 `AGENT_MANAGE` + `GOVERNANCE_QUERY` 口径）。
- **MCP 目录只读**：`CapMcpServerDefPort` 增 `listAll()`（每逻辑 id 取 `MAX(version)` 行，platform 上下文无 RLS）；`JdbcCapMcpServerDefRepository` 实现；`CapabilityCatalogController` 增 `GET /api/cap/catalog/mcps` + `/mcps/{id}`（含 `McpResponse`，**刻意不含 credentialRef**）。
- **连带修复**：`CapMcpServerDefPort` 新增 `listAll()` 抽象方法 → 3 处测试夹具（`CapFixture` / `ConfigPublishServiceTest` / `PlatformOpsPublishServiceTest`）补 `listAll()` 覆写。
- **测试**：`AgentControllerTest`（5：详情 200/404、版本 200/404、鉴权拒绝）+ `CapabilityCatalogControllerTest`（3：列表 200、单条 200/404）→ **8/8 通过**。

### 前端（`admin-console` 独立工程）
- **API 层**：`adminApi.ts` 移除 `getEntities` 占位，改为真实端点——Agent（`/api/agents` 列表/详情/版本/创建/发布）与 Tool/Skill/MCP（`/api/cap/catalog/*` 只读）；`types.ts` 补 8 个契约类型。
- **页面**：`/agents`（`AgentRegistryPage` 列表+创建）、`/agents/:id`（`AgentDetailPage` 概览/版本历史/发布版本）、`/tools` `/skills` `/mcp`（`ReadOnlyCatalogPage` 通用只读目录 + 3 个具型封装）；`router.tsx` 接入四路由，`navConfig.tsx` 收敛描述以反映真实作用域。
- **null≠[]**：`displayBits.tsx` 的 `allowlistCell` 如实区分「未配置(null)=取全集」与「显式空([])=∅」；Skill 的 `declaredMcp.toolAllowlist` 同口径呈现（§4.4）。
- **测试**：`tests/entityValidation.test.tsx`（6：null≠[] 三分支、风险等级渲染、definition JSON 预校验）→ **Vitest 10/10、`tsc --noEmit` 零错、`vite build` 通过**。

### 不在本阶段（及原因）
- **P1-T2 草稿保存**：Agent 生命周期是「不可变版本快照」模型，无独立 DRAFT 态（发布即新版本）；平台级对象本就不允许应用层写。故草稿服务无落点。
- **P1-T3 引用正反查**：属关系图谱能力，按计划自身口径留 **P3 关系视图**；本阶段聚焦实体可管理主干（列表/详情/版本）。
- **平台级写 / 发布审批 / 回滚**：留 P2，且须先建应用层 `PLATFORM_ADMIN` 授权通道（与 P0.5 待办一致）。

- [x] 前端四页面渲染通过 Vitest（10/10）+ 构建通过。
