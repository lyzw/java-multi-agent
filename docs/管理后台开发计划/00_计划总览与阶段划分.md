# 管理后台系统 · 开发计划总览

> **工作流编号**：`W-ADMIN`（平台之上新增的「管理控制台」切片，独立工作流）  
> **对标设计文档**：`docs/管理后台系统设计方案.html`（基于既有《Agent - Skill- Tool -MCP 统一配置与权限管控体系》领域模型）  
> **版本**：v1.1 · 计划口径：以「可验证增量」交付，复用既有领域服务，不重写安全语义  
> **与整体平台计划的关系**：本计划是《Java SaaS Agent 平台 v3.1》中「统一配置与权限管控体系」之上的**展示与编排层**细化阶段；领域模型、发布审批工作流、authzVersion 强一致授权与 RLS 多租户均直接复用。**前端以独立前端项目交付**（独立仓库/构建/部署），**后端复用既有 `platform/agent-api` 单一共享项目**（不新建独立后端工程，仅按需在其内扩展只读聚合/查询端点），控制台是共享后端的纯 API 消费方。

---

## 1. 定位：为什么是独立工作流

| 维度 | 说明 |
|---|---|
| 独立版本线 | 领域契约以《统一配置与权限管控体系》与《06 配置数据模型》《P6R4 配置发布管理端点》为唯一事实源；本计划只消费它们，不反向改写安全决策语义（§5 安全决策 / §8 冻结门槛为权威）。 |
| 前后端形态 | **前端独立工程**：独立仓库/包、`Vite` 构建、独立部署，根路由即控制台；**后端共用工程** `platform/agent-api`：不做副本，控制台所需只读聚合/查询端点直接在现有工程内新增/扩展（属正常业务扩展，非新模块/新部署单元）。 |
| 仅新增展示/编排层 | 列表/详情/表单/图谱、发布审批 UI、依赖与影响分析、运行监控面板、审计视图；领域规则（校验、闭包、指纹、CAS、双复核）全部复用既有服务。前端为**独立前端项目**，后端为**共用项目**，不新建后端工程。 |
| 作用域红线 | 平台级（Tool/Skill/MCP）写发布保持带外运维通道（BYPASSRLS）；**后端**显式对 PLATFORM 作用域 HTTP 写入口返回 403，仅「申请→运维受理」或只读。前端依据后端返回的当前用户角色/作用域条件渲染（如超级管理员专属写入口），但不承担安全判定。租户管理（开通/配置覆盖/主体角色/启停）属 PLATFORM 作用域，仅由超级管理员经运维通道访问。 |
| 独立验收门槛 | 以「可路由 + 端到端 E2E + 只读聚合 IT + RLS 隔离 IT」为冻结依据；不以后端代码行数或 Demo 代替验收。 |

### 1.1 独立前端项目与共享后端集成要点

- **独立构建部署**：控制台前端为独立 `package.json` 的 Vite + React 18 + TS 工程，经 `npm ci && npm run build` 产出静态产物，独立托管（子域名或路径）。
- **同源优先**：生产推荐经反向代理把 `/api` 转发至共享后端，规避 CORS；开发期以 Vite dev `server.proxy` 转发。如需跨域，后端开启 CORS 白名单（仅控制台域名）。
- **鉴权共用**：复用共享后端登录/会话体系（同一 token 颁发与校验）；前端从零实现 `session`/`tokenStorage`/`RequireRole`（搬运现有前端模式，但在独立工程内）。角色/作用域以后端 `/me` 或 token claims 为准，前端据此条件渲染。
- **后端零新增工程**：控制台所有端点都在 `platform/agent-api` 内（新增 controller 属正常扩展）；作用域闸门、RLS、发布工作流、authzVersion 全部复用既有实现，控制台不重写安全语义。
- **设计资产搬运**：现有前端的设计令牌、AppShell/RequireRole/tightening 等模式与组件，作为**参考资产**搬运到独立工程（而非跨工程 import），避免两个工程耦合，同时保证视觉/交互一致。

## 4. 里程碑与冻结门禁

### 4.1 里程碑

| 里程碑 | 触发阶段完成 | 判定 |
|---|---|---|
| M0 脚手架就绪 | P0 | 独立前端工程可构建部署 + 仪表盘骨架 + 守卫/单测通过 + dev proxy 连通共享后端 |
| M1 租户管理可用 | P0.5 | 租户生命周期 + 配置覆盖 + 主体角色 + RLS 隔离校验端到端通过 |
| M2 实体管理可用 | P1 | 四类实体列表/详情/草稿 CRUD + 版本历史 IT 通过 |
| M3 发布审批可用 | P2 | 发布-审批(双复核)-回滚 E2E 通过；生命周期迁移可用 |
| M4 关系视图可用 | P3 | 能力闭包图谱 + 影响分析 + 删除守卫 IT 通过 |
| M5 运行监控可用 | P4 | 监控面板 + 告警（只读聚合）IT 通过 |
| **M6 控制台基础闭环** | P5 | 审计视图 + 凭据引用登记可用；全量 E2E 冒烟通过 |

### 4.2 冻结门禁（V1 基础闭环唯一依据）

1. **功能**：四类实体 CRUD、发布审批双复核、回滚、依赖影响分析、租户生命周期与 RLS 校验全链路可用。  
2. **安全**：作用域闸门（后端 PLATFORM→403 / TENANT→放行）、收紧棘轮、fail-closed、凭据 `credential_ref` 非明文、RLS 隔离校验以非特权账号执行。  
3. **工程**：共享后端构建（`JAVA_HOME=/opt/homebrew/opt/openjdk@21 mvn -o clean verify`）全绿；独立前端 `npm ci && npm run build` 与 Vitest 通过；E2E 冒烟通过；文档与实现同版本。  
4. **硬约束**：**Demo ≠ 验收**；平台既有 cap_* 自动化与 RLS 夹具不被控制台改动破坏。

## 5. 通用执行原则（沿用整体计划 §1）

1. 每阶段必须有可运行软件、测试结果、文档、明确退出门禁。  
2. 先验证高风险协议：作用域闸门、收紧棘轮、RLS 隔离、双复核、fail-closed。  
3. 数据库为执行事实源；控制台只读聚合不新增写表（M10 凭据登记除外）。  
4. 复用优先：领域规则一律复用既有服务，控制台只调用与呈现，禁止在 admin 层重写安全决策。  
5. 安全不是后置阶段；越权（PLATFORM 经租户身份写）与正向授权测试成对出现；**安全判定一律在后端**，前端仅按角色/作用域条件渲染。  
6. 文档与实现同版本：导航树、API 契约、状态机、风险登记表随代码变更更新。  
7. **跨工程一致**：独立前端搬运既有设计令牌与 UI 模式（AppShell/RequireRole/tightening 风格），避免与现有前端视觉/交互漂移；不跨工程 import 源码。

### 5.1 单项 DoD（Definition of Done）

- [ ] 验收标准满足，未完成项已登记并获批。  
- [ ] 代码合并并通过非作者 Review；作用域/状态机/迁移/安全改动有领域负责人 Review。  
- [ ] 独立前端（Vitest + Testing Library + `npm run build`）与共享后端（JUnit5 + Maven `mvn -o clean verify`）测试通过，证据可追溯。  
- [ ] 涉及 API/DDL/状态机/配置/权限的文档同步更新。  
- [ ] 关键路径具备日志/指标/Trace/审计；不记录密钥或多余敏感内容。  
- [ ] 涉及权限时，正向授权 + 越权拒绝测试成对（含后端 PLATFORM 作用域 403）。  
- [ ] 涉及跨租户/RLS 时，以非特权 `app_agent` 账号在夹具中验证隔离。

## 6. 风险登记（摘要，源自设计文档 §9）

| 风险 | 影响 | 缓解（落点） |
|---|---|---|
| 平台级作用域经租户身份暴露 | 任一租户管理员自授权限改全平台配置 | 后端 PLATFORM 作用域 HTTP 写入口显式 403；写发布走 BYPASSRLS 运维通道（P0 闸门 / P2） |
| 收紧棘轮被放宽绕过 | 租户/参数策略被放大权限 | 复用/搬运收紧棘轮逻辑（独立工程内实现）；前端实时校验，放宽即拒（P0.5 / P1） |
| RLS 隔离校验用特权账号 | 校验结论不可信 | 必须用非特权 `app_agent` 且 `set_config` 在事务内（P0.5 / §5.5） |
| authzVersion 不可用 | 撤权阻断不及时 | 缺失 fail-closed（`AUTHZ_UNAVAILABLE`）；监控面板告警（P4） |
| null 与 [] 混淆 | allowlist 集合运算错误导致越权/误拦 | 前端显式区分「未配置(null)」与「显式空([])」（P1 / P3） |
| 嵌套 Skill / 动态发现提前引入 | V1 非目标越权面 | 表单层禁用 `inherits`、`dynamicDiscovery` 固定 false（P1） |
| 凭据明文泄露 | 凭据外泄 | `credential_ref` 仅存引用，永不入前端明文/日志/指纹（P5） |
| 独立前端与现有前端视觉/交互漂移 | 体验不一致、维护双份 | 搬运既有设计令牌与 UI 模式到独立工程，保持令牌同源（§1.1 / §5.7） |
| 独立前端跨域/代理配置缺失 | API 不可达 | dev proxy + 生产同源反向代理优先；CORS 白名单兜底（§1.1） |

- 状态枚举：`DESIGNED → DEMO_IMPLEMENTED → PLATFORM_IMPLEMENTED → UNIT_TESTED → INTEGRATION_TESTED → ACCEPTED`。  
- 每项任务（Pn-Tn）附**证据路径**（代码落点 / 测试类 / 构建或 commit id）。  
- 进入各态须满足：实现落点存在、对应验收用例通过、可审计日志就绪。  
- **当前无需求达到 `PLATFORM_IMPLEMENTED` 即冻结未达成**——本计划各阶段门禁以平台构建/IT/E2E 为准。
