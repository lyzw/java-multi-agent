0. 修订说明与范围

本文件是 docs/管理后台开发计划/（W-ADMIN-P0~P5，已于 2026-10-24 收官）的补充性重新规划， 专门把《多级 Agent 优化》变更集（docs/多级 Agent优化/）对管理台前端提出的能力要求， 系统地落到 admin-console 的交付计划里。

原则（沿用 00_修订说明）：保留现有架构、命名与 P0–P5 阶段，不另建并行体系。 admin-console 继续是「独立前端工程 + 共享后端 platform/agent-api」的纯 API 消费方； 领域规则（闭包、指纹、CAS、双复核、RLS）一律复用，不在前端重写安全语义。

决策结论对 admin-console 的约束落地状态

SEQUENTIAL 是否纳入 P2		 SEQUENTIAL 不纳入 P2：语义收敛为「父 Agent 自己串行并聚合，框架不代劳」 前端编排模式枚举保留 SEQUENTIAL 选项（供声明），但不得暗示框架做聚合；表单提示「聚合由父 Agent 自行实现」 第三十二批 C32-1 已落地

平台默认值		 取消平台默认值：非 LEAF 发布时必须显式声明最大深度 / 子调用数 / 超时，缺失即拒发布；深度不级联 编排表单：非 LEAF 三个上限必填、不预填默认（与 AgentOrchestrationParser 对齐） 第三十三批 C33 待落地
决策 3
状态机 / 取消 / 重试 / UNKNOWN		 已冻结 → ADR-012（状态枚举 / 父子取消语义 / 重试 / UNKNOWN 条件） 监控页状态机：七态封闭集合、终态不可覆盖；不得展示「补偿 / 重试」等 V1 不支持的动作 ADR-012 已冻结

A7 · 多级 Agent 配置闭环（缺口闭环） 规划中 · 最高优先

目标：把 G-1 / G-2 / G-3 / D-1 一次性闭环，使「编排声明 + 路由策略 + 输出契约」三类多级 Agent 配置在管理台可登记、可查看、可引用。

任务拆解

  • A7-1 路由策略登记表单（G-1）：新增 src/pages/catalog/RoutingPolicyPage.tsx，字段对齐 routing-policy.schema.json：id（可读字符串，非 UUID）、name/description、strategy（EXPLICIT_TARGETS / ORDERED_FALLBACK）、targets（有序 Agent id 列表，不含版本号）。复用三步工作流，不开旁路。
  • A7-2 契约目录 / 查看页（G-2）：新增 src/pages/catalog/ResultContractCatalogPage.tsx，列表展示契约（id / 版本 / lifecycle_state / fingerprint / published_at）；详情展示 schemaJson 与生命周期（DRAFT→VALIDATED→PUBLISHED→DEPRECATED）。
  • A7-3 子 Agent 候选下拉（G-3）：编排表单 childAgentRefs[].id 由手填改为按租户 Agent 列表下拉（依赖后端 B-1 接口）；下拉仅列出同租户已发布 Agent，从 UI 层阻断跨租户引用（MA-T04）。
  • A7-4 修复 failurePolicy 枚举（D-1）：orchestrationForm.ts 的 FAILURE_POLICIES 改为 ['FAIL_FAST','CONTINUE_ON_ERROR']，移除 COMPENSATE（V1 不支持），并补充对应单测断言后端仅接受两种值。
  • A7-5 契约草稿写入路径（G-2 根因）：与后端协同打通 DRAFT→VALIDATED 写入通道（数据层已可表达，缺入口）。

落点：前端 src/pages/catalog/* + orchestrationForm.ts；后端 platform/agent-api 扩展只读聚合与生命周期迁移端点。

验收：路由策略可登记并被 ROUTER 引用；契约可列表/查看/停用；子 Agent 候选下拉按租户过滤；表单不再放行 COMPENSATE。Vitest 新增 ≥ 12 例。

工作量：≈ 1.5 周（前端 1 周 + 后端协同 0.5 周）。
