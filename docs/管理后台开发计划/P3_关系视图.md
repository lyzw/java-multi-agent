# W-ADMIN-P3 · 关系与依赖视图（M7）：能力闭包图谱、影响分析与删除守卫

> **阶段目标**：构建 M7 关系与依赖视图——能力闭包可视化（Agent→Skill→{Tool,MCP}）、影响分析（改/删某对象影响哪些 Agent）、删除守卫（被引用对象禁止物理删除，置 DEPRECATED）。  
> **设计文档落点**：§2 M7、§3.2 关系与依赖方向、§3.3 关系规则要点、§5.3 依赖影响分析/删除守卫、§6 `/api/admin/dependencies/*` 端点。

## 0. 落地记录（2026-10-24）

**设计转向（与 P0.5 / P1 / P2 红线一致）**：原稿拟建「删除守卫」写侧服务（有引用→置 DEPRECATED，无引用且 DRAFT→允许删）。落地前核查：后端**不存在任何物理删除端点**——平台级对象（Tool / Skill / MCP）全程只读（P0.5 红线：写入口走带外运维通道），租户级 Agent 也无删除端点（变更通道 = 发布新版本，P2）。故删除守卫收敛为**读侧判据**：新增 `DependencyGraphService`（只读、无副作用）提供图谱 + 影响分析，UI 在各变更入口旁展示「改 / 删它会命中谁」；**写侧不新增任何入口**。若未来新增删除端点，须先过影响分析（本服务即判据源）。

**AgentOverrides 抽取（避免语义双实现）**：授权路径（`PermissionResolver`）与管理面图谱都要解析 Agent `overrides`（`removeSkills` / `removeTools` / `lowerRiskCeiling`）。从 `PermissionResolver` 私有嵌套 record 抽取为包级公共类 `AgentOverrides`（唯一实现），授权路径与管理面共用；异常类型保持 `ClosureResolutionException`（fail-closed 语义不变，既有 `PermissionResolverTest` 断言不破）。

**两套口径刻意分开**：管理面图谱取每对象**最高版本行**（含草稿，`published` 标注）——回答「声明了什么」；运行期闭包以**发布指针**为准（`PermissionResolver`，fail-closed）——回答「生效什么」。UI 与接口注释均有明示，二者不可互替。

**react-flow 偏差**：原稿指定 react-flow。`node_modules` 无该依赖，且图谱形态简单（分层 DAG + 7 种边 + 截断），引入重依赖不划算 → **纯 SVG 分层渲染 + 纯函数 `graphLayout`**（确定性布局可单测），零新依赖。

- **过程教训（3 条，均已修复）**：
  1. **Mockito 后桩覆盖先桩**：限流测试原先在 `controller()` helper **之前**桩 REJECTED，被 helper 内的 ALLOWED 覆盖 → 两例限流测试报红（graph 未抛异常 / impact NPE）；helper 内已存在的默认桩会覆盖测试的自定义桩，限流须在 helper **之后**桩。
  2. **vitest `singleFork` 共享外部模块缓存**：RTL 的 auto-cleanup 只在**首个导入它的文件**注册 `afterEach`；本测试文件按字母序排第一后，`entityValidation` 的 null≠[] 断言被渲染残留误伤 → `setup.ts` 显式 `afterEach(cleanup)`（setupFiles 每文件都执行）。
  3. **antd v5 无 `Link` 导出**：三个目录页误从 antd 导 `Link`（`to` prop 是 react-router API）→ 改 `react-router-dom`；另修 3 处未用导入与 `noUncheckedIndexedAccess` 索引不确定性（`graphLayout` 改「行记录」结构，零索引访问）。

### 0.4 边界与不在本阶段（及原因）

- **删除守卫写侧**：后端无物理删除端点（平台对象只读 + Agent 无删除），守卫以读侧判据落地（见上）。各实体「删除确认弹窗接入守卫」（原 P3-T7 一部分）无删除入口可接，自然消解。
- **循环依赖检测**：V2。当前 `walkUp` 有 onPath 环防御与深度 / 链数上限，异常配置不会死循环，仅不产出「循环」结论。
- **运行期实时拓扑**：留 P4。本图谱是管理面最高版本口径（含草稿），不是运行期视图。
- **真实 DB 的 IT（ADMIN-P3-GRAPH / IMPACT / GUARD / INTEG）**：本轮以 Mockito 单测锁定服务与端点契约；图谱 / 影响分析的真实库 IT 需按《集成测试（IT）运行指南》环境另行安排（不在本阶段门禁内）。
