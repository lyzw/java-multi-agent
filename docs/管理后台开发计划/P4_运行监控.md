# W-ADMIN-P4 · 运行监控与告警（M8）：authzVersion 水位、MCP 健康、DENY 告警与运行日志

> **阶段目标**：构建 M8 运行监控——`authzVersion` 水位监控、MCP 连接健康、调用准入 DENY 告警、运行日志流。全部为**只读聚合**，不新增写表，fail-closed 信号可观测。  
> **设计文档落点**：§2 M8、§5.3 authzVersion bump 监控、§6 `/api/admin/monitoring/*` 端点、§9 fail-closed。

## 1. 目标与范围

| 范围 | 内容 |
|---|---|
| 后端 | 在共享后端 `platform/agent-api` 内扩展（**不新建独立后端工程**）：`MonitoringViewService`（只读聚合）：`GET /api/admin/monitoring/health`（整体健康）、`/authz`（authzVersion 水位：最近 bump、在途 Run 失效检测）、`/alerts`（DENY 日志 + 告警）；复用 `cap_authz_version`、运行日志/ledger、MCP 连接状态 |

## 8. 落地记录（实际实现 vs 设计）

> 本阶段已落地（2026-10-24）。相比 §3 设计，做了两处收敛：① 三端点（health/authz/alerts）
> 收敛为**两端点**——authz 水位并入 `health` 的 `authzWatermark` 字段，告警（DENY 流）独立为 `denies`；
> ② 图表库 **未引入 ECharts/Recharts**——`health` 纯统计卡 + `denies` 表格即可表达，零新依赖（与 P3 纯 SVG 一致）。

### 8.1 端点（共享后端 `platform/agent-api`，复用优先、零新建工程）

| 端点 | 职责 | 红线 |
|---|---|---|
| `GET /api/admin/monitoring/health` | 聚合健康快照：状态、authz 水位、近期拒绝、审计覆盖 | 只读；authz 不可用 → `503`（`MonitoringUnavailableException`），**不返空快照冒充正常** |
| `GET /api/admin/monitoring/denies` | 近期 DENY 告警下钻（按窗口/limit） | 只读；后端仅返回 DENY 记录 |

- 鉴权：`AGENT_MANAGE` + `GOVERNANCE_QUERY` 限流；平台级对象无任何写入口（红线延续）。
- 后端结构：`agent-core/.../core/monitoring/`（DenySeverity / AuthzWatermark / DenyAlert / MonitoringHealth）→ `agent-ports`（AuthzVersionPort.watermark / DecisionAuditPort.findRecentDenies）→ `agent-infrastructure`（JdbcAuthzVersionRepository / JdbcDecisionAuditRepository）→ `agent-application`（MonitoringViewService，fail-closed 聚合）→ `agent-api`（AdminMonitoringController + ApiExceptionHandler 503 映射）→ `platform-bootstrap`（装配）。

### 8.2 前端（独立工程 `admin-console`）

- `src/pages/monitoring/`：`MonitoringHealthPage.tsx`（窗口切换 + 统计卡 + 授权水位 + 近期拒绝表）、`MonitoringDeniesPage.tsx`、纯函数 `monitoringFormat.ts`。
- `src/pages/DashboardPage.tsx`：P4-T7 回填「运行健康」卡片（状态 Tag、严重拒绝、被撤权主体、降级告警；**数据源不可用 → 红色 Alert「不可用≠健康」**，明确与「0 拒绝」区分）。
- 路由：`/monitoring` 下挂 health / denies 子路由；navConfig 描述更新。
- 测试：`tests/dashboard.test.tsx`（4 项：骨架 / 健康态 / 降级态 / 不可用态）。
