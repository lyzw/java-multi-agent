### 9.2 交付内容

**新增 `platform/agent-context/.../RagHitQuota.java`**（第 14 个纯算法类），把《方案》§4.1/§5.1/§6.4 的 RAG 配额五个动作内聚为确定性纯函数：

1. 按 `chunkId` 去重，保留全序最优候选；
2. 确定性二次排序：`score desc → locator asc → chunkId asc → text asc`（末级 tie-break 到 chunkId/text，不依赖 TimSort 稳定性）；
3. 按 token 配额**动态 top-k**（非固定条数）；
4. 单块正文按 token 截断到 `maxHitTokens`，只保留 `minKeptTokens` 以上的有效块；
5. 放不下的块只留 `chunkId + locator` 引用，支持按需回取。

**三条硬不变量**（撤掉对应修复点必须有测试变红）：

| 不变量 | 口径 | 违反后果（已由撤点证明） |
| --- | --- | --- |
| **硬顶** `afterTokens ≤ tokenBudget` | 引用也扣剩余预算；连引用都放不下就丢弃；`refCost ≥ full` 时绝不降级 | 撤掉后超预算块静默撑爆上下文 |
| **严格净省** `savedTokens = before - after ≥ 0` | `before` 按**含重复的原始全量**统计，去重/截断/降级/丢弃都体现为节省 | 撤掉 `before` 累加后 `saved` 为负、Result 构造抛异常 |
| **确定性全序** | 全序含 chunkId/text 末级 tie-break，输出与输入顺序无关 | 撤掉后同分同 locator 同正文顺序随输入漂移 |

**计数口径**：`TextTokens.count(String)` 只估算正文文本 token（要求对长度单调不减，截断靠最长可容纳前缀二分/线性搜索）；每条命中的元数据（chunkId/score/locator/edition/role/reason + JSON 标点 + 围栏）由调用方算成 `Candidate.overheadTokens()` 一并计入。算法层不耦合任何序列化格式，M10 接线时由 agent-worker 做薄适配。

**fail-closed**：`Candidate` / `Options` / `Result` 全参构造唯一且逐字段校验（空 chunkId/locator、负 overhead、非有限 score、非正配额、`minKeptTokens > maxHitTokens` 全拒）；`allocate` 参数非 null、`hits` 不含 null 元素；`after > tokenBudget` 直接抛 `IllegalStateException`，不做 fail-soft。
