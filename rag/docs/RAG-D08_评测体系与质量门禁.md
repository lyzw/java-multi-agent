## 0. 文档定位与章节映射

### 0.1 本片交付什么、不交付什么

> 伪造一个「已达标」的数字比不交付更糟——
> 它会让后续所有决策建立在一个无人复核的数字上。

### 1.3 本片继承的三条纪律（不可协商）

| 纪律 | 来源 | 在本片的体现 |
|---|---|---|
| **标注者与被评者必须分离** | P1-D08 R-016 / P3-D11 §2.1 | §3.4：case 的 `rationale` 写人工依据；评测结论不得由本项目实现方签署 |
| **AI 不得自行签署评测结论** | P3-D11 §5 退出条件 | §3.4、§4.7、§6.3：人工评审量表的签署人不得为本片实现方 |

> ⚠️ 额外一条本项目特有的纪律（比主平台更严）：
> **评测集不得从被测实现回读期望值。**
> 例如「期望版本正确率 = 100%」必须写死在 case 或门禁配置里，
> **不得**写成「读取 `EditionScope.admits` 的实现行为作为期望」——
> 那样评测集就只是实现的镜像，测不出任何东西。
> 唯一允许从实现读取的是**被测输入**（如 `minScore=0.35`），
> 期望值必须是**独立的外部判定**。

## 2. 评测对象分层

### 2.1 四层分层总览

| 层 | 名称 | 测什么 | 用什么数据集 | **失败意味着什么** |
|---|---|---|---|---|
| **L1** | 索引/切分层 | 文档 → 片段的**结构化正确性** | 真实 PDF 解析黄金集（`rag/eval/cases/l1-ingest-*.json`） | 语料本身是错的。检索与接地再正确也不可能答对——**此时的下游指标全部不可解释** |
| **L2** | 召回层 | 「该被找到的有没有找到、不该出现的有没有挡住」 | 查询-相关片段标注集（`l2-retrieval-*.json`） | 闸门失效（串版本 / 泄题）或召回不全。**这是安全指标的落点**：L2 红 = 泄题/串版本事故已发生 |
| **L3** | 接地层 | 「引用的内容是否真的支撑声明」 | 声明-引用-蕴含标注集（`l3-grounding-*.json`） | 装饰性引用、幻觉、冲突漏检。**这是可信度指标的落点** |
| **L4** | 端到端层 | 「对学生而言，这个回答好不好用、有没有依据、该拒答有没有拒」 | 完整问答对（`l4-e2e-*.json`） | 业务不可用。注意 L4 指标**依赖 L1～L3**，L1～L3 不达标时 L4 结论不成立 |

### 2.2 各层边界（不要越层断言）

| 越界断言（禁止） | 为什么禁止 | 正确表述 |
|---|---|---|
| 「回答有用」说明检索没问题 | 可能是回答层自己写得好 | 「L2 Recall@10 = X，**在** L1 切分完整率 100% 的前提下」 |
| 「没泄题」基于「回答里没出现答案」 | 生成期约束不可靠（`RetrievalPolicy` 注释：模型可能以暗示形式泄漏） | 「**检索结果集中**不含 `EXERCISE_ANSWER`/`EXAMPLE_SOLUTION`」 |
| 「引用存在」说明回答可信 | 装饰性引用能骗过存在性检查 | 「引用存在率 100% **且** 蕴含判定准确率 ≥ X」 |
| 「拒答率 30%」说明系统谨慎 | 也可能说明检索全废 | 「拒答率 30%，其中应拒答集拒答率 100%（RC-08），误拒率 ≤ X%（RC-07）」 |

>

## 3. 评测集设计与标注规范

### 3.1 可执行形态：case 变更即测试变更

| 项 | 约定 |
|---|---|
| 目录 | `rag/eval/cases/*.json`（与主平台 `platform/agent-application/src/main/resources/eval/cases/` **同构**；`rag/eval/cases/` 目录已存在，当前为空） |
| 加载 | 由测试代码加载并断言；**case 文件被修改 = 测试被修改**，必须走 PR 评审 |
| 一条 case 的最小必备字段 | `id`、`layer`、`query`/`documentRef`、`expected`、`rationale`（**人工标注依据**）、`acceptance`（声明服务哪条验收项） |
| `rationale` | **必填且不得为空串**。无依据的标注不可复核，等于没有评测集 |
| `acceptance` | 必填。每个 case 必须声明它服务哪条 `AT-RAG-xxx` 验收项，使「验收 ↔ 用例」可双向追溯 |
| 版本 | 每个 caseSet 带 `version`；case 变更须升版本并在 `changeNote` 说明 |

> ⚠️ **为什么必须是可执行资源而不是文档表格**：
> 「写在 Markdown 里的 20 道题」的失败形态是——没人跑、没人改、三个月后与实现脱节。
> 把 case 落成 JSON 并由 CI 加载，是唯一能让「评测集」与「代码」同生共死的办法。

> **合成夹具的评测结果不得用于对外宣称任何质量指标**（见 §8.1）。

### 3.3 case 字段规范

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 全局唯一，建议 `RAG-<L层><类型>-<序号>`，如 `RAG-TRAP-ED-001` |
| `layer` | enum | ✅ | `L1` / `L2` / `L3` / `L4` |
| `trap` | enum | ❌ | `EDITION` / `LEAK` / `HALLU` / `FRAGMENT` / `AUTHORITY` / `DECOR` / `CONFLICT`（见 §5） |
| `mode` | enum | ✅（L2/L4） | `EXPLAIN` / `SOLVE` / `VERIFY` / `OVERVIEW` |
| `query` | string | ✅（L2/L4） | 学生式提问原文 |
| `editionScope` | object | ✅（L2/L4） | `mode` + `preferred`（五轴：学科/年级/册次/出版社/版次） |
| `knowledgePointId` | string | ❌ | 已知知识点时指定（触发知识点补全） |
| `documentRef` | string | ✅（L1） | 指向已授权文档的稳定 ID（不含绝对路径） |
| `expected` | object | ✅ | 期望断言，见下表 |
| `rationale` | string | ✅ | **人工标注依据**：为什么这个期望是对的 |
| `acceptance` | string[] | ✅ | 服务哪条 `AT-RAG-xxx` |
| `annotatorId` | string | ✅ | 标注者标识（用于 §3.4 独立性核查） |
| `reviewedBy` | string | ❌ | 独立复核者标识 |

**`expected` 支持的断言键**：

| 键 | 含义 | 适用层 |
|---|---|---|
| `mustIncludeChunkIds` | 必须被召回的片段 | L2 |
| `mustExcludeChunkIds` | 不得被召回的片段 | L2 |
| `forbidRoles` | 结果集不得包含的角色 | L2 |
| `requireEditionSameAsPreferred` | 全部命中必须与首选版本同坐标 | L2 |
| `requireRolesPresent` | 结果集必须包含的角色（碎片陷阱用） | L2 |
| `expectEmptyResult` | 必须返回空结果（门禁漏拒用） | L2 |
| `expectDelivery` | `DELIVERABLE` / `REJECTED` / `PARTIAL_WITH_DISCLAIMER` | L3 |
| `expectCitationCount` | 期望引用条数（幻觉陷阱为 0） | L3 |
| `expectVerdict` | 期望三态判定 `GROUNDED` / `PARTIALLY_GROUNDED` / `UNGROUNDED` / `CONFLICTING` | L3 |
| `expectNoFabricatedLocator` | 不得出现语料中不存在的页码/题号 | L3/L4 |
| `expectRefusalText` | 拒答时必须包含的语义要点（如「未找到依据」） | L4 |

### 3.4 标注纪律（继承主平台，**不可协商**）

| 编号 | 纪律 | 执行方式 | 违反后果 |
|---|---|---|---|
| D-A | **标注者与被评者分离** | case 的 `annotatorId` 不得是本项目实现方；`reviewedBy` 独立于 `annotatorId` | 该 case 的评测结论作废并重标 |
| D-B | **AI 不得自行签署评测结论** | 人工评审记录须有具名签署人；AI 可产出评审辅助材料，**不得**产出签署结论 | 评审记录无效 |
| D-C | **期望值不得从实现回读** | `expected` 中的期望一律写死为外部可判定的值 | 评测集退化为实现的镜像，测不出问题 |
| D-D | **每条 case 必须有 `rationale`** | CI 断言：非空、长度 ≥ 20 字符、且**不得**包含「TODO」「待补」「TBD」 | CI 直接失败 |
| D-E | **每条 case 必须声明 `acceptance`** | CI 断言非空且每项存在于 AT-RAG 追踪矩阵 | CI 直接失败 |
| D-F | **case 与门禁双向可追溯** | 每个 `AT-RAG-xxx` 至少被 1 条 case 引用；每条 case 的 `acceptance` 至少被 1 条 AT 覆盖 | CI 直接失败（孤儿检测） |
| D-G | **语料授权前置** | 不得使用未授权教材/教辅构建评测集（法律与合规红线） | 评测集整体废弃 |

> ⚠️ **D-A 的技术注脚**：同基座模型存在相关盲区（P1-D08 R-016）。
> 若标注由 AI 辅助生成，**必须**经独立人工逐条复核后方可入库；
> 且该批 case 的评测结论**不得**单独作为验收依据。
> 本片不提供「AI 标注质量」的保证，只提供**分离机制**。

### 3.5 标注质量本身的度量（标注者也会出错）

| 代号 | 指标 | 定义 | 初始阈值 | 判定 |
|---|---|---|---|---|
| AN-01 | 标注覆盖率 | 已标注片段 / 应标注片段 | 100% | 自动 |
| AN-02 | 双标一致率 | 两位标注者标签一致的比例 | ≥ 0.85 | 自动（需两人独立标） |
| AN-03 | 分歧仲裁率 | 双标不一致且经第三方仲裁的比例 | ≤ 0.15 | 自动 |
| AN-04 | 标注时效 | 语料代际切换后重标完成度 | 100% | 自动（§7.4） |

> ⚠️ **标注质量是评测质量的乘数**。
> 若 AN-02 = 0.70，则任何基于该标注的指标都带有约 0.30 的不可解释区间。
> 因此 **AN-02 低于 0.85 时，相关层的指标结论一律标注为「低可信」**，不得用于门禁判定。

## 4. 指标定义与阈值表

### 4.1 指标判定方式三档

| 档 | 名称 | 含义 | 能否进 CI 门禁 |
|---|---|---|---|
| **A** | 工程可测 | 期望值完全由 case 定义，无人工参与，CI 可自动断言 | ✅ 可（不变式或回归） |
| **B** | 工程可测 + 人工标注基准 | 评测**执行**全自动，但 gold label 需人工标注（成本高、不可每次重标） | ✅ 可（gold 冻结后） |
| **C** | 需人工评审 | 判定本身依赖人的判断（有用性、依据充分性、拒答恰当性） | ❌ 不可进 PR 门禁；只能作**阶段验收**（§6.3） |

> ⚠️ **B 与 C 的区别必须讲清楚**：
> B 类（如「蕴含判定准确率」）的**判定规则是确定的**——给定人工标好的三态标签，
> 程序即可算出准确率；难的是**标注**，不是**判定**。
> C 类（如「回答有用性」）连判定规则都需要人来解释，程序无从下手。
> 把 C 类硬做成自动指标，是自欺欺人的开始。

### 4.6 阈值标定与变更流程

| 规则 | 内容 |
|---|---|
| T-1 | 本文档所有**非 100% / 非 0%** 的阈值均为**占位初值**，标注为「待实测标定」或「待人工评审」 |
| T-2 | 阈值标定的**唯一**依据是本片定义的评测集在真实语料上的实测分布（P50 分位作初始门禁线） |
| T-3 | **阈值只能变严，不能变松**（RAG-D00 §3 原则 7）。放宽必须走变更流程 + 外部抽检 |
| T-4 | 每次阈值变更必须：① 更新本文档表格；② 升评测集版本；③ 在 §9 变更记录留痕；④ 附上「放宽前后的实测对比」 |
| T-5 | 标定所需的最小样本量：每层 ≥ 100 条有效样本；不足时该层阈值标注为「**样本不足，暂不设门禁**」，只做观察 |

### 4.7 人工评审量表（E2E-01 / E2E-02 / E2E-03）

**统一为 5 分制**，每一维给出锚点：

| 分值 | 回答有用性（E2E-01） | 依据充分性（E2E-02） | 拒答恰当性（E2E-03） |
|---|---|---|---|
| 5 | 学生看完能直接做题，步骤完整、无冗余 | 每条实质断言都有逐字引文，且引文真的支撑该断言 | 应拒答时明确拒答且给出可行动的下一步（换个问法/指出缺哪本书） |
| 3 | 能解答主要问题但有跳跃或冗余 | 主要断言有依据，个别次要断言依据偏弱 | 拒答了但理由含糊，或本可回答却拒答 |
| 1 | 答非所问，学生无法使用 | 只有结论没有依据，或依据与结论无关 | 该答不答且编造依据，或该拒不拒并编造 |
| 0 | 内容错误 | 依据与断言矛盾 | 输出编造的出处/页码 |

**评审纪律**：

| 编号 | 规则 |
|---|---|
| H-1 | **评审人不得是本片实现方**（P0-D04 §2.1 ISO-3 同构：同一 Agent 不得同时承担 R 与 C/A） |
| H-2 | 每条被评审输出**双评**；分差 ≥ 2 分时由第三人仲裁 |
| H-3 | 评审人**互不可见**对方的评分（防止锚定效应） |
| H-4 | 抽样量：每层 ≥ 30 条，且必须覆盖 4 种检索模式与全部难度档；抽样种子固定并写入评测集 |
| H-5 | 评审记录须含：评审人 ID、日期、逐条评分、仲裁记录、抽样种子 |
| H-6 | 评审结论由**具名评审人**签署；AI 可产出评审辅助材料但**不得签署** |
| H-7 | 评审集**不得**由本片实现方独家构造；构造集与评审集应有交集但来源不同（对应 D-A） |

## 5. 反例集与对抗集

> ⚠️ **本节是本项目最有价值的部分**。
> 正例只能证明「系统在能回答时能回答」；
> 反例才能证明「系统在不该回答时不瞎答」「在不该泄露时不泄露」。
> 主平台 P3-D11 的教训是：编造出处是 Sev-0 级失败判据，
> 而它在评测集为零时**完全没有防线**。

### 5.1 反例集总览

| 陷阱 | 代号 | 主要检测层 | 关联指标 | 违反的不可妥协原则 |
|---|---|---|---|---|
| 串版本陷阱 | TRAP-EDITION | L2 + L3 | RC-04、GD-06 | 版本锁定 |
| 泄题陷阱 | TRAP-LEAK | **L2** | RC-05、IDX-05a | 「不进 prompt 即不泄露」 |
| 幻觉陷阱 | TRAP-HALLU | L3 + L4 | GD-07、RC-08、GD-08 | 「无语料不回答」 |
| 碎片陷阱 | TRAP-FRAGMENT | L2 | RC-06 | 知识点成组 |
| 权威陷阱 | TRAP-AUTHORITY | L2 + L3 | RC-04b | 「准入 fail-closed」 |
| 装饰性引用陷阱 | TRAP-DECOR | L3 | GD-03 | 「逐字引文不可省」+ 蕴含校验 |
| 冲突陷阱 | TRAP-CONFLICT | L3 | GD-04 | 「三重校验」 |

### 5.2 串版本陷阱（TRAP-EDITION）

**构造**：同一问题在两个版本中**结论或页码不同**。例：
「二次函数的顶点公式是什么？」——人教版 2024 修订版在第 3 章 3.2 节、2023 版在第 2 章 4.1 节，
且两版对「顶点式」符号约定不同。

**期望**：

| 场景 | 期望行为 | 断言 |
|---|---|---|
| `EditionScope.Mode.STRICT` | 只返回学生版本内容；**找不到就说找不到**，绝不回退到另一版凑合 | `requireEditionSameAsPreferred=true`；引用中的版本坐标与 `preferred` 五轴全等 |
| `PREFERRED_WITH_FALLBACK` | 允许同册其他版次，但**必须**带差异标注 | 命中集版本属于同册；`RetrievalResult.versionMismatchDetected()==true`；回答含差异提示 |
| `CROSS_EDITION` | 全部接纳，但**必须按版本分组呈现，不允许混排** | 结果按版本分组；每组内版本唯一；`CitationSet.hasMixedEditions()==true` 是**允许**的，但**不得**在同一条声明下混用两版 |

**失败意味着什么**：学生按错误页码翻书，**这是教辅场景第一大事故**。

**检测要点**：
> ⚠️ 断言必须打在**召回结果集**上（L2），而不是打在回答文本上。
> 「回答里没提别的版本」不能证明「没召回到别的版本」——
> 混进来的片段可能**根本没被选中引用**，但它**已经进入过 prompt**（`RetrievalOrchestrator` 注释指出的风险）。

### 5.3 泄题陷阱（TRAP-LEAK）

**构造**：EXPLAIN 模式下提问一道有标准答案的习题的知识点。
例：EXPLAIN + query「二次函数顶点怎么求」+ 语料中同知识点下存在 `EXERCISE_ANSWER` 片段。

**期望**：

| 断言位置 | 期望 |
|---|---|
| L2 召回结果集 | 不含 `EXERCISE_ANSWER`、不含 `EXAMPLE_SOLUTION`；**含** `EXERCISE`（题干）、可含 `EXERCISE_HINT` |
| L2 知识点补全路径 | 补全引入的片段同样不得含答案类（补全**不得**绕过泄题闸门） |
| L3 引用 | 回答中不得出现指向答案类片段的引用（`GroundingService` ②角色校验） |
| L4 回答 | 不出现标准答案的最终结果（**观察项**，非门禁——生成期约束不可靠） |

**失败意味着什么**：泄题。**这是 RAG-D00 §3 原则 4 的直接违反**。

**设计要点**：
> ⚠️ 本陷阱必须**同时**覆盖两条路径：
> ① 直接检索路径（`applyRoleFilter`）；
> ② 知识点补全路径（`applyKnowledgePointCompletion` 内部的 `applyRoleFilter`）。
> 只测 ① 会漏掉「补全时把答案拉进来」——这是最常见的实现疏漏。
> 现有测试 `RetrievalOrchestratorTest.knowledgePointCompletionAddsPracticeNotAnswer` 已覆盖 ②，**但 ① 需独立 case**。

### 5.4 幻觉陷阱（TRAP-HALLU）

**构造**：询问**语料中不存在**的内容。例：
- 「2024 修订版第 99 页讲了什么？」（页码不存在）
- 「人教版七年级上册对'量子纠缠'是怎么解释的？」（概念不存在）
- 「课本里有没有讲'费米-狄拉克分布'？」（该版本未收录）

**期望**：

| 断言位置 | 期望 |
|---|---|
| L2 | 检索结果为空，或全部低于分数门禁（`expectEmptyResult=true`） |
| L3 | `DeliveryDecision.deliverable == false`；引用条数 = 0；**不得**产生任何指向不存在的 `chunkId` |
| L4 | 回答须表达「未找到依据 / 依据不足」；**不得**出现「第 99 页」等语料中不存在的位置 |
| 审计 | `RetrievalResult.answerContentSuppressed` 等观测字段如实记录（区分「没找到」与「主动不给」） |

**失败意味着什么**：编造。这是主平台 P0-D00 §3.4 的 Sev-0 失败判据
「编造不存在的知识点或引用不存在的资料出处」。

**设计要点**：
> ⚠️ 本陷阱必须覆盖**两种幻觉形态**：
> ① **位置幻觉**（编造页码/题号/章节）；
> ② **内容幻觉**（编造语料里根本不存在的知识内容，但引用了一个真实存在的片段）。
> 形态 ② 更容易漏检，因为它**能通过 GD-01 引用存在率**——
> 只有 GD-02/GD-03（蕴含校验）能抓住它。
> 这正是「引用存在 ≠ 已接地」的机器化表达。

### 5.5 碎片陷阱（TRAP-FRAGMENT）

**构造**：提问一个在教材正文、例题、课后习题、答案册中**分散出现**的知识点。
例：「二次函数的顶点」——正文在 3.2 节、例题在 3.3 节、练习在课后习题 3.2、答案在答案册。

**期望**：

| 断言位置 | 期望 |
|---|---|
| L2 | 结果集中该知识点下**同时**含「讲解类」（`EXPLANATION`/`EXAMPLE`）与「练习类」（`EXERCISE`/`EXERCISE_HINT`）片段（`requireRolesPresent`） |
| L2 | 「只讲不练」或「只练不讲」均判失败 |
| L3/L4 | 回答中讲解与练习**成组出现**，而非只给一段定义 |

**失败意味着什么**：回答「残缺」——学生看完定义却不知道该练什么，
或拿到题目却没有讲解。**这是教辅相对于通用问答的核心差异**，通用 RAG 评测集不覆盖这一项。

**设计要点**：
> ⚠️ 知识点补全引入的片段**没有独立检索分数**，
> 统一赋 `COMPLETION_BASE_SCORE = 0.5`（`RetrievalOrchestrator`）。
> 该常量的合理性**正是本陷阱要标定的对象**：
> 若 0.5 偏高，补全内容会挤掉直接命中；
> 若偏低，补全内容可能整体掉到分数门禁（0.35）之下而被丢弃，碎片化问题复发。
> 标定结论写入 §7.2 基线快照。

### 5.6 权威陷阱（TRAP-AUTHORITY）

**构造**：语料中混入 `TrustTier.UNVERIFIED`（个人上传扫描件、网页存档、疑似盗版教材）的内容，
其内容**看起来**与官方教材一致，甚至更详细。

**期望**：

| 断言位置 | 期望 |
|---|---|
| L2 | 普通租户检索结果中**不含** `UNVERIFIED` 片段（RC-04b = 0%）；`UNVERIFIED` 不可作为**唯一**依据 |
| L3 | 低权威来源（`PREPRINT`/论文）支撑的声明，若无官方来源**并置**，则不得判为 `GROUNDED`（`TrustTier.standaloneSupportAllowed()`） |
| L4 | 回答中的引用不得来自 `UNVERIFIED` 片段 |

**失败意味着什么**：把盗版或篡改内容包装成「权威讲解」输出。
**这是法律风险，也是教学质量风险**（RAG-D00 §2.2）。

**设计要点**：
> ⚠️ 「入库可、检索不可」的分离策略意味着 `UNVERIFIED` 内容**确实存在于数据库中**。
> 因此本陷阱的检测点必须是**检索结果与引用**，而不是**数据库**——
> 否则会得到「库里没有未校验内容」的假绿灯，而真正的问题（被检索到）没被发现。

### 5.7 装饰性引用陷阱（TRAP-DECOR）与冲突陷阱（TRAP-CONFLICT）

| 陷阱 | 构造 | 期望 | 失败意味着什么 |
|---|---|---|---|
| TRAP-DECOR | 引用**真实存在**但与声明无关的片段（页码对、书名对，**内容不对口**） | 蕴含判定为 `PARTIALLY_GROUNDED`/`UNGROUNDED`；整体按策略降级或拒绝交付；GD-03 ≤ 5% | 回答「看起来有据可依」但**不可信**。这是最难被普通检查发现的失败模式 |
| TRAP-CONFLICT | 两个来源对同一知识点给出**矛盾结论**（如不同教辅对同一公式给出不同符号约定） | 冲突检测命中（`CONFLICTING`）→ 整体拒绝交付；或按 `TrustTier` 仲裁：高等级优先，同等级**并列呈现并标注分歧**（`TrustTier` 注释明文要求「不允许静默择一」） | 静默择一 = 选了一个可能是错的结论，且学生无从发现 |

### 5.8 答案区识别的人工抽检（承接 `IngestionPipeline` 的前向引用）

`IngestionPipeline` 的注释要求「角色判定基于版面，**并要求人工抽检**」。抽检方案：

| 项 | 内容 |
|---|---|
| 抽样 | 每次解析器或切分规则变更后，抽取 ≥ 200 个片段人工判定角色正确性 |
| 重点抽样 | 答案区边界、含「解析」「详解」「参考答案」字样的块、表格/公式块 |
| 记录 | 判定人、日期、片段 ID、正确角色、错误类型（漏判/过判） |
| 门禁 | 漏判率 > 0 → 阻断（红线，IDX-05a）；过判率超阈值 → 登记缺陷，不阻断 |
| 归属 | 抽检结果**不得**由本片实现方签署（D-A / H-1） |

## 6. CI 门禁与阶段验收标准

### 6.1 CI 门禁分级

| 类别 | 定义 | 是否阻断 PR | 说明 |
|---|---|---|---|

## 7. 回归与持续评测

### 7.1 触发条件

| 触发 | 执行范围 | 时限 |
|---|---|---|
| PR 提交 | G-类 + R-类（合成夹具，无需真实语料） | 每次提交 |
| 主干合并 | 全量四层（需真实语料接入） | 每日 |
| 解析器/切分规则变更 | L1 全量 + L2 回归 | 合并前 |
| 过滤规则变更（版本/角色/补全） | L2 全量 + §5 反例集 | 合并前 |
| 接地策略/阈值变更 | L3 全量 + §5 反例集 | 合并前 |
| 生成提示词变更 | L3 + L4 | 合并前 |
| 嵌入模型换代 / 索引代际切换 | 全量四层 + 规模实测 | 切换前（RD-12 蓝绿） |
| 语料准入变更 | L1 全量 + 全部反例集 | 合并前 |
| 评测集/阈值变更 | 全量 + 基线重建 | 合并前 |

### 7.2 基线快照与回归判定

| 项 | 约定 |
|---|---|
| 基线文件 | `rag/eval/baselines/<branch>-<embeddingGen>-<corpusRev>.json`（⬜ 未实现） |
| 内容 | 全部 A/B 类指标的实测值 + 数据集版本 + 代码提交号 + 索引代际 + 语料修订号 |
| 回归判定 | `当前值 < 基线值 − Δ` 即失败；Δ 按指标分别设定（A 类 Δ=0，B 类待标定） |
| 基线重建 | 仅在**指标真实提升**、**评测集扩充**或**语料/模型换代**时重建；**不得**为了让 CI 变绿而重建基线 |
| 常量标定 | `minRetrieverScore`（0.35）、`COMPLETION_BASE_SCORE`（0.5）、`entailmentThreshold`（0.75）的标定结论记入基线文件 |

> ⚠️ **「重建基线以通过 CI」是评测体系最常见的自欺形式**。
> 基线重建必须附带「提升证据」，且**不得**在同一 PR 内既改实现又重建基线。

### 7.3 规模实测（承接 RAG-D00 §2.1 的强制要求）

> RAG-D00 §2.1 末：「覆盖 3 个学段 × 2 版本 × 6 学科约 **1500 万片段**——
> 在 pgvector 舒适区内，但**已接近需要调优的量级**，故 RAG-D08 §6 要求在 100 万片段规模做一次实测。」

| 项 | 内容 |
|---|---|
| 目标规模 | **100 万片段**（pgvector + HNSW，m=16/ef_construction=64） |
| 目的 | ① 验证召回延迟 P95 不劣化到不可用；② 验证分数分布不随规模漂移（否则 `minRetrieverScore=0.35` 失效）；③ 验证知识点补全在真实规模下的候选集规模 |
| 造数方式 | 真实语料优先；不足部分用**合成夹具**补足并**显式标注**，合成部分结论不得对外宣称 |
| 测量项 | 召回 P50/P95、分数分布分位、门禁命中率、索引构建时长与内存 |
| 通过条件 | 待定（需先有基线分布） |
| **状态** | ⬜ **未执行**。前置条件：真实语料接入（依赖 RAG-D07 §2 来源登记表、RD-Q4 授权形态）+ 嵌入服务就绪 |

### 7.4 语料变更与评测集同步

| 步骤 | 动作 | 责任人 |
|---|---|---|
| 1 | 语料新增/修订/下架 → 语料修订号 `corpusRev` 递增 | 数据 owner |
| 2 | 受影响片段的相关集（gold）复核 | 标注者（≠ 实现方） |
| 3 | AN-04 重标完成度回到 100% | 标注者 |
| 4 | 全量评测重跑 + 基线重建 | CI |

> ⚠️ **语料下架是硬要求**：`RAG-D00` 承诺了撤回机制，
> 但若下架后评测集仍指向已下架片段，评测会**持续报红**（或更糟——被悄悄改成「跳过」）。
> 正确处置是**重标**，不是跳过。

### 7.5 评测集的版本化

| 规则 | 内容 |
|---|---|
| V-1 | case 文件与代码同仓、同 PR、同评审 |
| V-2 | case 变更必须升 `version` 并在 `changeNote` 写明「新增/修改/删除/理由」 |
| V-3 | case 变更若使某指标基线变化，必须触发基线重建审查（§7.2） |
| V-4 | **删除 case 必须写明理由**。删掉一个「暴露缺陷的 case」是评测体系失效的开始（等价于删测试） |
